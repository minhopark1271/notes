# 테스트 레벨

> 상태: 도입 (2026-09-14). 레벨 축·실행 스크립트·git 훅 구현 완료. CI 연결은 후속
> 구현 이슈: [#359](https://github.com/NumeRealWorks/DashOpti_GUI/issues/359)
> 실행 경로 상세: [test-execution.md](test-execution.md)

## 1. 목적

테스트 실행을 **누적 레벨**로 나눈다. `Level N` 을 주면 1..N 이 전부 돈다.

목적은 **CI 와 커밋 경로가 항상 비싼 테스트를 돌리지 않게 하는 것**이다. 테스트 케이스는 앞으로 늘어나고, Level 3 에만 들어갈 초장시간 외부 테스트가 예정돼 있다. 축을 지금 세워 두지 않으면 스위트가 커진 뒤 수백 개를 소급 분류해야 한다.

레벨은 **서브테스트(Qt Test 슬롯) 단위**다. 실행 파일 단위가 아니다. 한 실행 파일 안에 Level 1 과 Level 3 이 섞여 있다.

## 2. 레벨과 트리거

| 레벨 | 트리거 | 성격 |
|---|---|---|
| **1** | `.githooks/pre-commit` | 커밋마다 무조건 도는 최소 가드 |
| **2** | `.githooks/pre-push` | push 전 방어선 |
| **3** | CI | 전부. 트리거(merge 시점 / package build 시점)는 규모가 정해진 뒤 판단 |

훅은 한 클론당 1회 `git config core.hooksPath .githooks` 로 켠다. 스크립트 구성과 동작은 [test-execution.md](test-execution.md).

git 훅은 **게이트가 아니다.** `--no-verify` 로 우회된다. 훅은 실수 방지이고 강제는 CI 뿐이다. 둘은 대체가 아니라 계층이다.

## 3. 분류 기준

**레벨은 구조로 정한다. 실행 시간으로 정하지 않는다** (→ 5절).

위에서부터 순서대로 판정하고, 걸리는 첫 항목의 레벨을 쓴다.

### Level 3 — 하나라도 해당하면

- 고정 대기를 한다 (`QTest::qWait`)
- 타임아웃이 만료되기를 기다린다 (ready timeout, watchdog)
- 외부 상태를 폴링한다 (`tasklist` 로 PID 생존 확인 등)
- 저장소 밖 산출물에 의존한다 (실 extension exe, 대용량 입력)

저장소 밖 산출물에 의존하는 Level 3 케이스는 그 산출물의 루트를 `DASH_TEST_RESOURCES` 환경변수로 받는다. 상대 경로는 케이스마다 고정한다(예: `tests/TestDataLoaderCache.cpp` 의 `largeXmlPrefetchThenLoadParsesOnce`). 환경변수가 없거나 가리키는 디렉터리·파일이 없으면 `QSKIP` — 리소스 저장소가 아직 없어도 스위트는 항상 통과해야 한다.

### Level 1 — 전부 해당하면

- 프로세스를 띄우지 않는다
- 스레드를 만들지 않는다
- 이벤트 루프에서 조건을 기다리지 않는다 (`QTRY_*`, `QSignalSpy::wait`)

즉 순수 로직·자료구조·문자열·직렬화. 파일 하나 읽고 쓰는 정도는 위 셋에 걸리지 않으므로 Level 1 이다.

### Level 2 — 나머지

실프로세스·파일·스레드를 쓰되 고정 대기가 없는 것. 조건이 충족되는 즉시 반환하는 대기(`QTRY_*`, `QSignalSpy::wait`)는 여기다.

### 예외 — 실패 비용이 구조를 이긴다

트리거의 예산 안에 들어온다면, **실패했을 때의 피해가 큰 검사는 구조 기준보다 한 단계 낮게 둔다.**

현재 유일한 예외는 고아 프로세스 3종이다 — `cancelReapsGrandchild`, `killOrphansReapsGrandchild`, `killOrphansSparesSameNamedBystander`. 구조상 폴링이라 Level 3 이지만 Level 2 에 둔다. 실패하면 사용자 PC 에 프로세스가 영구히 남거나, 우리가 띄우지도 않은 동명 프로세스를 죽인다. 사용자 환경에 흔적을 남기는 실패는 push 이후에 발견하면 늦다.

예외는 예외로 남긴다. 기본은 구조 기준이다.

## 4. 기본값은 Level 1

표에 없는 함수는 **Level 1** 로 취급한다. 그래서 표에는 **Level 2 와 3 만 적는다.**

미기재 테스트는 Level 1 로 돌아 **커밋이 실제로 느려진다.** 그 느려짐이 곧 "분류를 빠뜨렸다" 는 신호다. 기본값을 3 으로 두면 새 테스트가 조용히 빠른 레인에서 사라져 아무도 모르게 커버리지가 비는데, 그쪽이 더 위험하다.

느려진 것을 자동으로 잡아내는 장치는 두지 않는다. 임계값을 기계가 정할 수 없기 때문이다 — 실행 환경마다 다르고, 스위트가 커진 뒤 어느 정도가 정상인지 예측할 방법이 없다. **사람이 판단한다.**

## 5. 실행 시간을 기준으로 쓰지 않는다

측정한 실행 시간은 기계 성능·부하·디스크에 따라 달라진다. 다음에 쓰지 않는다.

- 레벨 판정 (→ 3절 구조 기준을 쓴다)
- 통과·실패 판정
- 문서나 이슈에 박아 두는 고정 수치

측정치가 의미 있는 경우는 **같은 기계에서 비교**할 때다. CI 가 바로 그 고정된 기계이므로, 거기서 재는 레인 전체의 소요 시간은 예외다 — 6절.

## 6. 레벨 건강 한도 (CI)

5절이 배제하는 것은 *제각각인 개발자 기계의 절대 시간으로 개별 테스트의 레벨을 판정하는 것*이다. **고정된 CI 머신에서 레인 전체의 소요 시간을 추적하는 것은 다른 이야기이고, 유효하다.** 같은 조건에서 반복 측정하므로 비교 가능한 수치가 된다.

**CI 는 Level 1 레인의 소요 시간을 측정하고, 한도를 넘으면 관리가 필요함을 알린다.**

|---|---|---|
| **1** | **5분** | 임시값 |
| 2 | — | 미정 (아래) |
| 3 | — | 미정 (아래) |

측정 대상은 **ctest 실행 구간**이다. 빌드 시간은 넣지 않는다 — 빌드는 레인 분류와 무관한 별도 문제다.

한도 초과는 **개별 테스트의 실패가 아니라 레인 전체가 손볼 때가 됐다는 신호**다. 빌드를 깨뜨리지 않는다. 대응은 셋 중 하나다.

1. 분류를 빠뜨린 테스트를 표에 Level 2/3 으로 올린다 — 기본값이 1이므로 가장 흔한 원인이다 (4절)
2. 3절 기준으로 다시 봐서 Level 1 이 아닌 것을 내린다
3. 테스트 자체를 줄인다 (고정 대기를 조건 대기로 바꾸는 등)

5분은 현재 Level 1 레인 대비 여유가 매우 크다. **드리프트가 아니라 파국을 잡는 값**이다 — 누군가 무거운 테스트를 미기재로 흘려 넣었을 때 걸리게 하는 1차 저지선이고, CI 에서 기준선이 쌓이면 그때 조여도 된다.

### Level 2·3 의 한도

지금은 두지 않는다. **같은 방식(고정 CI 머신에서 레인 소요 시간 측정 + 한도 초과 시 알림)을 그대로 적용할 수 있으므로, 필요해질 때 정책으로 수립한다.** 정할 때 고려할 것:

- **Level 2** 는 pre-push 레인이라 사람이 기다린다. Level 1 보다 큰 값이겠지만 여전히 사람 기준이다.
- **Level 3** 은 CI 가 기다리므로 사람 기준이 아니다. 초장시간 외부 테스트가 들어오면 그것이 사실상 한도를 정의하게 되므로, 대상이 정해진 뒤에 잡는 편이 맞다.
- 어느 쪽이든 한도는 **알림 조건이지 실패 조건이 아니다.**

CI 구성 자체는 이 문서 범위 밖이다. 요구사항은 [#372](https://github.com/NumeRealWorks/DashOpti_GUI/issues/372) 에 있다.

## 7. 새 테스트를 추가할 때

1. 슬롯을 평소대로 추가한다.
2. 3절 기준으로 레벨을 판정한다.
3. Level 2 나 3 이면 그 파일의 `kTestLevels` 표에 한 줄 추가한다 — 값은 `DashTestLevel::Level::Push` / `::Ci`. **Level 1 이면 아무것도 하지 않는다.**
4. `DASH_TEST_LEVEL=1` 로 돌려 의도한 레인에 들어갔는지 확인한다.

레벨을 바꿀 때도 표만 고친다. 테스트 본문은 건드리지 않는다.

## 8. 실행 방법

```powershell
scripts\run_tests.ps1 -Level 1
```

훅을 켜 두면 커밋·push 때 자동으로 돈다. 스크립트 구성·직접 실행·실패 정책은 [test-execution.md](test-execution.md).

레벨과 관련해 알아 둘 것만:

- `DASH_TEST_LEVEL` 이 없거나 1~3 밖의 값이면 **전부 실행**한다. 기존 동작이 기본이다.
- 스킵된 케이스는 ctest 출력에 `SKIP` 과 사유로 남는다. 조용히 사라지지 않는다.
- `-Level` 과 `-Filter`(`ctest -R`) 는 **직교한다.** 함께 쓰면 둘 다 적용된다.

## 10. 구현

`tests/TestLevel.h` 가 전부다.

- 레벨은 `enum class DashTestLevel::Level { Commit = 1, Push = 2, Ci = 3 }` 이다. 이름은 **그 테스트가 어느 레인부터 도는지**를 가리킨다 — 레벨은 누적이라 `Commit` 테스트는 push·CI 에서도 돈다. 숫자는 `DASH_TEST_LEVEL` 값과 그대로 대응하므로 바꾸지 않는다 (훅·스크립트가 숫자로 준다).
- `DASH_TEST_LEVEL` 을 읽어 요청 레벨을 돌려준다. 없거나 범위 밖이면 3.
- 각 테스트 클래스가 파일 로컬 네임스페이스에 `kTestLevels` (`DashTestLevel::Table` = 함수명 → `Level`) 를 들고 있다. 없는 키는 `Level::Commit`. 테스트마다 실행 파일이 따로라(`tests/CMakeLists.txt`) 이 네임스페이스는 익명이어도 이름이 있어도 된다.
- 각 클래스의 `init()` 이 `skipReasonIfAny()` 를 불러, 비어 있지 않으면 `QSKIP` 한다. `QSKIP` 은 매크로라 테스트 함수 안에서만 호출할 수 있어 헤더는 사유 문자열까지만 만든다.

CMake 변경은 없다. 테스트 등록 구조도 그대로다.
