# #565 조건 파라미터화 모델이 자기가 보여 주는 문서를 값으로 들게 한다 — 전역 원장 방송 의존을 걷는다

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/565
- Board status: Done
- Labels: ['refactor']

## 무엇이 문제인가

`DashConditionParameterization` 은 자기가 보여 주는 문서를 들지 않는다. 경로 하나(`m_loadedFilePath`)만 들고, 값이 필요할 때마다 전역 싱글턴 원장 `DashAnalysisModelContextRegistry` 를 가리킨다.

그래서 테이블이 낡았다는 것을 스스로 알 수 없고, 원장 전체에 대고 쏘는 `documentChanged(QString filePath)` 방송을 들어야만 안다. 이 신호에는 출처가 없다. 모델은 "내가 방금 publish 한 세대" 와 "남이 올린 세대" 를 구별하지 못한다.

그런데 이 방송의 유일한 발신자는 `DashConditionParameterization::commitEntryValue` 이고, 유일한 수신자도 같은 모델이다. 즉 지금 구조는 이렇다.

```
commitEntryValue: toMutable → edit → seal → publish(원장)
                                              ↓ documentChanged 방송
                          같은 모델의 람다 ←──┘
                                    ↓
                     refreshFromLoadedAnalysis → 원장을 다시 읽어 테이블 재구축
```

방금 손에 들고 있던 sealed 문서를 원장에 넣고, 전역 방송으로 자기에게 되돌려 받은 다음, 원장에서 도로 꺼내 테이블을 짓는다.

## 왜 지금 내는가

PR #564 에서 이 구조가 두 번 새어 나왔다.

1. 첫 적재도 방송을 내게 했더니(c0c386f) 모델이 자기가 시킨 적재를 되돌려 듣고 갱신이 두 번 돌았다. 처음에는 세대 식별자를 달아 걸러냈다가, 근거가 성립하지 않아 그 방송 자체를 지웠다(9a9858b).
2. publish 가 `commitData` 스택 위에서 나기 때문에 방송을 `QueuedConnection` 으로 한 틱 늦춰야 했다. 모델이 자기 문서로 직접 테이블을 지었다면 애초에 스택을 건너뛸 이유가 없다.

둘 다 "모델에 로컬 상태가 없고 신호에 출처가 없다" 는 한 가지 결함의 증상이다.

## 제안

- `DashConditionParameterization` 이 `DashRwDocument` 를 **값으로** 든다. 문서는 불변 값이므로(#324 #429) 들고 있어도 남의 편집에 흔들리지 않는다.
- `commitEntryValue` 가 seal 한 문서로 **자기 테이블을 직접 다시 짓고** 그다음에 publish 한다. 화면 갱신이 방송 왕복을 타지 않는다.
- `DashConditionParameterizationWidget` 의 FE 조건 하이라이트도 `ctx->document()` 로 원장을 읽는다. 모델이 든 문서를 쓰게 따라간다.
- 남이 올린 세대를 들어야 하는 소비가 남는다면, 방송을 지우는 대신 어느 세대인지 실어 보내는 쪽을 검토한다.

## 범위 밖

- `documentChanged` 를 아예 없앨지는 이 이슈에서 정하지 않는다. 지금 수신자는 하나지만, 렌더링·모델링 트리가 세대 교체를 들어야 할 수 있다.
- 메시 publish 가 생기면 `replaceDocument` 의 블록 속성 재바인딩이 선행 항목이다(코드에 TODO 있음).

## 확인 방법

- 조건 값을 편집하면 `documentChanged` 를 거치지 않고 테이블이 갱신된다.
- 편집 커밋과 테이블 재구축이 같은 스택에서 돌지 않는다(편집 중 아이템 파괴 없음).
- 조건 모델·위젯에서 `DashAnalysisModelContextRegistry::Instance()` 직접 참조가 사라지거나 적재 한 곳으로 줄어든다.
