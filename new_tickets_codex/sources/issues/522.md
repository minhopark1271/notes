# #522 Data Preprocessor:  Data Upload 탭에서 run마다 이름이 다른 .rst 파일이 파일별로 테이블 분리됨

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/522
- Board status: Done
- Labels: ['bug', 'refactor', 'source:QC']

## 현상
DataPreprocessor > Data Upload 탭에서 ANSYS 결과(.rst) 파일명이 run마다 다르면(예: `runs115/j00c81c06_17cb_4f37__000.rst`) 파일 하나마다 "Analysis Type : STATIC | <파일명>" 헤더와 1행 테이블이 생성되어 수천 개의 테이블이 나열된다. 같은 구조의 Abaqus(.odb)는 하나의 테이블로 묶인다.

<img width="2149" height="1764" alt="Image" src="https://github.com/user-attachments/assets/48a1df2b-cb27-498c-87eb-4556dd3c7cf8" />

## 원인
`model/DashDataProcessor.cpp`의 `onAnalysisFileSelected()`에서 그룹 키(`patternFileName`)를 정할 때, 1개 run에만 등장하는 파일명을 `result.<ext>`로 통일하는 분기가 `.rst`를 명시적으로 제외한다(`extLower != ".rst"`). 5a4388b(2026-04-17)에서 확장자 기반 fallback 매칭이 제거된 뒤, 후속 수정 eb1f841·1aa42ae가 .odb만 다시 묶고 .rst는 그대로 두어 회귀가 남았다.

## 기대
.rst도 다른 확장자와 같은 규칙(run마다 이름이 다르면 하나의 그룹으로 통일)을 적용해, Abaqus 예시처럼 Analysis Type당 테이블 하나에 모든 run이 나열된다.

## 추가 현상: job이 생성하는 .rst 파일명
ANSYS run 폴더의 결과가 `j00c81c06_17cb_4f37__000.rst` 형태의 UUID 기반 이름으로 생성되고, 같은 폴더에 `..._000_0.rst` ~ `..._000_15.rst` 16개가 함께 남는다. 이전에는 입력 `.dat`와 같은 이름(`<key>.rst`)으로 생성되었다.

## 원인
b0d412f(2026-08-27)에서 Ansys 실행을 cae-launcher C++ API로 치환하면서 job 이름을 GUI가 넘기지 않고 라이브러리가 발급하는 TaskID(UUID)에서 파생하게 되었다(`dash::cl::ansys_mechanical::make_job_name`, 서브태스크 접미 `{}_{:03}`). `AnsysMechanicalTaskConfig`에는 `job_name` 항목이 없어 GUI에서 이름을 지정할 수 없고, Abaqus만 `job_name = runKey`로 `<runKey>.odb`를 보존했다. 이 이름 변화가 run마다 고유한 .rst 이름을 만들어 본 이슈의 테이블 분리를 유발한다.
`_0`~`_15` 부속 파일은 DMP(`-dis -np`) 랭크별 결과가 정리되지 않고 남은 것으로 추정된다. `DashDataProcessor::filterSplitFiles()`는 `<base>N.rst` 패턴만 걸러 `<base>_N.rst`는 통과시킨다.

## 기대
Abaqus와 같이 ANSYS도 `<key>.rst`로 산출물 이름이 보존되거나(cae-launcher에 job_name 지정 경로 필요), 그것이 불가하면 Data Upload 쪽이 UUID 이름과 `_N` 부속 파일을 처리한다.
