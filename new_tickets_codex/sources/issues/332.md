## 2. `selectHandlesGreedyByUnit` 을 mesh-ops `sample_handles()` 로 대체

> **#305(analyzer Eigen 정리)의 선행 조건**

### As-is

GUI 가 `controller/DashMorphingController.cpp:974~` 에서 직접 구현한다:

Wendland C2 커널 행렬 → `M.llt().solve(...)`(Cholesky) → `A * coeff` 잔차 → argmax 반복 채택.

### To-be

mesh-ops 에 **같은 알고리즘이 이미 공개돼 있다** — `MeshOps/Morphing/Sampling.hpp` 의 `sample_handles(pinned, samplable, SamplingPolicy)`:

> *"pinned 합집합을 초기 basis 로, 잔차의 argmax 를 반복 채택하고 최저 잔차 prefix 를 돌려준다"*

- `SamplingPolicy` 가 `tolerance` · `maximum_handles` · `regularization` · `stagnation_patience` · `minimum_improvement` 를 노출
- Cholesky 자리는 **MKL PARDISO** 가 대신한다

### 효과

교체하면 GUI 의 Eigen 선형대수 사용처가 `DashPearsonPlotter` **하나로 줄어** `eigen3` 제거가 사거리에 들어온다(#305).

### 리스크

**반복 채택 순서가 달라지면 선택되는 핸들 집합이 바뀔 수 있다.** 결과 동등성 확인 필요.

## GUI 핸들 모델의 실체

`DashHandlePickingInteraction::OnHandleGizmoChanged` 가 기즈모 조작을 핸들의 세 속성에 나눠 싣는다.

```
translate → points->SetPoint(index, pos)                    핸들 위치
rotate    → handleNormals->SetTuple(index, dir)             핸들 방향
range     → UpdateHandleRange(index, -RangeMin, RangeMax)   변위 범위
```

즉 설계변수는 **"방향 `dir` 을 따라 `[lower, upper]` 범위의 스칼라 변위"** 다.

## 대조표

| GUI | mesh-ops | 판정 |
|---|---|---|
| 표면 핸들 = 위치 + `HandleNormal` + 스칼라 변위 | `GroupHandles` + `GroupControl::FieldRate`<br>좌표 = base + **rate × field** | **정확히 일치.** field = 법선, rate = 변위 |
| **단건 핸들** (`groupId == 0`) | **항목 1개짜리 `GroupHandles`** | **덮음** — 아래 별도 절 |
| `GizmoGroup` 병진 (delta, 멤버 동일 offset) | `GroupControl::Translation` (절대값) | **덮음.** delta → 절대 어댑터 1줄 |
| 기즈모 회전 = 방향 편집 | field 는 최초 주입분 고정 (`with_field_control` 재주입 금지) | **덮음**, 단 "편집 = 재생성" 으로 번역 |
| 핸들 위치 이동 | base 변경 → 새 `GroupHandles` | **덮음** (지금도 `SetInitialHandles` 가 재구축) |
| `LowerRange` / `UpperRange` | 없음 | **대응 불필요** — DOE 설계변수의 범위지 morphing 의 성질이 아니다. 책임 경계가 맞다 |
| per-handle `SupportRadius` | `GroupHandlesOptions::support_radius` 또는 `"SupportRadius"` array | **덮음** — 본 티켓 1번 항목 |
| 허공 핸들 hexa (`HexaGridParams`) | — | **갈림길**, 아래 |
| 실린더 (`CylinderGridParams`) | — | GUI 가 점군을 만들어 `GroupHandles` 에 넘기면 **덮음** |
| marching plane (`HandleType 2` · `PlaneIds` · `Bounds` 2D) | 없음 | **유일한 미대응** |

`with_translation_control()` / `with_field_control()` 이 *"현재 pose 를 base 로 하는 파생 · 현재 pose 로 뜬 baseline 과 start 가 일치"* 를 보장하므로 **"편집 = 재생성" 번역이 계약 안에서 성립한다.**

## 단건 핸들 = 항목 1개짜리 GroupHandles

핸들 추가를 **개별 핸들이 아니라 항목 1개인 그룹**으로 본다. field 는 그 핸들의 법선 하나, rate 는 그 핸들의 변위다. 그룹이 커지는 것은 항목 수가 느는 것일 뿐 종류가 달라지지 않는다.

귀결:

- **개별/그룹 이원화가 소멸한다.** 지금은 기즈모 콜백이 개별(`DashHandlePickingInteraction.cpp:2036`·`:2060`)과 그룹(`:2356`)으로 갈려 있고 실행 경로도 그만큼 갈린다
- **`GroupIds` array 와 `groupId == 0` 특례가 사라진다.** `OnHandleGizmoChanged` 의
  ```cpp
  // only update local normal when it is not controlled by group gizmo
  if (groupId == 0) { localNormals->SetTuple(index, dir); }
  ```
  분기가 없어진다 — 소속은 "어느 `GroupHandles` 인가" 로 표현되고 무소속이라는 상태가 없다
- **`LocalNormal` / `HandleNormal` 이원화의 근거도 같이 검토 대상이 된다.** 둘이 갈린 이유가 위 특례였다면 하나로 준다
- freeze 는 `MorphingConfiguration::create(blocks, ...)` 가 **block 목록**을 받으므로, 그룹이 그대로 block 이 된다 — 단건이든 N개든 같은 자리에 들어간다

## BoxHandles — 다른 물건이다

```
GUI       HexaGridParams{gridX, gridY, gridZ, bbox 6값, isBoxAuto}
          → setHandlesBoxhandle → vector<BoxHandleInfo{position[3], vector[3]}>
          → 생성 1회. 이후 각 점이 독립 핸들

mesh-ops  BoxHandlesOptions{x, y, z, width, height, depth, num_subdivisions, support_radius_scale}
          → (n+1)³ lattice + control box 6면
          → move_face(FaceId, disp) 로 면을 끌면 전 lattice 재배치 — FFD
```

차이 셋 — **살아있는 생성기 vs 생성 1회**, **`num_subdivisions` 하나 vs 축당 `gridX/Y/Z`**, **방향 벡터 유무**.

| 선택 | 결과 |
|---|---|
| `GroupHandles` 로 치환 | 현재 UX 유지. 점군은 지금처럼 GUI 가 생성. hexa·실린더가 **한 번에** 덮인다. mesh-ops 요청 **0건** |
| `BoxHandles` 로 치환 | UX 가 FFD(면 드래그)로 **바뀐다**. 축당 분할 수가 없어 mesh-ops 요청 **1건** |

## 본 티켓에 대한 귀결

작업 2건의 성격이 바뀐다.

**1번 (per-handle `SupportRadius`)** — "UI/계면을 만든다" 가 아니라 **`GroupHandles` 치환에 포함**된다. `GroupHandlesOptions::support_radius` 와 `"SupportRadius"` array 를 그 타입이 이미 소유하므로, 별도 계면이 아니라 그룹 생성 인자가 된다.

**2번 (greedy → `sample_handles()`)** — 그대로 유효하되, 0.2.0 문서가 *"선별은 한 번만 돌리고 `Sampled::selected` 를 저장해 모든 실행이 같은 block 으로 freeze 한다"* 를 계약으로 못박았다. 수용 조건이 "결과 동등성 확인" 이 아니라 **"선별 1회 + 영속화"** 다.

**신규 3번 — `DashMorphingEngine` 해체.** 그 객체가 들고 있는 `m_baselineHandles`(`HandleConfiguration`)·`m_morphingConfig`(`MorphingConfiguration`)는 **승격 1·2단의 산출물이자 불변 값**이고 mesh-ops 가 동시 사용 안전을 명시한 타입이다. 값 3단 승격을 가변 2콜 프로토콜(`SetInitialHandles` → `ExecuteMorphing`)로 되접은 래퍼이며, 공유 엔진 문제 · 2콜 프로토콜 · 레인별 `SolverOptions` 불가의 공통 원인이다. #281 Phase B3(엔진 인스턴스 격리)은 이 해체로 대체된다 — 나누는 것이 아니라 없어진다.
