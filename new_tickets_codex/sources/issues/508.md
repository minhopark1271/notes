## 배경

#507 리뷰 커멘트([discussion_r4058848794](https://github.com/NumeRealWorks/DashOpti_GUI/pull/507#discussion_r4058848794))에서 지적. `DashProjectManager::Instance()` 는 lazy new 라 nullptr 를 반환하지 않는데, 직후 `if (!prjMgr)` 가드가 코드 전반에 반복됨. 가드가 걸리면 hard fail 이 아니라 로그 후 조용히 건너뛰므로, 실제로 도달하면 원인 추적이 어려운 silent path 가 됨.

d23e723 에서 CAD·Condition `setModel` 재로드 경로 2곳을 먼저 정리 — 나머지는 본 이슈.

## 대상 접근자 (항상 non-null)

| 접근자 | 근거 |
|---|---|
| `DashProjectManager::Instance()` | lazy new — [controller/DashProjectManager.cpp:16](controller/DashProjectManager.cpp#L16) |
| `DashManager::Mgr()` · `PrjMgr()` | lazy new — [controller/DashManager.cpp:207](controller/DashManager.cpp#L207) |
| `PrjMgr()->GetProject()` | 생성자에서 `new DashProject()`, 재할당 없음 |
| `Mgr()->GetDesignVariableModel()` | 생성자에서 생성, 재할당 없음 — [controller/DashManager.cpp:97](controller/DashManager.cpp#L97) |

`GetIOController()` 는 프로젝트 열기 전·닫은 후 null 이므로 **대상 아님**. 단, 호출 순서상 열린 프로젝트가 전제되는 지점(Set 선택 후 진입하는 `setModel` 류)은 개별 판단.

- 복합 가드는 살아 있는 뒤 항만 남김 (`if (!prjMgr->IsProjectOpen())`)
- 삭제로 고아가 되는 로그 문자열·변수만 정리. 주변 코드 리팩터링 금지
