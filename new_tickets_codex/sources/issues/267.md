# #267 Direct 경로 케이스 상태 키 분열 — status vs status_<stale>

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/267
- Board status: Won't do
- Labels: ['bug']

## Goal

Direct Launcher 실행에서 같은 케이스의 상태가 DOE JSON 의 두 키로 갈리는 것을 고친다.

> **좌표 기준**: `refactor/async-execution` @ `3666dd7`

## Background

`DashDoeConfigManager::setSampleStatus` 는 `analysisType` 이 비면 `status`, 아니면 `status_<analysisType>` 키에 쓴다. Direct 경로는 착수와 완료에서 서로 다른 값을 넘긴다.

| 시점 | 넘기는 analysisType | 결과 키 |
|---|---|---|
| 착수 | `QString()` — `runDirectJobs:2360` / `:2419` / `:2443` / `:2480` | `status` |
| 완료 | `m_currentAnalysisType` — `reportCaseStatus:1221` | `status_<직전 DOE 값>` |

`m_currentAnalysisType` 은 `generateInputCases:1845` 에서만 세팅되고 **초기화되지 않는다.** 그래서 Direct 실행 직전에 DOE 를 돌렸다면 그때의 analysisType 이 남아 있고, 앱 시작 직후 Direct 만 돌리면 빈 값이다.

**증상**: 같은 케이스의 착수 상태와 완료 상태가 다른 컬럼에 기록되어, 표나 JSON 에서 상태가 갱신되지 않은 것처럼 보인다.

## Implementation Plan

- [ ] Direct 경로의 analysisType 규칙을 하나로 확정 — 빈 값으로 통일하거나, Direct 전용 값을 정한다
- [ ] `m_currentAnalysisType` 을 실행 진입 시 초기화 (경로별 값이 다음 실행으로 새지 않게)

## Acceptance Criteria

- [ ] Direct 실행에서 한 케이스의 착수·완료 상태가 같은 키에 기록된다
- [ ] DOE 실행 직후 Direct 를 실행해도 직전 analysisType 이 새지 않는다
- [ ] Release 빌드 경고 0, `ctest` 전건 통과

## Relations

- 제출 로직 중복 통합 티켓에 흡수될 수 있다 — Direct 제출부가 한 벌로 합쳐지면 analysisType 규칙도 한 곳에서 정해진다

## 닫음 — #264 Phase 3 이 해소한다

코드 재확인 결과 본 티켓은 #264 완료 시 **자동 소멸**한다.

키 분열의 원인은 착수와 완료가 서로 다른 analysisType 을 넘기는 것이다.

| 시점 | 현재 넘기는 값 | 결과 키 |
|---|---|---|
| 착수 | `QString()` — `runDirectJobs:2360`/`:2419`/`:2443`/`:2480` | `status` |
| 완료 | `m_currentAnalysisType` — `reportCaseStatus:1221` | `status_<직전 DOE 값>` |

#264 Phase 3 이 Direct 경로를 장부로 올리면 **두 시점이 모두 `setStageState` 를 거친다.**

```
착수   setStageState(key, 0, Running) → caseStatusUpdated(key, "Running", ctx.analysisType)
완료   handleTaskCompletion → reportCaseStatus → 장부에 있음 → setStageState → 같은 ctx.analysisType
```

`ctx` 가 하나이므로 두 값이 같아진다. FE-safe 완료 콜백(`:344`)의 `m_currentAnalysisType` 사용도 #264 Phase 2 에서 `reportCaseStatus` 로 바뀌며 사라진다.

검증 항목은 #264 의 AC 로 옮겼다. #264 완료 후에도 분열이 남으면 재개설한다.
