# #635 결과 XML 작성기가 Motion 컴포넌트의 entity_name 을 질의에 싣지 않아 전체 모델을 읽는다

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/635
- Board status: Backlog
- Labels: ['bug', 'refactor']

## 증상
Ansys Motion 배치에서 컴포넌트를 골라도 형상·필드를 전체 모델로 조회한다. 코드 경로로 확인했고 `.dfr` 실측은 하지 않았다.

- 어댑터는 Motion 형상에 `entity_name`·`location` 만 낸다 (`model/preprocessor/wrapper/LegacyJsonPreprocessor.cpp:470-472`). 질의에 `named_selection`·`entity_name` 이 없으면 전체 모델을 읽는다 (`:210-224`)
- 결과 XML 작성기의 `addComponentToQuery` 는 `location`·`named_selection` 만 옮긴다 (`model/preprocessor/DashResultXmlWriter.cpp:1316-1333`). 그래서 Motion 질의에는 `location` 만 실린다
- 미리보기는 `entity_name` 을 싣는다 (dev `DashAnalysisLauncher::addComponentToQuery`, 스택 끝 `DashResultQuery::putComponentTerm`)

## 원인
작성기와 런처가 컴포넌트 항을 따로 만들고, 작성기는 Mechanical 형식만 다룬다.

## 수정 방향
- 작성기도 `DashResultQuery::putComponentTerm` 을 쓴다 — #433 후속 공통화(9항)와 함께 한다
- 작성기는 솔버를 모르므로 Motion 판정 기준을 함께 넘긴다. 지금 판정이 세 가지(런처 `solverType`, 처리기·작성기 `currentAnalysisType == "Dynamic"`, 초기화기)라 같이 정리한다

## 확인 방법
`.dfr` DOE 에서 BODY 컴포넌트 하나를 골라 Process → 결과 XML 의 노드 수가 전체 모델과 같으면 재현이다.
