## Background

```
                              Visual actor does not exist to control visibility.
17:28:43.807  INFO  Analysis  DashAnalysisModelContextRegistry::updateActor
                              createVisualActor took 207 ms (actor 생성됨)
```

**결정적 순서다.** deck 4개(`Buckling_Tension` · `Buckling_Compression` · `Fatigue_Compression` · `Fatigue_Tension`) 전부 같은 패턴이고, 같은 날 16:35 의 별도 세션에서도 2건 재현된다. 타이밍 의존이 아니다.

`createVisualActor` 자체는 `(actor 생성됨)` 으로 끝나므로 **생성 실패가 아니라 표시 상태 유실** 쪽이다.

### 관련 위치

| 역할 | 위치 |
|---|---|
| 경고 지점 | `controller/DashAnalysisModelContext.cpp:172` — `controlVisibility` 가 `m_visualActor` null 일 때 WARN 후 반환 |

### 확증되지 않은 것

- **호출 유발 경로는 추정이다.** 로그 함수명으로 이어 붙인 것이고 호출 스택으로 확인하지 않았다.
- **사용자 영향과의 인과도 미확증이다.** 좌측 트리에서 `.inp` Load 시 형상이 화면에 나오지 않는 현상이 같은 세션에서 관찰됐으나, 이 결함이 원인인지는 확인하지 않았다. **연관 가능성**으로만 둔다.

### 범위 밖

- **#455(view 펌핑 제거)와 무관하다.** 그 변경 이전부터 있었고, 해당 한 줄을 되돌린 빌드에서도 동일하게 재현했다.
- **207 ms 를 성능 근거로 쓰지 않는다.** 계측 전용 빌드(머지하지 않음)의 값이고, 이 이슈의 논점은 순서이지 속도가 아니다.
- 수정안·설계 방향 — 원인 미조사 상태라 적지 않는다.
