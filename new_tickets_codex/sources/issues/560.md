# #560 프로젝트 전환 시 CAD 형상 모델만 정리되지 않는다 — clearAllSets() 누락으로 누수와 교차 프로젝트 오염

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/560
- Board status: Done
- Labels: ['bugfix', 'refactor']

## Goal
프로젝트를 바꿔 열면 이전 프로젝트의 CAD 형상 모델이 지워지게 한다.

## Background
> #551 / PR #554 작업 중 전수조사로 확인. 다른 8종과 달리 CAD 목록만 정리 대상에서 빠져 있다.

`DashProject::clearAllSets()`(`model/DashProject.cpp:1230`)가 프로젝트 전환 때 Set 모델 목록을 비우는데, **`m_geometryParametersCAD` 하나만 `qDeleteAll` 도 `clear()` 도 하지 않는다**. `DashProject` 인스턴스는 `DashProjectManager::Instance()` 에서 한 번 만들어져 계속 재사용되므로(`controller/DashProjectManager.cpp:28`, 소멸자는 호출되지 않는다) 그 목록이 프로젝트를 넘어 쌓인다.

객체가 해제되지 않으니 dangling 은 아니다. 대신 **누수**와 **교차 프로젝트 오염**이 생긴다.

## Technical Details

### as-is

`clearAllSets()` 가 비우는 목록 9종 — `m_geometryParameters` · `m_conditionParameterizations` · `m_analysisLaunchers` · `m_dataProcessors` · `m_aiGeometryGenerations` · `m_modelBuilders` · `m_modelBuildersMCU` · `m_modelRunners` · `m_optimizers`. `m_geometryParametersCAD`(`model/DashProject.h:145`)는 없다. Set 단위 삭제(`:1032~1035`)만 있다.

그래서 프로젝트 B 를 열면:

1. **누수** — A 의 CAD 모델이 앱 종료까지 남는다.
2. **B 의 CAD 모델이 만들어지지 않는다.** `restoreExistingModules()`(`controller/DashProjectManager.cpp:135` 에서 호출)가 `:1355~1358` 에서 `m->getSetName() == setName` 으로 중복을 판정하는데, 그 목록에 A 의 항목이 남아 있다. **두 프로젝트에 같은 이름의 CAD Set 이 있으면**(흔한 `Set1`) `exists = true` 가 되어 B 의 모델을 생성하지 않는다.
3. **UI 가 A 의 모델에 묶인다.** 소비자는 이름으로 찾는다 — `view/DashMainWindow.cpp:995`(`displayWidgetForNewSet`) · `:1207`(`handleGeometryParameterSelection`). B 의 Set 을 클릭해도 A 의 `DashGeometryParameterCAD` 가 위젯에 바인딩되어, **B 를 보면서 A 의 데이터를 읽고 쓴다.**
4. **NX CAD 파라미터가 이전 프로젝트 모델에도 적용된다.** `controller/DashManager.cpp:193` 이 `getGeometryParametersCAD()` 를 순회하며 `applyNxCadParameterJson()` 을 **전부**에 건다.

재현: 프로젝트 A 에서 CAD 형상 Set(`Set1`) 생성 → File▸Open 으로 같은 이름의 CAD Set 을 가진 프로젝트 B 열기 → B 의 `Set1` 클릭 → A 의 모델이 뜬다.

### to-be
- `clearAllSets()` 에 `qDeleteAll(m_geometryParametersCAD); m_geometryParametersCAD.clear();` 를 다른 8종과 같은 형태로 추가한다.
- 추가 후 `DashGeometryParameterCADWidget::mModel`(이미 `QPointer`, #551)이 정상적으로 null 이 되는지 확인한다.
- 다른 목록도 같은 누락이 없는지 `DashProject.h` 의 컨테이너 선언 ↔ `clearAllSets()` 를 1:1 대조하는 것이 완료 기준.

### not-to-be
- 위젯의 모델 포인터 수명 방어 — #549·#551 소관(이미 `QPointer`).
- 수명·리셋 계약의 명문화 — #431 소관.
