# #520 G11 setId 도입 + #491·#367 조인 setId 전환 (T28·T29)

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/520
- Board status: Done
- Labels: ['in-progress', 'feature', 'refactor', 'split-group:360']

## 현상
> Set 에 uuid 를 부여하고 Set name 소비자를 uuid 소비로 전환하는 것은 어려운가? 이 때 uuid 발행 규칙은 어떻게 해야 구분자로 쓸 수 있을까? — #510 리뷰 "판단 필요: 재-morph 후 deck/part 불일치" 후속

DOE 영속물이 Set 을 이름으로 조인한다 — #491 의 DOE Table 열 `{set, key}` · #367(#510)의 `parameterization` `geometry.set`·`conditions` 맵 키. Set 을 지우고 동명으로 재생성하면 다른 실체가 옛 기록에 조인되어 `getMorphingSourceInfo` 가 기록 deck(A) + live part(B) 혼합을 돌려주고, rename 시 조인이 조용히 죽는다.

**2026-09-21 재스펙 — G11(T28·T29)로 재발행.** setId 결정(SI-1\~SI-6) 확정에 따라 종전 스펙과의 결정 충돌 2건을 처분 문서 정본으로 정정: ① 형식 — `QUuid` v4 전체·`setUuid` 키 → **12자리 hex(v4 절단)·`setId` 키**(SI-1) ② 조인 지위 — "이름 주소 + uuid 검증 전용" → **setId 조인 + `name` 병기**(SI-4). DOE Table `{set, key}` 전환은 종전 범위 밖이었으나 편입. 종전 본문은 이 Issue 의 편집 이력이 갖는다.

## 범위
- 건드림: 각 `{Module}_{Set}.json` 의 `setId` 키(발급·백필·복원) · DOE Table 열 `{set, key}` · Launcher `parameterization` 조인 · 소비자 해석(치환 소속 판정·morph 매칭·part 추천)
- 안 건드림: 이름 주소 체계(`getConfigFilePath` 파일명 · run 폴더명 · DV 표시명 · 접두 headers · 도크 제목·콤보 표시) — 이름 유지(SI-4)
- 안 건드림: 하류 산출물 재바인딩 차단 — #368(조합 id) 소유 · 산출물 폴더 전환 — SI-6 별개 2단계(마스터 후속작업 14)

## 현재 구조
- Set 의 유일 식별자가 이름 — 가변(rename)·재사용 가능(삭제 후 동명 재생성)
- DOE Table 열 메타데이터가 `{set: 이름, key}` (#491 — T25) · `parameterization` 의 `geometry.set`·`conditions` 맵 키가 이름 (#510 — T20)
- 소비자 — 치환 소속 판정(`DashJobRunner`) · morph 매칭(`DashMorphingDoeExecutor`) · Preprocessor 판독기(`DashDataProcessor`) · `getMorphingSourceInfo` — 전부 이름으로 Set 을 푼다
- deck uuid 는 상대경로 v5 파생 — 위치 주소이지 실체 identity 가 아니다(sha256 이관은 후속작업 4)

## 문제
이름은 재사용 가능한 값이라 identity 가 못 된다. D26 이 산출물 스탬프에서 Set 이름을 배제한 근거(rename·동명 재생성)가 DOE 영속물 조인 전반에서 그대로 재발한다.

## 변경
정본은 [처분 문서](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Project-Manifest-Set-Identity-And-Decision-Revisions) SI-1\~SI-4.

- **T28 발급·영속·복원** — SI-1: 12자리 랜덤 hex(v4 절단) + 발급 시 프로젝트 내 중복 검사, 생성 순서는 id 에 싣지 않는다. SI-2: 각 `{Module}_{Set}.json` 의 `setId` 키가 정본(별도 Set 원장 없음), 역조회는 열기 시 전 Set 스캔, 열기 시 중복 감지(json 손 복제) → 나중 파일 재발급 + 로그. SI-3: 신규 Set 은 생성 핸들러에서, 구버전(키 부재)은 열기 복원 시 발급 + 즉시 write-back 1회 — 쓰기 실패는 로그 + 메모리 유지, 다음 열기 재발급
- **T29 조인 setId 전환** — SI-4: DOE Table 열을 `{set: setId, name: 병기, key: bare}` 로, `parameterization` 의 `geometry.set`·`conditions` 맵 키를 setId + `name` 병기로(불일치 시 Set json 정본). 소비자 해석을 setId → Set json → `referenceModel.uuid` 로 전환
- **구 기록(`{set: 이름}` Table · 이름 키 parameterization)은 기록된 대로 해석 — 이름 폴백, 재기록 없음**

## 기대
- 신규 Set 생성 → json 에 `setId` · 구프로젝트 열기 1회에 전 Set 발급 + write-back, 재열기에 값 불변 · json 손 복제 시 나중 파일 재발급 + 로그
- Set rename·동명 재생성 뒤에도 치환·morph 매칭·part 추천이 옛 실체에 조인되지 않는다(재-morph 후 deck/part 불일치 재현 케이스로 검증)
- 신규 DOE Table 열·`parameterization` 이 setId·`name` 을 들고, 구 기록은 이름 폴백으로 그대로 동작한다
