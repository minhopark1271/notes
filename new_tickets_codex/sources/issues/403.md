## Goal

모핑 실행 경로 5곳(프리뷰 · MeshQC · DOE 배치 · Optimizer · ModelRunner)이 공유하던 `DashManager::m_morphingEngine` 을 없애고, **반경과 핸들을 함께 받는 원자 계면** `DashMorphingBasis::Freeze(points, radius)` 로 대체한다. 고정점 마커 선별에 소유자(`DashFixedMarkerSelection`)를 세우고 선별 결과를 핸들 VTP 의 fieldData 에 영속화해 세 경로가 **같은 값을 읽게** 한다. 실행 경로가 GUI live 핸들 폴리데이터를 덮어쓰던 결함을 함께 닫는다.

#281 의 "워커 진입을 막는 결합 5건" 중 **⑴⑵⑶ 을 해소하는 선행 정지작업**이다. 워커화 자체는 하지 않는다.

## Background

#355(`feat/morphing-axis`)가 프리뷰·MeshQC·DOE 의 basis 불일치 4건을 고쳤으나, 고친 방식이 **주석 규율**이었다 — "반경을 `SetInitialHandles` 보다 먼저 실어라" 가 호출부 주석 3곳으로만 유지됐고, 마커 일치는 "같은 입력에 같은 시드(`0x5EEDu`)로 각자 다시 돌린다" 가 근거였다. #333 은 그 규율이 한 번 깨진 사고다.

#281 이 워커화 전제로 적은 결합 5건 중 셋이 정확히 이 구조에서 나온다:

| # | #281 의 서술 | 이 티켓의 처분 |
|---|---|---|
| ⑴ | `DashMorphingEngine` 이 멤버 상태를 들고 2콜 프로토콜(`SetInitialHandles` → `ExecuteMorphing`)을 요구 | `Freeze(points, radius)` 가 둘을 함께 받는다. 실패하면 객체가 생기지 않아(`optional`) "basis is not frozen" 상태가 표현 불가능해진다 |
| ⑵ | QC 가 프리뷰 엔진을 빌려 쓴다 | MeshQC 가 함수 지역 `const` basis 를 동결한다 |
| ⑶ | `loadHandlesFromVtp(vtp, interaction)` 이 GUI live 핸들을 통째로 교체하고 말미에 렌더를 부른다 | `loadHandleSnapshotFromVtp(path)` 가 **새 폴리데이터를 돌려준다**. `performMorphingAndExport` · `ExecuteOneSample` 이 `interaction` 대신 스냅샷을 받는다 — #281 이 제안한 "배치 정해로 교체" 그대로 |

⑷(`MakeMorphingInputSnapshot` 의 main-thread assert) · ⑸(`registry.getOrLoad`)는 **무접촉**이다 — 여전히 #281 의 blocker 다.

## Technical Details

### 브랜치 `refactor/morphing-basis-ownership` — 9 커밋

**Track B — 마커 영속화**

- `DashFixedMarkerSelection` 신설. `m_hiddenFixedIds` 를 대체하며 무효화는 신호 구독이 아니라 **입력 지문(FNV-1a 64)** 이다 — `m_handleGeometry` 에는 변이 창구가 없어 신호를 배선하면 빠뜨린 하나가 조용히 틀린 basis 를 낳는다. 종전 `empty()` 판정은 반경을 바꿔도 마커를 다시 뽑지 않았다(실버그).
- 지문 판정은 **프리뷰를 켤 때와 Save 시점에만** 한다(`MarkerPolicy::Reselect`). 제스처 종료 재동결은 켤 때의 선별을 재사용한다(`Reuse`) — 지문에 핸들 초기 좌표가 들어가 드래그마다 지문이 바뀌므로, 제스처마다 판정하면 포아송 샘플링이 놓을 때마다 돌고 마커 집합이 갈아치워져 형상이 튄다. 수동 검증 중 프리뷰 지연으로 발견해 브랜치 안에서 고쳤다.
- Save Design Variable 이 선별을 `handles_vtp` fieldData 3종(`FixedMarkerPoints` · `FixedMarkerSurfaceIds` · `FixedMarkerBasisKey`)에 싣고, 실행 경로는 `ReadFrom` 우선. 점이 아니라 fieldData 인 이유: VTP point index 공간이 handle id 재매핑과 경계 검사에 쓰이고 있다.
- 마커 없는 구 VTP 는 **실행 시점 1회 재계산 + WARN**, 파일은 고치지 않는다. 시드가 상수라 기존 DOE 결과가 비트 단위로 보존된다. 재계산조차 불가하면 **실패시킨다** — 종전엔 마커 없이 그냥 돌아 고정점 없는 basis 로 동결됐다.
- `DashMorphingUtils::loadHandlesFromVtp` · `DashMorphingDoeExecutor::loadHandlesFromVtp` 를 스냅샷 로더 하나로 합쳤다. live 를 덮는 것이 본업인 GUI 로드 경로(`DashGeometryParameterWidget::loadHandlesFromVtp`)만 남는다.

**Track A — 엔진 소유권**

- `DashMorphingBasis` 신설. `QObject` 를 버렸다(시그널 0건 · parent/`unique_ptr` 이중 소유). pimpl 대신 전방 선언 + baseline 을 `vector<array<double,3>>` 로 뽑아 MeshOps 헤더를 `.cpp` 에 가둔다. `Freeze` 가 입력 점군을 DeepCopy 한다 — 종전 엔진은 호출자의 `vtkPoints` 를 세션 내내 붙들었다.
- 프리뷰는 `DashManager::m_previewBasis`(`unique_ptr<const>`, private, **getter 없음**). 반경 fallback 을 `kDefaultMorphingKernelRadius` 상수로 — "마지막으로 쓴 사람의 값" 이라는 종전 fallback 의 성격이 #333 의 기제였다.
- `RunVolumeMorphing(const DashMorphingBasis&, targetHandles, volumeFixedIds, straight) const`. 메시 4종은 `DashManager` 에 남긴다 — `SetInputVTU` 가 함께 만드는 불변 세트라 인자로 풀면 짝이 어긋난 조합이 가능해진다.
- `DashMorphingEngine` · `m_morphingEngine` · `GetMorphingEngine()` 삭제. 순서 계약 주석 3곳은 옮겨 적은 것이 아니라 **불필요해져 사라졌다**.
