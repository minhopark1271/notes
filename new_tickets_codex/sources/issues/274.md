## Goal

**모핑 DLL 진입이 증명 없이는 컴파일되지 않는다.** 게이트가 질의(`busy()`)가 아니라 값(`Claim` / `Reservation`)으로 소비되고, DLL 실행 함수 4곳이 그 값을 인자로 요구한다. 진입점이 몇 곳이든 게이트를 빠뜨릴 수 없다.

아울러 그 불일치를 만든 **"판정이 여러 곳에 흩어져 있다"** 를 네 축에서 없앤다 — 재진입 판정은 `beginBatch`, 취소 자원 열거는 `releaseRunResources`, 종료 순서는 `AppShutdown::run`, 워커 생존은 `Reservation` 하나가 진다.

**따라서 본 티켓은 "버그 6개 수정" 이 아니라 "확정 설계와 구현을 다시 맞추기" 다.** 증상별 대응이 아니라 증상을 만든 구조를 고친다.

**최초 설계안의 기각**. 개정 1 이전 설계는 `tryAcquire() -> optional<Token>` 과 `workerExited()` 신설이었다. 실측 결과 게이트는 **상한 없는 카운팅 세마포어**(`MorphingGate.cpp:8` `g_holders`)이고 **정당한 동시 보유자가 2명**(배치 축 + 워커 축, `tst_morphing_gate.cpp:49` 가 봉인)이므로, `optional` 의 "최대 1인" 의미와 충돌해 배치 모핑이 첫 샘플부터 멈춘다. 개정 설계는 그 2명을 서로 다른 타입으로 갈라 표현한다.

## Technical Details

### as-is

**게이트 표면** (`controller/async/MorphingGate.{h,cpp}`)
- 노출은 `static bool busy()`(`:29`) · `static Token acquire()`(`:62`) 둘. `acquire()` 는 `g_holders.fetch_add(1)` 로 **무조건 성공**한다 — 획득 실패라는 개념이 없어 호출부는 `busy()` 로 묻고 별도로 `acquire()` 한다(check-then-act).
- `busy()` 호출부 7곳: 진입점 6곳(`DashManager.cpp:491`·`:503`·`:553`·`:903`·`:1002` · `DashMorphingUtils.cpp:286`) + 표시용 1곳(`DashAnalysisLauncherWidget.cpp:81`). 획득은 `generateInputCases`(배치 축 · `DashJobRunner.cpp:2281`) 과 `runNextMorphSample`(워커 축 · `:1398`) 2곳.
- 워커 축은 task 캡처의 `shared_ptr<Token>` 이 들어 **워커가 DLL 을 떠날 때** 풀린다 — 이 부분은 확정 설계의 의도대로 동작하고 `tst_worker_job::cancelDefersGateReleaseUntilTaskReturns` 가 봉인한다.

**DLL 실행 함수(funnel) 는 4곳뿐이다**
- 동기 축 — `DashMorphingEngine::RunVolumeMorphing`(`DashManager.cpp:495`) · `::ExecuteMorphing`(`:542` 진입점 1 · `:598` 진입점 1b).
- 워커/실행기 축 — `DashMorphingDoeExecutor::RunOneSample`(배치) · `::ExecuteOneSample`(진입점 5). `::ExecuteOneSampleConditionOnly`(`:69`)는 **DLL 을 타지 않는다** — condition-only 는 `.dat` 내보내기뿐이라 증명 대상이 아니다.
- `GetMorphingEngine()` 호출부는 9곳이지만 **실행은 위 3곳**이고 나머지 6곳(`DashGeometryParameterWidget.cpp:763`·`:1288`·`:2098`, `DashManager.cpp:690`·`:733`, 헤더 접근자)은 커널 반경 setter·getter 다. 증명을 요구할 지점은 접근자가 아니라 실행 함수다.

**워커 생존 판정**
- `batchActive()`(`DashJobRunner.h:63`)는 3항이다 — `m_wbpjBatch.phase != WbpjPhase::Idle || m_ledger.hasBatch() || m_morphJob != nullptr`. 본 티켓이 건드리는 것은 3항뿐이고, 그 항이 **취소 경로에서 무효**다. `onMorphJobFinished:1423` 첫 줄(`:1427`)이 `Job::finished` 시점에 `m_morphJob = nullptr` 로 지우고, `cancel()` 의 `finished` 는 워커가 DLL 안일 때 즉시 발화한다.
- 오늘 등급 2 로 터지지는 않는다 — `batchActive()` 의 두 소비자(`runDirectJobs:2389` · `runWbpjDoeAsync:2687`)가 모핑을 하지 않고, 모핑 경로는 게이트가 막는다. 그러나 AC 가 명명한 불변식이 성립하지 않으므로, 모핑을 만지는 소비자가 추가되는 순간(#215) 등급 2 가 된다.

**진입점 5 — 최적화 · 모델러너** (`model/geometry/DashMorphingUtils.cpp:286`)
- 호출 사슬은 2-hop 이다 — 위젯이 `performMorphing` 래퍼를 부르고, `performMorphingAndExport` 의 실제 호출부는 `model/DashOptimizer.cpp:1498` · `model/DashModelRunner.cpp:2222` 다.
- `performMorphingAndExport` 가 `MorphingGate::busy()` 시 `false` 를 반환한다. **동시 `Morph()` 는 일어나지 않는다** — 등급 2 상호배제는 성립한다. 실패 처리가 문제다:
  - `view/DashOptimizerWidget.cpp:1487` 호출 → `:1488` `qWarning` + `:1489` `processEvents` + `continue`. **사용자에게 무음**. 프리뷰가 일부만 생성된다.

- **역순서 창이 실재한다**: `DashOptimizerWidget::onPreviewButtonClicked:1326` 의 템플릿 루프(`:1480-1514`)에 `QCoreApplication::processEvents()` 가 `:1489`(실패)·`:1514`(성공) 두 곳 있다. 즉 이 경로는 이미 **가짜 비동기**다 — 이벤트 루프를 돌리면서 토큰을 쥐지 않는다. 최적화가 먼저 시작된 뒤 그 틈에 배치 Start 가 들어올 수 있고, Run 버튼 비활성만으로는 이 순서를 막지 못한다.
- ModelRunner 쪽은 단발이다 — `performMorphingAndAddToFileTable:1528`(호출부 `:398`) → 모핑 호출 `:1553`.

**취소 대상 목록 2벌**
- `cancelAllRuns:862` — motion `QProcess`(take-then-kill) · FE-safe · Abaqus · ANSYS 4종을 **컨테이너 전수**로 처리. 장부 키가 아니라 컨테이너가 열거 기준이다.
- `cancelSolverTaskForKey:1294` — Abaqus · ANSYS · **motion 3종**. **FE-safe 만 빠져 있다.** 호출부는 `abortBatch:1269` 의 `:1288` 한 곳.
- **PR #275 가 motion 을 메웠고, 그 방식이 중복 비용을 드러낸다.** #275 는 순서를 뒤집는 대신 `waitForFinished` 를 생략했다(`:1318-1321` 주석) — 종료 통지가 이 호출 스택 **밖에서** 도착하고 그때는 케이스가 이미 닫혀 폐기되므로, `abortBatch` 의 `자원 → 상태` 순서로도 취소가 실패로 뒤집히지 않는다. 동작은 맞다. 그러나 그 판단은 **`cancelAllRuns` 쪽 규약(상태 → kill + `waitForFinished`)과 다른 두 번째 규약**이고, FE-safe 를 추가하는 사람은 같은 판정을 처음부터 다시 해야 한다. 목록이 두 벌이면 규약도 두 벌이 된다는 것이 이 항목의 실제 비용이다.
- **두 함수는 순서만이 아니라 세 축에서 다르다.**

  | | 열거 기준 | 자원 종류 | 순서 | stage | state |
  |---|---|---|---|---|---|
  | `cancelAllRuns:862` | 컨테이너 전수 | 4종 | 상태 → kill + `waitForFinished(3000)` | `terminalStage` (`reportCaseStatus`) | 항상 `Cancelled` |
  | `cancelSolverTaskForKey:1294` | 키 1개 | **3종** (FE-safe 누락) | 자원 → 상태 (호출부) · kill 후 대기 없음 | `currentStage` | 호출부 파라미터 |

  `cancelAllRuns:881` 주석: "취소를 kill 보다 먼저 확정한다 — 그 핸들러가 CrashExit 를 Failed 로 기록하는데, 순서가 반대면 종료 단조성이 취소를 삼켜 사용자 취소가 실패로 보고된다." 그런데 `abortBatch:1288-1289` 는 `cancelSolverTaskForKey(key)` → `setStageState(key, currentStage, state, reason)` 순서다.
- **순서 제약이 호출부에서 비국소적이다.** `abortBatch` 의 순서는 오늘 무해하다 — Abaqus·ANSYS 의 `CancelTask` 는 동기 완료 콜백을 만들지 않는다. 문제가 되는 건 motion `QProcess` 뿐이고, 그건 `kill()` + `waitForFinished(3000)` 이 **호출 스택 안에서** finished 핸들러를 펌프하기 때문이다. 두 줄만 보면 이상함이 보이지 않는다 — 호출부가 볼 수 없는 자원 속성에 의존한다.
- `m_motionLauncherQueue` 는 별도 처리 불요 — `finishBatch:1234` 가 비운다. `abortBatch` 의 장부 없는 분기(`:1275-1283`)만은 `finishBatch` 를 타지 않지만, 그 시점엔 직전 `finishBatch` 가 이미 큐를 비운 뒤다.

**종료 경로**

- 풀은 함수 지역 static(`ThreadPools.cpp:22`·`:29`) — `~QThreadPool` 이 정적 소멸에서 **다시** 무한 배수한다. **`aboutToQuit` 에 타임아웃만 넣으면 무효다.**
- 대기 상한이 실질적으로 없다. `m_morphWatchdog` 는 Job 만 취소하고 `Morph()` 는 계속 돈다 — "10분" 이 아니라 "DLL 이 끝날 때까지" 다.
- **데몬 종료가 정적 소멸에 실려 있다.** `~DashManager():132` 가 `shutdownBlocking()` 4회(`:135`·`:139`·`:143`·`:147`)로 NX CAD · Journal · MCU · Sensitivity 데몬을 거두고, `Mgr():209` 주석이 그 시점을 명시한다. `aboutToQuit`(`main.cpp:42-45`) 에는 `ProcessJob::cancelAllRunning()` 과 풀 배수만 있다.
- **정적 소멸은 요구와 배치가 어긋난 자리다.** `main()` 반환 후에 돌므로 `QApplication` 도 이벤트 루프도 없는데, 데몬 `shutdownBlocking()` 과 풀 배수는 둘 다 살아 있는 Qt 를 요구한다(`QProcess` · `QFutureWatcher` · IPC).
- 워커가 만지는 싱글턴이 실재한다 — `controller/DashMorphingDoeExecutor.cpp:940`·`:1017` 의 `DashContextMutationScope` 가 `DashAnalysisModelContextRegistry::Instance()` 를 잡는다. 타임아웃 후 어떤 소멸자든 돌면 그 대상이 해체된다.
- 로그 싱크는 커스텀 핸들러 없이 기본값(stderr)이다 — 즉시 종료 전 flush 대상이 stdio 로 확정된다.

### to-be

- **게이트를 질의에서 증명으로.** `tryClaim() -> std::optional<Claim>` 이 획득의 유일한 지점이 되고 `acquire()` 는 사라진다. `busy()` 는 위젯 비활성·스피너 같은 **표시 전용** 질의로만 남는다 — 배제 판정에는 쓰지 않는다.
- **두 축을 두 타입으로.** `Claim` 은 배타 점유(구간), `Reservation` 은 잔류 실행(Claim 보다 오래 산다). `Claim::reserve()` 만이 `Reservation` 을 발급하므로 "국면 안의 dispatch" 가 타입으로 표현된다. `tryClaim()` 은 **둘 중 하나라도 살아 있으면 실패**한다.
- **DLL 실행 함수가 증명을 인자로 요구한다.** 4곳이 `const MorphingGate::Witness&`(Claim·Reservation 의 공통 상한형, 외부 생성 불가)를 받는다. **게이트를 안 보고 모핑하는 코드가 컴파일되지 않는다** — 진입점 열거가 리뷰 대상에서 타입 대상으로 옮겨간다.
- **워커 생존 = 자기 `Reservation` 생존.** 러너가 task 에 넘긴 `shared_ptr<Reservation>` 의 `weak_ptr` 를 들고 `batchActive()` 의 3항을 `!expired()` 로 바꾼다. 신규 시그널 없이 자원 시점을 직접 읽는다.
- **착수 판정을 `beginBatch` 로, 착수 신호를 그 뒤로.** `beginBatch` 가 활성 배치를 감지하면 거부하고(`bool`), 성공 시 `batchBegun()` 을 낸다. `DashAnalysisLauncher` 가 그것을 `analysisStarted` 로 중계하고 선행 방출(`:1056`·`:1096`)을 제거한다. 거부는 아무 신호도 내지 않으므로 "모든 return 은 abort/finish 를 통과" 규약에 **예외가 생기지 않는다.**
- **취소를 자원 해제와 장부 기록으로 분리.** `releaseRunResources(runKey)` 가 4종(motion · FE-safe · Abaqus · ANSYS)을 키 단위로 회수하고 **상태는 건드리지 않는다.** 순서 규약("상태 확정이 먼저")은 진입 `Q_ASSERT` 로 **국소 검출**한다. `cancelAllRuns` 는 4개 컨테이너 키의 **합집합**을 순회하며 이 함수를 재사용한다.
- **종료 순서를 한 소유자에게.** `AppShutdown::run()`(신설 · 멱등)이 ⑴ `ProcessJob::cancelAllRunning()` ⑵ 데몬 4종 ⑶ 풀 배수(타임아웃) ⑷ 초과 시 flush + 즉시 프로세스 종료 를 순서대로 진다. `aboutToQuit` 은 그것만 부르고, `~DashManager()` 는 멱등 백스톱으로 축소된다.
- **`docs/ThreadingContract.md` 7절 갱신** — "새 모핑 진입점은 `busy()` 검사" → "**DLL 실행은 `Witness` 를 인자로 요구한다. `busy()` 는 표시 전용**" + "Claim 구간 안에서 `processEvents()` 금지" + 종료 4단계 순서.

### not-to-be

- **진입점 1·1b·2 의 비동기화 없음** — 핸들 드래그가 호출부(`DashHandlePickingInteraction.cpp:2033`·`:2057`·`:2353`)라 비동기화는 프레임 코얼레싱(stale 요청 폐기) · 드래그 응답성 · VTK 스냅샷을 **새로** 요구한다. `Claim` 만 쥐고 동기 유지. 전면 워커화는 별건.
- **`workerExited()` 신설 없음** — 자원 시점은 `Reservation` 이 이미 든다. 시그널을 더하면 같은 답을 두 곳에서 계산하고, `runNextMorphSample:1345` 의 `if (m_morphJob) return;` 직렬 가드가 방출 순서에 의존하는 load-bearing 배치가 된다.
- **취소자 레지스트리(제출 시점 등록) 없음** — 열거를 아예 없애는 안은 완료 경로마다 등록 해제가 필수여서 새 계급의 누락을 만든다. 취소가 한 벌로 수렴한 뒤 후속 후보.
- **풀 소유 승격(`static QThreadPool*` · main 스코프) 없음** — 정상 경로는 배수 후 빈 풀이라 정적 소멸이 즉시 반환하고, 초과 경로는 정적 소멸이 아예 돌지 않는다. 승격은 무의미.
- **`DashManager` 를 스코프 객체로 내리지 않음** — `Mgr()` 이 프로세스 전역 magic static 이고 호출부가 전면에 있다. 데몬 종료만 `shutdownDaemons()` 로 떼어내고 magic static 은 유지.
- **`.vtu` 파라미터 정합의 자동화 없음** — 골든 파일 회귀 하네스는 별건. 본 티켓은 실기 1회로 확인하고 결과를 기록한다.
- **진입점을 단위 테스트로 덮지 않음** — `DashManager`·`DashMorphingUtils` 가 VTK·OCCT·모핑 DLL 을 끌어와 Qt Core 전용 테스트 타깃에 못 들어가고, 앱은 단일 exe(`GLOB_RECURSE`)라 링크 대상이 없다. 게이트 표면과 증명 요구는 단위 테스트로 봉인하고, "각 진입점이 증명을 쥐는가" 는 **타입이 보증**한다.
- **3D 뷰포트 핸들 드래그 차단 없음** — 진입점 1·1b 의 조기 반환이 등급 2 를 막고 상태바가 통보를 맡는다. 인터랙터 비활성화는 #221 영역.
- **`showLoadingIndicator`·상태바 메시지의 소유권 정리 없음** — 흐름 간 공유 자원이고 호출부가 10곳 이상인 기존 패턴. 별건.
- **`m_analysisActive` 의 `setModel` 재호출 리셋 없음** — 종전 동작, 회귀 아님.
- **워커 취소의 즉시성 개선 없음** — DLL 이 협조적 중단을 제공하지 않는 한 `Morph()` 는 세울 수 없다. 즉시 종료는 "기다리지 않는다" 이지 "멈춘다" 가 아니다.
- **`DashAnalysisLauncher.cpp:233` 경로 미변경** — `runAnalysisInThread` 는 `beginBatch` 를 타지 않는 별 경로다.
- **#214 재오픈 없음** — 미충족분의 기록은 본 티켓이 정본.

## Design

### 현황 분석

- 게이트·워커 인프라는 #214 가 세웠고 **의미론은 대부분 이미 맞다** — 워커 축 토큰이 DLL 종료까지 게이트를 들고, `tst_worker_job`(9케이스)·`tst_morphing_gate`(6케이스)가 그것을 봉인한다. 부족한 것은 **표면**(획득 실패·워커 종료를 표현할 수단)과 **적용 범위**(배제 구간이 증명을 쥐지 않는 곳)다.
- 게이트의 실제 구현은 `std::atomic<int> g_holders` 카운팅이고 **정당한 동시 보유자가 2명**이다. 이 사실이 표면 설계를 규정한다 — "최대 1인" 단일 토큰으로는 표현할 수 없다.
- DLL 실행 함수가 **4곳뿐**이라는 것이 증명 인자화를 가능하게 한다. 진입점(6곳)이 아니라 funnel(4곳)에 걸면 진입점이 늘어나도 규약이 유지된다.
- 신규 자료 구조는 게이트 상태 워드 하나뿐이다. 나머지는 기존 인프라의 표면 정리 + 소비자 정합이다.

### 대안 비교 — 결정 5건

**결정 A. 게이트의 배제 단위** (미충족 1·2 의 공통 뿌리)

| 방안 | 핵심 | 판정 |
|---|---|---|
| A-0. `busy()` 유지 | 지금 그대로 | 기각 — check-then-act 를 구조적으로 허용. 미충족 1·2 가 정확히 이 실패 |
| A-x. `tryAcquire() -> optional<Token>` | 단일 토큰, 최대 1인 | **기각 (개정 1)** — 동시 보유자 2명과 충돌해 배치 모핑이 첫 샘플부터 멈춘다. 진입점 5 가 루프를 쥐면 내부 `busy()` 검사에 자기가 걸려 전 iteration 실패 |
| A-1. `Claim` + `Reservation` 2단 표면 | 배타 점유와 잔류 실행을 타입으로 분리 | **채택** — 실패 조건이 한 문장("Claim 이나 Reservation 이 살아 있다") · 결정 D 를 흡수 · 진입점 전량 통일 가능 |
| A-2. 단일 토큰 + refcount | `shared_ptr<Token>` 을 국면 안에서 공유 | 기각 — 동작은 맞지만 "국면 안에서 재획득 금지" 가 규약이지 타입이 아니다. 거부 사유를 "다른 배치" / "이전 워커 잔류" 로 구분 못 함 |
| A-3. 전부 비동기 워커화 | 배제를 직렬 풀 하나로, 게이트는 표시 신호로 강등 | **부분 채택** — 진입점 5 에만. 1·1b 는 핸들 드래그가 호출부라 비동기화가 새 문제군(코얼레싱·응답성)을 만들고 2 는 동기 반환이라 호출부 재구성이 필요하다 |
| A-4. 소유자 신원 기반 재진입 | `tryAcquire(Owner)` | 기각 — 워커 축(다른 스레드·다른 Owner) 미해결. 신원 열거가 "진입점별 복제" 의 다른 형태 |

**증명 인자화가 A-1 의 핵심 귀결이다.** DLL 실행 함수 4곳이 `const Witness&` 를 요구하면 진입점 열거가 리뷰 대상에서 타입 대상으로 옮겨간다. `GetMorphingEngine()` 접근자(9곳 중 6곳이 setter·getter)에 걸면 과잉 제약이므로 **실행 함수에만** 건다.

**결정 B. 취소 대상 열거**

| 방안 | 핵심 | 판정 |
|---|---|---|
| B-0. 빠진 곳을 채운다 | 키별 함수에 motion·FE-safe 추가 | 기각 — 중복이 남아 다음 자원 종류에서 또 갈라진다. 게다가 순서 규약 위반으로 사용자 취소가 실패로 보고되는 회귀 |
| B-1. 자원 해제 / 장부 기록 분리 | `releaseRunResources(runKey)` 는 핸들만 | 부분 채택 — 순서 규약이 호출부에 남는 것이 문제 |
| **B-1'. B-1 + 진입 assert** | 위 + "상태 확정이 먼저" 를 `Q_ASSERT` 로 국소 검출 | **채택** — 1인자 유지 + 실질 보증은 B-2 와 같다. 순서 제약이 비국소적이라는 as-is 사실을 assert 가 국소화 |
| B-2. 단일 취소 함수 + 값 파라미터 | `cancelRun(runKey, stage, state, reason)` | 기각 — 보증은 같은데 시그니처가 4인자로 커진다 |
| B-3. 취소자 레지스트리 | 제출 시점에 취소법 등록, 열거 소멸 | 기각(후속) — 완료 경로마다 등록 해제가 필수여서 새 계급의 누락을 만든다 |

### 선택 — A-1(+A-3 부분) · B-1' · C-1+C-3 · D-3 · E-2

**선택 근거.** 결정 A 가 미충족 1·2 의 공통 뿌리를 없애고 결정 D 를 함께 흡수한다 — 증명이 곧 배제 구간이고 잔류 증명이 곧 워커 생존이므로, 세 증상(per-sample 거부 · 수명 불일치 · check-then-act)이 한 자원 모델로 수렴한다. 증명 인자화는 그 모델을 **컴파일러가 강제**하게 만들어, 진입점이 늘어도 누락이 재발하지 않는다. B-1'·C-1+C-3 은 #264 가 세운 "착수·종결의 단일 지점" 원칙을 판정과 자원 열거까지 확장하는 것이라 코드베이스 방향과 정합하고, 두 경우 모두 **규약을 문서가 아니라 코드가 검출**한다(assert / 신호 순서). E-2 는 확정된 정책을 담을 자리를 정하는 것이고, 즉시 종료가 오케스트레이터 안이어야 하는 이유는 그곳만이 배수 실패를 안다는 점이다.

**즉시 종료의 파급 — 데몬 이관이 필수다.** `~DashManager()` 가 정적 소멸에서 데몬 4개를 거두므로, 즉시 종료를 넣으면 그 경로가 통째로 건너뛰어져 **데몬 4개가 고아가 된다.** 종료 순서 재배치가 정책의 일부다.

**수용 비용 2건.** 진행 중 샘플의 산출 파일(`.vtu`/`.dat`)이 불완전하게 남을 수 있다 — 그 케이스의 장부 항목은 Done 이 아니므로 성공으로 오인되지 않는다. 수용. `std::_Exit` 는 stdio 를 flush 하지 않으므로 종료 사유 로그 유실을 막기 위해 flush 를 명시한다 — 로그 싱크가 커스텀 핸들러 없이 stderr 이므로 `std::fflush(nullptr)` 로 확정된다.

// controller/async/MorphingGate.h — 획득의 유일한 지점. acquire() 는 삭제한다.
class MorphingGate : public QObject {
public:
    // 증명의 공통 상한형. 외부에서 만들 수 없다 — DLL 실행 함수가 이것을 인자로 요구한다.
    class Witness { protected: Witness() = default; ~Witness() = default; };

    class Reservation : public Witness { /* 이동 전용. 소멸 시 워드에서 1칸 내린다 */ };
    class Claim : public Witness {
    public:
        // 국면 안에서만 발급된다 — Claim 을 쥐지 않은 코드는 이 함수를 부를 수 없다.
        Reservation reserve() const;
    };

    static std::optional<Claim> tryClaim();   // Claim·Reservation 중 하나라도 살아 있으면 실패
    static bool busy();                        // 표시 전용 (위젯 비활성 · 스피너). 배제 판정 금지

    void busyChanged(bool busy);
};

// controller/DashManager.h — check-then-act 제거. 준비 성공이 곧 Claim 획득이다.

std::weak_ptr<MorphingGate::Reservation> m_morphWorkerRes;
