## Goal
Condition·Morphing Set 이 각자의 기준 deck 을 소유한다 — 생성 시점에 핀된 `referenceModel` 이 {Set}.json 에 남고, 진입 시 전역이 아니라 그 값을 읽는다. 재기동 후에도 Set 마다 자기 deck 을 유지한다. CAD Set 은 해석 deck 을 소비하지 않아 이 PR 에서는 봉합만 한다(아래 "CAD 처분" — 기준 키 `cadSource` 는 문서 0 D31 유보, `.prt` 는 지금 고려하지 않는다).

## Background
> source: wiki [Project-Manifest-4-Ticket-Slicing](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Project-Manifest-4-Ticket-Slicing) "PR 상세" G7 절

Set 은 자기 deck 을 기록하지 않는다 — 진입 시점의 전역 커서가 그 Set 의 deck 을 정하고, 저장되지 않아 재기동하면 다시 전역을 따른다 (문서 3 "진입 1회 읽기 3좌표"). G1 이 전역 기준모델 층을 만들고 G5·G6 이 원장을 세운 뒤, 소유 주체를 Set 으로 내리는 단계다.

이 PR 은 G1 의 과도기 동작("Set 을 먼저 클릭하고 나중에 Load" 복구 경로 부재)과 과도기 연결(#389 `f1a859d` — `referenceModelChanged` → Condition `refreshFromFile`)을 닫는다.

**카디널리티와 조인 키** — Condition·Geometry Set : referenceModel = **1:1**(D23 A안). 다해석(deck N) 워크플로우는 DOE 가 Geometry Set 1 + Condition Set N 을 참조하는 것으로 담고, Condition DV 표에 여러 deck 을 쌓던 현행 동작은 폐기한다 — 대체재(DOE Condition Set 다중 선택 — **#491**)와 같은 dev 반영 회차여야 다해석 워크플로우가 끊기지 않는다. 모듈 JSON 의 조인 키는 `uuid` 다(D24).

### CAD 처분 — 봉합만
실측 — **CAD 는 해석 deck 을 소비하지 않는다**: `getContext()` 는 #389 가 삭제했고, `refreshFromLoadedAnalysis`(`model/DashGeometryParameterCAD.cpp:97-110`)가 쓰는 `m_loadedFilePath` 는 읽는 곳이 0건이며, 표는 `applyNxCadParameterJson` 이 채운다.
- **결정** — CAD Set 의 기준은 해석 deck 이 아니라 **CAD 파일**로 본다. 다만 그 키의 설계는 이 티켓에서 하지 않고 봉합만 한다 — 키(`cadSource`)는 문서 0 D29\~D31 유보(미래 CAD 경로 · 후속작업 13 동반), wbpj 실행 경로는 사장 판정이라 D32·D33 철회, **이 묶음에 CAD PR 은 없다**

- **범위** — T15 영속화·T19 표시 대상은 **Condition·Morphing 2모듈**이다

## Design

### {Set}.json 스키마 — D14
```json
{
  "variant": "…기존 키…",
  "referenceModel": {
    "uuid": "a3f2c1e0-…",
    "path": "models/wing.dat"
  }
}
```

| 항목 | 내용 |
|---|---|
| 낱말 | 원장 `referenceModels.json` 과 맞춘다. 두 값이 한 덩어리로 붙어 다닌다 |
| `uuid` | 원장 키 = content uuid (D24). **1차 조인 키** — 이 값으로 원장을 직조회한다 |
| `path` | 루트 상대경로 = 원장 `path` 필드와 같은 문자열(D3). 표시·디버깅·원장 유실 폴백 |
| 두 값 불일치 | uuid 로 찾힌 원장 항목의 `path` 가 저장값과 다르면 원장 값으로 backfill — 원장이 정본이다 (D11) |

### 채움 경로 (D13)
| 경로 | 자리 |
|---|---|
| 신규 Set — Condition·CAD | `DashProject::createNewSet`(`model/DashProject.cpp:705`, Condition `:724-728` · CAD `:713-715`)이 생성 직후 그 시점의 전역 `referenceFilePath()` 를 핀 |
| 신규 Set — Morphing | 좌표 9 의 Start Morphing 핀(T14) — 유일한 데이터 주입 지점이라 그 시점 핀이 곧 생성 시점 핀 |
| 기존 Set 복원 | `loadFromJson` 3곳 — Condition(`:405`) · CAD(`:376`) · Morphing(`model/DashGeometryParameter.cpp:127`). `setProjectDirectory`·`setSetName` 경로가 부른다 — 생성자는 부르지 않는다 |
| 구버전 backfill (D15) | 키 부재 시 위젯 진입(`setModel`)에서 전역을 1회 핀(구버전 한정). Morphing 은 Start Morphing 핀이 겸한다. 다음 저장이 키를 만든다 |

### 해석 순서 — D16 (재개정 · D24)
```
키 읽기
├─ 1. uuid 로 원장 직조회
│     ├─ 히트 -> path 의 파일 존재·적재 검사 -> 부재면 미지정 + 로그
│     └─ 미스 -> 2
└─ 2. path 로 원장 스캔 (원장 유실·구버전 한정)
      ├─ 찾음 -> uuid backfill + 같은 존재 검사
      └─ 실패 -> 미지정 + 로그
```

## PR #389 리뷰 이월 — CAD Set 생성이 해석 deck 을 요구하는 회귀 (@DCode-NumeReal 지적)

#389 `c3072bc` 가 넣은 회귀. CAD Set 의 deck 요건을 정하는 것이 이 티켓이므로 여기로 이월한다.

### 현상
CAD 파일만 로드한 상태에서는 Geometry Parameterization → for CAD 로 Set 을 만들 수 없다. 무관한 해석 deck 을 하나 더 Load 하면 생성된다.

### 원인 (코드 실측)
- 가드가 variant 를 보지 않는다 — `view/DashMainWindow.cpp:623` 의 조건은 `categoryName == "Geometry Parameterization"` 뿐인데, `for CAD` 메뉴도 같은 categoryName 으로 `newSetRequested` 를 낸다 (`view/DashProjectWidget.cpp:219-229`, 실제 분기는 `model/DashProject.cpp:709`).
- Load 는 `.stp`/`.step`/`.prt` 에 `setReferenceModel` 을 부르지 않는다 (`view/DashMainWindow.cpp:2276-2281`). CAD 만 로드하면 기준모델이 계속 비어 있다.

### 전제가 성립하지 않는다
CAD Set 은 해석 deck 을 쓰지 않는다. #389 가 `DashGeometryParameterCAD::getContext()` 를 삭제했고, 남은 `refreshFromLoadedAnalysis`(`model/DashGeometryParameterCAD.cpp:97-110`)는 경로만 저장한다. 표는 `applyNxCadParameterJson` 에서 온다.

### to-be 추가분
- 생성 가드에서 CAD variant 제외 — 판정은 `DashProject.cpp:709` 와 동일하게 `variant == "CAD" || variant == "cad"`.
- 이 티켓의 "Condition·CAD·Morphing Set 이 각자 기준 deck 을 소유" 에서 **CAD Set 의 `referenceModel` 을 선택으로 둘지** 확정한다. CAD 가 deck 을 안 쓰면 D14 스키마 적용 대상에서 빠지거나, 그 자리가 CAD 파일 경로라는 다른 의미가 된다.

### 주의
#389 병합 후 이 티켓이 닫힐 때까지 CAD Set 생성이 막힌 상태로 남는다. 우회는 아무 해석 deck 이나 1회 Load.
