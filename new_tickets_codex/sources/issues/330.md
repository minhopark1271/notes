# #330 최신 MSVC version (18.10.0) 에서, vcpkg 를 통해 build artifact 가 공급되지 않음

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/330
- Board status: Backlog
- Labels: ['area:DevEnv']

## Must Know

- **버그 아님**, 의도된 동작이고 정책 부재임.
- 해당 문제는 `DashOpti_Registry 의 동작`과, `DashOpti (Meta repo) 의 custom triplet` 에 의해 발생함.  
- **추후 결정 사항과 무관하게 Visual Studio version 을 올리지 말 것**
  : August 2026 기능 업데이트(18.9.2) 에 고정
- 추가로 결정사항에 따라, **후속 작업자의 작업을 위해 지금 버전의 visual studio install layout 을 따 놔야함.**
https://learn.microsoft.com/ko-kr/visualstudio/install/create-an-offline-installation-of-visual-studio?view=visualstudio
https://learn.microsoft.com/ko-kr/visualstudio/install/use-command-line-parameters-to-install-visual-studio?view=visualstudio#layout-command-and-command-line-parameters

## Root cause analysis

- vcpkg 작동 원리 상, stl + build tool 이 업데이트 되면 abi hash 를 깨버림. 이건 vcpkg 의 기능.
- 현재는 CI machine 이 모든 binary 의 SSOT 임. 이 CI machine 의 version 이 August 2026 기능 업데이트(18.9.2) 임.
- 공급이 불가하므로 hard fail, 우회로 없음.

## Solution

**아래 제안과 상관없이 visual studio version 을 고정할 것을 권고**

일단 제안할 수 있는 option 은 다음과 같음 :

- 모두 version 을 올리는 것을 기본 정책으로 확정.
   : 유지에 들어가는 man power 증가, 현재 충돌을 일으킨 업데이트 상황은 `08/25` -> `09/08` 이므로 거의 한달에 한번 꼴로 발생한다고 이해.

- version 을 영구적으로 고정하는 것을 기본 정책으로 확정.
   : 다른 비용이 증가, visual studio 는 이전 배포 버전을 community version 에서 제공하지 않으므로, install layout 을 따로 구워야 함. 

- 이전 version 의 build 환경에서 빌드 한 artifact 를 일정 기간 동안 같이 공급. 
   : 이전 build 환경을 불러오는 setup 이 필요하고 (windows 는 docker 가 잘 작동하지 않아서 setup 이 까다로움), CI 비용이 2배 임.

- custom triplet 에서 생성하는 abi hash 를 하위 호환 되도록 갈아 끼움.
   : 약간의 위험성을 감수하는 선택, abi 호환성은 CI 에서 잡힌다고 보는 방식. 안전하게 하고 싶다면 c abi 로 dll 구현을 갈아버려야 함.
