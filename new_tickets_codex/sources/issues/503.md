# #503 Morphing Settings physics 파일 표: browse 버튼이 캡처한 행 번호가 삭제 후 어긋나 엉뚱한 행 기록 또는 크래시 (#419 와 같은 결함)

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/503
- Board status: Done
- Labels: ['bug', 'refactor']

## 현상

Morphing Settings 의 Physics 파일 표에서 **행을 지운 뒤** 남은 행의 `...` (Browse) 버튼을 누르면 둘 중 하나가 발생.

- 표 끝을 가리키게 된 버튼 → `QTableWidget::item()` 이 nullptr 을 반환하고 그대로 역참조 → **크래시**
- 그 외 버튼 → 선택한 경로가 **한 칸 아래 행**에 기록되고, CSV 도 그 행의 슬롯으로 로드됨

재현:

1. Physics 파일 행 3개 추가 (A·B·C)
2. A 행 선택 후 Remove (남은 행은 A·B 로 재라벨)
3. 남은 두 행의 `...` 중 아래쪽 클릭 → 파일 선택 → 크래시
4. 위쪽 클릭 → 경로가 아래 행 칸에 기록

## 원인

#419 에서 고친 것과 같은 결함 — 행 번호를 람다에 값으로 캡처하고 행 삭제 후 갱신하지 않음.

[view/overlay/DashMorphingSettings.cpp:1596](view/overlay/DashMorphingSettings.cpp#L1596)

```cpp
connect(browseButton, &QPushButton::clicked, this, [this, row](){
    browseFile(row);
});
```

[`removeFileRow()`](view/overlay/DashMorphingSettings.cpp#L1602) 는 `removeRow` 로 표 행을 당기고 `updateFileLabels()` · `updateThresholdRowProperties()` 를 부르지만, browse 버튼이 캡처한 `row` 는 갱신 대상에 없음. 컨트롤러의 [`onPhysicsFileRemoved`](controller/DashMorphingController.cpp#L462) 도 `m_physicsFiles` / `m_physicsPreviews` 를 `erase` 로 당기므로 뷰·모델 인덱스가 함께 밀림.

그 결과 [`browseFile()`](view/overlay/DashMorphingSettings.cpp#L1627) 의

```cpp
m_physicsFileTable->item(row, 1)->setText(filePath);
emit physicsFilePathChanged(row, filePath);
```

이 범위 밖이면 nullptr 역참조, 범위 안이면 엉뚱한 행에 기록하고 [`onPhysicsFilePathChanged`](controller/DashMorphingController.cpp#L409) 가 다른 파일 슬롯에 CSV 를 로드. 로드된 값은 physics 핸들 생성의 threshold 판정에 그대로 쓰이므로, 크래시가 아닌 쪽은 조용히 잘못된 핸들 집합을 만듦.

## 구조 문제

같은 함수 [`addFileRow()`](view/overlay/DashMorphingSettings.cpp#L1559) 안에서 threshold 스핀박스는 **다른 방식**으로 같은 문제를 이미 피하고 있음 — `setProperty("row", row)` 후 삭제 시 [`updateThresholdRowProperties()`](view/overlay/DashMorphingSettings.cpp#L1615) 가 전 행을 재기입. 한 행을 만드는 코드에 행 해석 규칙이 둘 있고, 그중 하나만 갱신 경로를 가진 상태.

#419 은 같은 상황을 `constraintRowOfWidget(widget)` + `connectConstraintTypeCombo()` 로 정리 — 캡처를 없애고 **호출 시점에 위젯 위치로 행을 되찾는** 방식 한 곳으로 모음 ([view/DashOptimizerWidget.cpp:1803](view/DashOptimizerWidget.cpp#L1803)).

## 추가 결함 — 제거 시 한쪽 벡터만 지워짐

`onPhysicsFileRemoved` (controller/DashMorphingController.cpp:462) 가 `m_physicsPreviews` 크기만 보고 early return 하면서 두 벡터를 함께 지운다. `onPhysicsFilePathChanged` 는 CSV 읽기에 실패하면 `m_physicsFiles` 만 늘려둔 채 빠져나가므로 크기가 갈라진다. 그 상태에서 행을 지우면 `m_physicsFiles` 가 남아 표 행과 파일 슬롯이 한 칸씩 어긋나고, 이후 threshold 조작이 다른 파일에 걸린다. 같은 행 인덱스 계약 계열이라 함께 고친다.

## 기대

1. browse 버튼이 클릭 시점에 자기 행을 찾도록 변경 — `row` 캡처 제거.
2. threshold 의 `setProperty("row")` / `updateThresholdRowProperties()` 경로도 같은 헬퍼로 통일. 삭제 시 갱신을 잊으면 다시 어긋나는 구조 제거.
3. `browseFile()` 의 `item(row, 1)` null 방어.
4. `onPhysicsFileRemoved` 가 두 벡터를 각자의 크기로 지우도록 분리.

## 함께 확인한 것 (결함 없음)

- 핸들 트리(`m_handleTree`) 스핀박스 람다가 캡처하는 `index` / `i` 는 행 번호가 아니라 vtkPolyData 포인트 인덱스(핸들 id). 삭제는 STATUS 를 0 으로 내릴 뿐 포인트 배열을 압축하지 않고([view/DashGeometryParameterWidget.cpp:1762](view/DashGeometryParameterWidget.cpp#L1762)), 트리 갱신은 `clear()` 로 아이템 위젯까지 버리므로 스테일 캡처가 남지 않음.
- 그룹 행 람다는 `groupItem` 포인터를 캡처 → 항목이 지워지면 위젯도 함께 소멸.
- Constraint 표(`m_consTable`)의 삭제 버튼은 이미 `indexAt()` 위치 조회 방식.
- 부수 관찰: `onDeleteHandles` 는 0열 행 번호를 다시 매기지 않아 삭제 후 `1·2·4` 처럼 남음. 읽는 코드가 없어 표시만의 문제.
