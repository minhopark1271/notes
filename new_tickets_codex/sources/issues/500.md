# #500 DOE Launcher: Target Component 를 바꿔도 모핑 메시는 GP 세트 part 로 고정 — edit_mesh 위상 불일치로 해석 입력 생성 전 케이스 실패

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/500
- Board status: Done
- Labels: ['bugfix', 'source:QC']

## 현상

DOE Launcher 의 Input Reference File 표에서 Target Component 를 바꿔도 **모핑되는 메시는 바뀌지 않는다.** JSON 의 `target_component` 와 UI 표시값은 정상이고, 로그도 `Resolved target part 'CBlock'` 을 찍는다. 모핑은 성공해 .vtu 는 나오지만, 해석 입력(.dat/.inp) 생성은 전 케이스가 `edit_mesh failed for part CBlock` → 첫 part 폴백 `edit_mesh failed for part HCover` → `analysis input export failed` 로 실패한다.

## 원인

`edit_mesh` 에 넘기는 메시가 Target Component 의 메시가 아니다.

[controller/DashMorphingDoeExecutor.cpp:841](controller/DashMorphingDoeExecutor.cpp#L841) 의 `RunVolumeMorphing` 은 [controller/DashManager.cpp:523](controller/DashManager.cpp#L523) 에서 `GetInputVTU()` 를 ShallowCopy 하고 점만 교체한다. 이 `m_inputVTU` 는 Geometry Parameter 세트를 열 때 Modeling Tree 에서 선택한 part 로 고정된다 — [view/DashMainWindow.cpp:3275](view/DashMainWindow.cpp#L3275) 가 grid 를 세트에 넣고 [view/DashGeometryParameterWidget.cpp:1972](view/DashGeometryParameterWidget.cpp#L1972) 가 `SetInputVTU` 하는 것이 유일한 경로다.

그 결과 [controller/DashMorphingDoeExecutor.cpp:915](controller/DashMorphingDoeExecutor.cpp#L915) 는 **GP 세트 part 의 메시를 Target Component 심볼 UUID 에** `edit_mesh` 한다. reader-writer 계약(`IRWModule.hpp` — point/cell 수·연결성이 원본과 같아야 하며 다르면 `InvalidArgument`)에 걸려 실패하고, 첫 part 폴백도 같은 이유로 실패한다. Target Component 콤보는 `edit_mesh` 의 **대상 UUID 만** 바꾸고, **어떤 메시를 모핑할지에는 관여하지 않는다.**

`ug = getPartData(partName)`([:559](controller/DashMorphingDoeExecutor.cpp#L559)) 는 가져오지만 double 변환과 원복용 `basePart` 에만 쓰이고 모핑 소스가 아니다. 그래서 원복([:934](controller/DashMorphingDoeExecutor.cpp#L934))도 Target part 원본을 폴백 part 심볼에 되쓰려는 어긋난 상태다.

유입 시점은 e9a7d67 (2026-07-27). 그 전에는 `ExecuteMorphing(ug->GetPoints())` + `ShallowCopy(ug)` 로 Target Component part 자체를 모핑했다. GP 세트 part 와 Target Component 가 같은 경우에는 증상이 없어 드러나지 않았다. origin/dev 의 94247f9 · c9c9ded 도 basis 전달 방식만 바뀌었고 `GetInputVTU()` 를 모핑하는 구조는 같다. reader-writer DLL 은 vcpkg 이행 전후 모두 8/25 소스로 무관하다.

## 기대

GP 세트 part 와 Target Component 가 다를 때 300 케이스가 조용히 실패하지 않아야 한다. 둘 중 하나.

1. **정합성 검증** — DOE 실행 전 Target Component 와 GP 세트 part 이름을 비교해 다르면 명확한 에러로 중단한다.
2. **모핑 소스를 Target Component 로 통일** — `edit_mesh` 대상 part 의 grid 를 기준으로 핸들·`volumeFixedIds` 를 다시 매핑한다. 핸들과 고정점 인덱스가 GP 세트 메시 기준이라 단순히 `ug` 를 모핑하도록 되돌리는 것만으로는 안 된다.

어느 쪽이든 원복은 실제로 `edit_mesh` 에 성공한 part 에 대해 그 part 의 원본으로 해야 한다.
