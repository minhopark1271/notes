# #364 G5 기준모델 목록 파일(referenceModels.json) 도입 (T9·T10·T11)

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/364
- Board status: Done
- Labels: ['in-progress', 'feature', 'split-group:360']

## Original Request
> Project-Manifest-4-Ticket-Slicing.md 기반으로 issue 생성

## Goal
프로젝트가 등재된 기준모델 목록을 파일로 갖는다 — `referenceModels.json` 원장이 생기고, 전역 기준모델·모델링 트리·Load 버튼 표시가 재오픈 후에도 복원된다.

## Background
> source: wiki [Project-Manifest-4-Ticket-Slicing](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Project-Manifest-4-Ticket-Slicing) "PR 상세" G5 절

프로젝트 열기가 레지스트리를 채우지 않는다 — 적재 시점이 전부 사용자 조작 이후이고 일괄 적재 함수(`model/DashProject.cpp:1066` `loadSetsFromConfigs`)는 죽어 있다 (문서 1 2절). 어떤 deck 이 이 프로젝트의 기준모델인지 기록하는 자리가 없어 재오픈하면 기준모델도 모델링 트리도 빈 상태로 선다.

원장을 도입해 등록 N개 중 활성 1개를 파일로 남긴다. T1(G1)이 `m_referenceFilePath` 를 루트 상대경로로 들게 해 뒀으므로 `referenceFilePath()` 반환값이 **원장 `path` 필드와 같은 문자열**이다 — 변환 코드가 없다.

**원장의 1차 키는 uuid 다(D24).** 발급은 이 PR(T9)이 하고, T12(G6 — #365)는 소비 전환만 한다. rename·이동 복구가 원장 `path` 필드 1개 갱신으로 좁혀진다 — 모듈 JSON 은 불변이다.

## Technical Details

### as-is
- 원장 없음. 등록 개념 자체가 없고 Load 가 렌더·기준 지정만 한다
- `referenceFilePath()` 는 Registry 멤버(`m_referenceFilePath`)를 그대로 돌려준다 (T1)
- `Registry` 에 `clear()` 가 없다 — `CloseProject`(`controller/DashProjectManager.cpp:212-221`)가 컨텍스트 캐시·커서를 비우지 않는다
- `DashModelingTreeWidget::populate`(`view/DashModelingTreeWidget.cpp:369`)가 디렉터리 경로를 받아 스캔한다

### to-be
- 원장 클래스 + 숨김 configs 의 `referenceModels.json` · `DashProject` API (`registerReferenceModel` · `referenceModelPath` — uuid→path 조회)
- **키 = uuid** (D24) — 등록 시 루트 상대경로 v5 파생 1회로 발급하고 이후 재계산하지 않는다. 경로는 `path` 필드
- Load 핸들러가 등록을 부르고 **멱등** — 이미 등록된 모델의 재Load 는 등록 no-op, 기준·렌더만 이동 (D4). 멱등 판정은 `path` 필드 스캔(원장이 한 자리수라 선형으로 족하다)
- `referenceFilePath()` 구현이 Registry 멤버 조회에서 원장 최상위 `activeModel`(uuid) 조회로 바뀐다. 접근자가 uuid 를 `path` 로 풀어 돌려준다. `setReferenceModel` 이 그 키를 갱신한다. **호출부는 불변** (D2·D22·D24)
- reference 커서의 내부 표현이 T10 에서 상대경로 → uuid 로 전환된다 (D12 개정). displayed 커서는 상대경로 유지 — 원장 미등재 파일(프리뷰 산출물)도 렌더하므로 uuid 키가 성립하지 않는다
- 프로젝트 열기가 `activeModel` 로 전역 기준모델을 복원하고 Load 버튼 활성 표시(D7)를 동기화한다
- `Registry::clear()` 신설 — 컨텍스트 캐시 + 커서 3개(렌더 경로·렌더 actor·기준모델 경로)를 비우고 `CloseProject` 가 부른다
- `populate` 인자가 디렉터리에서 **활성 기준모델 1건**으로 바뀐다 — 원장은 해제 지점이 없어 단조 증가하므로(D5) 전량을 넘기면 한 번이라도 Load 한 deck 을 재오픈마다 전부 파싱한다. 등재 목록 API 를 두지 않는 근거이기도 하다

### not-to-be
- `unregisterReferenceModel` — 해제 지점을 두지 않는다 (D5). 모델링 트리 삭제는 등록 해제가 아니다
- `getOrLoad` 시그니처 변경
- uuid **소비** 전환 — 세션·모듈이 원장 키를 content uuid 로 쓰는 것은 T12(G6). 이 PR 은 발급·영속까지만 한다 (D24 개정)
- 지문 불일치 처리 — 판정에 필요한 값(`sha256`·`size`·`mtimeMs`)을 남기는 데까지만 한다
- 활성 전환 전용 UI — Load 재클릭이 유일 경로다 (D6)

## Design

### 원장 스키마 (문서 1 "스키마" 절 · D22)
```json
{
  "schemaVersion": 1,
  "activeModel": "a3f2c1e0-…",
  "models": {
    "a3f2c1e0-…": {
      "path": "models/wing.dat",
      "sha256": "9f86d0…",
      "size": 184320112,
      "mtimeMs": 1757400000000
    }
  }
}
```

| 필드 | 역할 | 이 PR 에서 |
|---|---|---|
| `activeModel` (최상위) | 전역 활성 기준모델(M2)의 영속 자리 — `models` 키(uuid) 중 하나 또는 빈 값 (D22·D24) | T10 이 채우고 읽는다 |
| 키 = uuid | RW content uuid. 등록 시 루트 상대경로 v5 파생 1회로 발급하고 재계산 금지 (P2·D24). 모듈 조인·`activeModel`·스탬프의 1차 키 | T9 가 발급·저장 |
| `path` | 루트 상대경로. 파일 접근·표시·원장 유실 폴백. 외부 파일은 복사 후 등록하므로 절대경로 항목이 생기지 않는다 (P1) | T9 |
| `sha256` | 등록 시점 지문. 계산 후 동결 | T9 |
| `size`·`mtimeMs` | 등록 시점 stat. 적재 시 현재 stat 과 같으면 해싱을 건너뛴다 | T9 |

비교 시점은 deck 적재(RW 세션 open)다. 프로젝트 열기는 원장 복원만 하고 stat·해싱을 하지 않는다 (P5). `role` 같은 분류 필드는 두지 않는다 — 원장에 들어오는 것이 이미 채택된 deck 뿐이다 (P4).

**원장과 모델링 트리는 레벨이 다르다** — 트리는 영속화되지 않으므로 T11 은 저장본 복원이 아니라 재파싱이다 (문서 0 "원장과 모델링 트리" 절).

#### 핵심 시그니처
```cpp

QString registerReferenceModel(const QString& relPath);  // 멱등 — 반환은 uuid, 기존 항목이면 그 값

// controller/DashAnalysisModelContextRegistry.h
void clear();   // 컨텍스트 캐시 + 커서 3개
```

## PR #389 리뷰 이월 — 기준모델 미지정 상태에서 Condition DV 소멸 (@DCode-NumeReal 지적)

#389 리뷰에서 재현된 건. 이 티켓이 근본 원인(프로젝트 열기가 기준모델을 복원하지 않음)을 닫으므로 여기로 이월한다.

### 현상
프로젝트를 열고 Load 없이 기존 Condition Set 에 진입해 Set DV 를 누르면 저장해 둔 DV 가 전부 소멸한다.

### 경로 (코드 실측)
1. `setReferenceModel` 호출부는 `view/DashMainWindow.cpp:2280` 한 곳 — 파일트리 Load 의 `.dat`/`.inp`/`.dfsxml` 분기 안이다. 프로젝트 열기에는 복원 경로가 없다 (이 티켓 as-is 와 같은 원인).
2. `DashConditionParameterization::loadFromJson`(`model/DashConditionParameterization.cpp:405`)은 **이미 있는 행에 체크 상태만 덧입힌다**. 행 자체는 `refreshFromLoadedAnalysis` 의 deck 파싱으로만 생기므로, 기준모델이 없으면 표가 빈 채로 열린다.
3. Set DV → `syncDvFromCheckedFeConditions` → `saveDvCondition` → `rootObj["DV-Condition"] = buildDvConditionJson(빈 목록)`(`viewmodel/DashConditionParameterizationPresentationModel.cpp:131`). 섹션 전체가 `{}` 로 교체된다.

dev 에서도 `setModel` 이 읽던 `activeFilePath()` 가 프로젝트 열기 시점엔 동일하게 비어 있었다 — #389 가 만든 회귀가 아니라 선행 결함이다.

### #389 `c3072bc` 가드로 닫히지 않는 이유
그 가드는 **Set 생성 시점**에 `referenceFilePath().isEmpty()` 만 본다.
- 재현 시나리오인 **기존 Set 열기**를 막지 않는다.
- 이 티켓 as-is 인 `Registry::clear()` 부재 때문에 프로젝트 전환 시 상대경로가 잔류하면, `referenceFilePath()` 가 비어있지 않아 가드를 통과하면서 `QFile::exists` 는 실패해 표가 빈 채로 열린다. 가드를 우회하는 경로가 이미 있다.

- `activeModel` 복원(이 티켓 to-be)이 정상 경로를 닫는다.
