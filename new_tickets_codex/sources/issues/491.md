## Goal
DOE Init·Resample 에서 조건 세트(Condition Set)를 여러 개 선택할 수 있게 한다. 선택된 세트들의 설계변수를 합산해 한 번에 샘플링하고(T24), 그 선택이 파일에 저장되어 재기동 후에도 복원되며(T25), 실행 시에는 실행 대상 해석파일에 속한 세트의 변수만 입력 파일에 치환된다(T26 치환부). #366(G7)이 없앤 "여러 해석파일의 조건을 조건 표 하나에 쌓던 방식"의 대체 기능이며, **이 이슈까지 끝나야 통합 브랜치를 dev 로 머지할 수 있다.**

**자동 반복 실행은 범위 밖** — 실행은 현행대로 Reference File 라디오에서 해석파일 1개를 골라 1회 실행하고, 여러 해석파일을 돌리려면 라디오를 바꿔 다시 실행한다(현행 수동 방식 유지). 자동화는 #502 로 넘긴다.

- 따라서 실행 결과의 정합성(옳은 세트의 값이 옳은 파일에)은 이 이슈에서 끝내고, 편의 자동화(#502)·조합 기록(T20)·화면 데이터 출처 교체(T17)는 뒤로 미룬다 — 뒤쪽은 dev 반영 시점 제약 없이 점진 개발이 가능하다

해석 종류(인장·압축·피로)가 여럿인 것이 일반적이고, Optimizer 가 여러 성능지표를 동시에 고려하려면 샘플링이 한 번에 일어나야 한다(D23). 세트와 해석파일의 연결 키는 uuid 다(D24).

### to-be

## Design

### 착수 확정 2건 (2026-09-20)
- **구버전 호환은 읽기 입구 일회 변환(normalize-on-read)으로 시도한다** — 로더 입구의 변환 함수 하나가 구형(2원소 배열, 접두 없는 Table)을 신형으로 바꿔 올리고, 이후 코드(Preprocessor 읽기·resample)는 신형만 안다. 구형은 단일 세트 전제라 세트 정보 합성이 성립한다. G7 의 D15(키 없으면 1회 보충, 다음 저장이 신형)와 같은 계열. **포기 기준**: 변환이 로더 한 곳을 넘어 읽기·resample 에 분기를 남기기 시작하면 호환을 포기하고, 구프로젝트는 DOE 재설정이 필요함을 명시한다
- **기준모델 미기록(미핀) 세트는 선택 시 차단 + 로그 안내** — 구프로젝트 세트는 화면에 진입한 적이 없으면 `referenceModel` 키가 없어 겹침 차단(D27)·실행 소속 판정이 불가하다. 선택을 거부하고 "세트 화면에 한 번 진입 후 다시 선택" 을 로그로 안내한다. 선택 시점 자동 보충은 하지 않는다 — 그 시점 전역이 그 세트의 해석파일이라는 보장이 없어 잘못 고정될 위험

스키마는 아래 "확정 스키마 샘플"이 정본이다 — 필드 이름 수준의 조정만 허용, 구조(동형 맵 · 병렬 배열 · module 구분)는 고정. 나머지(체크 콤보 위젯 구현 · `source` 소비처 점검)는 구현 중 결정한다.

### 확정 스키마 샘플 (2026-09-20)

시나리오 — Condition Set1(인장 `analysis/tension.dat`) · Condition Set2(압축 `analysis/compression.dat`, 같은 이름 변수 `Force` 보유) · Geometry Set1(`analysis/wing.dat`). 셋 다 원장 등록·`referenceModel` 보유.

**선택 저장 — `geometry` 필드 + 세트 이름 키 맵, 값은 빈 객체**
```jsonc
// 구형 (현행) — DV json 파일명 2원소 배열 [condition, geometry] (DashAnalysisLauncher.cpp:1140-1143)
"Selected Design Variables": ["DvCondition_Set1.json", "DvGeometry_Set1.json"]

// 신형
"Selected Design Variables": {
  "geometry":   { "set": "Set1" },
  "conditions": { "Set1": {}, "Set2": {} }
}
```
- 값이 빈 객체인 이유 — 복원에 필요한 것은 세트 이름뿐이다. 변수 체크 상태는 `DvCondition_{Set}.json` 의 `boolean` 필드가, 해석파일 정보는 세트의 `referenceModel` 이 정본이라 여기 두면 이중 기록이다. 빈 자리는 T20 이 `deck{uuid, path}` 를 채워 `parameterization` 으로 완성한다 — 구조 변환 없이 값만 추가된다
- 구/신 판정: 배열이면 구형, 객체면 신형. 일회 변환은 구형 파일명 `DvCondition_{Set}.json` 에서 세트 이름을 추출한다

**DOE Table — `columns` 를 `headers` 와 인덱스 병렬로 추가, `module` 구분 포함**
```jsonc
"DOE Table": {
  "headers": ["Set1.Force", "Set1.Temp", "Set2.Force", "Set1.H1_x"],
  "source":  ["tension", "tension", "compression", "Morphing|wing.dat|WING"],
  "columns": [
    { "module": "condition", "set": "Set1", "key": "Force" },
    { "module": "condition", "set": "Set1", "key": "Temp"  },
    { "module": "condition", "set": "Set2", "key": "Force" },
    { "module": "geometry",  "set": "Set1", "key": "H1_x"  }
  ],
  "samples": [ { "key": "case_001", "active": true, "values": [1000.0, 25.0, 950.0, 0.35] } ]
}
```
- `module` 이 필요한 이유 — 세트 이름은 모듈별로 따로 매겨져 Condition Set1 과 Geometry Set1 이 공존할 수 있다. 치환 소속 판정은 `condition` 열만 본다
- `headers` 의 접두 문자열은 표시 전용이고 연결은 `columns` 로만 한다. `source` 는 그 열 세트의 해석파일 이름(표기 교체는 T17·3회차). `columns` 없는 구 Table 은 일회 변환이 "단일 조건 세트"로 합성한다
- 점검 — `DashDoeConfigManager.cpp:237-252` 가 첫 열에서 대표 파일명(`refFileName`) 하나를 뽑는 단일 세트 전제 코드다. 다중 세트에서 그 값의 소비처를 구현 중 확인한다

**치환 소속 판정 (T26 치환부) — 4단계**
```
1. 라디오 선택 파일 → 프로젝트 루트 상대경로     analysis/tension.dat
2. 원장 path 스캔 → 템플릿 uuid                  0d9f…
3. 열의 {set} → 그 세트의 referenceModel.uuid 와 비교
   Set1(0d9f…) == 템플릿 → 치환 대상
   Set2(7c21…) ≠ 템플릿  → 제외
   일치 0건               → 조건 변수 0건 적용 + 경고 로그
4. 접두 뗀 key("Force")로 입력 파일의 ${Force} 자리를 채운다
```
경로 문자열 비교가 아니라 uuid 비교다 — 경로는 파일 이동·개명으로 변하지만 uuid 는 원장이 관리하는 안정 식별자다(D24).

### 왜 T24·T25·T26 치환부를 한 덩어리로 하나
어느 하나가 빠져도 중간 상태가 **틀린 결과**를 낸다 — T25 가 없으면 여러 세트의 선택을 저장할 자리가 없고, 치환부가 없으면 접두 이름이 조용히 전부 매칭에 실패해 조건 변수가 적용되지 않은 산출물이 나온다. 문서 0 D8 이 허용하는 과도기는 "현행과 같게"이지 잘못된 결과가 아니다.

### 왜 자동 반복은 빼나
치환부가 "옳은 세트의 값만 적용"을 보장하고 나면, 반복 자동화는 편의 기능이다. 라디오를 바꿔 다시 실행하는 것은 현행 방식 그대로라 D8 "현행과 같게"에 해당한다. #367 구판의 "T25 까지만 하면 틀린 결과" 논거는 치환부를 이 이슈에 함께 넣는 것으로 해소된다 — 라디오로 고른 해석파일의 실행은 그 파일에 속한 세트의 변수만 옳게 치환한다.

### 치환 범위 규칙
- 실행 대상 해석파일 = 라디오로 고른 템플릿 1개. 소속 판정은 열의 `{set}` → 그 세트의 `referenceModel.uuid` == 템플릿의 uuid
- 같은 해석파일을 쓰는 세트 여러 개는 한 번의 실행에 함께 적용(D23) — 이름 겹침은 T24 의 선택 거부(D27)가 미리 막는다
- 일치하는 세트가 없으면(조합에 없는 파일을 고른 경우) 조건 변수 0건 + 경고 로그 — 형상 변수는 현행대로
- 접두 문자열은 표시 전용 — 연결·판정은 전부 `{set, key}` 메타데이터와 uuid 로 한다
