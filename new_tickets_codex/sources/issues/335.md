## 1. `ports/mesh-ops/portfile.cmake` 주석이 소비자를 함정에 빠뜨린다

주석이 지금도 이렇게 말한다:

> *"Consumers MUST pin intel-mkl to 2023.2.0 … the symptom is an intel-mkl build failure, **not a silent ABI mismatch**"*

**예측이 정확히 반대다.** 메타 저장소는 `82f2679`("chore: intel-mkl pin 을 삭제 #43")로 핀을 지웠고, 레지스트리 CI 의 Validation Test 는 `intel-mkl 2025.2.0#1` 로 빌드해 성공한다. 캐시가 `2025.2.0#1` 로 워밍돼 있으므로 **이 지시를 따르는 소비자는 빌드 실패가 아니라 조용한 ABI 불일치 → 캐시 미스**를 겪는다.

**실제 피해** — #313 브랜치가 이 함정에 빠졌고 `70eca82` 가 정정했다.

**수정** — 주석 삭제 또는 현재 사실로 갱신. 1줄짜리 변경이다.

## 3. `preprocessor` 가 메타 저장소에 없다

메타 저장소의 `repos.json` · `vcpkg.json` 모두 `preprocessor` 언급 **0건**.

**영향** — feature 선택의 **정본이 없다.** #313 의 매니페스트는 `[test]` 를 다른 포트와의 유추로 정했고 **CI 교차 검증도 받지 않는다.** 나머지 5개는 `repos.json` 과 일치시켰다(`core-lib[test]` · `reader-writer[test]` · `doe[test]` · `mesh-ops[]` · `cae-launcher[]`).

feature 가 어긋나면 **ABI 해시가 달라져 `--only-binarycaching` 이 하드 실패**한다.

**수정** — 메타 저장소에 `preprocessor` 등록 + feature 확정 + CI 검증 대상 포함.

## 4. SSOT provider CI 러너에 Abaqus 2024 SDK 스냅샷이 없어 V2020 플러그인만 공급된다

**현상** — vcpkg 로 오는 preprocessor 는 `Preprocessor_Abaqus_V2020.dll` **하나만** 준다. 레거시 `external/DashOptiPreprocessor-1.2.2` 는 `Preprocessor_Abaqus_V2024.dll` 을 줬다. **이행으로 Abaqus 지원 버전이 후퇴했다.**

**원인** — 플러그인은 **호스트에 설치된 Abaqus SDK 스냅샷**(`win_b64/code/{include,lib}`)을 보고 버전별로 빌드된다. 빌드할 버전 목록은 `DASH_PR_ABAQUS_VERSIONS` 이고, 각 버전마다 `ABAQUS_BASE_DIR_<ver>` 루트가 있어야 한다.

- 소스 저장소의 개발자 프리셋은 두 버전을 빌드한다 — `DashOpti_Preprocessor/CMakeUserPresets.json:19-21` (`DASH_PR_ABAQUS_VERSIONS: "2020;2024"`, `ABAQUS_BASE_DIR_2020` · `ABAQUS_BASE_DIR_2024`)
- **레지스트리 포트는 소스 기본값 `"2020"` 을 그대로 쓴다.** `ports/preprocessor/portfile.cmake:27-32` 의 주석이 이유를 직접 적고 있다:

  > *"Abaqus: headers + import libraries of each version in DASH_PR_ABAQUS_VERSIONS (source default "2020" — **the runner has only the 2020 SDK; 2024 is opt-in until its snapshot is on the runner**). … Root: ABAQUS_BASE_DIR_2020"*

즉 **SSOT provider(바이너리 캐시를 공급하는 CI 머신)에 Abaqus 2024 SDK 스냅샷이 없어서** 2024 플러그인이 애초에 생산되지 않는다. 포트는 `-DDASH_PR_WITH_ABAQUS=ON` 을 명시해 "호스트 SDK 가 없으면 조용히 빠지지 않고 configure 가 FATAL_ERROR" 로 끊도록 설계돼 있는데, **버전 목록 자체가 2020 하나라 그 안전장치에 걸리지 않는다.**

**영향** — 현장이 Abaqus 2024 를 쓰면 ODB 를 읽지 못한다. Abaqus ODB API 는 버전 간 호환이 보장되지 않으므로 V2020 플러그인으로 2024 ODB 를 여는 것은 기대할 수 없다. (참고 — Mechanical 은 `V251` · `V261`, Motion 은 `V261` + `AnsysMotionBridge` 가 정상적으로 온다.)

**To-be**

1. **CI 러너에 Abaqus 2024 SDK 스냅샷 배치** — 설치본 전체가 아니라 `win_b64/code/{include,lib}` 스냅샷이면 된다(`DashOpti_Preprocessor/CMakeLists.txt:94-95` 가 명시)
2. 포트에서 `DASH_PR_ABAQUS_VERSIONS` 를 `"2020;2024"` 로 올리고 `ABAQUS_BASE_DIR_2024` 를 OPTIONS 로 전달
3. 새 버전 발급 + 바이너리 캐시 재워밍 (ABI 해시가 바뀐다)
4. portfile 주석의 *"2024 is opt-in until its snapshot is on the runner"* 문구 갱신

**선행 결정** — **현장에서 실제 쓰는 Abaqus 버전 확정.** 2024 만이면 2020 을 뺄지, 둘 다 유지할지가 갈린다. 러너 디스크·라이선스 제약도 확인 대상.
