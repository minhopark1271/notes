## Goal
서브시스템 직렬 풀 2종(모핑·RW, 각 `maxThreadCount=1`)과 `WorkerJob`(`QtConcurrent::run(pool)` + `QFutureWatcher` → Job 시그널 번역)이 도입되고, #260 이 세운 **`RunOneSample` 1건 = WorkerJob 1개**가 모핑 직렬 풀에서 실행되고, 모핑 진입점 6곳이 "한 번에 하나"로 단일화되고, per-case 상한이 **선점 판정**으로 바뀐다 — 목표는 동시성이 아니라 **응답성**.

> **범위 확정 (2026-08-18 · #260·#251·#264 머지 반영).** 초판의 "executor 통지 표면 QObject 화·시그널화" 는 **무효** — #260 이 통지를 값 반환(`DashSampleResult`)으로 닫아 승격할 표면이 없다. 대신 워커화가 새로 여는 3건이 본 티켓 몫으로 들어온다: **한 Job 이 두 서브시스템(모핑 + RW)을 만지는 풀 배치 규약** · **취소·상한 시 UI 해방 축 분리** · **per-case 상한 선점 워치독**.

## Technical Details

### as-is

**스레드 현황**
- 워커 스레드를 만드는 코드는 `QtConcurrent::run(this, &DashAnalysisLauncher::runAnalysisInThread)`(`model/DashAnalysisLauncher.cpp:234`, 본체 `:312`) **1건뿐**. DOE 샘플링 전용 — WorkerJob 의 원형.
- `QThreadPool`·`moveToThread` **0건** → 풀 인프라 신설이 본 티켓 몫.
- `controller/async/` = `Job` · `ProcessJob` · `ProcessKill` · `LineAssembler`. `ThreadPools`·`WorkerJob` 없음.
- 앱 빌드는 `CMakeLists.txt` 의 `GLOB_RECURSE controller/*.cpp` 라 신설 파일 자동 포함. 명시 목록은 `tests/CMakeLists.txt` 뿐 — Qt Core+Test 전용(VTK·OCCT 없음)이라 `WorkerJob.cpp` + `Job.cpp` 만으로 단위 테스트가 성립한다.

**Job 표면** (#207 산출 — `controller/async/Job.h`)
- `State{Pending,Running,Succeeded,Failed,Cancelled}` · 시그널 `started()`·`progressed(int)`(`:37`)·`finished(Job::State, QString)`(`:39`) · 단일 전이점 `setState`(`:45`)에 **터미널 잠금**(`:50-53`) 내장 — 늦은 완료가 두 번째 `finished` 를 못 낸다.
- `progressed(-1) = indeterminate` 규약 선언됨, **소비자 0건**(`:37`).
- 구현체는 `ProcessJob` 1종 → WorkerJob 이 두 번째. `ProcessJob` 규약 2가지: 결과는 **pull 접근자**, 앱 종료 상한은 **static 훅**(`ProcessJob::cancelAllRunning()`, `main.cpp:40-41` 의 `aboutToQuit`).

- **오늘은 안전하다** — 6곳 전부 GUI 스레드라 동시 실행이 원리적으로 불가.
- **배치만 풀로 옮기면 처음으로 진짜 동시가 된다** — 워커의 `Morph()` 와 GUI 의 1·1b·2·5 가 겹친다. 계획의 착수 전 확인 ⑴("워커가 도는 동안 메인이 같은 모핑 operator 를 설정하지 못함")은 확인 항목이 아니라 **구현 항목**이다.
- 프리뷰(1·1b·2)는 live 그리드를 그대로 읽는다 — `RunVolumeMorphing:489` 가 `GetMorphingMeshSet()`(DeepCopy 아님)을 넘긴다. 워커로 보내려면 프리뷰도 스냅샷을 떠야 한다.

**워커화가 새로 여는 구멍 3건** — 재조사(2026-08-18) 신규

1. **한 샘플 Job 이 두 서브시스템을 만진다.** `ExecuteOneSample`(`.cpp:584`) 은 RW 모듈(`getPartData:605` → `updateMeshPoints:948`→`edit_mesh` → `exportSolverInput:960`)과 모핑 DLL(`RunVolumeMorphing:874`)을 번갈아 호출한다. 두 풀을 독립 병렬로 두면 #215 가 `rwSerialPool()` 에 첫 소비자를 붙이는 순간 **풀 사이로 등급 2 가 뚫린다**. RW 모듈은 컨텍스트당 인스턴스(`DashAnalysisModelContext.cpp:1217` `create_*_module()`)이나 벤더 문서 근거가 없어 등급 2 판정은 유지된다([#194](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/194-1-async-execution-patterns) 5-2절).
2. **공유 컨텍스트 변이 창이 워커로 넘어간다.** 배치 컨텍스트는 `registry.getOrLoad(canonicalPath)`(`DashManager.cpp:1017`)로 얻은 **GUI 활성 컨텍스트와 같은 인스턴스**다. 변이 창은 `DashContextMutationScope`(executor `:940`·`:1017`)로 열리는데 이 창은 **GUI 심층 편집만 거부**하고 그 검사 지점은 `model/DashConditionParameterization.cpp:347` **1곳뿐**이다. 오늘은 배치가 GUI 스레드를 점유해 다른 편집이 물리적으로 불가능하지만, 워커화 후엔 배치 중 GUI 편집 경로가 열린다.
3. **per-case 상한이 사후 판정**이다. `kMorphSampleBudgetMs`(600000ms) 검사는 `RunOneSample` 이 **반환한 뒤**(`:1360-1364`) 돌고, 주석이 `"스레드가 없어 선점은 못 하므로 샘플 경계에서 판정한다 (선점은 #214)"` 라고 소유를 지목한다. A(wbpj) 배치는 같은 상한을 `m_stpWatchdog`(QTimer) + `kStpCaseTimeoutMs` 로 **선점** 판정한다 — 참조 구현이 이미 있다.

**취소 현황** — `cancelAllRuns:844`
- 모핑 분기(`:956-969`)는 P2 협조적 취소: `m_batchCancelled = true` 만 세우고 잔여 미착수분은 다음 샘플 경계에서 확정, 진행 1건은 완료를 수용(P1). 디스패치가 끝나 경계가 없으면 즉시 `abortBatch`.
- 워커 Job 은 아직 없으므로 취소 대상에 들어 있지 않다.
- 동기 실행이라 Stop 클릭 자체가 샘플 반환 뒤에야 처리된다 → **P1 과 P4("UI 즉시 해방")가 부딪히지 않는다.** 워커화가 이 충돌을 처음으로 관측 가능하게 만든다.

**Start/Stop UI**
- `analysisStarted`/`analysisFinished`/`analysisFailed` 로만 구동(`view/DashAnalysisLauncherWidget.cpp:473-487`). `batchActive()` 소비자는 아직 0건.
- **`batchActive()` 는 모핑 진입점에서 도달 불가** — `DashJobRunner` 는 세트별 `DashAnalysisLauncher`(`model/DashProject.cpp:84`) 소유이고 `DashManager` 는 둘 중 어느 것도 참조하지 않는다. 진입점 1·1b·2·4·5 는 `DashManager`/`DashMorphingUtils` 쪽이라 판정자를 따로 세워야 한다.

**모핑 operator**
- `DashMorphingEngine::MorphingConfiguration()`(`:40-60`)이 내부적으로 16 스레드를 띄운다 — `MT_DIRECT` `:51`, `SetSolverNumberOfThreads(16)` `:53`. 직렬 풀(`maxThreadCount=1`)은 CPU 활용을 낮추는 선택이 아니라 **operator 설정 상태의 상호배제**가 목적이다.
- `m_morphingOperator` 는 `unique_ptr` 소유이고 `nullptr` 일 때만 생성된다(`:48-54`) → 엔진 인스턴스당 operator 1개. `SetKernelFunction`(`:57`) → `SetInitialConfiguration`(`:59`) → `Morph()` 3단 시퀀스는 비원자.

### to-be

- **`controller/async/ThreadPools` 신설** — `morphingSerialPool()`·`rwSerialPool()`, 각 `maxThreadCount=1`, `waitForAllSerialPools()`. 두 풀은 서로 병렬.
- **풀 배치 규약을 `docs/ThreadingContract.md` 에 신설(7절)** — "**두 풀 동시 사용은 두 Job 의 서브시스템 집합이 서로소일 때만.** 두 서브시스템을 함께 만지는 Job(= 모핑 샘플)은 모핑 풀 하나에만 오르고, 그 Job 이 활성인 동안 RW 풀에 제출하지 않는다." `rwSerialPool()` 은 선언만 하고 첫 소비자(#215)가 이 규약을 준수한다.
- **`WorkerJob` 신설** — `QtConcurrent::run(pool)` + `QFutureWatcher` → Job 시그널 번역, `shared_ptr<atomic<bool>>` 취소 채널(맨 멤버 플래그 금지 — [#205](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/205-5-w6-w10-async-minimal-example) 3-4절), 결과는 pull 접근자(`ProcessJob` 규약 계승).
- **`RunOneSample` 1건 = 모핑 직렬 풀 위 WorkerJob 1개.** 완료 원천만 `DashSampleResult` 반환 → `Job::finished` 로 교체. `onMorphSampleFinished(result)` 가 `finished` 슬롯이 되고 연쇄·정책·장부·단일 종료 지점은 무수정. `m_morphJob` 은 `finished` 슬롯에서만 비운다.
- **모핑 단일화 가드 — 방안 A(모핑 국면 전면 차단).** 진입점 1·1b·2·4·5 는 모핑 활성 중 조기 반환하고, 3 은 `tryAcquire()` 실패로 재실행을 거부한다. 사용자 트리거(1·1b·2·3)는 위젯 비활성 + 상태바 안내로 거부가 드러나지 않게 한다.
- **위젯 비활성은 루트 컨테이너 1개** — 모핑 파라미터 편집 표면의 루트를 `setEnabled(false)` 로 끄고, **그 루트를 티켓에 이름으로 못 박는다**(착수 시 실측). 위젯을 열거하면 목록이 드리프트한다(#243 이 .ui 드리프트를 따로 추적 중). 진입 버튼만 끄는 안은 as-is 구멍 2(변이 창 검사 지점 1곳)를 못 덮어 채택하지 않는다.
- **진입점 5 는 루프 시작에서 1회 거부 + per-sample `false`** — `DashOptimizer.cpp:1498`·`DashModelRunner.cpp:2222` 는 GUI 스레드 실측 확인. per-sample `false` 만 두면 최적화가 전 iteration 을 실패시키며 완주해 "결과가 이상함" 으로만 보인다. 루프 **진입 전** `MorphingGate::busy()` 검사 + 사용자 통보로 그 실패 모드를 없애고, per-sample `false` 는 레이스 방어로 남긴다.
- **판정자 — 프로세스 전역 게이트 `MorphingGate`**(`controller/async/`). `batchActive()` 는 진입점에서 도달 불가하므로(아래 as-is) 게이트가 "모핑 진행 중" 의 정본이 된다. 조회 진입점(1·1b·2·4·5)은 `MorphingGate::busy()` 만 보고, **획득 진입점(3)은 `tryAcquire()` 의 실패를 거부 사유로 쓴다** — 획득과 판정이 한 호출이라 검사·획득 사이가 벌어지지 않는다. 상태 정본을 두 벌 두지 않기 위해 `DashManager` 미러 bool 은 만들지 않는다.
- **진입점 3 의 술어는 `tryAcquire()` 실패 ‖ `batchActive()`** — 두 술어가 서로 다른 구멍을 덮는다. `DashJobRunner` 는 **세트당 1개**(`DashProject.cpp:708`)이고 재진입 가드 `:2327`·`:2731` 은 러너 로컬이라, 워커화 후 Set1 워커가 도는 중 **Set2 의 Start 가 통과한다** — 전역 게이트만 이걸 막는다. 반대로 게이트 수명은 모핑 국면뿐이라 솔버 구간의 재진입은 `batchActive()` 만 막는다.
- **세트가 달라도 모핑 배치는 직렬화한다** (2026-08-18 확정). 게이트가 프로세스 전역이므로 Set1·Set2 의 모핑 DOE 배치가 순차 실행된다. 등급 2 상호배제가 구조적으로 보장되는 대가로 세트별 동시 실행을 포기한다 — 동시 실행을 살리려면 `Morph()` 의 등급 2 판정을 벤더 문서로 뒤집어야 하고([#194](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/194-1-async-execution-patterns) 5-2절 재개봉) 그건 본 티켓 범위가 아니다.
- **게이트 수명 = 모핑 국면**(배치 전체가 아니다). `PrepareDoeMorphingBatch` 성공에서 획득, **`releaseMorphBatch()` 와 워커의 물리적 종료 중 나중 것**에서 해제. 배치 종결(`finishBatch`)까지 쥐면 모핑이 0건인 솔버 구간 — 배치에서 가장 긴 구간 — 까지 프리뷰가 막힌다. `releaseMorphBatch()` 는 정상 소진 · 취소 · `abortBatch` · `finishBatch` 모든 이탈 경로가 지나므로(`finishBatch:1224`) **해제 판정이 한 곳으로 수렴한다** — 해제 *지점* 은 두 곳(양쪽에서 나머지 조건을 재검사)이다.
- **★ `Job::finished` 는 워커 종료를 뜻하지 않는다 — 생존 판정은 `workerExited` 로 가른다.** `Job` 의 cancel 규약은 즉시 터미널이다: `ProcessJob::cancel:95-119` 는 `QProcess` 를 **떼어내 자기 종료를 자기가 회수하게** 만든 뒤 `setState(Cancelled)` 를 동기 방출한다. 풀 스레드는 그 "떼어내기" 가 불가능해 — 스레드가 모핑 operator 를 계속 쥔다 — 같은 규약을 그대로 쓰면 `Morph()` 가 도는 중에 `finished(Cancelled)` 가 나고, 게이트가 풀려 **프리뷰가 열린다(정확히 본 티켓이 막으려던 등급 2 위반)**. 따라서 `WorkerJob` 은 터미널 잠금 **밖**에 `workerExited()`(= `QFutureWatcher::finished`)를 하나 더 두고, **게이트 해제 · `m_morphJob` 정리 · `batchActive()` 생존 항을 전부 그 시그널 기준**으로 판정한다. 이 분리는 아래 "UI 해방 2축" 을 시그널 2개에 1:1 로 얹는 것이기도 하다 — `finished` = 즉시축, `workerExited` = 지연축.
- **`WorkerJob` 수명 규약** — `workerExited` 방출 후에만 `deleteLater`. watcher 가 task 보다 오래 살아야 한다.
- **`batchActive()` 에 워커 생존 항 추가** — `m_wbpjBatch.phase != Idle || m_ledger.hasBatch() || m_morphWorkerAlive`. 생존 항의 기준은 **`workerExited` 미도달**이지 `m_morphJob != nullptr` 이 아니다(위 ★). Start 재활성이 워커보다 앞서면 다음 배치가 진행 중 워커와 겹쳐 등급 2 가 뚫린다.
- **취소·상한 시 UI 해방 축 분리** — Stop 직후 **즉시**(`Job::finished`): 스피너 해제 · 로그 · 잔여 케이스 Cancelled 기록(P4 충족). **워커 종료 후**(`workerExited`): Start 재활성(등급 2 유지). 진행 1건의 늦은 결과는 장부의 터미널 잠금과 `Job::setState` 터미널 잠금이 이중으로 폐기한다.
- **취소 채널은 착수 전 차단 전용** — `WorkerJob` 의 `atomic<bool>` 채널은 task 착수 **전** 에만 유효하다. task 본문이 `RunOneSample(ctx, sample, index)` 1회이고 그 서명(`DashMorphingDoeExecutor.h:48`)에 채널 인자가 없어 폴링 주체가 없기 때문이다. 이는 이미 확정된 **P1(진행 1건 완료 수용)과 같은 의미**다 — "협조적 취소" 는 여기서 *미착수분 차단 + 늦은 결과 폐기* 를 뜻하고, 실행 중 중단은 없다. `RunOneSample` 에 채널 인자를 넣는 안은 기각: 폴링 지점이 `ExecuteOneSample` 의 단계 사이뿐이라 **가장 긴 `Morph()` 를 못 자르는데** #260 산출(2표면)을 재개봉해야 한다. RW 를 워커로 올리는 #215 가 같이 판단한다.
- **per-case 상한 선점 워치독** — `m_stpWatchdog`/`kStpCaseTimeoutMs` 와 같은 형태의 QTimer 를 모핑 칸에 건다. 상한 초과 시 위 취소 경로와 동일 처리(즉시 통지 · Start 는 워커 종료 후). 사후 판정 `:1360-1364` 은 워치독으로 대체한다.
- **앱 종료 상한 — 배수에 타임아웃을 둔다.** `waitForAllSerialPools(int timeoutMs)` 가 `QThreadPool::waitForDone(msec)` 를 쓰고, 초과하면 **기다리지 않고 종료를 진행**하며 로그를 남긴다. 무한 대기는 안전해 보이지만 `Morph()` 가 kill 불가라 최대 `kMorphSampleBudgetMs`(10분) 이상 응답 없는 종료가 되고, 그러면 사용자가 작업관리자로 강제 종료해 **더 나쁜 상태**를 만든다. 타임아웃은 짧게(수 초) 둔다.
- **앱 종료 배수 위치** — `main.cpp:40-41` 의 `aboutToQuit` 훅에서 `ProcessJob::cancelAllRunning()` 과 나란히. `~DashManager()`(`:131`)의 `shutdownBlocking()` x4(`:134`·`:138`·`:142`·`:146`)는 정적 소멸 시점이라 배수 자리로 부적절 — `aboutToQuit` 이 정적 소멸보다 앞서므로 순서 요구가 자연히 만족된다.
- **워커가 매달릴 때의 Start** — 게이트를 강제 해제하지 않는다(등급 2 위반 허용이 된다). 대신 상태바에 "이전 배치의 모핑 작업 종료를 기다리는 중" 을 표시해 **잠긴 이유를 관측 가능하게** 한다.
- **진행 표시** — indeterminate 스피너. `progressed(-1)` 의 첫 소비 또는 `started`/`finished` 기반.

### not-to-be

- **executor QObject 화·시그널화 없음** — 초판 항목 철회. #260 이 통지를 값 반환으로 닫았고 `SampleStatusCallback` 은 executor 내부 전용이다. 워커 경계를 넘는 것은 `DashSampleResult` 값뿐이라 마샬링 대상이 없다.
- **프리뷰 모핑 워커화(방안 B) 없음** — 프리뷰 스냅샷 캐시·무효화 정책과 메시 QC 모달(`:1387`) 재구조화로 +400~650줄. 귀속은 #215(또는 별건). `DashMorphingRunContext` 가 재사용 가능한 형태로 서 있으므로 착수 비용은 이미 절반 내려가 있다.
- **모핑 국면 중 과차단 수용** — 게이트는 모핑 국면만 세우므로 A(wbpj) 배치 중과 솔버 구간에는 프리뷰가 열린다. 반대로 모핑 국면 중에는 모핑과 무관한 편집까지 위젯 비활성으로 함께 막힌다 — 정합성 우선으로 수용하고 세분화는 하지 않는다.
- **모듈 전환·파트 변경·프로젝트 로드 차단 없음** — 워커화하면 샘플 실행 중 GUI 이벤트 루프가 살아나므로 이 경로들이 열리는데, 게이트는 모핑 진입점 6곳만 막는다. 위젯 비활성이 덮는 범위(모핑 파라미터 편집 표면) 밖의 내비게이션은 본 티켓이 다루지 않는다 — 진입 계약 자체는 #221 소유다.
- **`rwSerialPool()` 소비자 없음** — 선언만. 첫 소비자(RST/KPI 파싱 · 배치 프롤로그의 `getOrLoad` `.dat` 파싱)는 #215 이며 위 7절 규약을 준수해야 한다.
- **준비 단계 워커화 없음** — `MakeMorphingInputSnapshot()` DeepCopy 와 `getOrLoad` `.dat` 파싱은 GUI 에 남긴다(D6 규약·프로젝트 상태 조회). 배치 시작 직후 짧은 정지는 통과 대상이고 이동은 측정 후 판단.
- **꼬리 계속화·폴링 제거 없음** — #260 완료분. 본 티켓은 완료 원천만 교체한다.
- **`generateInputCases` 분해 없음** — #269 소유. model `processEvents` 전량 제거는 #215.
- **최적화·배치 동시 실행 지원 없음** — 진입점 5 는 차단으로 확정. 대기·큐잉 의미론은 도입하지 않는다.
- **결정형 진행바 없음** — indeterminate 스피너까지. 케이스별 진행 상세는 W11.
- **선결 조건 수리 없음** · **등급 1 실측 승급 비권장**(MSVC — TSAN 부재) · **외부 축 재작업 없음**(#210·#211·#212 완료분 불변).
- **모듈 진입·재진입 크래시(#221) 무관** — 같은 프리뷰 경로를 만지지만 결함 계급이 다르다(모듈 전환 시 상태 누적·무가드 역참조). 본 티켓의 가드가 그 6건을 고치지 않는다.

## Design

### 현황 분석
- Job 표면(#207)에 **두 번째 구현**을 추가하는 작업. `QThreadPool`/`moveToThread` 0건이라 풀 인프라는 신설.
- #213(진입 경계) · #260(준비/실행 2표면 · 값 결과) · #251·#264(장부 · 단일 종결 · 활성 질의)로 **워커를 끼울 자리가 완성돼 있다**. `RunOneSample` 호출 1줄(`:1355`)이 Job 으로 바뀌고 `onMorphSampleFinished` 가 슬롯이 되는 것이 변경의 핵심이다.
- 남은 설계 문제는 스레드 안전이 아니라 **경계 정의** 4건: 상호배제 판정자를 어디에 두는가 · 두 풀에 한 Job 을 어떻게 배치하는가 · UI 해방을 어느 축으로 가르는가 · 상한을 선점으로 볼 것인가.

### 대안 비교 — 등급 2 상호배제 (결정 완료)

| 방안 | 핵심 | 게이트 토큰 구간 | 비용 | 프리뷰 가능 시점 |
|---|---|---|---|---|
| **A. UI 가드 (전면 차단)** | 모핑 국면 중 다른 모핑 진입 전면 차단 + 위젯 비활성 | 모핑 국면 (준비 성공 ~ `releaseMorphBatch`) | 40~60줄 | 모핑 국면 종료 후 (= 솔버 구간부터) |
| A′. 샘플 틈 허용 | 프리뷰는 GUI 유지, 샘플 경계 틈에서만 통과 | 샘플 1건 (Job `start` ~ `finished`) | **A 와 동일** — 초판의 "~0" 은 무효 | 샘플 사이 틈 N−1 개 |
| B. 프리뷰도 같은 직렬 풀 | 프리뷰 1·1b·2 도 WorkerJob 화 | 불요 (풀이 구조적 배제) | 400~650줄 + 설계 결정 2건 | 샘플 1건 대기, GUI 무블로킹 |
| C. 전역 모핑 mutex | `Morph()` 를 락으로 감쌈 | — | 진입점 수정 불요 | **기각** — GUI 스레드가 락을 기다림 = 응답성 목표와 정면 충돌 |

**A′ 의 비용 정정.** 초판 표의 "~0" 은 배치가 동기 실행이던 시절 서술이다. 워커화 후엔 샘플이 도는 **동안** GUI 이벤트 루프가 살아 있어 프리뷰 클릭이 워커와 동시에 디스패치된다 — 정확히 등급 2 위반이다. 따라서 A′ 도 "지금 샘플이 도는 중인가" 를 물어야 하고 **A 와 같은 게이트 배선이 필요하다.** 두 방안의 차이는 코드가 아니라 토큰을 쥐는 구간뿐이다.

### 선택 — A · 두 풀 유지 · UI 해방 2축 · 선점 워치독

**A (상호배제)** — 배선 비용이 A′ 와 같으므로 판단 근거는 의미론뿐이다. 프리뷰는 `interaction->GetSurfaceGeometry()` 와 `DashManager` 소유 엔진만 만지고 RW 모듈·해석 컨텍스트는 건드리지 않으므로(`:493-534`), A′ 에서 프리뷰가 통과해도 오염되는 산출은 없다 — 걸리는 것은 순수하게 등급 2(모핑 DLL 동시 실행) 하나다. 그래도 A 를 고르는 이유 2가지:

1. **A′ 는 거부를 사용자에게 감출 수 없다.** 샘플이 5초면 버튼이 5초마다 on/off 하고, 누른 순간이 틈인지 실행 중인지 알 수 없어 "될 때도 있고 안 될 때도 있는" UI 가 된다 — "거부 자체가 드러나지 않게 한다" 는 원래 의도와 반대다. A 는 국면 내내 상태가 일정하다.
2. **A′ 는 배치가 틈마다 임의의 GUI 상태 변화를 견뎌야 한다는 요구를 새로 만든다.** 그 영역은 #221 이 구조적 결함 6건(진입 전제 미영속화 · 조용한 지오메트리 대체 · 비-idempotent 진입 · 무가드 역참조)을 열어 둔 곳이고, 본 티켓에 그것을 검증할 수단이 없다. A 는 모핑 국면을 닫힌 구간으로 만든다.

**A → A′ 전환은 문이 닫히지 않는다** — 토큰을 쥐는 위치를 배치에서 Job 으로 옮기는 변경이다. B 도 마찬가지로 "게이트를 지우는 변경" 이 된다. B 를 지금 사지 않는 이유는 프리뷰 스냅샷 캐시·무효화 정책과 메시 QC 모달 재구조화가 인프라 도입과 UX 재설계를 한 티켓에 섞기 때문이다. C 만 확정 기각.

**두 풀 유지 (풀 위상)** — `rwSerialPool()` 은 선언만 두고, 위상의 안전성을 **규약**으로 세운다: 두 풀 동시 사용은 서브시스템 집합이 서로소일 때만. 단일 풀로 합치면 등급 2 정합성은 최고지만 #215 의 RST 파싱이 잔여 모핑 샘플 뒤에 줄 서서 결과 표시가 배치 종료까지 밀린다. 규약을 명문화하면 그 비용 없이 같은 안전성을 얻고, 위반은 #215 리뷰에서 걸린다.

**UI 해방 2축 (취소·상한)** — P1(진행 1건 완료 수용)과 P4(UI 즉시 해방)는 "UI 해방" 을 통지와 재실행 허가로 가르면 둘 다 성립한다. 통지·스피너·케이스 Cancelled 기록은 즉시(P4), Start 재활성만 워커 종료까지 미룬다(등급 2). 완전 즉시 해방은 진행 워커와 다음 배치가 겹쳐 등급 2 를 뚫고, P1 유지는 Stop 후 최대 10분 UI 가 굳는다.

**선점 워치독 (상한)** — 사후 판정은 "이미 10분 태운 뒤" 알려 상한의 목적을 달성하지 못한다. A 배치가 같은 상한을 QTimer 로 선점 판정하므로 형태를 맞춘다.

#### 핵심 시그니처

```cpp
// controller/async/ThreadPools.h — 서브시스템별 직렬 풀 접근자
QThreadPool* morphingSerialPool();      // maxThreadCount = 1
QThreadPool* rwSerialPool();            // maxThreadCount = 1 — 첫 소비자는 #215
// 앱 종료 상한 — main.cpp aboutToQuit. 초과하면 기다리지 않고 종료를 진행하고 로그를
// 남긴다 (Morph() 는 kill 불가라 무한 대기가 응답 없는 종료를 만든다).
bool         waitForAllSerialPools(int timeoutMs);   // false = 타임아웃

// controller/async/MorphingGate.h — 모핑 단일화 가드의 판정자.
// DashManager 는 DashJobRunner 를 참조하지 않으므로(세트별 launcher 소유) 진입점이
// 도달할 수 있는 자리는 프로세스 전역 게이트뿐이다. 상태 정본은 여기 한 벌만 둔다.
// 풀 활동(activeThreadCount)은 기준이 아니다 — 샘플 사이 빈 구간이 "없음" 으로 읽힌다.
class MorphingGate {
public:
    // 조회 전용 — 획득하지 않는 진입점 1·1b·2·4·5 가 쓴다.
    static bool busy();

    class Token;
    // 획득 진입점(3)용. 실패를 값으로 낸다 — 검사와 획득이 한 호출이라 그 사이가
    // 벌어지지 않고, "이미 busy 일 때 두 번째 Token 을 만들면?" 이 정의될 필요가 없다.
    static std::optional<Token> tryAcquire();

    // 수명 = 모핑 국면. PrepareDoeMorphingBatch 성공에서 획득,
    // releaseMorphBatch() 와 워커의 물리적 종료(workerExited) 중 나중 것에서 해제
    // (배치 종결까지 쥐면 모핑 0건인 솔버 구간까지 막는다). 해제 판정은 한 곳,
    // 해제 지점은 두 곳 — 양쪽에서 나머지 조건을 재검사한다.
    class Token {
    public:
        ~Token();
        Token(Token&&) noexcept;  Token& operator=(Token&&) noexcept;
    private:
        Token();   // tryAcquire 만 만든다
        friend class MorphingGate;
    };
};

// controller/async/WorkerJob.h (minimal-example 3-4절)
class WorkerJob : public Job {
    Q_OBJECT
public:
    // task: 워커 스레드에서 실행 — 입력 스냅샷만 캡처, 위젯/GUI 접근 금지.
    // 채널은 shared_ptr<atomic<bool>> 로 task 인자에 넘긴다 (맨 멤버 플래그 금지 — #205 3-4절).
    // 모핑 task 는 RunOneSample 1회라 폴링 지점이 없다 — 채널은 착수 전 차단 전용이다.
    WorkerJob(std::function<WorkerResult(const std::atomic<bool>& cancelled)> task,
              QThreadPool* pool, QObject* parent = nullptr);
    ~WorkerJob() override;

    void start() override;    // QFutureWatcher::finished → Job 시그널 번역 (마샬링 자동)
    void cancel() override;   // 협조적 — 채널 set + 즉시 Cancelled (ProcessJob 규약 계승)

    WorkerResult result() const;   // finished 슬롯에서 pull (ProcessJob 규약)

signals:
    // ★ Job::finished 와 다른 축이다. finished 는 cancel() 에서 즉시 나지만 풀 스레드는
    // 계속 Morph() 를 쥐고 있다 — QProcess 와 달리 떼어내 회수시킬 수 없다. 이 시그널이
    // "워커가 실제로 빠져나왔다" 의 유일한 근거이고, 게이트 해제·m_morphJob 정리·
    // batchActive() 생존 항이 전부 여기 걸린다. 터미널 잠금 밖이라 취소 후에도 반드시 온다.
    void workerExited();
};

// model/DashJobRunner.h — 슬롯 1개가 동기 호출을 Job 으로 바꾼다.
// 준비(스냅샷·ioPaths·context·핸들·커널 반경)는 GUI 스레드 1회 — #260 산출을 그대로 쓴다.
void runNextMorphSample();                       // 기존 — RunOneSample 직접 호출을 Job 착수로 교체
void onMorphSampleFinished(const DashSampleResult& result);   // 기존 — Job::finished 슬롯이 된다
bool batchActive() const;                        // + m_morphWorkerAlive (워커 생존 항)

WorkerJob*  m_morphJob = nullptr;                // 진행 중 1건. workerExited 슬롯에서만 비운다
bool        m_morphWorkerAlive = false;          // start() 에서 참, workerExited 에서 거짓
QTimer*     m_morphWatchdog = nullptr;           // per-case 선점 상한 (kMorphSampleBudgetMs)
std::optional<MorphingGate::Token> m_morphGate;  // 모핑 국면 = 게이트 수명
```

## Acceptance Criteria
> #260·#264 가 이미 충족시키는 항목(꼬리 정상 실행 · 폴링·`msleep` 제거 · 케이스 통지 정확히 1회 · 단일 종료 지점 · 비모핑 폴백 무회귀)은 본 티켓 AC 에서 제외 — 본 티켓은 **회귀 없음**만 확인한다.

- **샘플 내부까지 UI 반응 정상** — 상태바 스피너가 실제로 동작. 남는 정지원은 준비 단계의 스냅샷 DeepCopy·`.dat` 파싱이므로 **배치 시작 직후 짧은 정지는 통과 대상** — 측정해서 잔여 정지 시간을 기록한다. #260 대비 개선분은 "샘플 경계" → "샘플 내부" 다
- **취소 2축** — Stop 직후 ⑴ 스피너·로그·잔여 케이스 Cancelled 가 `Job::finished` 시점에 즉시 반영되고 ⑵ Start 는 **`workerExited`** 시점에 풀린다. **두 시점이 실제로 갈리는 것을 확인한다** — 취소 후 `finished` 와 `workerExited` 사이에 프리뷰·Start 가 열리지 않아야 한다. 늦은 결과가 Cancelled 로 닫힌 케이스를 되살리지 않는다(장부 + `Job::setState` 이중 터미널 잠금). #260 정책 P1·P2 무회귀
- **선점 상한** — `kMorphSampleBudgetMs` 초과가 샘플 **진행 중** 판정되고 취소와 같은 경로로 처리된다. A 배치의 STP 상한 동작 무회귀
- **강제 종결의 완결성** — 상한 초과 · P3 차단기 · `abortBatch` 로 배치를 닫을 때 motion-launcher `QProcess` 와 FE-safe 태스크까지 정리된다. 배치가 닫힌 뒤 도착한 그 프로세스의 exit 0 이 **다음 배치의 케이스를 조용히 Done 으로 닫지 않는다** (터미널 잠금으로는 안 덮이는 경로 — 새 장부의 `Pending` 키다)
- **모핑 6곳이 한 번에 하나** — 모핑 국면 중 프리뷰(1·1b)·메시 QC(2)·모델러너/최적화(5)·재실행(3) 트리거가 전부 거부되고 위젯 상태가 그에 일치. 배치 2건 연속 실행 시 순차 처리
- **세트를 넘어서도 하나** — Set1 의 모핑 배치가 도는 중 **Set2 의 Start 가 거부된다**. 러너 로컬 `batchActive()` 로는 안 막히는 경로이므로 전역 게이트가 실제로 판정하는지를 이 항목으로 확인한다
- **진입점 5 는 루프 시작에서 거부된다** — 모핑 국면 중 최적화·모델러너를 시작하면 **iteration 0건**으로 즉시 거부되고 사용자에게 사유가 보인다. 전 iteration 을 실패시키며 완주하지 않는다
- **게이트 해제 누락 0** — `releaseMorphBatch()` 를 지나는 **모든** 이탈 경로(정상 소진 · 사용자 취소 · P3 연쇄 실패 · 상한 초과 · 착수 거부 · `abortBatch`)에서, **`workerExited` 까지 도달한 뒤** 게이트가 풀리고 프리뷰가 되살아난다. 모핑 국면이 끝나면 솔버 구간에서는 프리뷰가 열려 있다 — 게이트를 배치 종결까지 쥐지 않았음을 이 항목으로 확인한다
- **워커 본문의 위젯/GUI 접근 0건** · `DashManager::Mgr()`/`DashProjectManager::Instance()` 접근 0건 — 판정은 `docs/ThreadingContract.md` 5절 체크리스트 7항 + 2절 금지 타입 화이트리스트
- **풀 위상 규약 성립** — 모핑 샘플 Job 이 활성인 동안 RW 풀 제출 0건. `docs/ThreadingContract.md` 7절이 근거로 존재하고 `rwSerialPool()` 소비자가 0건임을 확인
- **결과 정합 회귀**: 배치 중 메인에서 프리뷰 모핑을 의도적으로 시도했을 때 ⑴ 거부되고 ⑵ 배치 산출 `.vtu` 가 배치 파라미터와 일치 — 크래시가 아니라 **조용한 오형상**이 주 실패 모드이므로 "안 죽었다"를 통과 기준으로 쓰지 않는다
- **종료 안전**: 워커 실행 중 앱 종료 시 크래시·고아 스레드 0 — `aboutToQuit` 의 풀 배수가 정적 소멸(`~DashManager()` 의 `shutdownBlocking()`)보다 먼저 완료. **종료가 유한 시간에 끝난다** — 샘플이 도는 중 종료해도 `waitForAllSerialPools(timeoutMs)` 가 초과 시 대기를 포기하고 로그를 남긴다 ("크래시 안 남" 만으로는 무한 대기가 통과하므로 시간 상한을 함께 본다)
- **단위 테스트**: `tst_worker_job` 통과 (터미널 잠금 · 직렬 실행 · 취소 · 예외 번역 · **`cancel()` 후 `finished` 와 `workerExited` 의 시점 분리**). 기존 `tst_job_state`·`tst_batch_ledger`·`tst_process_runtime` 무회귀

### Notes / Issues

**1. Stop 의 P1 관측 동작이 바뀌었다.** #260 에서는 동기 실행이라 Stop 이 샘플 반환 뒤 처리돼 진행 1건의 결과가 보존됐다. 이제 Stop 은 진행 케이스를 즉시 `Cancelled` 로 닫고 늦은 결과를 폐기한다 — DLL 은 계속 돈다(약속은 "UI 즉시 해방"이지 "CPU 즉시 해방"이 아니다). Phase 5 "즉시: 잔여 케이스 Cancelled 기록" 과 AC "늦은 결과가 Cancelled 로 닫힌 케이스를 되살리지 않는다" 를 따른 선택이다.

**2. 설계 골격에서의 의도적 이탈 2건.**
- `MorphingGate::Token` 기본 생성은 **비어 있다**. Design 스케치의 `Token()` 이 획득이면 `DashJobRunner` 멤버로 두는 순간 러너 생성 시점에 게이트가 잠긴다. 획득은 `acquire()` 하나로 모았다.
- 국면 참가자를 **2토큰 카운트**로 센다 (배치 축 / 워커 축). Design 의 "`releaseMorphBatch()` + 진행 워커 종료에서 해제" 를 그대로 구현한 형태다. 워커 축을 `Job::finished` 에 걸면 안 된다 — `cancel()` 은 즉시 터미널로 가지만 DLL 은 계속 돌아 그 시점에 게이트를 놓으면 UI 해방 2축이 무너진다.

**3. 흡수 후보 1건은 이미 해소돼 있었다.** 2026-08-17 코멘트의 `cancelAllRuns` 이중 종결(`analysisFailed` 2회)은 `DashAnalysisLauncher::cancelAllRuns` 가 직접 방출을 이미 제거해(#264 산출) 재작업이 불요했다.

**4. 워커화가 기존 방어선 하나를 처음으로 발화시킨다.** 공유 컨텍스트 변이 창의 GUI 심층 편집 거부(`DashConditionParameterization.cpp:347`)는 종전에 배치가 GUI 스레드를 점유해 **도달 불가**했다. 이제 실제로 동작하며, 판정 근거인 레지스트리 `m_mutating` 맵은 `std::mutex` 로 보호돼 워커에서 읽어도 race 가 없다.

**5. 자동화 범위의 한계.** 진입점 6곳의 **실제** 거부는 단위 테스트로 못 옮긴다 — `DashManager`·`DashMorphingUtils` 가 VTK·OCCT·모핑 DLL 을 끌어와 Qt Core 전용 테스트 타깃에 들어가지 못하고, 앱은 라이브러리가 아니라 단일 exe(`GLOB_RECURSE`)라 링크할 대상 자체가 없다. 게이트 술어는 `tst_morphing_gate` 가 봉인하므로 남는 미검증분은 "각 진입점이 그 술어를 호출하는지" 6줄로 좁혀진다.

### Follow-up

1. **`.vtu` 파라미터 정합 실기 확인 (본 티켓 AC 잔여 1건).** 배치 중 프리뷰를 의도적으로 시도했을 때 산출 `.vtu` 가 배치 파라미터와 일치하는지. 주 실패 모드가 크래시가 아니라 **조용한 오형상**이라 "안 죽었다" 를 통과 기준으로 쓸 수 없다. 골든 파일 회귀 하네스가 있으면 자동화 가능.
