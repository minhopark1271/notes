# #376 프로젝트 열기 시 미열림 상태가 ERROR로 오탐지되는 문제 수정

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/376
- Board status: Backlog
- Labels: ['in-progress', 'bugfix', 'refactor']

## Original Request
> 지금 빌드에서 프로젝트 열기를 누르면 다음과 같이 에럭가 발생함
> (스크린샷: Log 패널에 `ERROR Project DashProjectManager::GetProjectPath: Project is not open. m_projectFolderPath: m_projectName:` 표시됨)

## Goal
"프로젝트 열기"를 눌렀을 때, 아직 프로젝트를 연 적이 없는 정상 상태에서도 `ERROR` 레벨 로그가 찍히는 문제를 없애서, Log 패널에 실제 오류가 아닌 노이즈가 보이지 않도록 한다.

## Background
`DashMainWindow::onFileOpen()` 은 새 프로젝트를 열기 전에 `DashProjectManager::IsProjectOpen()` 으로 현재 상태를 확인한다. 그런데 `IsProjectOpen()` 이 내부적으로 `GetProjectPath()` 를 그대로 재사용하는데, `GetProjectPath()` 는 "프로젝트가 열려있지 않으면" 항상 `DASH_LOG_ERROR` 를 남기도록 작성되어 있다. 그 결과, 앱을 켠 직후 프로젝트를 한 번도 열지 않은 상태에서 "프로젝트 열기"를 누르기만 해도(폴더 선택 여부와 무관하게) 정상적인 "아직 프로젝트 없음" 상태가 에러로 로깅된다. 실제 파일 열기 자체가 실패한 것이 아니라, 상태 조회용 헬퍼가 에러 로그 채널로 새는 로깅 버그다.

## Technical Details
- 원인 위치: `controller/DashProjectManager.cpp`
  - `GetProjectPath()` (L244-253): `m_projectFolderPath`/`m_projectName` 이 비어있으면 항상 `DASH_LOG_ERROR` 후 빈 문자열 반환
  - `IsProjectOpen()` (L223-234, 수정 전): 상태 확인을 위해 `GetProjectPath()` 를 호출 → 위 ERROR 로그가 부수효과로 발생
- 호출 지점: `view/DashMainWindow.cpp:3038` `onFileOpen()` 시작부에서 `IsProjectOpen()` 호출
- 수정 방향: `IsProjectOpen()` 이 `GetProjectPath()` 를 거치지 않고 `m_projectFolderPath`/`m_projectName` 을 직접 확인하도록 변경. `GetProjectPath()` 자체의 ERROR 로깅은 유지 (실제로 프로젝트가 열려 있어야 하는데 안 열린 경우, 예: `GetConfigsDirectory()` 등에서의 호출은 여전히 진짜 오류이므로).

## Implementation Plan
- [x] **Phase 1: IsProjectOpen 상태 확인 로직 분리**
  - Files: `controller/DashProjectManager.cpp`
  - Changes: `IsProjectOpen()` 이 `GetProjectPath()` 대신 `m_projectFolderPath`/`m_projectName` 을 직접 확인 후, `.dproj` 폴더 존재 여부만 `QDir::exists()` 로 확인하도록 변경. 기존 "Inconsistent state" 경고 로그는 더 이상 필요하지 않아 제거.
  - Notes: `GetProjectPath()` 의 ERROR 로깅 자체는 변경하지 않음 (정상적으로 열려 있어야 할 때 호출되는 경우엔 여전히 유효한 에러 신호).
