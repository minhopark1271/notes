## Goal
모핑 DOE 배치가 **샘플 1건 단위로 착수·완료**되고, 케이스 성공 판정의 근거가 **파일 존재 추정에서 `bool` 반환**으로 바뀌며, 배치 상태 변경이 **배열형 장부의 단일 전이 함수·단일 종료 지점**을 통과한다. 결과로 C(DOE 모핑 dat 경로) 배치가 완성되고 F(dfsxml 모핑+MBD)의 stage 0 이 이벤트 구동이 된다.

**스레드는 도입하지 않는다** — 이득은 GUI 무블로킹이 아니라 ⑴ 샘플 경계 취소 지점 신설 ⑵ 폴링·고정 슬립 낭비(`1000ms + N × 500ms`) 소멸 ⑶ 잔존 산출물이 성공으로 위장되는 결함 해소다. 샘플 내부 블로킹은 #214 몫.

- **#215 가 이 루프를 #214 후행으로 묶은 근거가 실측과 어긋난다.** #215 는 "VTU 대기는 모핑 per-sample 완료 시그널 구독이 정답 — 생산자 완료 시그널만이 flush 레이스를 없앤다. 따라서 #214 가 전제" 로 적었다. 실제로 생산자는 **동기로 완주하며 `bool` 로 성패를 판정까지 한다** — 문제는 레이스가 아니라 그 값을 호출부에 전달하지 않는 것이다(205-4 1절·2절). per-sample 경계는 워커와 무관하게 만들 수 있으므로 #214 는 하드 선행이 아니다.
- **#214 보다 먼저 해야 한다.** 지금 형태의 `Execute`(N 샘플 1회 호출)를 통째로 한 `WorkerJob` 에 감싸면 케이스 입자가 배치 1건으로 굳어, #251 이 A(DOE `.wbpj`) 2단계에서 지적한 결함(진행 이벤트 없음 · per-case 성패 사후 판정 · 개별 취소 불가 · 케이스별 상한 없음)을 모핑 쪽에 복제한다(205-4 3-1절). 반대로 분해를 먼저 하면 #214 는 "`ExecuteOneSample` 1건을 Job 에 넣고 완료 원천만 `bool` → `Job::finished` 로 교체" 로 축소된다.
- **파일럿 범위가 외부 설치 무의존 구간과 정확히 일치한다.** A 경로는 양 단계가 NX·Ansys 에 묶이고, #249 는 NX 수동 회귀 4케이스가 하드 게이트다. 모핑 stage 0 은 in-process 이고, F 의 stage 2(motion-launcher)는 `ansysPath` 가 비면 큐에 넣지 않고 `Done` 으로 확정하는 skip 분기(`DashJobRunner.cpp:1650-1661`, skip `:1658-1660`)가 이미 있어 **Ansys 미설정 구성이 F 의 유효한 실행 경로**다. 그래서 경로 무관 규약을 여기서 먼저 세워 실물 검증하고, #251·#249 는 검증된 형태를 A 로 옮기는 작업으로 좁아진다(205-4 3-4절·6-1절).
- **#251·#249 의 규약을 흡수한다** — 이벤트 완전성 + 단일 종료 지점 · 발신/수신 3단 슬롯 · 단일 전이 함수 · `abortBatch` · 정보 폐기 금지 · 통지 대칭. 기제(A 고유 요청 태그 왕복 · `m_batchMode`)는 두 티켓에 남는다(205-4 4-3절·5-1절).

**집계는 키별 첫 터미널 상태로 케이스를 닫는다** (`:1053-1062`) — `"Done"`/`"Failed"`/`"Cancelled"` 중 아무거나 한 번 오면 그 키는 완료로 확정되고, 전 키가 차면 `m_isLauncherRunTracking` 이 꺼져 **이후 통지는 전부 무시**된다. 오늘 이 함정이 드러나지 않는 이유는 모핑 콜백이 실패 전용이고, Ansys 미설정 skip(`:1660`)조차 `setSampleStatus` 만 쓰고 시그널을 내지 않기 때문이다.

꼬리의 실패 분기는 `configManager.setSampleStatus(..., "Failed", ...)` 로 DOE JSON 만 쓰고 시그널을 내지 않아(dfsxml `:1593`·`:1609`·`:1633`·`:1643` · dat `:1945`·`:1958`·`:2005`) 테이블도 집계도 움직이지 않는다. 따라서 **모핑이 착수조차 못 하면 네 채널 중 어느 것도 울리지 않아** 사용자가 Stop 을 눌러야 UI 가 풀린다. 이때 dfsxml 은 `:1607` 폴링으로 활성 샘플 수 × 최대 60초를 태우고 전부 Failed 로 끝내면서 종료 로그는 `"=== Completed processing ..."` 로 성공처럼 읽힌다.

**per-sample 호출 선례** — `DashManager::MorphFromDoeDirectory`(`:882`, 호출부 0곳)가 파일별로 executor 를 세우고 `ExecuteOneSample` 의 `bool` 을 직접 읽어 판정한다(`:936-940`). 다만 항목마다 executor 를 새로 만들어 `Execute` 의 준비 구간을 통과하지 않으므로 **"per-sample 호출 + `bool` 판정" 의 선례이지 "준비/실행 분리" 의 선례는 아니다.**

### to-be

- **`Execute` 를 준비/실행 2표면으로 가른다** — `:49-317` 은 배치 1회 `PrepareBatch`, `:318-403` 의 루프 본문은 `RunOneSample` 1건. 준비 산물은 값 타입 `DashMorphingRunContext` 로 나오고 `RunOneSample` 이 인자로 받는다(순서 의존을 타입으로 강제).
- **`MorphFromDoeSamples` 파사드도 2표면화** — 준비(스냅샷·`ioPaths`·context·executor)는 GUI 스레드 1회, 실행은 샘플 1건. 조기 이탈 7곳 전부 준비 단계의 **착수 거부**로 수렴한다.
- **성공 판정을 `bool` 로 승격** — `RunOneSample` 이 `DashSampleResult{runKey, ok, reason}` 를 돌려준다. `ExecuteOneSample`·`ExecuteOneSampleConditionOnly` 두 함수의 반환값이 근거이고, `SampleStatusCallback` 은 실패 **사유** 전달용으로만 남는다(반환값이 성패, 콜백이 사유 — 205-4 4-2절).
- **상태 장부 — 배열형 `QVector<StageRecord>` + 단일 전이 함수 + 단일 종료 지점.** C 는 stages 1칸, F 는 3칸(모핑 / motion-writer / motion-launcher)을 선언하되 파일럿 시점에 stage 1·2 는 슬롯 내부 동기 실행이라 전이가 즉시 확정된다 — #215 Phase 6 이 두 칸을 이벤트 구동으로 채운다(additive).
- **전이가 반드시 `caseStatusUpdated` 를 방출하되, 터미널 문자열은 케이스의 마지막 스테이지만 낸다.** 단일 전이 함수만으로는 부족하다 — 방출 없는 전이는 UI 를 잠근 채로 두고, 반대로 중간 스테이지가 터미널 문자열을 내면 집계기가 케이스를 조기에 닫는다(as-is "집계는 키별 첫 터미널 상태로 케이스를 닫는다"). 매핑은 아래 Design "스테이지 → 통지 문자열 매핑" 에서 고정한다.
- **배치 종료가 `jobFinished`/`jobFailed` 중 하나를 방출한다.** 둘 다 `DashJobRunner` 소유이고 `DashAnalysisLauncher` 의 `analysisFinished`/`analysisFailed` 로 이미 중계돼 있다(`:54`·`:55`) — 신규 시그널도, 계층을 넘는 방출도 필요 없다. `generateInputCases` 에 소비자가 없던 두 채널의 첫 사용이 된다.
- **디스패치 후 이탈 5곳도 종료 지점으로 수렴** — `:1698`·`:1722`·`:1728`·`:1737`·`:1919` 는 활성 키 전량 Failed + `finishBatch(reason)` 으로 바꾼다. `:1998` 의 `break` 는 잔여 키를 Failed 로 확정한 뒤 같은 종료 지점을 통과한다.
- **꼬리 2개를 per-sample 완료 슬롯으로 이동** — dfsxml `:1560-1676` · dat `:1694-2019`. 스레드는 GUI 유지, 실행 시점만 샘플 완료 시점으로 옮긴다. 상위 지역변수 11개는 장부의 배치 컨텍스트가 든다(`h` 는 멤버 `m_flLauncher` 사본이라 제외).
- **`waitForVtuFileComplete` 정의(`:572-638`)·호출(`:1607`) 삭제 · `msleep(1000)`(`:1562-1563`) 삭제.**
- **취소 지점 신설** — 샘플 경계마다 이벤트 루프로 복귀하므로 취소 반응이 샘플 1건 시간 단위가 된다. 정책 P1(진행 1건 완료 수용) · P2(잔여 미착수 Cancelled) · P3(연속 실패 차단기) · P5 를 #210 골격에서 승계하고 케이스별 워치독을 둔다.
- **배치 활성 질의 노출** — #214 모핑 단일화 가드의 `morphingBusy()` 판정 근거. per-sample 분해 후엔 Job 이 없는 구간이 N−1 개 생기므로 판정 소유자가 Job 이 아니라 장부여야 한다(205-4 5-3절 ⑺-1).

## Design

### 현황 분석

- 문제는 성격이 둘로 갈린다. **⑴ 입자** — `Execute` 가 준비와 N회 실행을 한 함수에 담아 per-sample 경계가 없다. **⑵ 값 전달** — 하위(`ExecuteOneSample`)가 판정한 `bool` 을 상위가 버리고 파일 존재로 재추정한다. 둘은 독립이 아니다: per-sample 경계를 만들면 반환값이 자연히 호출부에 도달하므로 ⑵ 가 ⑴ 의 부산물로 닫힌다.
- **절반은 이미 서 있다.** executor 는 #213 D2 로 "1회 실행(Job) 단위 객체" 가 되어 엔진과 입력 스냅샷을 자기 소유로 든다(`.h:33` 주석) — 싱글톤 접근 6곳이 제거되고 경로는 `DashDoeIoPaths`(`.h:23`)로 값 전달된다. 남은 것은 준비 산물이 `Execute` **지역변수**로 갇혀 있다는 것뿐이다.
- 공개 표면 변경이지만 소비자가 좁다 — 파사드 1곳(`MorphFromDoeSamples`), 그 호출자 2곳(`DashJobRunner:1547`·`:1680`), per-sample 선례 1곳(`MorphFromDoeDirectory:936`, 준비 구간 미사용이라 무영향).

### 대안 비교 — 준비/실행 분리의 형태

| 방안 | 핵심 | 장점 | 단점 |
|---|---|---|---|
| A. executor 내부 상태 + 준비 플래그 | `Prepare()` 가 준비 산물을 멤버로 저장, `RunOneSample(sample)` 이 `m_prepared` 를 검사 | 시그니처 최소. 기존 멤버 스타일과 동일 | **잘못 쓸 수 있는 API** — "준비 후 실행" 이 암묵 규약이라 순서 위반이 런타임 assert 로만 드러난다. 배치 컨텍스트가 executor 수명에 묶여 프리뷰 재사용이 막힌다 |
| B. 준비 산물을 값 타입으로 뽑고 실행 인자로 | `PrepareBatch(...) → optional<DashMorphingRunContext>`, `RunOneSample(ctx, sample) → DashSampleResult` | 순서 위반이 **컴파일 불가**. context 가 executor 밖 값이라 프리뷰가 같은 타입을 재사용 가능(#214 B 의 절반이 미리 섬). 착수 거부가 `nullopt` 하나로 수렴 | 필드 12개 안팎의 구조체 신설. 엔진 내부 상태(`loadHandlesFromVtp`)는 여전히 executor 소유라 강제가 완전하지 않음 |
| C. 준비 결과를 호출부(`DashJobRunner`)가 개별 지역변수로 보관 | 구조체 없이 필요한 값만 멤버 승격 | 신규 타입 0 | 상위 지역변수 11개 + 준비 산물 8개가 `DashJobRunner` 멤버로 산포. 수명·리셋 책임이 흩어지고 프리뷰 재사용 불가 |

### 대안 비교 — 배치 상태 인코딩

| 방안 | 핵심 | 장점 | 단점 |
|---|---|---|---|
| A. 배열형 `QVector<StageRecord>` | 케이스당 단계 배열. C 는 1칸, F 는 3칸 | F(3단계)·A(2단계)가 같은 타입에 담긴다. #215 Phase 6 이 칸을 채우는 것이 additive | C 만 보면 1칸 배열이라 과해 보인다 |
| B. flat enum `CaseState` 8종 (#251 안) | 상태를 평면 열거로 | 단일 값이라 읽기 쉬움 | F 는 3 × 5 = 15종으로 부푼다(205-3 3-3절). 파일럿이 flat 을 쓰고 #215 Phase 6 에서 갈아엎는 것은 이중 작업 |

### 선택 — 분리 형태 B · 인코딩 A

**선택 근거**: 분리는 B — 준비/실행 2표면의 유일한 실질 위험이 "준비 없이 실행" 이고, context 를 인자로 받으면 그 위험이 타입으로 사라진다. 같은 타입이 #214 의 프리뷰 처분 B 에서 재사용되므로 배치 전용 구조체를 만드는 것보다 총비용이 낮다(205-4 4-1절). 인코딩은 A — 첫 상태 장부를 세우는 지점이 인코딩을 고를 수밖에 없고, F 가 3단계인 것이 이미 확정이라 flat enum 은 파일럿 다음 티켓에서 폐기된다.

**기각된 대안**: 분리 A — 순서 의존이 런타임에만 드러나고 프리뷰 재사용을 막는다. 분리 C — 멤버 산포로 수명 관리가 흩어진다. 인코딩 B — #215 Phase 6 에서 이중 작업.

**Phase 순서를 205-4 4-5절 권고에서 하나 바꾼다.** 위키 권고는 ⑴준비/실행 ⑵F연쇄 ⑶C꼬리 ⑷장부 순이나, 장부를 마지막에 두면 Phase 2·3 이 기존 `setSampleStatus` 산발 호출로 상태를 쓰고 Phase 4 가 그것을 다시 고치게 된다 — 위키 4-3절이 인코딩에 대해 경계한 이중 작업과 같은 형태다. 따라서 **장부를 Phase 2 로 올린다**(⑴준비/실행 → ⑵장부 → ⑶F → ⑷C). ⑶·⑷ 를 가르는 위키의 근거(회귀 표면이 다름 — ⑶은 폴링 제거, ⑷는 폴백 사망·ANSYS 중복 제출)는 그대로 유지한다.

#### 스테이지 → 통지 문자열 매핑

장부는 스테이지 단위지만 집계기(`DashAnalysisLauncher::onCaseStatusUpdated:1048-1064`)는 **키 단위이고 첫 터미널 문자열로 케이스를 닫는다.** 파일럿 범위에 집계기 수정이 없으므로(Phase 2 Files 참조) 매핑 쪽에서 맞춘다:

| 스테이지 전이 | `caseStatusUpdated` 문자열 |
|---|---|
| 임의 스테이지 `Running` | `"Running"` |
| **마지막이 아닌** 스테이지 `Done` | `"Running"` — 터미널 문자열 금지 |
| **마지막** 스테이지 `Done` | `"Done"` |
| 임의 스테이지 `Failed` | `"Failed"` — 케이스 전체가 즉시 종료되므로 그대로 터미널 |
| `Cancelled` | `"Cancelled"` |

"마지막 스테이지" 는 C = stage 0(모핑), F = stage 2(motion-launcher)이고, F 에서 Ansys 미설정 skip(`:1660`)이면 stage 1 이 마지막이 된다 — 즉 **케이스마다 유효 마지막 스테이지 인덱스를 장부가 들어야 한다**(`DashCaseRecord::terminalStage`). 이 규칙 없이 stage 0 성공을 `"Done"` 으로 내면 전 샘플 모핑이 끝나는 순간 `analysisFinished` 가 떠 Start 가 살아나고, 뒤이은 솔버 완료 통지는 추적이 꺼진 뒤라 전부 버려진다.

## Acceptance Criteria

- **폴링·슬립 소멸** — 레포 전체 `grep waitForVtuFileComplete` → 0 · dfsxml stage 0 경로에 `msleep`·파일 폴링 0. 배치 소요에서 `1000ms + N × 500ms` 가 사라진 것을 측정 기록
- **성공 판정에 파일 존재·크기 검사 0건** — 케이스 성공의 유일한 근거가 per-sample 함수의 `bool`. 검증은 **이전 실행 산출물(`{key}.dat`·`{key}.vtu`)을 run 디렉터리에 남겨둔 상태**에서 모핑을 실패시켜 수행하고, 낡은 산출물이 성공으로 위장되지 않아야 한다
- **케이스 회계** — 케이스별로 성공·실패가 **정확히 1회** 기록(성공 통지 신설분 포함) · 착수 거부 7곳 + 디스패치 후 이탈 5곳에서도 통지 누락 0 · **배치를 떠나는 모든 경로가 `finishBatch` 를 통과**(`return` 이탈 0) · 종료가 `jobFinished`/`jobFailed` 중 하나를 반드시 방출
- **집계 조기 종료 0건** — F 를 stage 2 까지 도는 구성에서, stage 0(모핑) 전 샘플 완료 시점에 `analysisFinished` 가 **뜨지 않는다**. C 도 ANSYS 제출 전에 뜨지 않는다. 솔버 완료 통지가 `m_isLauncherRunTracking` 이 꺼진 뒤 도착해 버려지는 일이 없어야 한다
- **inp 런처 미설정 종결** — **(구현 중 규약 변경)** 착수 거부 대신 "모핑만" 배치로 낮췄다. 구 코드가 모핑을 마친 뒤 return 해 산출물을 남겼으므로, 착수 거부로 수렴시키면 `.inp`/`.dat` 이 아예 생기지 않는 회귀가 된다. `terminalStage` 를 모핑 칸으로 낮춰 F 의 Ansys 미설정 skip 과 대칭이 되게 했다 — 활성 샘플은 Failed 가 아니라 **모핑 완료 후 Done** 으로 종결되고, Start 복구 · 폴백 미도달(`.dat` 생성 0 · ANSYS 제출 0)은 그대로다. **실물 미검증.**
