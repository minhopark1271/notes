## Goal
파일 생성 대기의 폴링 루프(`waitForFile`·`waitForVtuFileComplete`·motion-writer 루프·dfsxml 루프)가 **작업 완료 이벤트 구독("완료 시그널 수신 → 파일 검증" 순서)** 으로 전환되어, 해당 경로의 `processEvents`/`msleep` 이 제거된다. 완료 시그널이 없는 외부 산출물에 한해 `QFileSystemWatcher`/`QTimer` 콜백을 보조 수단으로 쓴다.

## Background
> source: `DashOpti_Docs/dashgui2-async-execution-patterns.md` 7절 서브태스크 b · 2-2절 블로킹 지점 목록

- **W10 분할 b (2/6) — 외부 축.** W10-a(#210) 완료 후 착수, W10-c 와 병렬 가능.
- 실측 앵커 (`model/DashJobRunner.cpp` — [#205](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/205-5-w6-w10-async-minimal-example) 부록 8절 재검증 2026-07-21): `waitForFile` `:2351-2364`(processEvents + msleep(2000) 폴링, 최대 600s) · `waitForVtuFileComplete` `:598-664`(msleep(100) + processEvents, 60s — 크기 0.5s 안정화 휴리스틱의 오판 레이스 내장) · `runMotionWriter` `:666-729`(waitForFinished(500) + processEvents, 300s) · dfsxml 모핑+MBD 루프 `:1561-1676`(`:1576` msleep(1000) 고정 슬립 포함).
- `processEvents` 폴링은 재진입 창(#64 크래시 계급의 원천)을 여는 진통제 — 폴링 제거가 곧 재진입 창 폐쇄.

## Technical Details
- **주 수단 = 완료 이벤트 구독** ([#205](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/205-5-w6-w10-async-minimal-example) 4장 개정 — 원칙 역전): `waitForFile` 폴링 제거의 본질은 워처 도입이 아니라 **"작업 완료 시그널 구독 → 파일 검증"** 순서다 — "파일 존재"는 완료의 근거가 아님 (flush 레이스 오탐 방지, [#194](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/194-1-async-execution-patterns) 4절). 파일럿의 `updatePrtGeometryCompleted` 구독이 그 예 (데몬 축 ②의 완료 시그널).
- **워처/타이머는 보조 수단** — 완료 시그널이 없는 외부 산출물에 한정. `QFileSystemWatcher` 는 디렉토리 감시 + 대상 파일 필터, 타임아웃은 `QTimer` 로 — 폴링 아님. 파일 생성 대기는 Job 내부 구현 디테일로 흡수.
- W10-a 의 파일럿(`runWbpjDoeAsync`)이 이미 `waitForFile` 1곳을 시그널 구독으로 대체 — 본 티켓은 잔여 소비처 전체.
