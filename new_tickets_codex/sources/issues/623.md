# #623 Ansys 배치가 카탈로그의 field 이름 키를 못 읽어 모든 샘플을 건너뛴다

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/623
- Board status: Done
- Labels: ['bug', 'refactor']

## 증상
`.rst` 를 Load 하고 Process 하면 모든 샘플이 빠지고 결과 XML 이 만들어지지 않는다. 처리 로그:

```
Warning: field '' (operator 'U') not found in [Displacement]. Skipping...
Warning: No scalar array found for 'Displacement' (Operator: U). Skipping...
Warning: Skipped sample runs1: 'Displacement' is not available in file.rst
```

## 원인
`DashResultXmlWriter::writeFieldOutputToXml` 이 카탈로그 항목의 field 이름을 `"result"` 키로 읽는다(`model/preprocessor/DashResultXmlWriter.cpp:812`). 그런데 레거시 어댑터 `LegacyJsonPreprocessor::GetAvailableResponses` 는 그 값을 `"field_output_name"` 키로 낸다. 그래서 field 이름이 항상 비고 operator 이름으로만 배열을 찾는다.

grid 의 배열 이름은 `sub_result` 또는 `result`(= `field_output_name`)이고 operator 이름이 아니다(preprocessor SDK `Types.hpp:302`). Abaqus 는 둘이 같아(`S` = `S`) 드러나지 않았고, Ansys Mechanical 은 `Displacement` ≠ `U` 라 전부 빠진다.

## 재현
#433 8단계의 Level 3 테스트 `test_real_result_files::ansysBatchWritesXmlFromTheCatalogFieldName` (`DASH_TEST_RST_FILE` · `DASH_TEST_ANSYS_ROOT`). 실측: written 0 / missing 1.

## 수정
- `field_output_name` 을 먼저 읽고, 없으면 `result`(옛 카탈로그 형식)로 폴백한다
- Level 1 회귀 테스트: 카탈로그 항목의 field 이름과 operator 가 다르고 grid 배열이 field 이름을 가질 때 샘플이 쓰인다
