# #407 모델 교체 시 wholesale disconnect 에 걸리지 않는 시그널 연결이 누적된다 — 패턴 기준 전수조사 (#401 후속)

https://github.com/NumeRealWorks/DashOpti_GUI/issues/407

## 패턴

위젯의 `setModel(...)` 계열 함수는 대개 앞머리에서 이전 모델과의 연결을 한 번에 끊는다.

```cpp
if (m_model) {
    disconnect(m_model, nullptr, this, nullptr);   // 이전 모델 -> this 전부
}
m_model = model;
```

이 wholesale `disconnect` 는 **sender 가 `m_model` 이고 receiver 가 `this` 인 연결만** 끊는다. 같은 함수 안에서 맺는 연결 중 아래 두 형태는 여기에 걸리지 않으므로, `setModel` 이 다시 불릴 때마다 **연결이 누적된다.**

- **(a) sender 가 `this` 소유 자식인 연결** — 버튼, 테이블, 내부 위젯 등. 모델이 아니라 자기 자식이 sender 이므로 대상이 아니다.
- **(b) receiver 가 `this` 가 아닌 연결** — 모델 → 자식 위젯처럼 `this` 를 거치지 않는 연결. 이전 모델의 연결이 그대로 남아 **교차 모델 누수**가 된다.

누적된 연결은 시그널 1회에 슬롯이 N회 돈다. 슬롯이 멱등이면 무증상이지만, 요청을 보내거나 위젯을 만드는 슬롯이면 그대로 증상이 된다.

## 왜 지금 나왔나

#401 은 `Qt::UniqueConnection` **키워드를 기준으로** sweep 했다. 그 플래그가 람다에 무효라는 것이 문제였기 때문이다. 이 이슈는 기준을 **구조**로 바꾼 것이다 — 플래그가 있든 없든, 위 (a)/(b) 에 해당하면 누적된다.

#401 에서 처리된 `DashModelBuilderMCUWidget` 의 moveTo 버튼 2곳이 (a) 의 사례였고, 리뷰에서 "이번 sweep 이 키워드 기준이라 놓친 같은 부류" 로 지목된 건이다.

## 확인된 사례 (패턴이 실재한다는 근거)

`DashModelRunnerWidget::setModel` / `DashModelRunnerMCUWidget::setModel` 의

```cpp
connect(m_sensitivityAnalyzerWidget, &DashResultsAnalyzerWidget::plotRequested,
        this, &DashModelRunnerWidget::onSensitivityPlotRequested);
```

- `m_sensitivityAnalyzerWidget` 은 생성자에서 1회만 만들어진다 (재생성 없음)
- `setModel` 은 트리에서 같은 세트를 다시 클릭할 때마다 호출된다
- 앞뒤 어디에도 이 연결을 끊는 코드가 없다
- 슬롯은 `m_modelRunner->requestPlot()` 에 가드 없이 위임하고, `requestPlot` 에도 중복 방지가 없다 — **비멱등**

결과:
- **캐시 적중**: `plotSpecReady` 가 N회 emit 되어 **플롯이 N개 생긴다**
- **캐시 미적중**: 데몬 큐에 N개가 쌓인다. 첫 응답만 쓰이고 나머지는 버려지지만 morris/sobol/shap 분석이 N-1회 낭비되고, 직렬 큐라 그동안 다른 명령이 막힌다

반응형 재플롯(`debouncedReplot`)도 같은 경로를 타므로 설정을 바꿀 때마다 배수가 붙는다.

## 할 일

**1. 전수조사.** 위 (a)/(b) 기준으로 저장소를 다시 훑는다. 예비 스캔에서 최소 5개 파일에 추가 후보가 더 있었으나, 그 목록은 슬롯 본문까지 확인하지 않은 상태라 **이 이슈에 싣지 않는다.** 그 목록을 고치는 게 아니라 기준으로 다시 찾는 것이 이 작업이다.

조사 대상은 `view/` 에 한정하지 않는다. `setModel` 이라는 이름에도 한정하지 않는다 — "모델 교체 시 wholesale disconnect 로 이전 연결을 정리하는 함수" 면 전부 대상이다.

**2. 항목별 해악 검증.** 찾은 곳마다 슬롯 본문을 읽고 판정한다.
- 멱등인가, 비멱등인가
- 비멱등이면 N배일 때 실제로 무엇이 일어나는가 (요청 N회 / 위젯 N개 / 파일 N회 읽기 등)
- 누적이 실제로 가능한 호출 경로가 있는가 (sender 가 재생성되지 않는가, 해당 함수가 2회 이상 불리는가)

멱등이라 무증상인 곳도 목록에는 남긴다. 판정 근거를 함께 적는다.

**3. 수정.** 항목마다 커밋을 나눈다.
- 슬롯이 **PMF** 면 `Qt::UniqueConnection` 토큰 하나
- 슬롯이 **람다** 면 `disconnect(sender, &Cls::signal, this, nullptr)` 를 앞에 둔다 (`Qt::UniqueConnection` 은 람다에 무효 — #401 참고)
- **(b) 교차 모델 연결**은 이전 모델을 대상으로 표적 disconnect

와일드카드 `disconnect(sender, nullptr, this, nullptr)` 는 쓰지 않는다. 같은 sender 의 다른 연결을 함께 끊을 수 있다.

## 하지 말 것

**연결 관리 헬퍼나 base class 훅을 만들지 말 것.** 각 위치는 토큰 하나 또는 한 줄로 끝난다. 추상화를 세우면 이 이슈의 diff 가 본래 문제보다 커진다.

`DashResultsAnalyzerWidget::connectReactiveSignals` 는 이미 PMF + `Qt::UniqueConnection` 으로 방어돼 있다. 건드리지 않는다.

## 완료 기준

- 기준 (a)/(b) 로 찾은 전체 목록과 항목별 해악 판정
- 비멱등 항목은 전부 수정, 멱등 항목은 판정 근거와 함께 보류 사유 기재
- 각 수정이 다른 연결을 함께 끊지 않는지 리뷰 확인
- `setModel(nullptr)` 경로에서도 문제가 없는지 확인
