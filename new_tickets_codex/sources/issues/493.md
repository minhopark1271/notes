# #493 미리보기에서 어댑터 예외를 아무도 받지 않아 프로세스가 abort 된다

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/493
- Board status: Done
- Labels: ['bugfix', 'refactor', 'source:QC']

## Goal

결과 미리보기에서 preprocessor 어댑터가 던진 예외가 아무도 받지 않아 프로세스를 끝내는 경로를 없앤다. 실패를 사용자에게 보이는 오류로 바꾼다.

## 착수 상태

2026-09-18 기준 **예정**. 조사만 끝났고 코드 변경은 없다.

## 증상 (실측, GUI rev 866abb5)

정적 스텝과 fe-safe 스텝이 함께 든 ODB 를 단일 결과 파일로 불러 Name 목록에서 `S` 또는 `U` 를 고르고 Preview 를 누르면 **프로세스가 종료된다.** 2026-09-16 앱 로그(`%LOCALAPPDATA%\NumeReal\Logs\`)에 FATAL 2건이 남았다.

```
unhandled C++ exception: GetFieldOutputVtk failed — get_response: field output not found: S
unhandled C++ exception: GetFieldOutputVtk failed — get_response: field output not found: U
```

선택된 스텝은 fe-safe 스텝이었고, 그 스텝에는 `S`·`U` 가 존재하지 않는다(해당 스텝의 필드는 수명 결과 하나뿐). 값을 만들어 낼 수 없으므로 **예외 자체는 옳다.**

## 원인

던진 곳은 `model/preprocessor/wrapper/LegacyJsonPreprocessor.cpp:597-600` 이다 — 로그의 `GetFieldOutputVtk failed — ` 접두는 `:598` 의 문구다. 어댑터의 응답 매칭(`:587-589`)은 통과했고, 그 뒤 Preprocessor 파사드가 "그 시점에 해당 field output 이 없다"로 돌려준 오류를 어댑터가 예외로 올렸다.

받는 곳이 없다. `model/DashDataProcessor.cpp:2400` 의 `m_preprocessor->GetFieldOutputVtk(queryString.toStdString())` 호출에 try/catch 가 없다. `requestVtkPreview`(`:2233`) 안의 유일한 try/catch 는 Modal 의 Natural Frequency 분기(`:2279-2310`)라 이 경로를 덮지 않고, 호출자도 직접 호출이다(`view/DashDataProcessorWidget.cpp:942`).

그래서 예외가 `std::terminate` 까지 올라가고, `onTerminate`(`utils/log/DashLogCrashFlush.cpp:31`)이 위 FATAL 한 줄을 남긴 뒤 `std::abort()`(`:49`) 한다.

## To-be

- `requestVtkPreview` 가 어댑터 예외를 받아 사용자에게 보이는 오류로 바꾼다. **원 메시지를 보존**하고, 조용히 삼키거나 빈 결과로 접지 않는다.
- "값이 없음"과 "질의가 성립하지 않음"을 구분해 사용자에게 알린다.

같은 렌더링 경로에 조용한 폴백 2곳이 있어 함께 정리 대상이다.

- `controller/DashRenderingManager.cpp:205-208` — 요청한 스칼라가 point/cell 어디에도 없으면 오류·로그 없이 형상만 그린다. 사용자는 값이 평평한 필드로 읽는다.
- `model/DashDataProcessor.cpp:2420-2448` — 이름이 맞는 배열이 없으면 그리드의 첫 non-ID 배열로 색칠한다. `view/DashMainWindow.cpp:1334-1336`(rev 866abb5) 의 컬러바 제목 덮어쓰기와 겹치면 **요청한 응답 이름을 달고 다른 필드를 그린 그림**이 나온다.
