# #422 DashMorphingBasis::Morph 가 수치 실패를 nullptr 로 접는다 — 실패 사유를 호출자에게 전달

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/422
- Board status: Done
- Labels: ['refactor', 'split-group:215']

## Goal

`DashMorphingBasis::Morph` 가 mesh-ops 의 수치 실패를 `nullptr` 하나로 접어 돌려준다. 호출자는 "실패했다" 만 알고 **왜** 실패했는지, 그것이 **입력 결함**인지 **수치 결함**인지 구분할 수 없다. 실패 사유가 호출자까지 전달되어 사용자 통지와 진단이 가능해야 한다.

## 귀결 (PR #506)

`Morph`·`Freeze` 가 `dash::core::Result<T>`(RW 계층과 같은 타입)를 돌려준다. mesh-ops 실패는 `DASH_REF_OR_WRAP` 으로 단계 컨텍스트를 붙여 감싸고 원인은 cause 체인에 남는다. 바깥 `ErrorCode` 가 곧 분류다.

본문 표의 6경로가 전부 분류되어 나온다.

| # | 조건 | 분류 | 자리 |
|---|---|---|---|
| a | `originalPoints`/`targetHandles` 가 null | `InvalidArgument` | `Morph` 진입 검사 |
| b | target 점 수 ≠ 동결 시 핸들 수 | `LogicError` | `DashMorphingBasis.cpp` · `submitMorph` 이중 검사 |
| c1 | 비유한 변위 성분 | `InvalidArgument` | GUI 선검사 |
| c2 | PARDISO 분해·solve 실패, 비유한 해 | `OperationFailed` | `DASH_REF_OR_WRAP(..., "Morph: solve prescription")` |
| d1 | 비유한 입력 좌표 | `InvalidArgument` | `toVec3` 선검사 |
| d2 | 비유한 출력 좌표 | `OperationFailed` | `DASH_RETURN_WRAP_IF_ERROR(..., "evaluate displacement field")` |

| 분류 | 사용자 조치 |
|---|---|
| `InvalidArgument` | 핸들 위치·반경 값을 고친다 |
| `LogicError` | 재동결. 동결과 실행 사이에 handle 집합이나 메시가 바뀌었다 |
| `OperationFailed` | 겹친 핸들·마커를 떨어뜨리거나 반경을 바꾼다. 재시도는 무의미 |
| `Canceled` | 알리지 않는다 |
| 그 외 | 계약 밖 코드는 다른 분류로 뭉개지 않는다 |

소비 지점 세 곳이 `DashMorphingError::describe`/`advice` 로 같은 문구를 만든다 — 프리뷰 `DashNotify::warning`, Mesh QC `QMessageBox::warning`, DOE 샘플 상태 문자열 `Failed: morphing (<분류>: <메시지>)`.

**계면 형태 결정** — `dash::core::Result<T>` 를 그대로 노출한다. 본문이 우려한 "`DashMorphingBasis.h` 의 MeshOps 헤더 격리와 충돌" 은 성립하지 않는다. CoreLib 은 MeshOps 가 아니고 RW 계층이 이미 같은 타입을 쓴다.
