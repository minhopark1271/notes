# #638 Analysis Launcher 설정 저장이 0바이트 파일을 거절하고 실패 사유를 알리지 않는다

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/638
- Board status: Backlog
- Labels: ['bug', 'refactor']

## 증상
PR #595 리뷰(병합 뒤 코멘트)의 보완 권고 3건이 dev 에 남아 있다.

1. **0바이트 설정 파일** — `readRoot` 가 빈 파일을 파싱 실패로 보고 저장을 거절한다 (`model/preprocessor/DashAnalysisLauncherConfig.cpp:14-16`, `:28-37`). 해석 타입을 고르거나 DOE 를 Load 할 때마다 "Failed to save …: <경로>" 모달이 뜨고 DOE Table 스냅샷이 저장되지 않는다 (`model/DashAnalysisLauncher.cpp:548-551`, `:1007-1010`). 스냅샷이 없으면 일반 배치는 데이터셋에서 run 을 합성해, 결과 XML 에 설계변수 값이 빠진다(코드 경로 기준)
2. **저장 실패 사유 미표시** — 읽기·파싱·쓰기 실패 사유는 로그에만 남고 모달에는 경로만 나온다 (`DashAnalysisLauncherConfig.cpp:18-58`)
3. **`solverType_` 주석** — "Load 메타데이터와 같은 수명"이라고 적혀 있다 (`model/preprocessor/DashReaderSession.h:42-43`). 실제 값은 `initialize()` 에서만 바뀌고, `clearLoadedContext()` 는 건드리지 않으며, `.rst` 판별용 초기화도 값을 덮어쓴다

## 원인
#595 리뷰 보완 커밋(`75d2fa0`)이 "기존 파일을 읽거나 파싱하지 못하면 저장 거절"을 넣을 때 빈 파일을 따로 보지 않았고, 사유는 로그에만 남겼다. 그 전에는 0바이트 파일이 빈 객체로 조용히 복구됐다.

## 수정 방향
1. 내용이 비었거나 공백뿐이면 없는 파일처럼 빈 객체에서 시작한다. 깨진 파일(잘림·배열·스칼라)은 지금처럼 보존하고 거절한다. 테스트 `invalidExistingConfigIsPreserved` 의 `empty` 행은 새 파일 케이스로 옮긴다
2. 쓰기 함수가 사유를 `QString` 으로 돌려주고(`model/preprocessor` 관례), 호출부가 경로 뒤에 붙여 `errorOccurred` 로 낸다
3. 주석을 실제 수명(리더 생성을 시도한 마지막 `initialize()` 의 솔버)에 맞춘다

같이 정리(비차단)
- 삭제된 멤버를 가리키는 주석 (`model/DashAnalysisLauncher.cpp:2075`)
- 쓰지 않는 include — `DashAnalysisLauncher.h` 의 `<filesystem>`, `DashAnalysisLauncher.cpp` 의 `<algorithm>`·`<cmath>`
- 참조가 없는 `ExtractedKeys::frequencies` (`model/preprocessor/DashResultTypes.h:15`)

## 확인 방법
- `test_analysis_launcher_config` — 0바이트·공백 파일에서 두 쓰기가 성공하고, 깨진 파일은 거절되며 반환 문구에 사유가 담긴다
- 앱 — `configs/AnalysisLauncher_{Set}.json` 을 0바이트로 만든 뒤 해석 타입을 고르면 모달 없이 저장된다. 깨진 JSON 이면 모달에 사유가 함께 나온다
