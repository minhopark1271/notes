# #548 MCU Model Builder 의 Stop 이 학습 중지·데몬 재기동에 도달하지 않는다 — DashModelBuilder::stopTraining() 비가상 hiding

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/548
- Board status: Done
- Labels: ['bugfix', 'refactor']

## Goal
MCU 탭의 Stop 버튼이 `DashModelBuilderMCU::stopTraining()`(→ `restartDaemon()`) 을 실제로 실행하게 한다.

## Background
> #437 적대적 코드 리뷰(PR #531) 중 발견. 기록: `D:/dev/docs/03-external-process-sequences.md` §8.8

MCU 학습 취소는 명령 취소 채널이 없어 **데몬 재기동**으로 구현돼 있다(`stopTraining()` → `restartDaemon()`). 그런데 그 경로가 UI 에서 도달하지 않는다.

## Technical Details

### as-is
- `model/DashModelBuilder.h:82` `void stopTraining();` — **비가상**. 같은 헤더의 `getModelsForDimension`·`refreshTrainedModelInfo` 등은 `virtual` 인데 이 함수만 아니다.
- `model/DashModelBuilderMCU.h:84` `void stopTraining();` — 오버라이드가 아니라 **hiding**.
- Stop 버튼 핸들러 `view/DashModelBuilderWidgetBase.cpp:75` 는 `modelBuilder()->stopTraining()` 을 `DashModelBuilder*`(`DashModelBuilderWidgetBase.h:52`) 로 호출한다.
- 결과: MCU 탭에서 Stop 을 눌러도 **base 판** `DashModelBuilder::stopTraining()` 이 실행된다. MCU 는 `ProcessJob` 이 아니라 데몬 명령으로 학습하므로 base 판은 멈출 대상이 없고, MCU 의 `restartDaemon()` 은 돌지 않는다 → 학습이 계속되고 데몬도 그대로다.
- 핸들러는 그 직후 `startButton->setEnabled(true)` 로 Start 를 다시 켠다(`DashModelBuilderWidgetBase.cpp:77`).

### to-be
- `DashModelBuilder::stopTraining()` 을 `virtual` 로, `DashModelBuilderMCU::stopTraining()` 에 `override`.
- (또는) base 위젯의 Stop 핸들러가 가상 훅을 통해 파생 모델의 중지 경로를 부르도록 정리 — 어느 쪽이든 base 포인터 호출로 파생 판이 숨겨지지 않아야 한다.
- 완료 기준: MCU 탭 학습 중 Stop → 데몬 재기동(`daemonReadyChanged` false→true 전이 관측) → 진행 중 모델 상태가 `Interrupted` 로 갱신.

### not-to-be
- 학습 중 사고사 뒤 버튼 라벨·복구 경로 — #436(데몬 수명 규칙) 소관.
