## 현상
> doe 및 launcher 쪽 분해를 하려고 함. DashJobRunner.cpp의 generateInputCases는 이름과 다르게 입력 파일을 만들고 계산을 돌리는 것 까지 수행하고 있음. 이 파일의 함수들을 .inp, .dat, .wbpj, .dfsxml, .stli 케이스를 나누어 함수단위로 모두 분해하는 계획 수립

`model/DashJobRunner.cpp` 2804줄. `generateInputCases`(1225-2023, 800줄)가 확장자 5종을 한 본문에서 분기하며 입력 생성과 솔버 제출을 함께 한다. `runDirectJobs`(2025-2181)도 같은 5종을 한 본문에서 분기한다. (줄 번호는 `ca68a57`, 서식 커밋 전)

## 범위
- 건드림: `model/DashJobRunner.{h,cpp}` 전체, `model/DashAnalysisLauncher.{h,cpp}` (개명 1건)
- 안 건드림: 배선 (분기 순서 · 상태 보고 · 런처 초기화 · 로그 문구) · 공용부 추출 (후속 일괄) · `processEvents`/`msleep` 폴링 (#456) · `templateFilePaths.first()` 단일 사용 (Manifest-3) · Direct `.wbpj` 시그널 체인 · `DashAnalysisLauncher` 의 중복 2건과 `writeCaseDat` 래퍼

## 현재 구조
- `generateInputCases` — 공통 전처리 → isStli → isWbpj → 모핑(dfsxml/inp/dat) → 치환 폴백 순 분기. 각 분기가 샘플 루프 안에서 생성과 제출을 교차
- 치환 폴백은 확장자 무관하게 `{key}.dat` 를 써서 MAPDL 에 제출. 모핑 없는 `.dfsxml` 은 모핑 뒤 `{key}.dat` 를 찾음 (모핑 실행기는 dfsxml 에 `.dat` 를 쓰지 않음)
- 호출자는 `DashAnalysisLauncher` 하나. 외부 사용은 `generateInputCases` · `runDirectJobs` · `cancelAllRuns` · `applyLauncherCPUCoreCount` · setter 4개 · 시그널
- 테스트 없음. `tests/` 는 Qt Core 전용이라 이 클래스는 올릴 수 없음

## 문제
한 함수가 다섯 워크플로를 분기하므로 한 케이스를 고치면 나머지를 스친다. 생성과 제출이 교차해 "입력만 만든다" 경계가 없고, 케이스 전용 계산이 공통에 있어 무엇이 어느 케이스 것인지 읽히지 않는다. 폴백 분기 2곳은 엉뚱한 케이스로 지정돼 결과물이 나올 수 없다.

## 변경
**방안 B(함수 분해 + 케이스별 TU) 채택** — 클래스·시그널·런처 상태를 그대로 두고 파일만 나뉜다. 선례 `model/DashDataProcessorKPI.cpp`.
(A 단일 파일 재배치: 2800줄이 한 파일에 그대로 남음 · C 케이스별 전략 클래스: 런처·task 맵·시그널 공유 설계가 추가로 필요, 원안 ⑴) → [설계 상세](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/269-1-jobrunner-case-decomposition-design)

- **기계적 분해** — Extract Method 와 파일 이동뿐. 분기 순서 · 상태 보고 · 런처 초기화 · 로그 원문 유지. 헬퍼 도입 없음
- `generateInputCases` → `runDoeJobs` 디스패처. 원문 블록을 `makeDoeRunContext` / `emitEnqueued` / `runStliDoe` / `runWbpjDoe` / `prepareMorphingBatch` / `runDfsxmlMorphingDoe` / `morphFromTemplate` / `submitMorphedInpJobs` / `submitMorphedDatJobs` / `runTemplateFallback` 로 추출
- 공통 전처리 결과는 `DoeRunContext`, 모핑 준비 결과는 `MorphingPrep` (헤더 private 중첩)
- `runDirectJobs` 는 버킷 4함수로, wbpj 내부는 JSON 조립 3함수 + 완료 슬롯 1함수로 분리
- .cpp 6개(공통 + Dat·Inp·Dfsxml·Wbpj·Stli) + 내부 헤더 `DashJobRunnerCae.h`. 헤더 1개 유지, 공개 표면 변경 없음
- 오작동 경로 2곳만 ERROR + return: ① `.inp`/`.dfsxml` 이 `.dat` 치환 폴백으로 흐르는 경로 ② 모핑 없는 `.dfsxml`
- 죽은 코드 3건 삭제: `createRunsFolders`, anon `copyFilesToDirectory`, 지역 `rawSamples`

## 기대
- 한 함수가 여러 워크플로를 분기하지 않는다. 케이스 파일 하나에 그 케이스의 생성·제출 전부가 있다
- 동작 변경 2건 외 회귀 없음 — `git diff -M --color-moved` 로 옮긴 블록이 원문과 같고, 케이스별 로그 문구·순서가 같다
- DOE 5경로 + Direct 4경로가 실행·종결·취소된다 (검증 표는 설계 상세)
- Windows Release 빌드 경고 0
