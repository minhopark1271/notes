## Goal
Registry 가 렌더 커서와 별개로 기준모델 층을 들고, Condition·CAD·Morphing 의 데이터 출처 9좌표가 그 층을 읽는다. 체크박스 토글·프리뷰 같은 화면 조작이 모듈의 기준 deck 을 바꾸지 않는다.

## Background
> source: wiki [Project-Manifest-4-Ticket-Slicing](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Project-Manifest-4-Ticket-Slicing) "PR 상세" G1 절

`DashAnalysisModelContextRegistry` 의 커서 1개가 "렌더 중인 파일" 과 "모듈이 기준으로 삼는 파일" 두 역할을 겸한다. 커서를 옮기는 4곳은 전부 렌더를 의도하는데 모듈 9좌표가 같은 커서를 데이터 출처로 읽어, 화면 조작이 데이터 정의를 바꾼다 (문서 2 "커서 하나가 두 역할을 겸한다" 절).

이 PR 이 작업 묶음의 첫 PR 이고 렌더 갈래(G2~G4)·원장 갈래(G5~G9) 양쪽의 선행이다.

## Technical Details

### as-is
- 커서 1개 — `m_activeFilePath`(canonical 절대) · `m_activeActor`. 파일 커서의 세터 `setActiveContext`(`controller/DashAnalysisModelContextRegistry.cpp:50-63`) 하나, 알림 `activeContextChanged`(`Registry.h:42`) 하나. Registry 시그널은 2개이고 나머지 `activeActorUpdated`(`:44`)는 액터 갱신용이라 이 PR 대상이 아니다
- 모듈 9좌표가 `activeContext()`·`activeFilePath()` 를 직접 읽는다 (문서 2 "수정부 — 9좌표")
- `getContext()` 2곳(`model/DashConditionParameterization.cpp:111` · `model/DashGeometryParameterCAD.cpp:99`)이 `get` 을 쓰고, 안전성이 "`m_loadedFilePath` 대입자가 곧 로더" 불변식에 의존한다

### to-be
- 기준모델 층 신설 — `m_referenceFilePath`(루트 상대) · `setReferenceModel()` · `referenceContext()` · `referenceFilePath()`(상대) · `referenceAbsolutePath()`(절대) · `referenceModelChanged`
- 루트 해석은 Registry 내부 헬퍼 1개로 한정 — `getProjectRootDir()` 경유 + nullptr 가드 (D9)
- Load 핸들러(`view/DashMainWindow.cpp:2140`)가 기존 `setActiveContext`(`:2267`)에 더해 `setReferenceModel` 을 부른다
- 좌표 8·3·1·2(Condition·CAD)와 4·5·6·7·9(Morphing)의 출처가 기준모델 층으로 바뀌고, `view/overlay/DashMorphingSettings.cpp:90-92` 구독이 `referenceModelChanged` 로 교체된다
- 위 `getContext()` 2좌표를 `get` → `getOrLoad` (T6 흡수분)

### not-to-be
- 원장 `referenceModels.json` · uuid 영속 — G5·G6
- 렌더 커서의 상대경로 전환 · `active*` → `displayed*` 개명 — G2·G3
- Set 별 `referenceModel` 소유 — G7. 이 PR 뒤 "Set 을 먼저 클릭하고 나중에 Load" 순서의 복구 경로가 없어져 Set 재클릭이 필요하다. G7 이 닫을 때까지 남는 문서화된 과도기 동작(D8)이라 S2 위반이 아니다

## Design

### 현황 분석
- 렌더 커서 경로의 외부 소비자 5곳 — `viewmodel/DashGeometryParameterPresentationModel.cpp:46` · `view/DashConditionParameterizationWidget.cpp:313` · `view/DashGeometryParameterCADWidget.cpp:345` · `view/DashMainWindow.cpp:2436`·`:2463` (전수 grep)
- 셋(좌표 1·2·4)은 반환값을 `QFile::exists`·`refreshFromFile`·`QFile::copy` 에 넘겨 **절대경로**를 요구한다 — 이 PR 이 그 셋을 기준모델 층으로 옮기고, 남는 비교 2곳은 G2 가 감싼다
- 시그널 구독 `DashMorphingSettings.cpp:90-92`(시그널 인자는 `:91`)는 `activeContextChanged` 를 node set 목록 갱신에 쓴다 — 소멸이 아니라 교체 대상

### 확정 결정 (문서 0 "결정 사항")
| 결정 | 내용 |
|---|---|
| D2 | `m_referenceFilePath` 소유는 Registry. 접근자 이름을 `referenceFilePath()` 로 고정하고 G5 에서 구현만 원장 조회로 교체 |
| D3 · D12 | 값 표현은 프로젝트 루트 상대경로. 상대·절대 두 형태를 노출하고 표현은 Registry 안의 구현 세부로 남긴다 |
| D9 | 상대경로 해석 지점은 Registry 안. `m_contexts` 캐시 키는 canonical 절대경로 그대로 |

대안 비교는 문서 0 "결정 근거"(D9·D12)와 문서 1 4절에서 확정됐다. 이 티켓은 그 구현이라 새 대안을 세우지 않는다.

#### 핵심 시그니처
```cpp
// controller/DashAnalysisModelContextRegistry.h
void setReferenceModel(const QString& filePath);      // 인자 표현 무관, 루트 상대로 저장
DashAnalysisModelContext* referenceContext() const;   // 프로젝트 미개방·미지정 시 nullptr
QString referenceFilePath() const;                    // 루트 상대 — 원장 키·모듈 JSON 키와 같은 문자열
QString referenceAbsolutePath() const;                // 절대 — QFile::exists·refreshFromFile·QFile::copy 용
signals: void referenceModelChanged(const QString& relPath);
```
