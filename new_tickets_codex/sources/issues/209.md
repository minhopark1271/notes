## Goal
뷰 소유 QProcess 2곳(`DashOptimizerWidget::m_fitProcess`·`TopOptPostprocessDialog::m_postprocessProcess`)의 실행 주체와 소유가 controller 경유 엔진 위임으로 이전되어 계층 위반과 "창 닫힘 = 작업 사망" 문제가 해소된다. 실행 중 프로세스의 수명 상한은 앱 종료이며, 취소는 PyInstaller 워커까지 완전히 도달한다.

## Technical Details

- **소유권 규칙** (thread-execution-design 3-6절): 실행 객체의 소유자는 뷰가 아니라 모델/컨트롤러 계층 — 창 무관 소유 체인(`DashManager`·`DashProjectManager`)이 이미 실존하며 그것이 숙주. 위젯은 **구독만** 한다.
- view 는 controller 경유로 실행 요청 — 계층 위반(뷰가 직접 실행)을 동시에 해소.
- 창 닫힘 시: Qt 가 시그널 연결 자동 해제 → 통지는 조용히 유실(크래시 없음), 외부 프로세스는 계속 실행.

재검토로 드러난 제약 4건:

1. **fit 전 경로가 `#ifdef DASH_BUILD_LGE_COMPSPRING` 안에 있다** (`DashOptimizerWidget.h:141-152`, `.cpp:64`~`2228`). model 로 옮길 때 같은 가드가 따라가야 한다. 선례 `model/DashDataProcessor.h:93-96` (선언 묶음을 가드로 감쌈).
2. **TopOpt 다이얼로그는 모달·스택 할당** (`DashMainWindow.cpp:3372` `TopOptPostprocessDialog dialog(this); dialog.exec();`). 러너를 다이얼로그가 소유하면 목적 자체가 무산된다. `TopOptPostprocessConfig` 는 `TopOptPostprocessDialog.h:84` 의 중첩 struct.
3. **싱글턴 소멸자는 돌지 않는다.** `DashManager::Destroy()`·`DashProjectManager::Destroy()` 는 선언만 있고 **호출처가 없다**. 소유 체인이 앱 종료 시 해체되지 않으므로, 다이얼로그 소멸자의 `terminate()` 를 걷어내면 Windows 특성상 프로세스가 고아로 남는다 → 종료 훅이 필요한 이유.
4. **`ProcessJob::cancel()` 의 `kill()` 은 반쪽 취소다.** PyInstaller onefile 은 "부트로더 부모 + 실제 워커 자식" 2계층이고 `processId()` 는 부트로더 PID 이므로, `/T` 없이는 워커가 살아남는다 (`DashExtensionProcess.cpp:29-34` 주석). 트리 kill 헬퍼 `forceKillPid()` 는 존재하나 익명 네임스페이스(`:22-39`)에 갇혀 있다.

| # | 쟁점 | 결정 | 근거 |
|---|---|---|---|
| D1 | TopOpt 러너의 소유자 | 로직은 신설 `DashTopOptPostprocessRunner`, **소유는 `DashManager` 필드 1개 + 접근자** | 데몬 3종(`DashManager.h:147-149`)과 같은 자리·같은 접근자 규약(`:224-226`). 로직이 러너에 있어 W20 분해 시 필드 1줄만 제거 |
| D2 | 재진입 정책 | **진행 중이면 새 실행만 거부** (러너 핸들 1개 가드) | 모달이라 동시 오픈 불가 → 유일 경로는 닫고 재오픈. 현행 "동시 1개" 의미 보존 |
| D3 | 러너의 경계 | **thin** — `run(configJson, outputStlPath)`. JSON 조립은 다이얼로그 잔류 | 본 티켓 Goal 은 실행 주체·소유의 이전이지 도메인 로직 전면 이관이 아님. 조립 이관은 W20 후보 |
| D4 | fit 완료 시그널 | **thin** — `fitFinished(success, stdoutText, stderrText)`. JSON 파싱·3분기 정책은 위젯 잔류 | 현행은 실패/부분/성공 3-way. 파싱을 옮기지 않으면 정책이 자동 보존되고 기계적 전환에 머문다. D3 와 대칭 |
| D5 | Set 전환 시 버튼 고착 | **상태 복원** — `isFitRunning()` pull + `setModel()` 에서 버튼 상태 재계산 | 전환 차단은 오늘 되는 조작을 금지(AC 충돌)하고 프로그램적 선택 변경 경로에 구멍이 남는다. 복원은 경로 열거 없이 성립 |
| D6 | stderr 정책 | **Job 단위**로 분기 — optimization 미구독 유지, fit 은 `errorOutputLine` 구독 축적 | fit 의 실패 메시지는 stderr 전문이 유일 정보원(`:2034`). 클래스 단위로 통일하면 한쪽이 깨진다 |
| D7 | exe 미존재 검증 | 엔진 위임 — `finished(Failed)` 의 엔진 문구 사용 | 사전 모달 대신 시그널 왕복. 같은 이벤트 루프 턴이라 체감 동일 |
| E1 | 트리 kill 범위 | **`ProcessJob::cancel()` 전면 승격** | 생산 호출처가 `DashModelBuilder::stopTraining()` (`:1231`) 1곳뿐이라 회귀 범위가 좁다. 종료 경로 한정은 PID 접근자 + 소유자별 훅 배선이 필요해 총량은 비슷한데 반쪽 취소 결함이 남는다 |
| E2 | 프로세스 수명 상한 | **앱 종료** — `aboutToQuit` 에서 실행 중 Job 일괄 cancel | 창 닫힘은 통과, 앱 종료는 상한. 상한 없음은 고아 프로세스를 남긴다 |
