# #543 비동기 작업 중 UI 차단·진행 표시의 UI/UX 정리

## 현상

`#458` 에서 대용량 XML 파싱을 워커로 옮기면서, 그 동안 사용자 조작을 막는 최소 장치를 넣었다. `DashAsyncJobRunner` 가 작업을 제출할 때 최상단 위젯을 `setEnabled(false)` 하고 상태바에 무한 진행바를 띄운다. 끝나면 되돌린다.

**딱 그것뿐이다.** 조작 차단과 "살아 있다" 는 표시만 한다. UI/UX 로서는 다음이 비어 있다.

- **진행 표시의 형태와 자리가 임시다.** 상태바 좌측에 폭만 늘린 무한 진행바 하나다. 무엇을 하는 중인지 문구가 없고, 진행률도 없다(작업이 진행률을 낼 수단이 없다).
- **취소가 없다.** 실행 기제(`QtConcurrent::run`)에도 reader-writer SDK 에도 취소 수단이 없어 지금은 기다리는 것 말고 할 수 있는 것이 없다.
- **창 이동·리사이즈·타이틀바 닫기 버튼이 같이 막힌다.** 이 앱은 프레임리스라(`view/DashMainWindow.cpp:147`) 창 이동은 `DashTitleBar`, 리사이즈는 `QSizeGrip` 이 맡는데 둘 다 윈도우의 자식이다. 최상단을 끄면 함께 꺼진다. Alt+F4 와 작업 표시줄 종료는 창 관리자를 지나므로 살아 있다.
- **반려된 요청에 화면 안내가 없다.** 작업이 도는 중 들어온 요청은 단일 슬롯 정책으로 반려되고 로그에만 남는다. 차단이 걸린 뒤로는 사용자가 애초에 조작할 수 없으므로 실제로 반려가 나는 창은 좁지만, 없지는 않다.
- **기존 차단 기제와 별개로 존재한다.** `DashMainWindow::setUIEnabled()` + `showLoadingIndicator()` 짝이 프로젝트 생성·열기·저장 경로에서 쓰이는데(툴바와 독 5개만 끄고 메뉴바는 열어 둔다), 이번 것과 범위도 표시 수단도 다르다. 지금은 서로를 부르지 않아 충돌하지 않지만 두 벌이다.

## 기대

비동기 작업 중 사용자에게 보이는 상태를 하나의 형태로 정리한다. 무엇을 정해야 하는지:

- 진행 표시의 형태(문구 유무, 자리, 모달 여부)와 기존 `showLoadingIndicator` 와의 관계
- 차단 범위 — 창 이동·리사이즈를 살릴 것인가. 살리려면 `DashTitleBar`·`QSizeGrip` 을 차단 대상에서 빼야 한다
- 취소가 가능해지는 시점(실행 기제나 SDK 에 취소가 생길 때)의 표면
- `setUIEnabled` 계열과 통합할 것인가, 용도를 갈라 둘 것인가
