# #573 Data Upload: 새 결과 읽기 작업마다 리더 재생성

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/573
- Board status: Done
- Labels: ['refactor']

같은 Data Upload Set에서 `.odb ↔ .rst` 전환은 지원 대상입니다. 현재는 래퍼가 있으면 초기화를 건너뛰어 이전 솔버 리더가 남을 수 있습니다.

**수정 방향**

- 새 스캔·단일 파일 가져오기·Load에서 리더가 필요하면, 솔버·파일 동일 여부와 관계없이 `Clear/reset` 후 재생성합니다.
- 진행 중인 조회가 끝난 뒤 작업당 1회 초기화하고, 작업 내 조회는 같은 리더를 사용합니다. `loadRstDataFromTable()`의 중복 초기화 지점은 통합합니다.
- 초기화 실패 시 이전 리더를 사용하지 않습니다. 같은 스캔의 재시도·반복 팝업은 방지하고(#517), 다음 작업의 재시도는 허용합니다.

**완료 기준 — 구현·검증 전**

- [ ] 같은 솔버·같은 파일의 다시 읽기와 `.odb ↔ .rst` 전환에서 새 리더 사용
- [ ] 스텁으로 정리·파괴·생성 순서, 작업당 초기화 1회, 실패 후 재시도 검증
- [ ] Release 빌드 오류 0 및 관련 테스트 통과
- [ ] 실제 파일의 조회·응답·형상 읽기와 실패 후 재시도 검증 — 래퍼 생성 성공과 실제 읽기 성공은 별도로 확인

**관련 작업**

- #569 / PR #571의 스캐너 추출은 병합 완료입니다. #573은 리뷰에서 발견한 기존 경로의 동작을 변경하는 별도 이슈이며, #571에서 새로 발생한 회귀가 아닙니다.
- #433(DataProcessor 분해)과 같은 클래스를 수정하므로 반영 순서를 조율합니다. #530도 `loadDvTable()`·`loadRstDataDirectly()`를 수정하므로 충돌과 입력 검증 동작을 확인합니다.
- #431의 정리 계약, #508의 싱글턴 null 가드 제거, #269 / PR #570의 JobRunner 분해에 이 수정이 포함됐다고 보지 않습니다. 상위 리팩터 전체의 완료를 선행 조건으로 두지 않습니다.
- launcher 영속화·구버전 프로젝트 호환 정책 변경은 범위에 포함하지 않습니다.

코드 근거: [초기화·재사용 분기](https://github.com/NumeRealWorks/DashOpti_GUI/blob/33de7d10ebb397540e9dd6d20761e32787ae05fc/model/DashDataProcessor.cpp#L108), [DOE 판별](https://github.com/NumeRealWorks/DashOpti_GUI/blob/33de7d10ebb397540e9dd6d20761e32787ae05fc/model/DashDataProcessor.cpp#L404), [단일 파일 판별](https://github.com/NumeRealWorks/DashOpti_GUI/blob/33de7d10ebb397540e9dd6d20761e32787ae05fc/model/DashDataProcessor.cpp#L553), [Load 초기화 두 지점](https://github.com/NumeRealWorks/DashOpti_GUI/blob/33de7d10ebb397540e9dd6d20761e32787ae05fc/model/DashDataProcessor.cpp#L749).
