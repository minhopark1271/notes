# #408 Morphing 요청 서비스 — 레인 스케줄링·스레드 예산·결과 반환

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/408
- Board status: Done
- Labels: ['refactor', 'split-group:215']

## Goal

**모핑 실행 요청을 한 곳으로 모아 레인별로 스케줄링하고 결과를 돌려주는 계층을 세운다.**

호출자는 요청(동결 입력 + 실행 입력)을 **값으로** 조립해 제출하고 결말을 `QFuture` 로 받는다. 스레드도 basis 도 스레드 수도 호출자가 다루지 않는다. 게이트·`Reservation`·호출부별 풀 선택은 없다.

## 귀결 (PR #506)

계층이 섰다. **정본은 [`docs/morphing-request-service.md`](https://github.com/NumeRealWorks/DashOpti_GUI/blob/dev/docs/morphing-request-service.md)** 이고 아래는 목차만 남긴다 — 규약을 두 곳에 두면 갱신이 갈라진다.

| 산출물 | |
|---|---|
| `controller/DashMorphingService` | 진입점 둘 — `submitFreeze` · `submitMorph`. 레인 2종(`Interactive` 최신 1건 · `Background` FIFO), 실행 슬롯 각 1 |
| 스레드 예산 | `max(1, 물리 코어 / 레인 수)`. 서비스 생성 시 1회 확정, 동결 시점에 basis 에 구워진다. `GetLogicalProcessorInformationEx` — `idealThreadCount` 는 논리 코어라 쓰지 않는다 |
| 승격 모델 | 승격 뒤 안정화된 상태가 **개별 타입**이다. `static create` 만 생성, 전이는 멤버가 `QCoro::Task<Result<Next>>` 반환. 프리뷰 `Armed → Frozen → Shown`, Mesh QC `Prepared → LowerChecked → Checked → Decided` |
| 상태 스냅샷 | `<stem>.json`(메타, `"type"` 키 필수) + `<stem>.<name>.vtp\|.vtu`. 사이드카 → 메타(`QSaveFile`) 순. 앱은 자동으로 남기지 않는다 |
| 취소 | `std::stop_token` → `stop_callback` → `future.cancel()`. 협조적. 결말은 `ErrorCode::Canceled` 이고 드라이버는 조용히 처분한다 |
| 실패 사유 | RW 계층과 같은 `dash::core::Result<T>`. `ErrorCode` 가 분류 (#422 해소) |
| `DashHandleBlock` | MeshOps 헤더를 끌지 않는 GUI 값. 설계 handle 과 마커가 **별도 블록**. #499 작업 1·2 가 랜딩해도 이 타입과 스냅샷 형식은 그대로다 |

### 이관 상태

| 요청원 | 상태 |
|---|---|
| 프리뷰 (제스처 릴리즈 · 토글 · 반경 변경 · 마커 동기화) | **이관** — `Interactive` 레인. 범위·방향 스핀박스는 동결된 basis 를 재사용한다(재동결 없음) |
| Mesh QC (`onSaveDesignVariableClicked`) | **이관** — `Background` 레인. 볼륨 메시는 `DashVolumeMeshAccess` 로 주입. 다이얼로그는 `show()` + `co_await qCoro(dialog, finished)` — `processEvents` 3곳·중첩 `exec()` 1곳 소멸. 다이얼로그는 `ApplicationModal` 을 유지하므로 **QC 가 도는 동안 새 제스처는 들어오지 않는다** |
| DOE 배치 (`ExecuteOneSample`, Optimizer · ModelRunner 포함) | 미이관 — GUI 스레드 동기, 서비스 예산 밖(`threads = 0`). #281 |

## 이월

- **계측 (요청당 소요 시간 로그)** — 이 이슈에서 하지 않았다. `DashMorphingService` 가 요청 단위로 시간을 잴 수 있는 자리다. 모핑 1회 비용은 #313 이후 측정된 적이 없다(#347). → **#281 승계**
- **예산 재배정** — 지금은 레인당 고정 `코어/2`. 배치만 돌 때 절반이 유휴다. 동적 배정은 계측 뒤에 판단한다. → **#281 승계**
- **배치 이관 형태** — `ExecuteOneSample` 은 RW 모듈 호출과 모핑을 번갈아 한다. 모핑만 `Background` 에 제출할지, 샘플 전체를 워커로 옮길지. → **#281 소유**

## Out of scope

- `WorkerJob` · `ThreadPools` · `MorphingGate` 재도입 — 하지 않는다. 이 서비스가 그 자리다.
- DOE 샘플의 상태 타입(`DashDoeSampleArmed` 등) — #281. 같은 게이트·블록·스냅샷 라이터를 그대로 쓴다.
- preprocessor(DPF) 축 — 비재진입 DLL 이라 별개다.
- volume 메시 세트 스냅샷 — `RunVolumeMorphing` 이 `DashManager` 의 메시 4종을 읽는 결합. #281.
