# #437 데몬 준비 신호와 현재 상태 조회의 계약 일원화

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/437
- Board status: Done
- Labels: ['refactor']

## Goal
데몬 준비 상태의 전달을 "전이 통보 + 현재값 조회 + 표준 구독형" 한 계약으로 정하고, sensitivity·MCU 두 데몬 경로의 소비자 보정 4곳을 제거한다.

## Background
> source: wiki [Backlog-Issue-Publication-Plan](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Backlog-Issue-Publication-Plan) · 원 항목 구 B6 잔여 (RUN-D3)

`daemonReady` 는 부팅 완료 시 1회의 변화 통보다. 위젯은 Set 전환·탭 재초기화로 부팅 뒤에 다시 만들어지므로, 소비자마다 "connect + 현재값 즉시 조회" 2줄 보정이 필수 관례가 됐다. 버튼 상태를 실제로 결정하는 것은 시그널이 아니라 초기 조회 쪽이고, 시그널 계약은 이름뿐이다 (RUN-D3: "신호 계약이 아니라 현재 상태 재조회가 실제 동작").

## Technical Details

### as-is

신호 원천은 공용 호스트 하나다:

```
DashExtensionProcess (controller/DashExtensionProcess.h)
├── ready()           부팅 완료 시 1회 — 재기동하면 새 부팅에서 다시 발행
├── died()            사고사 — 자동 재기동 없음
├── stopped()         프로세스 정리 완료
└── isDaemonReady()   현재값 getter (m_state == Ready)
```

래퍼 3벌이 이를 제각각 전달한다:

| 래퍼 (데몬) | 준비 통보 | 비준비 통보 | 현재값 getter |
|---|---|---|---|
| `DashModelRunner` (sensitivity) | `daemonReady()` ← host `ready()` | `daemonError(msg)` ← host `died()` | `isDaemonRunning()` |
| `DashModelBuilderMCU` (MCU) | `daemonReady()` ← host `ready()` | 없음 | `isDaemonReady()` |
| `DashModelRunnerMCU` (MCU) | `daemonReady()` ← BuilderMCU 재전달 (host 기준 2단) | 없음 | `isDaemonReady()` → BuilderMCU 위임 |

소비 측 보정 실측 4곳 — 전부 "connect + 즉시 현재값 조회" 같은 무늬:

| 위치 | 데몬 | connect | 보정 조회 |
|---|---|---|---|
| `view/DashModelRunnerWidget.cpp` | sensitivity | `:172` → Plot 활성 | `:189` `isDaemonRunning()` |
| `view/DashModelRunnerMCUWidget.cpp` | sensitivity | `:102` → Plot 활성 | `:111` `isDaemonRunning()` |
| `view/DashModelBuilderMCUWidget.cpp` | MCU | `:167` → Start/Preview 활성 | `:171` `isDaemonReady()` |
| `view/DashModelRunnerMCUWidget.cpp` | MCU | `:141` → Preview 활성 | `:145` `isDaemonReady()` |

결함 4갈래:

1. **유실 보정 복제** — 4곳 모두 "daemonReady 는 부팅당 1회뿐이라 놓친다" 주석과 함께 같은 2줄을 복제. 보정을 빠뜨린 신규 소비자는 데몬이 이미 떠 있으면 버튼이 영영 비활성 — 컴파일도 시그널 연결도 잡아주지 않는 관례 의존.
2. **비준비 통보 부재 (MCU)** — MCU 래퍼 2벌은 `died()`/`stopped()` 를 전달하지 않아, 데몬 사고사 후에도 Start/Preview 가 활성으로 남는다. sensitivity 만 `daemonError` 로 비활성 복귀.
3. **getter 이름 분열** — 실체는 셋 다 host `isDaemonReady()` 위임인데 `isDaemonRunning` / `isDaemonReady` 로 갈려 계약이 하나로 읽히지 않는다.
4. **재구독 수동 관례** — `DashModelRunnerMCUWidget.cpp:140` 은 setModel 재진입 중복을 막으려 람다 connect 앞에 수동 disconnect (Qt::UniqueConnection 이 람다에 안 먹는 제약).

### to-be

표준 계약 1형태 — "전이 통보 + 현재값 조회 + 구독형". 래퍼 3벌·소비 4곳 전부 이 형태로 이행한다.

1. **전이 통보**: 준비 상태는 bool 전이 시그널 하나로 통보한다 — `daemonReadyChanged(bool)`. 부팅 완료 = true, `died()`/`stopped()` = false. 호스트 `DashExtensionProcess` 에서 발행하고 래퍼는 이름 그대로 전달한다 (RunnerMCU 의 2단 재전달 형태는 유지 — 이름·의미만 통일).
2. **현재값 조회**: getter 는 `isDaemonReady()` 하나로 통일 — `DashModelRunner::isDaemonRunning()` 개명 (호출처는 위 보정 2곳뿐).
3. **표준 구독형**: 소비자는 구독 헬퍼 하나만 쓴다 — 구독 시점에 현재값으로 즉시 1회 콜백 + 이후 전이마다 콜백. "놓친 신호" 개념 자체가 소멸한다.

```cpp
// 래퍼 공통 — 구독 즉시 현재값으로 1회 호출, 이후 전이마다 호출.
// 연결 수명은 ctx 에 묶이고, 같은 ctx 의 기존 구독은 교체된다
// (setModel 재진입 중복 방지가 계약에 내장 — 수동 disconnect 불요).
void observeDaemonReady(QObject* ctx, std::function<void(bool)> onChange);
```

4. 소비 4곳을 구독형으로 이행하고 보정 2줄·유실 설명 주석·`:140` 수동 disconnect 를 제거한다. 버튼 활성/비활성은 `onChange(bool)` 하나가 맡는다 — MCU 경로는 이 이행으로 비준비 복귀 (위 결함 2) 가 처음 생긴다. `daemonError` 는 메시지 표시 용도로만 남는다.

### not-to-be
- 데몬 기동·재기동·종료 시점 규칙 — #436 소유. 접점: #436 이 재기동을 도입해도 `daemonReadyChanged(false→true)` 두 전이로 표현될 뿐, 재발행 특례가 필요 없다.
- MCU 경로의 에러 메시지 표시 UI 신설 — 버튼 상태 복귀까지만 하고, `daemonError` 상당의 통지 추가는 별건 (통지 규칙은 구 D3 축).
- `DashModelBuilder` 의 1Hz 상태 폴링 타이머 (BLD-D13) — 별건.

## Acceptance Criteria
- 데몬이 이미 Ready 인 상태에서 위젯을 재생성 (Set 전환·탭 재초기화) 해도 Plot·Start/Preview 버튼이 즉시 활성.
- 데몬 사고사 시 버튼 비활성 복귀 — sensitivity 는 기존 `daemonError` 경로와 동등, MCU 는 신규 동작.
- 소비 4곳에 "connect + 초기 조회" 보정 무늬와 수동 disconnect 가 남지 않는다.
- `grep isDaemonRunning` 0건.
