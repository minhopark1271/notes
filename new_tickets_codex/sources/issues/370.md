# #370 ModelRunner: 1D 모델 Run AI Prediction 이 reference analysis file 없으면 차단됨

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/370
- Board status: Backlog
- Labels: ['bugfix', 'source:QC']

## 현상
Model Runner 에서 **1D 모델**을 체크하고 **Run AI Prediction** 을 누르면, Analysis Input Files 에 파일 행이 없을 때 `No input files selected in Analysis Input Files.` 로 막힌다.

Generate 버튼은 같은 상황에서 "Reference Input File and Target Part are not configured... Only surrogate model prediction will be performed." 안내 후 DV-only 행을 만들어 주는데, Run 에서 그 행이 무시되어 안내와 실제 동작이 모순된다.

## 원인
`view/DashModelRunnerWidget.cpp` `onRunAIPredictionClicked()`
- `:1094` — `if (!pc.active || pc.file.isEmpty()) continue;` 로 파일 경로가 빈 DV-only 케이스를 무조건 탈락
- `:1098-1101` — 남는 케이스가 없으면 에러 후 return

Python 측(`DeepOpt/main.py:415-427`)은 1D 예측에 `file` 을 로그에만 쓰고 실제 예측은 `values` 만 사용한다. 즉 1D 는 reference analysis file 이 필요 없다.

## 기대 동작
- ND 모델만 파일 케이스 필수
- 1D 모델은 파일 케이스가 없으면 dvTable 현재값으로 DV-only 케이스를 만들어 실행

## 주의
Run 경로의 `updateModelUploadConfig` 가 `Input Design Variables` 를 model_info 의 default 값으로 덮어쓴다. Prediction Case 없이 Python 폴백에만 맡기면 사용자가 입력한 DV 값이 아닌 기본값으로 예측되는 조용한 오답이 되므로, 게이트만 완화하는 방식은 부적절하다.

## 함께 발견된 문제 (별도 이슈 후보)
- `populateFileTable()` (`:962`) 이 `m_fileTableDvValues` 를 무조건 clear → 케이스 A 생성 후 B 를 Generate 하면 A 의 저장 DV 값(부호변환 적용값)이 소실. Morphing 의 .vtu 행은 재스캔 대상이 아니어서 refresh 후 행 자체가 사라짐
- `getReferenceFileAndPart()` 가 파라미터를 알파벳순 순회해 첫 매치로 sourceType 결정 → Morphing+Condition 혼합 모델에서 ND 가 거짓 거부될 수 있음
- Condition 브랜치가 `generateDatFile` 반환값을 무시하고 항상 "Input file generated." 표시
- ND+1D 동시 체크 시 `run1DPrediction` 이 `m_currentJob` 존재로 조용히 거절되고, 1D CSV 뷰어도 열리지 않음
