# #546 Morphing Handle 트리: Delete·Group 결함 정리 — 선택 모델 UI 명시·정렬·No.·그룹 유령 멤버십/번호 증가

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/546
- Board status: Done
- Labels: ['bug', 'in-progress', 'refactor']

## 현상
> #505 적용 후에도 핸들 데이터 delete 가 잘 안 됨 — 버튼을 눌러도 아무 일도 없고, 일부를 지운 뒤 다른 것을 선택해 지우면 안 지워짐(인덱싱이 밀리는 느낌). 10번 이후부터 숫자(No.)가 안 나오고 선택 후 삭제도 안 됨. 전체선택 체크박스가 항상 선택된 모양. Group 버튼을 누르면 그루핑 번호가 계속 올라감. 행을 선택해 하이라이트되어야 삭제 대상으로 작동한다는 것을 상상하지 못함.

행 하이라이트 후 Delete 는 정상 동작함을 실사용으로 확인. 결함은 (a) 선택 모델(하이라이트=조작, 체크=DV)이 UI 에 드러나지 않음, (b) 정렬·번호 표시, (c) 삭제가 남기는 그룹 잔재(유령 멤버십·번호 무한 증가)의 중첩.

## 범위
- 건드림: `view/DashGeometryParameterWidget.cpp`(트리 설정부·`onDeleteHandles`·재번호), `ui/DashGeometryParameterWidget.ui`(체크 열 헤더), `viewmodel/DashGeometryParameterPresentationModel.cpp`(`nextGroupId`), `controller/DashHandlePickingInteraction.cpp`(`RebuildGizmoGroups`·`SyncGroupGizmoDirections`·`Finalize`)
- 안 건드림: 선택 모델 역할 분리 자체(하이라이트=조작·체크=DV 유지 — 체크는 프리뷰 동결 집합이라 통합 불가), `collectAddValueTargets` 의 선택∪체크 규칙(후속 후보), `OnGroupGizmoChanged`(STATUS 가드 기존재 :2461), `m_consTable` 정렬

## 현재 구조
- 하이라이트(`selectedItems`)가 Delete(:1713)·Group/Ungroup(:1535/:1651)·3D 하이라이트와 기즈모 표시(:211-294)를 구동. 체크박스는 DV 집합(`CheckedHandleIds` :1049 → DV 저장 :1149, 프리뷰 동결 집합 `DashManager.cpp:622`, 프리뷰 중 잠금). 체크 열 헤더는 빈 문자열(`.ui:194`)
- `setSortingEnabled(true)` + `sortItems(2)` (:889-891) — Name 문자열 정렬 영구 on. 이름은 항상 코드 합성·편집 불가, DV `param%1` 번호도 표시 순서 종속(PresentationModel :154)
- No. 열 10px 고정(:842·:2243), 번호는 rebuild 때만 부여(:2670-2677), 삭제 후 재부여 없음(#503 부수 관찰). 헤더 체크박스 `setTristate(true)` (:847)
- `onDeleteHandles` 는 STATUS=0 만 기록하고 GROUPID 를 남김 — 삭제된 핸들이 영구 그룹 소속. `onUngroupHandles`(:1676)는 트리에 보이는 자식만 리셋
- gid 소비자 중 `RebuildGizmoGroups`(:2319)·`SyncGroupGizmoDirections`(:1926)는 STATUS 미필터, `nextGroupId`(PresentationModel :473)·physics `Finalize` 의 `currentMaxGroupId`(:1471)는 삭제 핸들·재그룹 대상의 기존 번호 포함 최댓값+1, `m_groupNormalModes` 는 그룹 소멸 시 미정리

## 문제
체크 열이 무엇인지 UI 가 말하지 않고 무선택 Delete 가 무반응이라, 사용자는 체크로 삭제를 시도하고 실패 원인을 발견할 수 없다. 문자열 정렬로 핸들 10개부터 화면 순서가 어긋나고 No. 는 두 자리부터 잘리며 삭제 후 구멍이 남는다. 삭제가 GROUPID 를 남겨 그룹 기즈모에 죽은 멤버가 끼고(멤버 수 판정·컨트롤 위치·평균 법선 오염), 그룹 번호는 Group 을 누를 때마다 무한 증가한다.

## 변경
- 선택 모델은 유지하고 UI 로 명시 — 체크 열 헤더 "DV" + 툴팁, Delete 무선택 시 "행을 클릭해 선택 후 삭제" `QMessageBox::information` 안내(:1219·:1899 관례), 선택 검사를 `PreviewCheck` 앞으로
- Name 열 정렬 제거 — 표시 순서 = 핸들 id 순 고정, DV `param` 번호 부여도 결정적이 됨
- No. 열 폭 10 → 32px 상수 통일(:842·:2243), 재번호 루프를 `renumberHandleTreeRows()` 헬퍼로 추출해 rebuild·삭제 끝에서 호출
- 헤더 체크박스 `setTristate(false)` — 사용자 클릭은 2단 토글, 프로그램적 혼합 표시 유지
- `onDeleteHandles` 가 STATUS 와 함께 GROUPID(전 컴포넌트)를 0 으로 리셋 — 유령 멤버십·번호 증가의 원천 차단
- `RebuildGizmoGroups`·`SyncGroupGizmoDirections` 에 STATUS≠0 가드(VTP DeepCopy 로드로 유입되는 잔재 방어), `RebuildGizmoGroups` 에서 `m_groupNormalModes` 를 live gid 기준 prune
- `nextGroupId` 를 STATUS≠0 한정 + 선택 전체가 이미 단일 그룹이면 기존 번호 유지(재그룹 no-op), physics `currentMaxGroupId` 동일 가드

## 기대
- 무선택 Delete 는 안내 메시지(프리뷰 다이얼로그보다 먼저), 체크 열에 "DV" 표시 — DV 저장·프리뷰 동작은 불변
- 핸들 12개 생성 시 id 순·No. 두 자리 표시, 중간 삭제 후 1..N 재부여, 헤더 체크박스 2단 토글
- 그룹 일부/전부 삭제 후 그룹 기즈모에 죽은 멤버 없음, Group 반복 클릭·삭제 반복에도 그룹 번호 무한 증가 없음
- 검증: Windows `local-msvc-release` 빌드 + 위 시나리오 수동 확인
