## Goal
읽기 캐시를 실행 단위 소유로 옮기고, 화면과 실행이 같은 캐시를 동시에 만지지 못하게 하는 규칙을 세운다.

## Background
> source: wiki [Backlog-Issue-Publication-Plan](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Backlog-Issue-Publication-Plan) · 원 항목 A6b

배치 축은 전용 읽기 세션으로 분리됐으나, 읽기 캐시는 화면과 실행 경로가 여전히 공유한다 — 캐시 승격·배제 기제가 남은 반쪽이다.

## Technical Details

### as-is (2026-09-21 실측 · dev)

공유 지점은 `DashAnalysisModelContextRegistry` 싱글턴이다 — 경로 키로 `DashAnalysisModelContext`(파싱 deck + RW 세션 + 렌더 표현)를 캐시하고, 화면 위젯들과 실행 경로가 같은 인스턴스를 나눠 쓴다. 실행 경로의 `registry.getOrLoad` 소비 6곳:

| 위치 | 소유 함수 |
|---|---|
| `model/DashOptimizer.cpp:1489` | `performMorphing` |
| `model/DashModelRunner.cpp:2142` | `performMorphing` |
| `model/geometry/DashMorphingUtils.cpp:202` | `extractPartVtuFromDat` |
| 같은 파일 `:253` · `:269` | `extractComponentVtuFromDat` (morphed·original deck) |
| `controller/DashManager.cpp:1190` | `MorphFromDoeSamples` |

귀결 — 실행이 만든 임시 산출물(morphed deck)이 화면과 같은 캐시에 등록되어 누적되고(축출 없음), 실행 중 화면의 같은 경로 접근이 같은 컨텍스트 인스턴스에 닿는다.

### to-be
- 위 실행 경로가 registry 대신 실행 단위 소유의 읽기 컨텍스트(전용 세션 또는 함수 스코프)를 연다 — 실행 경로의 `registry.getOrLoad` 소비 0곳
- 예외 판정 1건 — `extractComponentVtuFromDat` 의 `originalDatPath` 참조 deck 은 반복 간 고정된 읽기 전용이라, 세션 전환 시 없던 재파싱이 생긴다. GUI 에서 셋 라벨 값만 떠서 넘기는 대안(#281 Phase E 정해)과 비용 비교 후 결정
- 배제 규칙 명문화 — 실행 산출물이 화면 캐시(registry)에 등록되지 않는다. 읽기 캐시 승격(조건 읽기의 GUI 측 캐시) 도입 여부는 [215-1 스냅샷](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/215-1-w10-f-design-decision-review-snapshot)의 판정을 근거로 본 이슈에서 재판정

### 접점
- #281 Phase B2·E 가 같은 함수(`performMorphing` 2곳 · `extractComponentVtuFromDat`)를 재작성한다 — 범위가 겹치므로 먼저 착수하는 쪽이 본문을 만지고, 나머지가 재실측한다. #281 은 #452 대기 중이라 본 이슈가 선착할 가능성이 높다
