# #616 입력 파일 정책: RW 미지원 포맷(.dfsxml/.wbpj/.stli)의 Project Assets·Condition·Launcher 처리

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/616
- Board status: In review
- Labels: ['feature', 'refactor']

## 목적

RW가 파싱하지 못하는 해석 입력 파일 .dfsxml(Ansys Motion), .wbpj(Workbench + NX), .stli(fe-safe)를 Project Assets·Condition Parameter·Analysis Launcher에서 다루는 규칙을 정하고 연결한다. #601 이후 Analysis Launcher Set이 파일 하나에 묶이면서 .stli Set이 ODB 원본을 찾지 못해 모든 케이스가 "no ODB sources"로 Failed 처리되는 문제를 함께 해소한다.

## 결정 (2026-10-02)

| 항목 | .dfsxml | .wbpj | .stli |
|---|---|---|---|
| Add File 복사 범위 | 파일 하나 | `.wbpj` 파일 + `{파일명}_files` 폴더 | 파일이 있는 상위 폴더 통째 (기존 구현 재사용) |
| Project Assets 행 | Reference File 아래 부모 행만, 자식 없음. View·Color·Opacity 비활성 | 동일 | 동일. 행 이름은 `{상위폴더명}\{파일명}.stli` |
| Condition Parameter Set | 만들지 않음 | 만들지 않음 | 만들지 않음 |
| Analysis Launcher Set | `{파일명}_dfsxml`, 파일에 pin | `{파일명}_wbpj`, 파일에 pin | `{상위폴더명}_stli`, 파일에 pin |
| DV 출처 | 파일 안 `Morphing\|x.dat\|target`이 가리키는 Morphing Set(.dat)의 DV. Launcher에 별도 선택 UI를 두지 않는다 | CAD Set(.prt)의 DV | 없음. 자기 DOE Table 행 전체를 케이스로 쓰고(다른 Set과 동일), ODB는 Source Set의 같은 runKey에서 가져온다 |
| Launcher 탭 Target Part 자리 | "CBLOCK" 고정, 편집 불가 (현행 유지) | `{파일명}_files` 아래 .prt 목록 콤보 (현행 유지), CPU core 비활성 | "ODB Source Sets" 체크 콤보(DOE Sampler의 Condition Set 콤보와 같은 방식). .inp에 pin된 Analysis Launcher Set 목록, 기본값은 전부 체크. 선택은 Set json `odbSourceSets`에 저장. Material 버튼 활성 |
| 결과 파일 | `.dfr` 1개 | run 폴더 아래 `.rst` 여러 개. Preprocess의 Target file 콤보(#640)로 선택 | `.odb` 1개. Start 시 체크된 Set마다 `AnalysisLauncher_<Set>/<DoeSet>/<runKey>/<runKey>.odb`를 자기 run 폴더에 `<inp 파일명>.odb`로 복사(A.odb + B.odb → fe-safe → C.odb). 하나도 없으면 그 행만 Failed. Source Set 삭제는 막지 않는다 |
| Set 종류 구분 | `referenceModel.path` 확장자 | 동일 | 동일. Abaqus 결과와 fe-safe 결과 모두 .odb이므로 결과 파일로는 구분하지 않는다 |

추가 결정 (2026-10-02 저녁)
- Add File 때 Launcher Set 이름이 이미 있으면(같은 폴더의 .stli 두 개 등) 복사·등록 없이 경고만 띄우고 이름 변경을 권한다.
- 세 포맷을 삭제하면 연동 Set, 원장 항목과 함께 stli 상위 폴더·wbpj `{파일명}_files` 폴더도 지운다.
- #601 이전에는 한 Set의 `input_files`에 든 inp 전부가 ODB 원본이었고 `<inp 파일명>.odb`로 복사했다. 체크 콤보 기본값 전체 체크가 그 동작과 같다.

## 범위

1. Add File 필터에 `*.wbpj`를 추가하고, 세 포맷을 원장에 등록한 뒤 위 이름으로 Analysis Launcher Set만 만든다. Condition Set은 건너뛴다.
2. 세 포맷은 RW로 읽지 않으므로 Add File의 "could not be read as an analysis model" 검사를 .dat/.inp에만 적용한다.
3. Launcher 탭의 기존 dfsxml·wbpj·stli 분기가 새 Set에서 그대로 동작하는지 확인한다. .stli는 Reference가 `*.stli`, Target Part 콤보 비활성, Material 버튼이 파일 편집과 연결, Start 시 fe-safe 잡 실행.
4. .stli Set에 ODB Source Sets 체크 콤보를 넣고 선택값을 Set json에 저장한다. fe-safe 실행은 체크된 Set들의 run 폴더에서 ODB를 복사한다.
