# #640 Analysis Launcher: 런처가 Done 시점에 결과 파일을 기록하고 Preprocess는 추측 없이 그 기록을 쓴다 (Target file 선택)

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/640
- Board status: Done
- Labels: ['bug', 'refactor']

## 현상

run 폴더의 결과 파일 이름이 케이스마다 다르면(`runs1/j00a.rst`, `runs2/j00b.rst`) Preprocess가 한 그룹만 처리하고 나머지는 건너뛴다. Ansys Mechanical 런처가 job 이름을 TaskID(uuid)에서 파생하면서 `.rst`가 run마다 다른 이름이 됐고, Data Upload 탭이 사라져(#601) 다른 그룹을 고를 UI도 없다.

## 원인

Preprocess가 결과 파일을 **이름 패턴으로 추측**한다. `DashDatasetScanner::scan`이 run 폴더를 훑어 이름별로 그룹을 만들고(`.rst`는 이름 그대로, 그 외는 count==1이면 `result.<ext>`), #601이 넣은 `primaryGroup()`이 그중 하나를 자동 선택한다. 런처는 Done 시점에 결과 파일을 알고 있지만 기록하지 않는다.

## 기대

- 런처가 Done을 쓸 때 `Launcher Cases[<DoeSet>][runsN].resultFiles`에 결과 파일 목록(run 폴더 기준 상대 경로)을 기록한다.
  - `.inp` → `[<runKey>.odb]`, `.stli` → `[<runKey>.odb]`(복사한 입력 odb 제외), `.dfsxml` → `[<runKey>.dfr]`: 규칙으로 1개 확정
  - `.dat` → run 폴더의 `*.rst`(숫자 접미사 없는 최종본 우선), `.wbpj` → 하위 폴더 포함 `*.rst` 전부: 여러 개 가능
- Preprocess는 기록된 파일만 쓴다. 후보는 "run마다 같은 자리의 파일"(이름이 일치하면 이름으로, 아니면 순서로 묶음).
- Preprocess 탭 상단에 **Target file** 항목과 콤보를 둔다. 표시 형식 `<N> runs · <analysis type> · <file name>`. 후보가 1개면 비활성(정보만), 2개 이상이면 선택할 수 있다. 선택은 후보 수와 관계없이 항상 `AnalysisLauncher_<Set>.json`에 저장한다.
- 이름 추측 경로(`DashDatasetScanner`, `filterSplitFiles`, `primaryGroup`)와 그 테스트는 삭제한다. 폴백은 두지 않는다. `resultFiles`가 없는 옛 Done은 Preprocess에 포함되지 않는다(tableId 규칙과 같은 취급).
