## 이 이슈에 남는 것과 옮긴 것 (2026-09-22)

앞서 이 이슈에 붙였던 코멘트 넷을 정리했다. 대부분이 낡았고(PR #535 대기·순서 의존은 그 PR 이 머지되며 해소됐다), 실제 작업물은 이 이슈의 범위와 달라졌다.

**작업은 #544 로 옮겼다** — 범용 비동기 실행층(`DashAsyncJobRunner`)과 그 첫 소비자인 대용량 XML 파싱 워커 이관이다. 이 이슈의 제목·본문이 말하는 **해석 모델 적재(deck)** 와는 대상이 다르다.

## 이 이슈의 범위는 그대로 열려 있다

해석 모델 적재는 여전히 GUI 스레드에서 돈다. 착수할 때 쓸 실측치를 남긴다.

실프로젝트 `26_KU_ILJIN_TensionLink`, 46MB Abaqus deck 4종:

| 구간 | 시간 |
|---|---|
| `loadContent` (SDK 파일 파싱) | 645~685 ms |
| `createVisualActor` (`vtkGeometryFilter`) | 206~263 ms |
| `dataLoop` (`getData` 28~29회) | 127~140 ms |
| `openSession`·`getSymbolTree`·기타 | 0 ms |

deck 당 **약 1초** GUI 정지.

## PoC 에서 배운 것 — 재개할 때 반드시 볼 것

PR #529(닫힘, 브랜치 `perf/458-rw-actor-worker` 는 레퍼런스로 남김)에서 `DashRwActor` 를 전용 스레드로 옮기고 적재를 워커에서 시작했다. 그중 **~800ms(78%)가 GUI 스레드 밖으로 나갔다.**

**그러자 프리즈가 우연히 직렬화해 주던 재진입 경로가 열렸다.** 결함 6건이 나왔다 — 닫힌 프로젝트의 메시가 새 프로젝트에 올라옴 · 늦게 끝난 deck 이 최신 표시를 덮음 · 트리 항목 혼입 · 같은 deck 재클릭 시 UI 영구 잠김 · 적재 중 종료 시 프로세스 미종료, 그리고 대응 중 하나 더. 상세는 그 PR 의 1차 리뷰 코멘트에 있다.

전부 `DashAnalysisModelContextRegistry` 가 in-flight 상태(`m_pending`)를 들고 있는 데서 나왔다. **재개할 때 그 구조로 돌아가지 마라** — in-flight 는 실행층이 들고, registry 는 완성품을 받는 쪽이어야 한다. #544 의 `DashAsyncJobRunner` 가 그 실행층이다.

## 선행 조건

`DashRwActor` 를 전용 스레드로 옮기는 것이 먼저다. 액터가 GUI 스레드에 있는 한 워커가 `DashRwSession::open()` 을 불러도 `invokeOnActor` 가 `Qt::BlockingQueuedConnection` 으로 GUI 에 되돌려 **파싱이 GUI 에서 그대로 돈다.** 이주 없이는 비동기화가 0 효과다.

`createVisualActor`(206~263 ms) 의 워커 이관은 VTK actor 소유권 계약(#318·#319)이 없어 별도 판단이 필요하다.
