# #569 DashDataProcessor 절단면 1 — Data Upload 데이터셋 스캐너를 순수 함수로 추출 (동작 불변)

- Board status: Done

## Goal
`DashDataProcessor::onAnalysisFileSelected` 의 스캔 본체(runs 폴더 열거 · 결과 파일 패턴 감지 · 그룹 키 결정 · `DatasetItem` 구성)를 멤버 상태 없는 함수로 떼어내고, 현재 동작을 그대로 고정하는 특성 테스트를 붙인다. **동작은 바꾸지 않는다.**

## Background
- 부모 #433. 첫 절단면 #435 는 파일만 옮겨져 여전히 같은 클래스의 멤버 상태 18개를 공유한다. 이 클래스의 단위 테스트는 0건.
- 스캔 본체(`model/DashDataProcessor.cpp:389-691`, 약 300줄)가 멤버에서 읽는 것은 `m_preprocessor`(.rst 판별) 하나, 쓰는 것은 `m_dataset` 하나 — 상태를 옮기지 않고 떼어진다.
- #522(.rst 그룹핑 회귀)가 이 안에 있다(`:673`). 그 수정은 파일명 정책 결정이 걸려 있어 결정 전에 테스트 그물을 먼저 친다.
- Draft PR #530 이 고치는 함수 4개(`loadDvTable` · `loadRstDataDirectly` · `processResults` · `updateDatasetConfig`) 밖이라 지금 착수 가능.

## 작업
- `DatasetItem` 을 `model/preprocessor/DashDatasetTypes.h` 로 이동(Qt Core 만). `DashDataProcessor.h` 가 VTK 헤더를 포함해 지금은 스캔 코드를 테스트 타깃(Qt Core + Test)에 넣을 수 없다.
- `model/preprocessor/DashDatasetScanner.{h,cpp}` 신설 — 입력: analysis type 경로 · `.rst` 판별 콜백, 출력: `DatasetItem` 목록 · 실패 사유. `errorOccurred` 문구 4종은 문자 그대로 유지(QC 가 그 문구로 보고).
- `filterSplitFiles` 를 스캐너로 이동. `DashFileLocator` · `DashResponseInitializer` 의 다른 두 벌은 규칙이 달라(뒤 숫자 전체 vs `0` 접미) 무접촉 — 통일은 동작 변경.
- `tests/TestDatasetScanner.cpp` (Level 1) — runs 숫자 정렬 · 결과 파일 없는 runs1 건너뛰기 · run 당 1회 이름 → `result.<ext>` · **`.rst` 는 파일명 그대로(현재 동작, #522 수정 시 기대값 변경)** · split 필터 · Dynamic(.dfr) · 실패 4종 문구 · 콜백 고유 파일당 1회.
