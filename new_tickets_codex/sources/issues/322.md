# #322 refactor: GizmoGroup 의 인덱스 병렬 컨테이너 3개 정리 — checked/백업 상태를 DashGizmo 소유로 이관

## Original Request
> GizmoGroup.h/cpp 파일을 리뷰하고 있어. _members와 _active의 관계에 대해 설명해줘볼래? _active가 왜 필요한지 모르겠군.
> (이후 논의) gizmo들이 checked state를 들고있으면 다 상관없어지는 것 같은데

## Goal
`GizmoGroup` 이 멤버 인덱스로 병렬 컨테이너 3개를 동기화하는 구조를 없앤다. 체크 여부와 조작 플래그 백업을 `DashGizmo` 자신이 소유하게 하여, `GizmoGroup` 의 상태를 `_members` 하나로 줄이고 인덱스 재계산에서 파생된 결함을 구조적으로 제거한다.

## Background
`GizmoGroup` 은 세 컨테이너를 **같은 인덱스** 로 묶어 관리한다.

- `_members` (`std::vector<DashGizmo*>`) — 등록된 기즈모 전체
- `_active` (`std::set<int>`) — 그중 체크된 것의 인덱스
- `_savedState` (`std::map<int, SavedState>`) — 체크 시 꺼버린 축·슬라이더 플래그의 백업

`setChecked(true)` 는 단순 선택이 아니라 파괴적 조작이다. 대상 기즈모의 translation/rotation 축 6개와 슬라이더 활성 여부를 백업한 뒤 전부 끈다 (`GizmoGroup.cpp:72-87`). 개별 조작을 막고 공유 컨트롤 기즈모로만 움직이게 하려는 것이고, `setChecked(false)` 가 이를 되돌린다 (`:96-102`). 체크 해제된 멤버도 계속 추적해야 하는 이유가 여기 있다.

문제는 개념이 아니라 표현이다. 인덱스로 묶여 있어 멤버 하나를 제거할 때마다 나머지 두 컨테이너를 전부 리인덱싱해야 하고 (`:51-59`), 그 코드가 순전히 이 결합 때문에 존재한다.

조사 중 확인한 사실:

- `_active` 와 `_savedState` 의 **키 집합이 항상 동일하다**. 삽입 지점(`:72`·`:87`), 삭제 지점(`:91`·`:103`, `:47`·`:48`)이 정확히 짝을 이루고, 둘 중 하나만 건드리는 경로가 없다. 즉 `_active` 는 `_savedState` 키의 중복 저장이다
- 외부 호출부는 `DashHandlePickingInteraction` 하나뿐이며 `addMember` → `setChecked(gizmo, true)` (`:2309-2310`) 와 `isChecked` 조회 (`:2022`, `:2519`) 만 쓴다. `removeMember` · `setChecked(…, false)` · `activeMembers()` 는 호출처가 0
- 그룹은 `GROUPID` 배열로 나뉘고 핸들당 gid 가 하나다 (`:2286-2288`). **한 기즈모는 한 그룹에만 속한다** — `bool` 플래그로 표현 가능한 전제

## Technical Details

### as-is

**1. `removeMember` 가 백업을 복원 없이 폐기한다** — `GizmoGroup.cpp:48`
- `_savedState.erase(idx)` 를 `setChecked(gizmo, false)` 경유 없이 직접 호출한다
- 체크된 멤버를 제거하면 그 기즈모는 축 6개와 슬라이더가 전부 꺼진 채 남고, 백업본이 사라져 되살릴 방법이 없다
- 같은 줄에서 `_active` 도 지워지므로 순회 대상에서는 빠진다. 그래서 증상이 "제거된 기즈모가 조작 불가 상태로 남는 것" 하나로만 나타나고 조용히 넘어간다
- 현재 호출처가 없어 미발현. 그룹 편집 UI 가 붙는 순간 발현한다

**2. `setChecked(true)` 중복 호출이 백업을 오염시킨다** — `GizmoGroup.cpp:72`
- 이미 체크된 기즈모에 다시 호출하면 **이미 꺼진 상태** 를 백업본에 덮어쓴다
- 이후 `setChecked(false)` 는 전부 꺼진 상태로 "복원" 한다
- 재진입 가드가 없다

**3. `_active` 가 `_savedState` 키의 중복이다** — `GizmoGroup.h:91-92`
- 동기화해야 할 컨테이너가 하나 늘고, `removeMember` 의 리인덱싱 블록이 두 배가 된다
- `_savedState` 조회에는 `_active` 가 쓰이지 않는다. `_members` 에서 `find` 로 구한 `idx` 로 직접 찾는다 (`:68`, `:92`)

**4. `setChecked(false)` 의 else 분기가 체크되지 않은 기즈모의 축을 강제로 켠다** — `GizmoGroup.cpp:105-113`
- 백업본이 없으면 "원래 다 켜져 있었을 것" 으로 가정하고 전부 활성화한다
- 체크된 적 없는 기즈모에 호출하면 그 기즈모의 개별 설정이 덮어써진다

**5. 헤더 사본이 갈라질 수 있다**
- `external/DashGizmo/include/GizmoGroup.h` 가 `libs/DashGizmo/include/GizmoGroup.h` 와 현재 바이트 단위로 동일하다
- 빌드는 `libs/` 소스를 쓰지만 (`CMakeLists.txt:327`), API 를 바꾸면 사본이 낡은 채 남는다

### to-be

`DashGizmo` 가 자기 조작 플래그의 보류 상태를 소유한다. 백업 대상인 `_sliders_enabled` 와 축별 enable 플래그는 전부 `DashGizmo` 자신의 상태이므로, 그 push/pop 도 자신이 맡는 것이 응집도상 자연스럽다.

- `DashGizmo` 에 보류 상태 API 추가. 이름은 **그룹 개념을 노출하지 않는 중립적인 것** (예: `SetInteractionSuspended(bool)` / `IsInteractionSuspended()`) — 저수준 위젯이 "그룹" 을 알게 되면 계층이 뒤집힌다. 기즈모는 "내 조작 플래그가 잠시 보류됐다" 만 알고 그 이유는 모른다
- 이미 보류 중이면 재보류를 no-op 으로 막는다 (2 해결)
- `GizmoGroup` 의 private 상태가 `_members` 하나로 줄어든다
  - `_active`, `_savedState` 삭제 (3 해결)
  - `removeMember` 의 리인덱싱 블록 (`:47-59`) 전체 삭제 → 보류 해제 후 `_members.erase(it)` + `_recalculateCentroid()` (1 해결)
  - `isChecked` → `g->IsInteractionSuspended()`. 선형 탐색 불필요
  - `activeMembers` → `_members` 필터
  - `_onControlChanged` (`:149`) · `_recalculateCentroid` (`:183`) 의 인덱스 순회 → 포인터 순회
- `setChecked(false)` 는 보류 상태가 아닌 기즈모에 대해 no-op (4 해결)
- 공개 시그니처(`addMember` / `removeMember` / `setChecked` / `isChecked` / `activeMembers`)는 유지. 외부 호출부 수정 불요
- `external/DashGizmo/include/GizmoGroup.h` 사본 처리 방침 확정 — 삭제 또는 동기화

### not-to-be
- 다중 그룹 소속은 지원하지 않는다. `bool` 로 충분하다는 전제(핸들당 gid 1개)가 깨지면 그때 소유 그룹 포인터/id 로 확장한다
- `_members` 의 raw 포인터 수명 계약은 이 티켓에서 정하지 않는다. 현재는 `m_gizmoGroups` 가 `m_handleGizmos` 보다 뒤에 선언되어 (`DashHandlePickingInteraction.h:277`·`:280`) 먼저 파괴되고, `m_handleGizmos` 는 슬롯이 축소되지 않아 (`:1997-1998`) 실제 댕글링은 발생하지 않는다. 보증이 선언 순서에 의존한다는 점만 기록해 둔다
- `_recalculateCentroid` 의 평균 방향 벡터 계산(`:192-205`)과 roll 성분 소실은 별도 축이다. `RebuildGizmoGroups` 쪽 주석("average euler inside gizmo group control seems to have issue", `DashHandlePickingInteraction.cpp:2296`)이 가리키는 문제로, 본 티켓에서 다루지 않는다
- 슬라이더 비활성 상태에서 `GetMin/GetMax` 대신 `GetRangeMin/GetRangeMax` 를 쓰는 우회(`:155`, `:188`, `:206`)는 손대지 않는다
