# #648 fe-safe: Set이 파일 하나에 묶인 뒤 입력 ODB 위치를 찾지 못한다

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/648
- Board status: Backlog
- Labels: ['bug', 'refactor']

## 현상

fe-safe(.stli) Set을 Start하면 입력 ODB의 위치를 찾지 못해 케이스가 Failed 처리된다. 정확한 실패 지점은 아직 파악하지 못했고, 문제가 있다는 것만 확인한 상태다.

## 원인 (추정)

fe-safe 러너는 자기 run 폴더 안에 앞선 Abaqus 해석의 ODB가 이미 놓여 있다고 가정하고, ODB 출처 목록을 Launcher Set의 `input_files`에서 만든다. #601 이후 Set이 파일 하나에 묶이면서 `input_files`에 .inp가 없고, Abaqus 결과는 다른 Set의 `AnalysisLauncher_<Set>/<DoeSet>/runsN`에 있어 두 가정이 모두 깨진다.

## 기대

- #616의 ODB Source Set 선택값으로 출처 Set을 정하고, 그 Set의 run 폴더에서 같은 run의 ODB를 찾아 fe-safe run 폴더에 배치한다.
- 못 찾으면 어느 경로를 봤는지 사유와 함께 Failed로 기록한다.

## 관련

- #616 (.stli 정책, ODB Source Set 콤보)
