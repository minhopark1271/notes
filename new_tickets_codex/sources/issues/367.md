## Goal
Launcher Set 이 DOE 에서 고른 **조합**(Geometry Set 1개 + Condition Set N개 — D23)을 `parameterization` 키로 자기 파일에 기록하고(T20), Reference File 콤보·변수의 `source` 표기·해석파일 자동 추천·part 매칭이 기준모델 목록 파일(원장)과 이 기록을 근거로 동작한다(T17).

**dev 반영 시점 제약 없음** — "쌓기 방식 제거"의 대체 기능은 #491 이 가져갔다. 두 작업은 모듈별 저장물(위치·형식·읽는 방식) 정비와 묶어 점진 진행할 수 있다. 해석파일별 자동 반복 실행은 sub-issue #502 다.

## Background
> source: wiki [Project-Manifest-4-Ticket-Slicing](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Project-Manifest-4-Ticket-Slicing) "PR 상세" G8 절 — 재절단 반영 완료

Launcher 는 파이프라인 산출물에 찍힐 조합 식별자(D19\~D21 개정 · D23)의 출발점이다 — 여기 기록된 조합에서 T27(#368)이 식별자를 만들어 Preprocessor → Builder → Runner·Optimizer 로 전달한다. `getMorphingSourceInfo`(`view/DashReferenceFileWidget.cpp:543-604`)는 Launcher JSON 에 존재하지 않는 섹션을 읽어 항상 빈 값을 돌려주고, 그래서 해석파일 자동 추천과 part 노드수 매칭이 지금 동작하지 않는다.

Launcher 만 검증 예외다 — **기록만 하고 막지 않는다**(D21). `input_files` 라디오 선택은 자유이고 조합 기록을 바꾸지 않는다.

**생성 시점 고정이 아니라 선택 시점 기록이다** — Launcher Set 을 만들 때는 아직 변수 선택이 없어 기록할 값이 없다(`createNewSet` 은 variant 만 쓴다 — `model/DashProject.cpp:592`). 값은 DOE 선택(#491 T24)이 채우고, 선택이 바뀌면 다시 쓴다. **Launcher 는 `referenceModel` 키를 두지 않고 `parameterization` 하나만 든다**(D18 부속) — D18 의 "생성 시점에 현재 기준모델을 고정" 방식을 이 티켓이 대체한다.

### 재절단 후 남은 몫의 성격
#491 이 실행 정합성(옳은 세트의 값만 옳은 파일에 적용)을 확보했으므로, 이 이슈의 두 작업은 **기록과 화면**이다 — 없어도 실행 결과가 틀리지 않는다. 그래서 반영 시점이 자유롭다.

## Technical Details

### as-is (재절단 후 잔여분)
- `AnalysisLauncher_{Set}.json` 에 조합을 기록하는 키가 없다
- `getMorphingSourceInfo`(`DashReferenceFileWidget.cpp:543-604`)가 존재하지 않는 섹션을 읽어 항상 빈 값 — 해석파일 자동 추천(`:344-358`)·part 노드수 매칭(`:878-895`)이 동작하지 않는다
- Reference File 콤보가 디렉터리를 훑어 후보를 채운다. 변수의 `source` 가 파일명만(경로 없음) — 쓰는 곳 `buildDvGeometry`(`viewmodel/DashGeometryParameterPresentationModel.cpp:107`), 경로를 되찾는 곳 4곳(`view/DashModelRunnerWidget.cpp:1444-1450`·`:1460-1463` · `model/DashAnalysisLauncher.cpp:1612`·`:1736`) + `findAnalysisFiles` 의 파일명 중복 제거
- Parameters 도크 제목에 Launcher 표기가 없다 — #366 T19 가 Condition·Morphing 까지 하고 Launcher 는 이 티켓으로 남겼다(D17)

### to-be
- `AnalysisLauncher_{Set}.json` 에 `parameterization` 키 — `geometry` 객체 1개 + Condition Set 이름을 키로 하는 `conditions` 맵(D23·D25), 각 항목이 `{deck{uuid, path}}`. 해석파일의 uuid 는 각 세트의 `referenceModel`(#366 T15)에서 옮겨 적는다. 스키마·쓰기·읽기는 한 몸으로 간다 — 구버전 자동 보충(backfill)은 **생략**(호환성 포기 결정, "구현 설계" 절). 값을 채우는 지점은 #491 의 DOE 선택 처리 코드
- Reference File 콤보의 해석파일(`.dat`·`.inp`) 후보를 목록 파일 조회로 — 목록 밖 확장자(`.stli`·`.wbpj`·`.cdb`·`.dfsxml`)는 후속작업 2 까지 디렉터리 스캔 유지(콤보는 두 소스의 합) · 변수 `source` 를 파일명 → 프로젝트 루트 기준 상대경로로(연결·검증 키는 `referenceModel.uuid` — D24, `source` 는 표시·경로 복원용) · `getMorphingSourceInfo` 를 자기 `parameterization` 조회로 — 추천·매칭 기준은 **`geometry.deck`**(D25: morph 원본이고 형상은 조합 전체에 하나)
- Parameters 도크 제목의 **Launcher 표기**(D17): `{geometry.deck 파일명} +{조건 세트 수}`, 조건 세트 1개가 형상 해석파일과 같으면(uuid 비교) 접미 생략, `parameterization` 이 비면 기본 "Parameters"

- 옛 형식 읽기 제거 — 옛 프로젝트의 파일명만 있는 `source` 는 이 작업 뒤에도 읽힌다
- 구버전 자동 보충(backfill) — 생략(호환성 포기 결정). 키 없는 옛 파일은 empty 로 열리고 첫 DOE 선택이 기록을 만든다

## Design

### `parameterization` — 형상 1 + 조건 맵 (D25)
```json
"parameterization": {
  "geometry":   { "set": "<Set 이름>", "deck": { "uuid": "…", "path": "models/wing.dat" } },
  "conditions": {
    "<Set 이름>": { "deck": { "uuid": "…", "path": "…" } }
  }
}
```
- 읽는 쪽이 배열 위치로 짝을 맞추지 않는다 — 각 조건 항목이 자기 해석파일 정보를 직접 든다
- 형상 정보의 중복이 없다 — **모든 기준 해석파일의 형상은 같고 해석조건만 다르다**는 전제가 확정돼(D25) 해석파일마다 형상을 반복 기록할 이유가 없다
- `conditions` 가 세트 이름을 키로 하는 맵이라 같은 세트의 중복이 구조적으로 막히고, 조합 비교가 키 집합 비교로 끝난다
- **고정값이 아니다** — DOE 선택이 채우고 선택이 바뀌면 다시 쓴다. 하류 단계가 검증에 쓰는 기준은 DOE 실행 시점에 DOE Table 에 남는 기록(T27 — D26)이고, Launcher 의 `parameterization` 은 편집 중인 상태다

### 구현 설계 (2026-09-21 확정)

**값 타입 `model/DashParameterization`** — Launcher 비종속 이름·위치. T27(#368)이 DOE Table 스탬프에 같은 스키마를 재사용한다.

```cpp
// DashParameterization.h
class DashParameterization {
public:
    struct Entry {
        QString setName;
        DashSetReferenceModel deck;   // 세트 referenceModel 의 선택 시점 사본
    };

    bool isEmpty() const;
    const Entry& geometry() const { return m_geometry; }
    const QList<Entry>& conditions() const { return m_conditions; }

    void reset(const Entry& geometry, QList<Entry> conditions);
    void clear();
    void readFrom(const QJsonObject& root);
    void writeTo(QJsonObject& root) const;

private:
    Entry m_geometry;
    QList<Entry> m_conditions;   // setName 정렬·유일 — reset/readFrom 이 정규화
};
```

- deck 은 해당 세트 `referenceModel` 의 **값 사본**(참조 아님) — 세트 pin 변경을 자동 추종하지 않고, 동기화는 DOE 선택 시 재기록뿐
- mutator 가 전체 교체(`reset`)·`clear` 뿐인 것은 "선택이 바뀌면 다시 쓴다"의 타입 표현 — 부분 setter(`setGeometry`·`addCondition` 류)를 추가하지 말 것
- 이름 조회 accessor(`conditionDeck(setName)` 류)도 두지 않는다 — 현 소비자(도크 D17·추천/매칭·T27)에 필요 없음. 도크의 "조건 1개 uuid 비교"는 `conditions().first()` 로 충분
- JSON 의 두 인코딩(geometry 는 `set` 필드 내장 / conditions 는 이름 키 맵)은 `readFrom`/`writeTo` 안에만 존재하고 소비자는 Entry 어휘만 본다
- `isEmpty()` = 기본 생성 상태. empty 면 `writeTo` 가 키를 생략한다

**선행 리팩터 — `DashSetReferenceModel` 직렬화 2계층 분리**
- 키 없는 `fromObject`/`toObject`(값 계층 `{uuid, path}`) 추가, 기존 `readFrom`/`writeTo` 는 `referenceModel` 키 래퍼로(동작 무변경). parameterization 의 deck 은 `deck` 키 아래 같은 객체 형태
- "pinned 일 때만 기록" 가드는 키 계층 소관으로 유지 — `parameterization` 키의 생략은 `DashParameterization::writeTo` 의 `isEmpty` 가드가 같은 규약을 수행한다

**원장과의 관계** — 저장물은 원장을 모른다(uuid 만 보유, 포인터 없음). 조인은 소비 시점에 `DashProject::resolveSetReferenceDeck`(D16 경로) 재사용 — 단 **pinned deck 만** 태운다. D15 분기(미고정 → 활성 모델 pin)는 parameterization 에 부적용이다
- Phase 2 선행: 콤보 후보용 원장 열거 API — `DashReferenceModelLedger` 에 등록 항목 열거 추가, `DashProject` wrapper 로 노출, 확장자 필터는 호출부 책임

**보유·전파** — `DashAnalysisLauncher` 멤버로 보유, `loadSettings`/`saveSettings` 에 `readFrom`/`writeTo` 연결. `parameterizationChanged` 시그널 신설 → `updateParametersDockTitle`(`DashMainWindow.cpp:574`)에 Launcher 위젯 분기 추가(D17). `getMorphingSourceInfo` 는 파일 재파싱 대신 `m_analysisLauncher` 인메모리 조회로
- 생성 핸들러(`DashProject.cpp`)는 무변경 — Launcher 생성 분기는 이미 pin 을 타지 않아 D18 부속이 성립해 있다

**구버전 backfill 생략 (결정)** — 호환성 포기. `parameterization` 없는 옛 파일은 empty 로 읽혀 기본 동작(도크 기본 제목·추천/매칭 비활성)이고, 첫 DOE 선택이 기록을 만든다. 실행 정합성 영향 없음("재절단 후 남은 몫의 성격" 절)

**브랜치 순서** — #491 브랜치(`feat/doe-multi-condition-set`, 통합 브랜치 포함 상태)가 `feat/reference-model-manifest` 에 합류한 뒤 `feat/launcher-parameterization` 분기
