# #266 DOE JSON 설정/실행상태 분리 — 케이스 상태 단일 라이터

- URL: https://github.com/NumeRealWorks/DashOpti_GUI/issues/266
- Board status: Won't do
- Labels: ['refactor']

## Goal

DOE JSON 이 설정 파일이면서 실행 상태 저장소를 겸하는 구조를 분리한다.

> **좌표 기준**: `refactor/async-execution`

## Background

`AnalysisLauncher_Set{N}.json` 한 파일이 두 역할을 겸한다.

| 역할 | 내용 |
|---|---|
| 설정 | 설계변수, DOE Table 샘플, `input_files`, 방법·옵션 |
| 실행 상태 | 샘플별 `status` / `status_<analysisType>` |

실행 상태를 설정 파일에 쓰다 보니 "어느 시점의 설정 경로냐" 가 문제가 된다. 같은 필드를 두 곳이 다른 근거로 쓴다.

| 쓰는 곳 | 경로 근거 |
|---|---|
| `DashJobRunner::setStageState:1185` | `ctx.doeJsonPath` — 배치 착수 시점 스냅샷 |
| `DashAnalysisLauncher::onCaseStatusUpdated:1051` | `m_doeJsonPath` — 런처의 현재값 |

**happy case 는 깨지지 않는다.** 경로가 같으면 같은 값을 같은 파일에 두 번 쓸 뿐이다.

**재현**: 배치 실행 중 사용자가 다른 Set 을 선택해 `m_doeJsonPath` 가 바뀌면, 이후 전이가 배치 JSON 과 새 Set JSON 양쪽에 상태를 남긴다 — 실행한 적 없는 케이스의 Done/Failed 가 새 Set 파일에 생긴다.

#264 의 장부화로 폴백·FE-safe 기록이 `ctx.doeJsonPath` 스냅샷으로 바뀌어 범위는 줄었다. 남는 것은 런처의 이중 쓰기와 설계 자체다.

## Technical Details

`DashAnalysisLauncher::setSampleStatus:1045` 는 JSON 쓰기와 케이스 표 갱신을 겸한다 — 그 안의 `emit caseStatusUpdated(key, status)` 가 `DashAnalysisLauncher::caseStatusUpdated`(`h:57`)의 **유일한 방출점**이고 표는 거기에만 연결돼 있다 (`DashAnalysisLauncherWidget:155` → `DashDoeCasesWidget::updateCaseStatus`). 단순 삭제하면 상태 컬럼과 케이스 로그(`:1032-1043`)가 죽는다.

## 검토할 방향

- 실행 상태를 별도 파일(`.../runs/status.json` 등)로 분리 — 설정 파일은 읽기 전용에 가까워진다
- 또는 JSON 쓰기 책임을 러너 한 곳으로 모으고 런처는 표·로그만 담당 (분리 없이 정본만 단일화)

두 방향의 비용·이득을 티켓 착수 시 비교한다.

## Acceptance Criteria

- [ ] 케이스 상태를 쓰는 곳이 한 곳이다
- [ ] 배치 실행 중 Set 을 전환해도 배치와 무관한 파일에 상태가 써지지 않는다
- [ ] 회귀 없음 — 실행 중 케이스 표의 상태 컬럼과 케이스 로그가 계속 갱신된다
- [ ] Release 빌드 경고 0, `ctest` 전건 통과

## 종결 — 데이터 계층 축(Track B)으로 이관

본 티켓의 문제는 `AnalysisLauncher_Set{N}.json` 하나가 아니라 **`{Module}_{Set}.json` 패밀리 9종 전반**에 있고, 모듈마다 성격이 다르다는 것이 전수 측정으로 확인됐다. 비동기 실행 리팩터(Track A)와 무관한 축이므로 별개 작업 덩어리로 옮긴다.

**문서**: [설정·실행상태·산출물 3계층 분리 — config 파일 9종 필드 인벤토리](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/266-1-config-state-layer-separation)

### 종결 근거

1. **본 티켓의 "검토할 방향" 2안 중 하나가 성립하지 않는다.** `ModelBuilder_{Set}.json` 은 외부 도구(DeepOpt·MCU)가 `status` 를 되쓰는 **양방향 IPC 채널**이라(`"Done"` 을 쓰는 C++ 코드 0건 · `DashModelBuilder.cpp:1420` 주석 · 1초 폴링 구조), "라이터 1곳" 도 "별도 파일 분리" 도 그 모듈에서는 도구 계약 개정 없이 불가능하다. 열어 두면 오도한다.
2. **좌표가 Track A 에 묶여 있다.** 본 티켓은 `refactor/async-execution` + #264 관계로 등록돼 있으나 문제는 비동기가 아니라 데이터 모델이다. 그대로 두면 Track A 릴리스 창에 끌려간다.
3. **내용은 전부 보존됐고 오히려 늘었다.** 본 티켓에 없던 사실 4건이 실측으로 추가됐다 — 아래.
