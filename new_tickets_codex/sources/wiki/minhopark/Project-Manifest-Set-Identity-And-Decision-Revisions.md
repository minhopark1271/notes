## setId — 신규 결정

Set 의 안정 식별자. 이름(가변 — rename·번호 재사용)을 영속 조인에서 걷어내는 자리이고, D26 이 스탬프에서 Set 이름을 배제한 근거를 Set 참조 전반으로 일반화한다.

| # | 항목 | 결정 |
|---|---|---|
| SI-1 | 형식 | **12자리 랜덤 hex(v4 절단)** + 발급 시 프로젝트 내 중복 검사. 생성 순서는 id 에 싣지 않는다 — 필요 시 `createdAt` 필드. v5 파생 배제 — Set 은 안정된 자연 키가 없어(이름 가변) 파생 원천이 없다. 카운터 배제 — 고수위 유실 시 번호 재사용이 곧 재바인딩 결함의 재생산이다 |
| SI-2 | 저장 위치 | **각 `{Module}_{Set}.json` 의 `setId` 키가 정본.** 별도 Set 원장은 두지 않는다 — Set 은 파일별 영속이 이미 있어 원장 근거가 없다. setId → Set 역조회는 열기 시 전 Set 스캔(`restoreExistingModules` 가 이미 전 파일을 읽는다 — 추가 비용 0). 열기 시 중복 감지(json 손 복제) → 나중 파일 재발급 + 로그 |
| SI-3 | 발급·저장 시점 | **신규 Set = 생성 핸들러**(생성 시 json 이 어차피 써진다 — 추가 저장 규약 0). **구버전 Set(키 부재) = 열기 복원 시 발급 + 즉시 write-back 1회.** 쓰기 실패 = 로그 + 메모리 유지, 다음 열기 재발급. P5 와 무마찰 — P5 의 취지는 적재·해싱 지연이지 쓰기 금지가 아니다 |
| SI-4 | 이름의 지위 | **조인은 setId + `name` 병기**(referenceModel 의 `{uuid, path}` 동형), 불일치 시 Set json 이 정본. 대상: DOE Table 열 메타데이터 `{set, key}` · Launcher `parameterization` 의 `geometry.set`·`conditions` 맵 키. 접두 headers `{Set 이름}.{DV}`·model_info parameter 키·도크 제목·콤보 표시는 이름 유지(접두 파싱 금지 존속). 구 DOE Table(`{set: 이름}`)은 기록된 대로 해석 — 이름 폴백, 재기록 없음 |
| SI-5 | 조합 id 산식 | **정렬 연접 — `{geometry setId}+{condition setId 정렬 연접 ","}`.** 예: `a3f2c1e0b7d4+1f9e2a6c0d38,8b07c5e1f2a9`. 해시 없음 — 홉별 검증은 그대로 문자열 비교 1회, 멱등(같은 Set 집합 = 같은 문자열), 길이 13×(N+1). 자기 기술적이라 산출물만 열어도 조합이 보인다. **id 파싱 금지**(조인은 병기 필드) — `geometryDeck` 별도 동봉(D26)은 유지 |
| SI-6 | 산출물 폴더 전환 | **폐기(2026-09-22) — SI-6a 로 대체.** 종전 결정 원문: 별개 작업(이슈 덩어리)으로 분리 — 절차 2단계. ① 폴더명 스캔·파싱 소비자가 대상 식별자를 자체 보유(현재 이름, 추후 setId)하도록 먼저 전환 ② 그 뒤 폴더명 변환. ①이 끝나면 폴더명은 표시 전용이라 ②의 위험이 격리된다. 규모 실측: 중앙 헬퍼 `DashIOController::getModuleDir` 1곳(호출 72) + 우회 직접 구성 ~9곳 + 스캔·파싱 ~30곳/11파일 + 영속된 폴더명 값(Runner `modelBuilderFolder` · Optimizer 폴더 콤보) + `-MCU` 접미 관례 |
| SI-6a | 산출물 폴더 식별 (SI-6 대체) | **폴더명 `{Module}_{Set}` 유지 — 변환 없음.** 소비자는 setId 를 보유하고 사용 시점에 `DashProject::m_setIds` 색인(json 파일명 → setId)으로 이름을 역조회해 현행 `getModuleDir` 로 조립한다 — 조립 72곳 불변. 성립 조건 셋 — ① `renameSet` 이 산출물 폴더를 동반 개명(현행은 json 만 개명 — `DashProject.cpp:1485`). 실패 시 json 개명 롤백 또는 잡 실행 중 rename 거부 ② Set 참조를 보관하는 자리는 이름 대신 setId 보유 — Runner `modelBuilderFolder`(`DashModelRunner.cpp:489`) · Optimizer 폴더 콤보 · 폴더명 역파싱 3곳(`DashModelBuilder.cpp:1916` 등) ③ 동명 재생성 폴더 충돌 규칙 — **둘 다**: 삭제 시 산출물 폴더 동반 삭제(원천 제거 · 확인 다이얼로그 필수 — 현행 `deleteSet` 은 json 만 지운다 `DashProject.cpp:1005`) + 생성 시 동명 폴더 존재하면 거부 + 안내(삭제 실패·외부 복사·구 프로젝트 고아 폴더 방어). 사유 — 이름 폴더 유지로 구 앱 호환·`-MCU` 접미 판정 11곳이 그대로 성립하고, 두 명명 규칙의 혼재가 생기지 않는다. 선행: G9(#530) 머지 — 조건 ② 가 손댈 `loadModelInfoFromFolder` 와 자리가 겹친다. setId 자체는 통합 브랜치 반영 완료(#527) |
