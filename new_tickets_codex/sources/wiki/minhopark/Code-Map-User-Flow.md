# 사용자 단 모듈 ↔ 크리티컬 패스 코드 동작 대조표

> **성격**: 독립 참조 문서. 사용자가 화면에서 만나는 모듈마다 (1) 실제로 무엇을 하는지, (2) 그 동선의 크리티컬 패스에서 어떤 코드가 어떤 순서로 도는지, (3) 무엇이 갖춰져야 진입할 수 있고 무엇을 남기는지의 대조표. 선행·후행 열은 바로 앞뒤 한 칸만 적는다 — 모듈을 잇는 전체 흐름은 [[End-to-End-User-Flow]]
> **좌표 기준**: `dev` 실측 — Analysis Launcher·Data Preprocessor·Model Builder·Model Runner·Results Analyzer·Optimizer 는 `4c7608e`, Geometry Parameterization 2종·Condition Parameterization 은 `ac6e4e6`. 줄 번호·카운트는 각 모듈 문서 기준이다(유효기간 있음).
> **검증 수준**: 정적 코드 근거만. 빌드·실행 검증 없음.
> **용어**: 표 아래 "용어" 절에 모아 둔다.

화면은 dock 5종이다 — 좌측 **Project Tree**(프로젝트를 열면 제목이 프로젝트명으로 바뀐다) · **Modeling Tree**, 우측 **Parameters**, 가운데 **Mesh View** · **CAD View**, 하단 로그. 모듈은 전부 **Parameters** dock 안에서 사이드바 카테고리로 갈아 끼우는 스택 위젯이고, 그 안이 다시 탭으로 나뉜다. 아래 "사용자가 하는 일" 열은 이 dock → 탭 → 버튼 순서로 적었다.

모듈 목록과 순서의 근거는 `registerCategoryWidgets`(`view/DashMainWindow.cpp:517-525`)의 카테고리 7종이다 — 실제 dock 전환은 이 표가 아니라 선택 핸들러가 직접 한다. Geometry Parameterization 은 Set 생성 시 Morphing / CAD 두 경로로 갈리고 위젯·모델 쌍도 각각 별개이므로 두 행으로 나눴다. Model Builder · Model Runner 의 MCU 경로도 같다. Analysis Launcher 도 Init / Resample / Direct 3 variant 로 갈리지만 Resample 은 UI 만 있고 Direct 는 DOE 를 건너뛰는 곁가지라 한 행에 묶었다. Results Analyzer 는 카테고리가 아니라 6곳에서 생성되어 임베드되는 패널이다.

## 용어

### 이 문서의 표기 기준

- **해석 파일** — 솔버 입력 파일(`.inp`·`.dat`). 코드 주석은 deck 이라 부른다
- **활성 컨텍스트** — RW 가 해석 파일을 파싱해 만든 `DashAnalysisModelContext` 중 레지스트리가 활성으로 지정한 1개
- **대리모델** — Model Builder 가 학습시킨 AI 모델. 코드 구조상의 모델 계층과 구분한다
- **설정 JSON** — 모듈별 `configs/*.json`

### 형상 변형

- **모핑(morphing)** — 이미 만들어진 메시의 절점을 옮겨 형상을 바꾸는 방식. CAD 파라미터를 고쳐 재모델링·재메시하는 CAD 경로와 대비된다
- **볼륨 모핑 · 표면 모핑** — 변형 대상이 3차원 요소 전체인지 표면 절점만인지의 차이. 메시 품질 판정과 최종 산출은 볼륨 모핑이 한다
- **핸들(handle)** — 변형을 끌고 갈 제어점. 위치·방향 벡터와 변형 범위(Lower/Upper)를 갖는다
- **구속(constraint) · 비설계면** — 모핑 중 움직이지 않아야 할 면. 여기서 유도된 절점이 고정점이 된다
- **고정점** — 모핑 엔진 인터페이스에서는 변위 0 인 핸들로 취급된다

### 화면 조작

- **픽킹(picking)** — 렌더 화면의 클릭 좌표를 3차원 형상의 절점·면 id 로 되짚는 것
- **기즈모(gizmo)** — 선택한 핸들에 붙어 방향과 크기를 드래그로 조절하게 하는 3차원 조작 위젯
- **핸들데이터** — 핸들의 좌표·방향·범위·그룹을 담은 polydata 배열 11종(`DashHandleTypes.h` 의 `HandleArrayNames`)
- **구속오버레이** — 구속면·비설계면을 반투명 액터로 원본 형상 위에 겹쳐 그리는 표시. 표시 전용이라 고정점 산출에는 관여하지 않는다

### 파일 포맷

- **`.prt`** — Siemens NX 의 네이티브 CAD 파트 파일. 치수 수식(파라미터)을 그대로 갖고 있다
- **`.stp` (STEP)** — CAD 교환 표준 포맷. NX 데몬이 `.prt` 에서 변환해 내보내고 GUI 는 이것을 렌더링한다
- **`.inp`** — Abaqus 솔버 입력 파일
- **`.dat`** — Ansys Mechanical 솔버 입력 파일
- **FE 조건(FE Condition)** — 해석 파일에 적힌 하중·경계조건·열조건 등 유한요소 해석 조건
- **NSET** — 해석 파일의 절점 집합(node set) 이름

### VTK 자료형

- **VTK** — 시각화·형상 처리 라이브러리. 이 프로젝트의 형상 자료형은 전부 VTK 것이다
- **polydata (`.vtp`)** — 점·선·면으로 된 표면 자료형. 핸들과 표면 형상이 여기 담긴다
- **unstructured grid (`.vtu`)** — 3차원 요소로 된 볼륨 메시 자료형. 해석 파일에서 읽은 파트가 여기 담긴다
- **액터(actor)** — VTK 에서 화면에 그려지는 단위. 자료 + 매퍼 + 표시 속성의 묶음
- **스칼라 배열** — 점마다 값 하나를 붙인 배열. `ConstraintsAndHandles` 는 색칠과 판정을 겸한다

### 실행 구조

- **RW (Reader-Writer)** — 해석 파일을 읽고 쓰는 외부 모듈. 솔버별로 구현이 갈린다
- **액터 스레드** — RW 호출을 전담하는 별도 스레드. VTK 액터와는 무관한 이름이다
- **데몬** — 명령마다 새로 뜨지 않고 상주하며 stdin 으로 명령을 받는 외부 프로세스. NX · MCU · 민감도 3종
- **MCU** — 마이크로컨트롤러. 학습한 대리모델을 C 헤더로 인코딩해 펌웨어에 싣는 경로다

### 해석·분석

- **DOE (Design of Experiments)** — 설계변수 범위에 표본을 흩뿌려 해석 케이스 목록을 만드는 실험계획법
- **Sobol · Morris · SHAP** — 민감도 분석 기법 3종. 어떤 설계변수가 결과를 얼마나 흔드는지 본다
- **Pareto · Convergence** — 최적화 결과 플롯. 목적함수 간 상충 경계와 반복별 수렴 추이
- **KPI** — 해석 결과에서 뽑아내는 성능 지표. 고객사별 정의가 조건부 컴파일로 갈린다
