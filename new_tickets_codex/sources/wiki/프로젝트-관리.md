# 프로젝트 관리

DashOpti_GUI 를 굴리는 규칙의 목차다. 프로젝트에 처음 합류하면 아래 세 문서를 순서대로 읽는다.
규칙 변경은 해당 문서를 직접 고치면 된다.

| 문서 | 다루는 것 |
|---|---|
| [[저장소-관리-수칙]] | 브랜치 전략(`dev` / `main`), 코드 작업 절차(feature 분기 → PR → Review → squash merge), PR·Review 규약, Release/QC 이벤트 브랜치 절차(`version-rc*` 태그) |
| [[코딩-컨벤션]] | C++ 서식(clang-format, 조직 표준)·네이밍(Qt 스타일)·인코딩 규칙, git 훅이 강제하는 범위와 그 경계(커밋 시 서식, 푸시 시 네이밍, 개명 연쇄 확산 방지), 로컬 설정 |
| [[문서-관리]] | 문서를 어디에 두는지 — 수명(휘발성)이 위치를 정한다. 이슈·커밋/PR·저장소 `docs/`·Wiki·외부 도구가 담는 것, Wiki 와 `docs/` 의 경계 |

## 문서 형식

이 목차가 묶는 문서는 아래 형식을 따른다. 새 문서를 만들거나 고칠 때 맞춘다.

1. `# 제목` — 페이지명과 같게 쓰고 한 장에 하나만 둔다.
2. 제목 바로 아래 한 문단 — 이 문서가 무엇을 다루는지 한 문장, 그리고 상위 목차와 형제 문서 링크.
3. 본문 절은 `## N. 제목` 으로 번호를 매긴다. 절이 하나뿐인 짧은 문서는 번호를 생략한다.
4. 운영 문서를 추가하거나 개명하면 `_Sidebar` 도 같이 고친다. 위키 네비게이션은 그 한 장이 전부다.
