# 저장소 관리 수칙

DashOpti_GUI 저장소의 브랜치·PR·릴리스 절차다. 상위 목차는 [[프로젝트-관리]].
코딩 컨벤션(서식·네이밍·훅)은 [[코딩-컨벤션]], 문서를 어디에 두는지는 [[문서-관리]]에서 따로 다룬다.

## 1. 브랜치

- `dev`: 개발 브랜치. 모든 feature 작업은 여기서 분기하고 여기로 돌아온다.
- `main`: 배포 브랜치. QC를 마친 버전만 들어간다.
- 작업 브랜치는 `dev`에서 분기한다. 이름은 `feat/…`, `fix/…`, `chore/…`, `docs/…`, `refactor/…`, `perf/…` 접두를 쓴다.

## 2. 코드 작업 절차

1. `dev`에서 작업 브랜치를 분기해 수정한다.
2. `dev`로 유입시키는 PR을 작성한다.
3. Review를 받고 보완한다. 리뷰·적용을 보류하거나 폐기 예정인 PR은 draft로 돌린다.
4. Review가 끝나면 특별한 사유가 없는 한 **squash merge**한다. 작업 중 쌓인 중간 커밋이 모두 노출되면 로그 공해가 심해진다.
5. 병합된 브랜치는 확인 후 정리한다.
   - squash merge한 브랜치는 `git branch -d`가 "not fully merged"로 거부한다. 병합 기록이 남지 않아서다.
     `dev`에 들어간 것을 확인했으면 `-D`로 지운다.

## 3. PR과 Review

Review
- Reviewer는 아무에게나 지정한다. 특정 사람에게 집중시키지 않는다.
- 지정된 Reviewer는 최대한 빨리 처리하거나, LLM 리뷰를 돌리거나, 다른 사람에게 넘긴다.
- 급하면 직접 연락한다. 아니면 1일 정도는 기다린다.
- PR이 다루는 이슈가 리뷰로 인해 확장되면, 다른 이슈로 떼어낼지 신중하게 판단한다.

주의
- 코드에 자아를 담지 않는다. 작업물에 대한 비판은 작업자에 대한 비판이 아니다.
- 리뷰 결과 작업을 새로 해야 한다면 PR과 브랜치를 폐기하고 새로 시작한다. 그쪽이 더 저렴하다.
- 이 모든 비용을 줄이는 방법은 작업을 작게 자르는 것이다.

Tip — 이슈 자동 종료
- PR 본문에 `Closes #123` 을 쓰면 이슈와 PR 이 서로 연결되고, 그 PR 이 머지되면 이슈가 자동으로 닫힌다.
  손으로 닫는 일과 닫는 걸 잊는 일이 함께 사라진다.
- 키워드는 `Closes` 외에 `Close` · `Closed` · `Fixes` · `Fix` · `Fixed` · `Resolves` · `Resolve` · `Resolved` 가 같다.
  이슈마다 키워드를 붙인다 — `Closes #12, #13` 은 앞의 하나만 닫는다. `Closes #12, Closes #13` 으로 쓴다.
- **다만 자동 종료는 기본 브랜치(`main`)에 도달할 때 일어난다.** 이 저장소는 feature → `dev` 로 머지하므로
  PR 머지 시점이 아니라 그 변경이 릴리스를 타고 `main` 에 들어갈 때 닫힌다. 연결 자체는 PR 머지 즉시 걸리므로
  이슈 화면에서 어느 PR 이 처리했는지는 바로 보인다. 머지 직후 닫아야 하는 이슈는 손으로 닫는다.
- 다른 저장소의 이슈는 `Closes NumeRealWorks/DashOpti_GUI#123` 처럼 저장소를 붙여 쓴다.

## 4. Release / QC 이벤트 브랜치

절차 전문은 [[릴리스 / QC 이벤트 브랜치|릴리스-QC-이벤트-브랜치]]에 있다.

1. Release 시점에 `dev`에서 QC 브랜치(`rc/<version>`)를 개설하고 `<version>-rc0` 태그를 붙인다.
   QC 이슈를 처리해 바이너리를 전달할 때마다 rc 번호를 하나씩 올린다.
2. QC 이슈는 QC 브랜치에서 작업 브랜치를 분기해 PR → squash merge로 처리한다. `dev`에 바로 넣지 않는다.
3. QC가 끝나면 QC 브랜치를 `main`으로 **`--no-ff` merge**하고 정식 버전 태그(annotated)를 붙인다.
   그 버전으로 패키지를 만들어 Archive한다.
4. `main`을 `dev`로 **`--no-ff` merge**해 되돌린 뒤 로컬 QC 브랜치를 정리한다.
   원격 QC 브랜치는 남겨 둔다.

> squash와 cherry-pick은 **한 번 들어가고 버려지는 잎 브랜치**를 합칠 때만 쓴다
> (작업 브랜치 → `dev`, QC 작업 브랜치 → QC 브랜치, 핫픽스 브랜치 → `main`).
> 병합 후에도 살아남아 또 병합될 브랜치(QC → `main`, `main` → `dev`)에 쓰면
> 병합 기록이 남지 않아 **다음 릴리스가 충돌한다.**
