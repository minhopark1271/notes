# Execution 핵심 3건 교차 검토

2026-10-08. `execution_findings.json` EXDC-01~03과 인용 원문·카탈로그를 대조했다. 원본은 수정하지 않았다. 결론은 **01 범위 표현 보정, 02 확정 충돌 강도 완화, 03 폐기된 전제와 아직 유효한 키의 구분**이다.

## EXDC-01 — 일부 타당하나 양극단으로 단정하지 않기

`Issue-Revision-History.md:16–17`의 현재 #444는 측정과 기존 구조 개선을 우선하고 필요하면 파일을 분리한다. 이에 착수 관문을 맞추자는 권고는 타당하다.

다만 Codex AL-05(`new_tickets_codex/03_TASK_CATALOG.json:1081–1113`)가 요구한 것은 **설정/snapshot과 빈번한 상태의 기록 계약 분리, writer 정리, 행 단위 갱신**이다. 새 물리 파일 또는 모든 Set JSON 분할을 명시적으로 확정한 문장이 없다. validation도 쓰기량·행 갱신 계측을 포함한다. 따라서 AL-05 전체가 최신 정책과 반대라거나 새 파일을 필수로 만드는 작업으로 읽는 것은 과하다. 실제로 AL-05→AL-06의 기록 후 복구 순서는 #444→#441과도 방향이 같다.

Claude LCH-32(`new_tickets_claude/05-final/FINAL.md:1055–1060`)는 ‘분할하지 않음’ 결론을 적지만 LCH-07/08 효과 확인에 의존하고 로드 시간 실측에 의한 재검토도 남긴다. 무조건 영구 무분리 계약으로 확대하면 안 된다.

**권고:** `document_drift/medium`을 유지한다면 제목·요약을 ‘물리 파일 분리 여부의 측정 관문과 논리적 기록 분리를 구분해 최신 범위에 맞추기’로 좁힌다. Codex에서는 분리가 논리/물리 중 무엇인지 명확히 하고 물리 분할은 조건부임을 적으면 충분하다. Claude에서는 무분리 결론을 현재의 잠정 선택과 재검토 기준으로 표시한다. 전체 작업 취소나 ready 일괄 해제 근거는 아니다.

## EXDC-02 — 안전상 중요한 모호성이나 active_conflict 확정은 보류

Claude EXE-02(`FINAL.md:3003–3012`)는 ‘cancelAll 뒤 drainAll 즉시 반환’ **테스트**와 첫 소비자 비취소·SDK 협조 지점 대기를 동시에 적는다. 지적의 기술적 방향, 즉 취소 요청/논리 terminal/실제 작업·자원 회수의 분리는 타당하다.

그러나 즉시 반환 조건이 모든 실행 중 SDK 호출에 대한 제품 보장인지, 취소 가능한 시험 fixture에 관한 검증인지 원문에 적혀 있지 않다. 협조 fixture에서는 즉시 반환 시험과 비협조 소비자 대기 한계가 동시에 참일 수 있다. 실행 카드 자체도 한계를 명시하므로 ‘무조건’이라는 해석은 추가 전제다. 이번 검토는 실제 drain 구현도 검증하지 않았다.

**권고:** 확정 활성 설계 충돌의 수에는 넣지 말고 ‘취소 테스트 적용 범위·drain 완료 의미가 모호한 조건부 충돌’로 별도 표시한다. 현재 4분류만 사용할 경우 `active_conflict`를 유지하더라도 **확정 아님/조건부, confidence 중간**을 제목·집계에 반영해야 한다. 권고 자체는 유지한다: 미시작/협조/비협조 작업별 테스트를 분리하고 비협조 작업의 즉시 자원 해제를 보장하지 않는다.

## EXDC-03 — 스탬프 드리프트는 타당, uuid/tableId 폐기는 아님

현재 `Issue-Revision-History.md:9`가 폐기한 것은 `parameterizationId`와 최초 입력 영구핀이다. `referenceModel.uuid`(deck 식별)나 DOE `tableId` 자체를 폐기한 것이 아니다. 35행의 #643 식별 역할 정리는 27행에 따라 아직 추가 개정 계획이다.

따라서 Codex RES-12/13의 ‘다른 uuid/tableId 결과를 섞지 않음’(`03_TASK_CATALOG.json:1880,1925`)은 보수적인 충돌 방지 조건으로 여전히 양립 가능하다. 이 키들만으로 모든 append 허용 조건을 충분히 결정할 수 있다고 확정해서는 안 되지만, 그 조건을 삭제할 근거도 없다. ‘현재 두 키로 1차 정책을 세울 수 있다’는 문장도 최소 정책 선택 관문과 함께 읽어야 한다.

반면 Codex의 PR530 stamp 접점(`03_TASK_CATALOG.json:1910`)과 Claude PRE-29의 ‘스탬프 두 키가 D26으로 확정’(`FINAL.md:1375`)은 최신 #368 계약과 명백히 동기화해야 한다.

**권고:** `document_drift/medium`은 **폐기된 조합 스탬프 전제**에 한정해 유지한다. 제목을 ‘결과 포맷 계약에 폐기된 조합 스탬프 전제와 미결 append 기준이 남음’으로 좁히고, ‘uuid/tableId 자체 폐기 아님’을 명시한다. Set 묶음, deck, 실제 입력, 생성 버전의 역할 및 append 허용 행렬은 #643/#650 조율 관문으로 남긴다. 새 출처 계약 전체 완료를 포맷 검토의 무조건 선행으로 추가하지 않는다.
