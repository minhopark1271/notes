# board.txt 작업 대응 계획

## 목적과 기준

사용자가 지정한 board.txt의 기존 분류·계층 위에 Codex 작업 정의를 겹쳐 보고, 관계를 유지한 채 실행 작업 단위로 변환 가능한지 판단한다. 62개 이슈(상위 표시 항목17개)를 전수 대응한다. 줄 맨 앞 53~70은 보드 표시 번호이고 #번호가 GitHub 이슈 식별자다.

- 원본: 같은 폴더 `board.txt`에 사본 보존. 원본 수정 없음.
- 정의: `../../03_TASK_CATALOG.json` 123개. 2026-10-05 dev 기준임을 유지.
- 참고: Claude `05-final/FINAL.md`의 상세 분해와 설계 차이.
- 상태 비교: `../w4_review_2026-10-07/`의 2026-10-07 15:14 KST GitHub 읽기 스냅샷. board.txt는 16:44 파일이며 파일 내용/스냅샷 중 하나를 무조건 최신 정본으로 덮어쓰지 않는다.
- 이번 작업은 문서 간 범위 비교다. 최신 코드 빌드·실행·기능 완료 검증이 아니다.

## 역할

- geometry: 모핑·씬·창·생성기12개.
- execution: 실행·응답·비동기·표준화27개.
- downstream: 프로젝트·저장·식별·Launcher후속23개.
- root: 원본 파싱, 6대 핵심 축 겹침, 그룹/개별 작업 통합, 부모·중복·공백 검증, 보고서 생성.

## 규칙

- 기존 crosswalk의 tasks는 근거 연관도 포함한다. 동일 범위라고 간주하지 않는다.
- 주된 대응과 보조 관련을 분리한다. 작은 결함을 넓은 카드에 대응시켜도 카드 전체가 그 이슈와 같다는 뜻이 아니다.
- 부모를 별도 신규 구현으로 세지 않는다. 같은 카드에 모인 자식은 중복 발행하지 않는다.
- 원본 iteration/status/priority를 보존한다. 부모 W4를 미배정 자식에 자동 상속하지 않는다. High/Medium/Low를 Codex P1/P2/P3로 자동 치환하지 않는다.
- #530 폐기, #651/#652 병합, #471 대장 존폐, #444 분할 여부 등의 차이는 별도 검토 관문으로 남긴다.
- #664처럼 10월5일 카탈로그 이후 신설된 이슈는 작업 범위를 대조해 새 대응만 제안한다.
- GitHub 발행·수정 및 기존123개 정본 변경 없음.
