## Goal
프로젝트를 바꿔 열어도 나머지 모듈 위젯 7곳이 해제된 모델 포인터를 만지지 않게 한다.

## Background
> #549 / PR #550 작업 중 전수조사로 확인. #549 는 Model Runner(Sim·MCU) 2곳만 다뤘고, 같은 결함이 나머지에도 있다.

`DashProject::SetProjectPath()` → `clearAllSets()` 가 프로젝트 전환 시 Set 모델 9종을 전부 지우는데(`model/DashProject.cpp:79`, `:1252~`), 모듈 위젯은 `DashMainWindow::setupWidgets()` 에서 한 번만 만들어져 앱 수명 내내 산다. 전환 경로에 `setModel(nullptr)` 리셋이 없어(그 호출은 Set 삭제 경로 `onDeleteSetRequested` 에만 있다), 다음 `setModel` 의 "이전 모델 정리" 블록이 해제된 객체를 역참조한다.

## Technical Details

### as-is

전수조사 결과 — 모델이 `clearAllSets()` 로 삭제되고, setter 가 이전 모델을 역참조하는 위젯:

|---|---|--:|
| `DashAnalysisLauncherWidgetBase` | `m_analysisLauncher` | 16 |
| `DashModelBuilderMCUWidget` | `m_modelBuilder` | 9 |
| `DashDataProcessorWidget` | `m_model` | 6 |
| `DashConditionParameterizationWidget` | `mModel` | 6 |
| `DashModelBuilderWidget` | `m_modelBuilder` | 4 |

**`DashModelBuilderMCUWidget` 이 가장 확실히 터진다.** `view/DashMainWindow.cpp:948`·`:1484` 가 새 모델을 붙이기 직전에 **항상** `setModel(nullptr, QString())` 를 먼저 부르므로, 전환 후 MCU Model Builder Set 을 클릭만 해도 `DashModelBuilderMCUWidget.cpp:97~103` 의 `disconnect` 5개가 해제된 객체에 실행된다.

노출 없음으로 확인된 것(단순 대입만, 역참조 없음) — `DashDoeCasesWidget` · `DashReferenceFileWidget`. `DashAIGeometryGenerationWidget` 은 저장소 어디서도 인스턴스화되지 않는다.

### to-be
- 각 위젯의 모델 멤버를 `QPointer<T>` 로 바꾼다. 모델이 죽으면 null 이 되어 정리 블록을 건너뛴다 — 파괴된 QObject 는 연결이 이미 끊겨 있으므로 건너뛰는 것이 맞다. #549 와 같은 방식이다.
- 위젯마다 **"모델이 sender 가 아닌 연결"의 슬롯을 전수 점검**해 무가드 역참조에 널 가드를 넣는다. 그런 연결은 모델이 죽어도 살아남아 `QPointer` 만으로는 잠재 UB 가 확정 크래시로 바뀐다 — #549 에서 `onCadFileReadyForFileTable`·`onRunAIPredictionClicked` 2곳이 그랬다.
- 헤더 재포맷 비용 실측 합계 ±175줄(멤버 선언만 바꾸므로 `.cpp` 는 커밋에 오르지 않는다).

### not-to-be
- 수명·리셋 계약의 명문화 — #431 소관. 이 이슈는 그 계약이 서기 전까지의 방어다.
- `DashFeConditionValueDelegate::m_dataModel` — 2-인자 `setModel` 이 `if (!model) return;`(`DashConditionParameterizationWidget.cpp:273~275`)으로 빠져 delegate 갱신에 도달하지 않으므로 `QPointer` 로 해결되지 않는다. 호출 구조를 고쳐야 하는 별개 건.
- `m_geometryParametersCAD` — `clearAllSets()` 의 삭제 목록에 빠져 있어 프로젝트를 바꿀 때마다 CAD 모델이 **누수**된다(`model/DashProject.cpp:334` 추가, `:1032~1035` Set 단위 삭제만 있음). dangling 이 아니라 stale 참조라 성격이 다르다 — 별개 건.
