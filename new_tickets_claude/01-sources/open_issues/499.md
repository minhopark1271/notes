## Goal

**mesh-ops `dev` HEAD(`506f885`) 로 범프하고, 그 사이에 들어온 handle 생성기 계층을 GUI 에 랜딩한다.**

GUI 는 지금 handle 을 자기 코드로 만든다 — box lattice 는 `DashMorphingController::setHandlesBoxhandle`, marching plane 단면은 `libs/DashMarchingPlane`. mesh-ops 가 같은 두 생성기를 공개 API 로 제공하므로(`BoxHandles` · `SectionFrameHandles` + `section_frames()`), GUI 자체 구현을 걷어내고 그 API 위에 세운다.

**남은 산출물은 작업 1 · 2(생성기 랜딩)뿐이다.** 버전 범프와 고립 handle 통로는 끝났다.

**정책 (확정):** GUI 는 고립 handle 을 **항상 받아들인다** — `allowIsolatedHandles` 기본 `true`. 반경을 아무리 줄여도 동결이 거부되지 않고, 그 handle 의 처방은 달성되되 주변과 블렌딩되지 않는 국소 혹으로 남는다(`docs/morphing-policy.md` 6 절). UI 노출은 하지 않는다. #332-2 이후 `SamplingPolicy::allow_isolated_handles` 에 **같은 값**을 줘야 한다.

> 참고 — MeshOps 소스의 버전 표기가 어긋나 있다(`CMakeLists.txt` 0.4.0 · `vcpkg.json` 0.3.0). GUI 는 `find_package(mesh-ops CONFIG REQUIRED)` 에 버전 요구가 없어 영향이 없다. MeshOps 쪽에 별도 전달.

  | | as-is | to-be |

  | 조작 | gizmo 드래그가 handle 점을 직접 옮김 | `set_faces(BoxFaces)` — baseline 기준 **절대값** pose. baseline 을 옮기려면 `create(box->box())` 로 새 생성기 |
  | 반경 | `DashMorphingBasis::Freeze(points, kernelRadius)` 가 전 handle 에 스칼라 하나를 실음(`AttachUniformSupportRadius`) | `create()` 가 격자 간격 × `support_radius_scale` 로 유도하고 `support_radius()` 가 정본 |

  주의할 차이 — 결정이 필요하다:
  - mesh-ops `BoxHandles` 는 **내부까지 채우는** lattice 이고 GUI 는 shell 만 만든다. 내부 handle 을 받아들일지, 아니면 mesh-ops 에 shell 옵션을 요청할지.
  - mesh-ops 는 축당 분할 수가 **하나**(`num_subdivisions`)이고 GUI 는 축별 `gridX/Y/Z` 다. UI 를 줄일지, mesh-ops 에 축별 분할을 요청할지.
  - cylinder handle(`onGenerateCylinderHandles`) 은 mesh-ops 에 대응 생성기가 없다. GUI 구현을 남긴다.

## 설계 논점

- **live 생성기 vs raw polydata.** 현행 `DashMorphingBasis::Morph` 는 `displacement(span<Vec3>)` raw 경로다 — 처방을 GUI 가 target − baseline 으로 직접 계산한다. 생성기를 도입하면 `HandleConfiguration::capture(after, before)` motion 경로로 갈 수 있고, 그러면 `set_faces`/`set_edges` 로 놓은 pose 가 곧 처방이 된다. 어느 쪽으로 갈지, 두 경로를 얼마나 오래 공존시킬지.
- **handle polydata 소유.** 생성기는 output port 로만 handle 을 내고 raw polydata 를 공개하지 않는다. `DashHandlePickingInteraction::m_handleGeometry` 가 handle 을 직접 소유·편집하는 현행 구조와 충돌한다 — #428(핸들 데이터와 표시 코드의 결합 정리) 과 순서를 맞춘다.
- **영속화.** 생성기는 `dump()/load()` 텍스트 직렬화를 갖는다. 현행 handle 저장(vtp + JSON) 과 어떻게 맞출지, 마이그레이션이 필요한지.
- **gizmo 드래그.** 절대값 pose 계면에서 상호작용은 `set_face`/`set_edge` 단일 wrapper 로 표현된다. 드래그 중 매 프레임 `set_faces` 를 부르는 비용(전 lattice 재배치)이 허용되는지.
