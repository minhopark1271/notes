## Original Request
> #315 에서 Load 버튼이 그린 vtk 렌더 화면을 optimizer preview 가 덮어쓰는 케이스가 있음을 발견함. vtk 렌더 화면을 덮어쓰는 경우가 어디어디에 있는지, 그 각각의 경우가 의도치 않게 다른 모듈의 렌더를 덮어써서 복구하지 못하는 경우가 얼마나 있는지 실측해봐. 복구 경로를 지정하거나, 오작동하는 경우가 있다면 렌더 층을 분리하거나 해야할 듯

## Goal
공유 VTK 씬을 지금 어느 모듈이 그렸는지 외부에서 확인할 수 있고, 씬을 새로 그리는 어떤 경로도 다른 모듈이 그려 둔 화면을 예고 없이 지우지 않는다.

## Background

**모든 모듈이 renderer 하나를 나눠 쓴다.** `DashManager` 가 가진 `vtkRenderer` 1개와 `DashRenderingManager` 1개를 모든 모듈이 공유한다. `DashRenderingManager::Layer` enum 은 지오메트리 종류를 구분할 뿐이어서, 레이어 슬롯 5개에 그리는 모듈이 11개다. 실제 충돌은 모듈 단위로 일어나는데 이를 구분할 수단이 없다.

**12곳이 씬을 덮어쓰고, 그중 2곳은 복구가 불가능하다.** 코드 전체를 조사한 결과, 기존 화면을 지우고 씬을 새로 그리는 지점이 12곳이다. 그중 2곳은 지워진 화면을 되살릴 방법이 없다 — 하나는 Optimizer Preview 가 renderer 의 모든 actor 를 일괄 삭제하는 #316, 다른 하나는 split view 다 (아래 문제 상세 1). 최초 조사 (2026-09-08) 때는 13곳이었으나, Morphing Settings 프리뷰가 레이어를 지우던 1곳은 모핑 엔진 분리 (#406) 로 비파괴 오버레이가 되어 제외했다.

**이 문제가 #315 를 막는다.** #315 는 이미 로드된 파일에 대해 `Load` 재클릭을 무시하는 게이트를 넣으려 한다. 그런데 `Load` 가 그린 화면을 지우는 지점이 `Load` 자신 외에 5곳 있고 (모듈 전환 · Modeling Tree 항목 삭제 · Start Morphing · Model Runner Preview · Optimizer Preview), 지워진 화면을 되살리는 유일한 방법이 `Load` 재클릭이다. 소유자 확인 없이 게이트만 먼저 넣으면 화면을 복구할 수 없는 상황 5가지가 생긴다.

## Technical Details

### 해법 방향 — 2026-09-21 확정

**renderer 는 1개를 공유하고, 렌더링 데이터와 actor 는 각 모듈이 소유한다.** 최초 기안의 후보 4개 중 ① (씬 접근 단일 창구 + 소유자 태그) 계열로 결정. 세부 원칙:

- **소유와 창구의 분리** — actor 의 수명과 데이터는 모듈이 소유하되, 씬 등록·해제는 `DashRenderingManager` 단일 창구를 거친다. 모듈이 renderer 에 직접 붙이는 순간 아래 "관리 밖" 비대칭이 재생산된다.
- **인수는 파괴가 아니라 숨김** — 다른 모듈의 콘텐츠를 지우는 대신 visibility 를 끈다. `m_vtuVtkActors` 의 visibility 토글 캐시 (`view/DashMainWindow.h:254`) 가 이미 같은 패턴의 선례다.
- **유지 정책은 콘텐츠 부류별** — 문서형 (Project Tree Load 모델 · FE 해석 모델) 은 유지, 작업물형 (각 모듈의 preview · 결과) 은 모듈 이탈 시 폐기 (현행과 동일, 복구 = 재실행). 이 정책이면 추가 메모리 상주는 메시 1개분이다. 메모리 검토: `SetInputData` 는 참조 공유라 복사가 없고 (`controller/DashRenderingManager.cpp:523`), `DashManager` 는 이미 모핑 입력 메시 2벌을 렌더링과 무관하게 상주시킨다 (`controller/DashManager.h:147-149`).
- **공유 자원은 소유권 밖의 별도 정책** — 카메라 · scalar bar · cube axes · split view 의 `SetDraw` 는 씬에 하나뿐이므로 매니저가 중재한다. base actor 의 ghost 외형 변경·복원도 매니저 중재로 옮긴다.

이 결정에 따라 #316 · #319 가 본 티켓의 선행이 된다 (Related 참조).

### 현재 구조

공유 씬에 그려지는 콘텐츠와 관리 주체. 위 5행은 `DashRenderingManager` 가 목록으로 관리하고, 아래 4행과 split renderer 는 관리 밖이다.

| 콘텐츠 | 관리 위치 | 그리는 모듈 |
|---|---|---|
| `LAYER_BASE_GEOMETRY` | `m_actors` | Data Preprocessor · Project Tree Load(`.vtk/.vtu`) · Model Runner · Optimizer Preview (4) |
| `LAYER_COMPONENT_GEOMETRY` | `m_actors` | Data Preprocessor · Model Runner (2) |
| `LAYER_RESULT` | `m_actors` | Data Preprocessor · Model Runner (2) |
| `LAYER_MORPHING` | `m_actors` | Morphing Settings (1) |
| `LAYER_SELECTION` + arrow actor | `m_actors` · 전용 필드 | Condition Parameterization (1) |
| analysis model actor | `m_analysisModelActors` — 레이어 아님 | `DashAnalysisModelContextRegistry` |
| handle actor 4종 | 관리 안 됨 | `DashHandleVisualizer` |
| picking actor 4종 | 관리 안 됨 | `DashHandlePickingInteraction` |
| morphing preview actor 다수 | 관리 안 됨 | `DashMorphingController` |
| split renderer 2개 | 별도 `vtkRenderer` | Model Builder |

이 표의 비대칭이 복구 불가의 직접 원인이다. `clearLayer` · `clearAllLayers` 는 관리 밖 4행을 지우지 못하고, 반대로 renderer 를 직접 순회하며 지우는 코드는 관리 목록 (`m_actors` 등) 을 갱신하지 못한다.

### 문제 상세

**1. split view 에 한번 들어가면 빠져나오는 경로가 하나뿐이다** (`DashRenderingManager.cpp:1209-1513`)
- `updateSplitView` 가 메인 renderer 를 `SetDraw(false)` 로 끈다 (`:1223`).
- 다시 켜는 `SetDraw(true)` 는 `clearSplitView` (`:1472`) 에만 있고, `clearSplitView` 를 부르는 곳은 `DashModelRunnerWidget.cpp:1292` 한 곳뿐이다. `isSplitViewActive()` 를 확인하는 곳도 같은 줄이 유일하다.
- 재현: Model Builder 에서 Test Results Preview 를 열면 (`DashModelBuilderWidget.cpp:1409`) 메인 renderer 가 꺼진다. 이후 Project Tree Load · 모듈 전환 · Optimizer Preview · Morphing 이 전부 꺼진 renderer 에 그려져 화면에 나타나지 않는다. 빠져나오는 방법은 Model Runner 의 Preview 실행 하나다.

**2. 모듈 전환이 `Load` 로 띄운 모델을 지운다** (`DashMainWindow.cpp:996-1014`)
- 전환한 모듈의 categoryName 이 `"Geometry Parameterization"` 이 아니면 BASE · COMPONENT 레이어를 조건 없이 지운다 (`:1000-1001`).
- BASE 레이어의 내용이 이전 모듈의 작업물인지 Project Tree Load 로 띄운 모델인지 구분할 방법이 없어서 생기는 동작이다.
- `.dat/.inp` 로 로드한 FE actor 는 레이어 체계 밖에 있어 모듈 전환에도 살아남는다. 같은 `Load` 인데 파일 확장자에 따라 모델이 지워지기도 하고 남기도 한다.

**3. base actor 의 반투명 (ghost) 표시가 원래대로 돌아오지 않는다**
- `updateComponentGeometry` (`DashRenderingManager.cpp:118-133`) 와 `updateFieldOutput` (`:177-191`) 이 base actor 를 wireframe · 불투명도 0.05 · 조명 off 로 바꾼다.
- 원래 표시로 되돌리는 코드는 `updateComponentGeometry` 가 빈 grid 를 받는 경우 (`:106-116`) 하나뿐이다.
- 지금은 모듈 전환이 base actor 자체를 지워버려 드러나지 않는다. 인수를 숨김으로 바꾸면, 반투명 와이어프레임이 화면에 남는 문제가 새로 드러난다 — 해법 방향의 "공유 자원 중재" 가 이 복원을 담당한다.

### 완료 조건

- 씬을 지금 어느 모듈이 어떤 경로로 그렸는지 외부에서 질의할 수 있다. #315 의 재클릭 게이트가 이 값을 판정 근거로 쓴다.
- 어떤 경로로 씬을 새로 그리더라도 split view 가 먼저 해제된다. 메인 renderer 가 꺼진 채 방치되지 않는다.
- 모듈 전환이 Project Tree Load 로 띄운 모델을 지우지 않는다. 파일 확장자에 따라 동작이 달라지지 않는다.
- 모듈을 벗어날 때 base actor 의 반투명 표시가 원래대로 복원된다.
- 문서형 / 작업물형 유지 정책이 코드에 정의되고, 문서형 콘텐츠의 명시적 해제 시점 (프로젝트 전환 등) 이 정해진다.

### 범위에서 제외하는 것

- `DashRenderingManager` 를 거치지 않고 renderer 를 직접 조작하는 21곳 (`DashHandleVisualizer` 4 · `DashHandlePickingInteraction` 6 · `DashMorphingController` 11) 을 매니저 경유로 옮기는 작업. 핸들·피킹·모핑 오버레이는 모듈 수명에 묶인 일시 표시물이라 소유권 대상이 아니고, 존재 등록만으로 충분하다. 필요 시 후속 티켓.
- `DashOptimizerWidget.cpp:1533-1543` 의 actor 일괄 삭제 제거는 #316 담당이다.
- `TopOptPostprocessDialog` · `DashPareto3DWidget` · `DashScatter3DWidget` 은 각자 별도의 `vtkRenderer` 를 만들어 쓰므로 (`TopOptPostprocessDialog.cpp:1240-1252` · `DashPareto3DWidget.cpp:128` · `DashScatter3DWidget.cpp:43`) 이 문제와 무관하다.
- `DashRenderingManager::clearModuleLayers` (`:587-592`) 는 인자를 무시하고 `clearAllLayers()` 를 부르는 미완성 함수지만 호출하는 곳이 없어 무해하다. 소유자 태그 구현 시 함께 정리한다.
- 최초 조사에 있던 미사용 함수 `DashMainWindow::updateCheckedPartsGeometry` 는 이후 머지에서 이미 삭제되어 과제에서 제외한다.
