## Goal
ModelRunner 의 NodeSet 소스 선택이 `ModelRunner_{Set}.json` 에 남아 재기동·Set 재진입 후에도 유지되고, 빈 값일 때 morph 가 콤보 deck 으로 폴백해 빈 경로 실패가 사라진다.

## Background
> source: wiki [Project-Manifest-4-Ticket-Slicing](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Project-Manifest-4-Ticket-Slicing) "PR 상세" G10 절

다른 티켓과 성질이 다르다 — 진입 1회 읽기 교체가 아니라 **비영속 사용자 선택의 영속화**다 (D18). 다이얼로그로 고른 NodeSet 소스가 저장되지 않고 `updateReferenceFileAndPart` 가 무조건 클리어(`view/DashModelRunnerWidget.cpp:1020`)해, Set 재진입·재기동 시 선택이 사라진다. 그 뒤 NodeSet 을 고르면 morph 자체는 성공하고 `_input_geometry.vtu` 추출 단계에서 `performMorphing` 이 false 로 끊긴다(`model/DashModelRunner.cpp:2206-2209`).

키·주제가 스탬프 계열과 이질이라 G7~G9 와 병합하지 않는다(S1). G6 뒤 아무 때나 진행 가능하고 G7~G9 와 독립이다.

## Technical Details

### as-is
- NodeSet 소스 `m_datFilePath` 가 메모리에만 있다. 쓰기 지점은 다이얼로그 핸들러 `onDatFileEditClicked` 하나
- `updateReferenceFileAndPart`(`DashModelRunnerWidget.cpp:1020`)가 무조건 클리어
- 빈 경로로 NodeSet morph 를 돌리면 morph 성공 뒤 `_input_geometry.vtu` 추출 분기에서 `performMorphing` 이 false 반환 (`DashModelRunner.cpp:2206-2209`)

### to-be
- `m_datFilePath` 를 `ModelRunner_{Set}.json` 의 **별도 키 `nodeSetSource`** 에 D14 와 같은 `path`·`uuid` 객체로 영속화
- 무조건 클리어를 저장값 복원으로 교체
- 빈 값·키 부재 시 morph 는 콤보를 채운 deck 으로 폴백
- IO 는 기존 `readConfigFile`(`DashModelRunner.cpp:516`)·`writeConfigFile`(`:537`) 재사용
- 해석은 원장 조회 없이 **경로 직접 사용 + 존재 검사**. 표현은 **루트 상대만** — 루트 밖 선택 시 프로젝트 루트로 복사(Add Files to Project 관례 — P1 동형) 후 상대경로 저장. **절대경로 영속 없음** (T18 스펙 수정 2026-09-21)
- uuid 는 T12(G6)의 `resolveUuid` 산식 — 원장 밖 파일이면 파생만 하고 원장에 쓰지 않는다. 조회는 원장을 거치지 않는 경로 직접 사용 + 존재 검사다

### not-to-be
- `referenceModel` 키 재사용 — 기준 deck 핀이 그 키를 가져간다(T23). NodeSet 소스는 별도 키다 (D18 재개정)
- 콤보 deck 과의 일치 검증 — 다른 파일을 고르면 NSET 라벨이 어긋날 수 있다. 문서 3 이 영속화와 함께 **수용한 위험**이다
- 원장 등록 — NodeSet 소스는 해석 deck 이 아니다. 복사 후에도 uuid 는 파생만 하고 원장에 쓰지 않는다

## Design

- 스키마는 D14 형태(`uuid`·`path`)를 쓰되 키 이름만 `nodeSetSource` 다 — `referenceModel` 과 자리를 다투지 않는다 (D18 재개정)
- **D24 적용 제외** — NodeSet 소스는 원장 조회를 타지 않는다(경로 직접 사용 + 존재 검사 — 루트 밖 선택은 복사로 흡수). uuid 는 파생 기록일 뿐 조인 키가 아니다. D24 의 uuid 1차 키는 원장 등재 deck 에만 해당
- 해석에 원장을 쓰지 않는 이유: 원장 미등재 파일이라 원장 키가 성립하지 않는다. 존재 검사만 한다
- `DashModelRunner` 파일이 G9(T23)와 겹치나 키(`nodeSetSource` vs `referenceModel`)와 코드 자리가 달라 순서 무관이다
