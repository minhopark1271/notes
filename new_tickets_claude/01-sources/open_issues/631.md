## 증상
LGE 빌드(`DASH_BUILD_LGE_COMPSPRING`)의 Max. Side Force KPI 가 operator 를 찾지 못하면 0 을 정상 값처럼 결과 XML 에 쓴다.

- `processSideForceKPI` 는 `LGE_SpringRule::calculateMaxSideForce` 의 반환값을 샘플 값으로 그대로 저장한다 (`model/DashAnalysisLauncherKPI.cpp:788-826`)
- 규칙은 카탈로그에서 `Force` 의 `X` · `Y` 하위 항목 operator 를 찾는다 (`model/extensions/enterprise/LGE_SpringRule.cpp:76-84`, `:116-130`)
- 그런데 현재 어댑터 카탈로그는 결과마다 main(`_`) 하나만 내고, 성분은 `component_labels` 배열로 낸다 (`model/preprocessor/wrapper/LegacyJsonPreprocessor.cpp:492-517`). 그래서 opX · opY 가 비고 규칙은 0.0 을 돌려준다
- 처리 로그에는 `LGE_SpringRule: Force X/Y operator not found (opX='' opY='')` 가 남는다

## 원인
#313(vcpkg 이전)에서 pass-through 래퍼가 `LegacyJsonPreprocessor` 어댑터로 바뀌며 카탈로그 형식이 바뀌었다(성분은 하위 키가 아니라 `component_labels`). 규칙은 옛 형식(`Force/X`)을 그대로 본다.

## 수정 방향
- 값을 못 구하면 0 을 쓰지 않고 그 샘플을 뺀다 — #573 의 "실패 샘플은 결과에 남기지 않는다"와 같은 규칙. 반환값에 성공 여부를 싣고 KPI 가 그 샘플을 건너뛴다
- operator 는 `Force/_` 에서 얻고, X · Y 성분은 `component_labels` 의 위치로 고른다 — 실제 sideforce.rst 로 grid 배열 이름과 성분 순서를 확인한다

## 확인 방법
LGE 빌드에서 Side Force KPI 를 돌린다. 위 로그가 남고 XML 의 값이 0 이면 재현이다.
