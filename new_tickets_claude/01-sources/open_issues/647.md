## 현상

- Ansys Motion(.dfsxml) 실행이 LGE 압축기 예제에 맞춰 하드코딩되어 있다. Launcher 탭의 Target Part가 "CBLOCK"으로 고정되고, dfsxml 생성·모핑 연결 규칙이 GUI 쪽 C++ 코드에 들어 있다.
- run마다 .dfsxml만 만들고, 함께 필요한 .dfmm·.dfg 파일은 만들지 않는다.

## 원인

Motion 워크플로를 처음 붙일 때 예제 하나로 동작을 맞췄고, 모델별로 달라지는 부분을 설정이나 Python 쪽으로 빼지 않았다.

## 기대

- run마다 .dfsxml·.dfmm·.dfg를 모두 생성한다.
- 모델 종속 규칙(Target Part, 파일 생성, 모핑 연결)을 GUI C++에서 DashOptiMBD의 AnsysMotion Python 코드로 옮기고, GUI는 입력 파일 경로와 DOE 값만 넘긴다.
