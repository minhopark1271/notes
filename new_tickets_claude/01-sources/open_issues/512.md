## 잔존 1곳이 실제 결함을 만든다

단순 정리 항목이 아니다. #506 의 새 순서가 이 펌핑에 노출된다.

```cpp
// view/DashGeometryParameterWidget.cpp
disconnect(cancelOnClose);                                    // :1442
dialog->setResults(...);                                      // :1443 — 안에서 processEvents(AllEvents, 100)
const auto decision = co_await qCoro(dialog.data(), &QDialog::finished);  // :1449 — 여기서야 connect
```

그 100 ms 안에 사용자가 Esc 를 누르거나 다이얼로그를 닫으면:

1. `QDialog::finished` 가 `setResults` **안에서** 발화한다
2. `cancelOnClose` 는 직전 줄에서 끊겼으므로 `qcStop_` 은 요청되지 않는다
3. 다이얼로그는 숨겨질 뿐 파괴되지 않는다(`WA_DeleteOnClose` 없음, 위젯의 자식)
4. 그 다음에야 `qCoro(dialog, finished)` 가 connect 한다 — 지나간 시그널은 잡지 못하고, 숨은 다이얼로그는 두 번 다시 `finished` 를 내지 않는다

| 귀결 | |
|---|---|
| 코루틴 | 영구 suspend. 프레임과 `DashMeshQcChecked`(볼륨 fixedIds 10^5 규모 포함)가 위젯 파괴까지 잔존 |
| `qcDialog_` | non-null 고정 |
| **Set Design Variable** | `onSaveDesignVariableClicked` 의 `if (qcDialog_)` 가드(`:1233`)에 걸려 **세션 내내 "already running" 로그만 남기고 동작하지 않는다** |
| 다이얼로그 | `deleteLater` 되지 않고 숨은 채 잔존 |

`Esc` 는 `QDialog` 기본 동작이라 별도 바인딩 없이 `reject()` → `finished(Rejected)` 를 낸다. 창이 "Analysis Complete" 로 바뀌는 순간이 곧 이 구간의 시작이라, 결과를 보고 바로 닫는 동작과 겹친다.

dev 의 `dialog.exec()` 에는 이 틈이 없었다 — exec 는 진입 전에 연결을 세운다. #506 이 `exec()` 를 `show()` + 시그널 await 로 바꾸면서 "연결 전에 발화할 수 있는 구간" 이 생겼다.

## 작업

- [ ] **1. `setResults` 의 `processEvents` 제거** — 근본. 진행 텍스트·버튼 활성화는 이벤트 루프가 다음 틱에 그린다. 호출자가 `show()` 로 띄운 뒤 `co_await` 로 양보하므로 강제 flush 가 필요 없다
- [ ] **2. 노출 구간 차단** — 1 이 랜딩하기 전이라도 호출자 쪽에서 닫을 수 있다. await 를 `setResults` 앞에 세운다

  ```cpp
  disconnect(cancelOnClose);
  auto decisionAwaitable = qCoro(dialog.data(), &QDialog::finished);  // 먼저 건다
  dialog->setResults(...);
  const std::optional<int> decision = co_await decisionAwaitable;
  ```

  또는 `cancelOnClose` 를 결정 수신까지 유지하고 취소 대신 결정 플래그로 분기한다
- [ ] **3. 회귀 테스트** — `test_meshqc_states` 는 다이얼로그를 모르므로 위젯 레벨이 필요하다. 최소한 "결과 표시 중 닫힘 → `qcDialog_` 가 비워진다" 하나
