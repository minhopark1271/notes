## 완료 기준 (2026-10-02 확인)

아래 항목을 모두 확인한 뒤 종료한다. 파일 이동이나 줄 수 감소만으로 완료 판정하지 않는다.

- [ ] **일반 처리 경로의 책임 분리** — 데이터셋 탐색·인덱스 매핑, DOE/설정 입출력, 리더·Load 상태, 응답 조회·VTK 미리보기, 결과 처리·저장의 소유자가 명확하다. `DashAnalysisLauncher` 본체는 이들을 호출하고 기존 공개 진입점·시그널을 연결하는 역할에 집중한다.
- [x] **공용 타입과 의존 방향 정리** — 공용 값 타입 때문에 하위 처리 코드가 `DashAnalysisLauncher.h`(구 `DashDataProcessor.h`)를 포함하지 않는다. 순수 매핑·파싱 코드는 QObject·VTK·프로젝트 전역 객체 없이 검증할 수 있다. 분리한 객체가 본체 전체를 전달받아 내부 상태를 대신 조작하는 구조로 바꾸지 않는다. **확인:** #593~#595·#619·#620 통합분의 공용 타입과 순수 함수, 독립 테스트 계면을 현재 `dev`에서 확인했다.
- [x] **상태·수명 계약 유지** — 리더와 해당 입력·솔버·응답·형상·Modal 상태의 소유 및 갱신 경계를 명시한다. 상태 묶음의 불변식을 유지하며, 중복 상태 저장소를 만들지 않는다. #573의 작업별 리더 수명·재진입·실패 후 재시도 계약을 유지한다. **확인:** #595의 `DashReaderSession`·`DashLoadedResult` 소유권과 실패 시 정리·재시도 계약, 세션 회귀 테스트를 확인했다.
- [ ] **기존 처리 클래스 재사용** — `DashDatasetScanner`, `DashResultProcessor`, `DashResultXmlWriter`, `DashResponseInitializer`, `DashPlotSpecBuilder` 등 목적지가 있는 책임은 기존 구현을 활용한다. 같은 책임의 새 관리자·병렬 구현을 추가하지 않는다.
- [x] **PM·위젯·KPI 호출부 반영** — `viewmodel/`뿐 아니라 `view/DashAnalysisLauncherWidget`에 남은 직접 모델 호출·시그널 연결도 변경 범위에 포함한다. 공개 API 변경은 호출자와 함께 반영한다. KPI 계산 내용과 이벤트 펌핑은 유지하고, 공용 타입·상태 접근의 연결부만 필요한 만큼 치환한다. **확인:** #621에서 호출부·연결을 점검하고 죽은 공개 진입점 제거, KPI 진입점 비공개화, 남은 API의 역할·신호 순서를 반영했다.
- [ ] **동작과 저장 결과 유지** — 선행 변경을 반영한 기준 커밋을 기록하고, 분해 전후의 표 구성·선택·응답 조회·미리보기·결과 XML·설정 JSON을 비교한다. 단일 파일/DOE, 일부·전체 샘플 누락, 후속 요청, 배치 후 미리보기, 실패 후 재시도, 모델·Set 전환 시 변경된 연결과 상태 정리를 검증한다. 결함 수정은 분해와 구분해 기록한다.
- [ ] **빌드·회귀 검증** — 각 증분에서 Release 구성 앱 빌드 오류 0, 관련 테스트와 Level 1 테스트 통과를 확인한다. 변경된 KPI 조건부 컴파일 경로도 포함한다. Abaqus `.odb`, ANSYS `.rst`의 Static/Modal, Motion `.dfr` 대표 시나리오의 실제 파일 확인 결과를 남긴다.
- [ ] **새 세션 검토** — 구현 후 별도 세션에서 과도한 변경, 실제 발생 시나리오, 컨벤션, 불필요한 기능, 프로젝트 컨셉 이탈을 검토하고 필요한 수정을 반영한다. 컨셉 확장이 필요하면 먼저 논의·문서화한다. 1~7단계의 리뷰 보완과 #642 독립 리뷰는 완료했다. 8·9단계 완료 후 전체 종료 검토는 남아 있다.
- [ ] **증분 통합** — #246의 호출부·게터 단위 치환 방식을 따른다. 각 증분이 빌드·동작 가능한 상태로 통합되어 있고, 남겨 둔 호환 진입점과 후속 이슈의 경계를 기록한다. #454가 일반 처리의 분리된 경계에서 후속 작업을 시작할 수 있다.
