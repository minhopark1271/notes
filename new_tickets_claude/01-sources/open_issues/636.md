## 증상
Output Response 에 Modal Frequency KPI 행이 있으면 Process 한 번에 "All processing completed successfully." 팝업이 같은 파일 목록으로 두 번 뜬다. Modal 행이 n 개면 n+1 번이고, 일반 행이 섞이면 한 번 더 뜬다. 팝업을 닫을 때까지 배치가 멈춘다. LGE_CompSpring 과 Dev 빌드(KPI 플래그 ON)에서 일어난다.

## 원인
- Modal KPI 가 함수 끝에서 `allProcessFinished` 를 직접 낸다 (`model/DashAnalysisLauncherKPI.cpp:535-537`)
- 래퍼 `processResultsWithKPI` 도 KPI 의 `processFinished` 를 모아 `allProcessFinished` 를 한 번 더 낸다 (`model/DashAnalysisLauncher.cpp:2014-2020`, `:2056-2058`)
- 위젯은 `allProcessFinished` 마다 팝업을 띄운다 (`view/DashAnalysisLauncherWidget.cpp:421-430`)
- #139 에서 래퍼가 완료를 모으도록 바꿀 때 Side Force 의 자체 방출만 지우고 Modal 의 방출은 남겼다. 나머지 KPI 4종은 `processFinished` 만 낸다

혼합 배치에서는 순서 문제도 있다. 래퍼는 KPI 완료 팝업을 일반 행 처리 **전에** 내고(`:2056-2062`), 안쪽 `processResults` 는 자기 완료 알림을 따로 낸다(`:1986-2000`).

## 수정 방향
1. Modal KPI 의 자체 방출(`DashAnalysisLauncherKPI.cpp:535-537`)을 지운다 — 나머지 KPI 와 같은 규칙
2. KPI + 일반 행 배치의 알림을 Process 1회당 1번으로 모을지 정한다. 모은다면 래퍼가 일반 행까지 처리한 뒤 한 번만 내고, 안쪽 `processResults` 는 생성 파일과 보고 줄을 래퍼에 돌려준다

## 확인 방법
Dev 빌드에서 Ansys Modal DOE 를 불러 Custom KPI 로 Modal Frequency 행 하나를 넣고 Process → 수정 전 팝업 2회, 수정 후 1회. 런처를 링크하는 자동 테스트 타깃은 없다.
