## 증상
모달 Name `Mode Shape` → x · y · z · magnitude 로 변위 결과를 찾는 규칙이 #313 이후 카탈로그 형식과 맞지 않는다. 지금 카탈로그는 결과마다 하위 키 `_` 하나만 내고, 성분은 `component_labels` 로 낸다 (`model/preprocessor/wrapper/LegacyJsonPreprocessor.cpp:492-518`).

- **미리보기 x · y · z** — 하위 키 `X`·`Y`·`Z` 를 찾는데 없어서 항상 "Could not find operator for: Mode Shape / x" 로 끝난다 (`model/DashAnalysisLauncher.cpp:2180-2193`, `:2226-2229`)
- **미리보기 magnitude** — `_` 를 가진 첫 결과, 즉 이름 정렬상 첫 결과를 쓴다 (`:2214-2225`). Abaqus 는 `E`·`RF`·`S` 처럼 `U` 보다 앞서는 결과가 있으면 변위 대신 그 결과를 그린다
- **배치** — `availableResponses["Displacement"]` 고정 키만 본다 (`model/preprocessor/DashResultXmlWriter.cpp:384-392`). Abaqus(`U`)는 전부 Missing 이다
- **단일 파일 배치** — 모달 선택은 카탈로그를 채우지 않고, 배치도 단일 파일이면 초기화를 건너뛴다 (`DashAnalysisLauncher.cpp:1203-1217`, `:1503-1504`). Mode Shape Preview 를 한 번도 하지 않고 Process 하면 Missing 이다

| | Ansys Mechanical | Abaqus |
|---|---|---|
| 미리보기 x · y · z | 항상 실패 | 항상 실패 |
| 미리보기 magnitude | 정적 `.rst` 실측 순서로는 맞음(모달 미측정) | `U` 앞 결과가 있으면 다른 결과 |
| 배치 | DOE 는 동작, 단일 파일은 Preview 가 먼저 필요 | 항상 Missing |

Abaqus 는 단일 파일 이름에 `modal` 이 있을 때만 모달 경로로 들어간다(DOE 스캔은 `.odb` 를 Static 으로 둔다). 스택 끝에서도 동작은 같다(`DashResultQuery::modeShapeLeaf`).

## 원인
- x · y · z → `X`·`Y`·`Z` 매핑은 #313 이전 카탈로그의 하위 키를 전제로 한다. #631 과 같은 원인이다
- 변위 결과를 고르는 규칙이 미리보기(성분 키를 가진 첫 결과)와 배치(`Displacement` 고정)로 두 벌이고, 툴별 이름(Abaqus `U`, Ansys `Displacement`)을 다루지 않는다

## 수정 방향
- 변위 항목을 한 곳에서 고른다 — 카탈로그 main(`_`) 중 operator 가 `U` 인 항목. 못 찾으면 다른 항목으로 넘어가지 않고 오류로 끝낸다(#493 규칙)
- 미리보기 x · y · z 는 벡터 배열의 성분 0 · 1 · 2 를 스칼라로 쓴다(배치와 같은 규칙, 순서는 `component_labels` 로 확인). 스택 끝 기준 `DashResultQuery::modeShapeLeaf` 와 `DashFieldPreview::selectScalars` 에 넣는다
- 배치는 고정 키를 같은 함수로 바꾸고, 단일 파일 배치도 시작할 때 카탈로그를 읽는다

## 확인 방법
- Ansys 모달 `.rst` 단일 파일 → Mode 1 → `Mode Shape / x` Preview: 지금은 "Could not find operator" 팝업이 뜬다
- 같은 파일을 새로 Load 하고 Preview 없이 Process: 로그에 `'Displacement' not in availableResponses` 가 남고 결과가 생성되지 않는다
- #626 의 `TestRealResultFiles` 에 모달 `.rst`·`.odb` 케이스를 더해 확인한다. 지금 로컬 실측 파일은 정적 해석뿐이다
