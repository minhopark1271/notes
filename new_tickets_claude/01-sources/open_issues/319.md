## Original Request
> #315 에서 Load 버튼이 그린 vtk 렌더 화면을 optimizer preview 가 덮어쓰는 케이스가 있음을 발견함. vtk 렌더 화면을 덮어쓰는 경우가 어디어디에 있는지, 그 각각의 경우가 의도치 않게 다른 모듈의 렌더를 덮어써서 복구하지 못하는 경우가 얼마나 있는지 실측해봐. 복구 경로를 지정하거나, 오작동하는 경우가 있다면 렌더 층을 분리하거나 해야할 듯

## Goal
레이어 체계 밖에 있는 actor 의 수명·상태 결함 4건을 없앤다 — 숨긴 채 방치되는 FE actor, 사용자 조작 없는 카메라 리셋, 정리 대상에서 누락되는 actor, 등록과 해제가 다른 경로를 타서 어긋나는 관리 목록.

## Background

씬 덮어쓰기 전수 조사 (#318) 중 발견한 4건이다. 공통점은 **`DashRenderingManager::Layer` 체계 밖에 있는 actor** 를 다루는 코드라는 것이고, 그래서 `clearLayer` · `clearAllLayers` 어느 쪽에도 걸리지 않는다.

**#318 과의 관계 (2026-09-21 정정).** #318 의 해법 방향이 "renderer 1개 공유 + 데이터·actor 는 모듈 소유 + 인수는 숨김 + 문서형/작업물형 유지 정책" 으로 확정되면서, 원래 "#318 종속" 이던 3·4 의 해법 방향도 정해졌다. 4건 전부 확정된 방향과 충돌 없이 지금 수정할 수 있으므로 본 이슈는 #318 본 구현의 **선행**이다. 특히 1 (FE actor 복원) 은 문서형 유지 정책의, 2 (카메라 리셋 제거) 는 공유 자원 중재 정책의 첫 적용이다.

## Technical Details

### 현재 동작

**1. Start Morphing 이 FE actor 를 숨긴 채 복원 경로를 남기지 않는다**
- `DashMainWindow.cpp:3257-3267` 이 `DashAnalysisModelContextRegistry::displayedActor()` 와 `m_vtuVtkActors` 전체에 `SetVisibility(false)` 를 건다. 주석은 "미리보기 겹침 현상 해결"
- 되돌리는 곳은 registry 의 `updateActor` (`DashAnalysisModelContextRegistry.cpp:141-171`) 가 actor 를 새로 만드는 경로뿐. 새 actor 는 `SetVisibility(true)` 로 시작한다 (`:162`)
- Modeling Tree 의 `dat_parent` 체크박스는 같은 파일이 표시 중이면 `setDisplayedContext` 를 건너뛰고 (`DashMainWindow.cpp:2454-2456` `isDisplaying` 가드) `ctx->controlVisibility` (`:2470` · `:2484`) 만 부른다. actor 레벨 visibility 가 false 면 파트를 켜도 아무것도 보이지 않는다
- 결과: Morphing 진입 후 FE 모델을 되살리는 유일한 수단이 Project Tree `Load` 재클릭 — 같은 경로라도 `setDisplayedContext` 가 `updateActor` 를 실행해 (`:63-66`) actor 를 재생성하기 때문이다. #315 의 재클릭 무시 게이트가 들어가면 복구 수단이 사라진다

**2. `updateActor` 가 무조건 카메라를 리셋한다**
- `DashAnalysisModelContextRegistry.cpp:166` 의 `renderMgr->resetCamera()` 에 조건이 없다
- `setDisplayedContext` 는 경로가 같아도 `updateActor` 를 부른다 (`:63-66`). 호출처: Project Tree Load (`DashMainWindow.cpp:2284`), Modeling Tree `dat_parent` (`:2455`) · `dat_part` (`:2479`), Optimizer Preview (`DashOptimizerWidget.cpp:1549`)
- 호출처 2곳에는 `isDisplaying` 가드가 생겨 같은 파일 반복 클릭은 회피되지만, 표시 모델이 바뀔 때 · `Load` 재클릭 · Optimizer Preview 에서는 사용자가 맞춰 둔 카메라가 여전히 초기화된다

**3. `clearAllLayers()` 가 analysis model actor 를 남긴다**
- `DashRenderingManager::clearAllLayers` (`:561-585`) 는 `m_actors` 5슬롯 · arrow actor · scalar bar · cube axes 를 지우고 `m_analysisModelActors` 는 건드리지 않는다
- 호출처 `DashModelRunnerWidget.cpp:1295` — "Clear all layers so repeated Preview always starts from a clean slate" 주석과 어긋난다
- 결과: Model Runner Preview 실행 시 FE 모델 actor 가 결과 위에 남는다

**4. Geometry Parameterization actor 의 등록과 해제가 다른 경로를 탄다**
- 최초 조사 때는 `DashGeometryParameter::m_actor` (`model/DashGeometryParameter.cpp:50-51` 생성) 가 renderer 에 추가된 적 없는 죽은 멤버로 보였으나, 이후 머지로 렌더 경로가 생겼다 — `DashGeometryParameterWidget.cpp:2096` → `DashManager::SetCurrentActor` (`controller/DashManager.cpp:1106-1112`) → `addAnalysisModelActor`
- 문제는 경로 불일치다. 등록은 매니저 경유인데 (`addAnalysisModelActor` 는 `m_analysisModelActors` 에 append, 중복 가드 없음 — `DashRenderingManager.cpp:1040-1044`), 해제는 renderer 직접 호출이다 (`DashMainWindow.cpp:3198` `GetRenderer()->RemoveActor(actor)`)
- 결과: 화면에서 사라진 actor 가 `m_analysisModelActors` 목록에 남고, 모델을 바꿔 등록할 때마다 항목이 누적된다. 목록을 순회하는 wireframe · visibility 일괄 처리가 죽은 항목까지 만진다
- 모듈 전환 시의 `actor->SetVisibility(isGeomParam)` (`DashMainWindow.cpp:1021-1023`) 은 이제 실제로 동작한다

### 완료 조건
- Morphing 진입으로 숨겨진 FE actor 가 모듈 이탈 또는 Modeling Tree 조작으로 되살아난다. `Load` 재클릭이 유일한 수단이 아니다
- 카메라 리셋이 사용자 조작 없이 일어나지 않는다
- Model Runner Preview 가 FE 모델 actor 를 결과 위에 남기지 않는다 — 파괴 확장이 아니라 `setAnalysisModelActorVisibility` 로 숨긴다 (#318 의 문서형 유지 정책과 정합)
- Geometry Parameterization actor 의 등록·해제가 같은 창구 (매니저 API) 를 타고, `m_analysisModelActors` 에 죽은 항목이 누적되지 않는다

### 범위에서 제외하는 것
- 4건을 하나의 추상화로 묶지 않는다. 공통 원인 (레이어 밖 actor 의 소유권 부재) 은 #318 본 구현이 다룬다
- `DashHandleVisualizer` · `DashHandlePickingInteraction` · `DashMorphingController` 의 직접 renderer 조작 21곳은 손대지 않는다 — #318 의 범위 제외 항목
- Optimizer Preview 의 actor 일괄 삭제가 이 actor 들을 함께 지우는 문제는 #316 이 담당한다
