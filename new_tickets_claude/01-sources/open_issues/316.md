## Original Request
> 2의 Optimizer Preview가 Load 시점에 사용하는 렌더뷰를 덮어쓴 자체가 문제인듯. 깨끗하게 해결할 방법이 있을까?

## Goal
Optimizer Preview 가 Project Tree `Load` 로 띄운 모델을 지우지 않고, 다른 모듈의 actor 를 renderer 에서 떼어내지 않는다. 프리뷰 실행 후에도 로드된 모델 · 카메라 · 표시 중인 해석 모델 컨텍스트가 유지된다.

## Background

공유 VTK 씬에 소유자 개념이 없는 문제 (#318) 중 Optimizer Preview 는 파괴 범위가 가장 넓다 — 레이어 3개를 지우는 데 그치지 않고 `renderer->GetActors()` 를 전부 순회해 **모든 `vtkActor` 를 제거**한다 (`view/DashOptimizerWidget.cpp:1532-1543`).

같은 앱에 비파괴 선례가 있다. Morphing Settings 프리뷰는 기존 씬을 지우지 않고 반투명 preview actor 를 위에 겹치며 (`controller/DashManager.cpp:947` `MorphingPreview`, 등록 `:1034`), 끄면 `removeMorphingPreviewActor` 로 원복한다 (`:1050`). 레이어도 카메라도 건드리지 않는다.

| | Morphing Settings 프리뷰 | Optimizer Preview |
|---|---|---|
| 기존 씬 | 유지, 위에 겹침 | 전체 actor 일괄 삭제 + `updateAllGeometry` 로 BASE 교체 |
| 타 모듈 actor | 무영향 | 전부 제거 |
| 표시 컨텍스트 | 손대지 않음 | 프리뷰 임시 파일로 `setDisplayedContext` (`:1549`) |
| 카메라 | 유지 | `resetCamera()` (`:1578`) |
| 되돌리기 | `removeMorphingPreviewActor` | 수단 없음 |

이 결함은 #315 를 막는다. #315 는 "이미 로드된 파일의 `Load` 재클릭 무시" 게이트를 넣는데, Preview 가 씬을 덮어쓴 뒤에는 재클릭이 유일한 복구 수단이다.

**#318 과의 관계 (2026-09-21 정정).** #318 의 해법 방향이 "renderer 1개 공유 + 데이터·actor 는 모듈 소유 + 인수는 파괴가 아니라 숨김" 으로 확정되면서, 본 이슈는 #318 에 종속된 후속이 아니라 **선행이자 파일럿**이 되었다. 아래 결함 대부분 (일괄 삭제, 표시 컨텍스트 이동, 무조건 카메라 리셋, 관리 목록 불일치) 은 소유권 모델 없이 지금 고칠 수 있고, 표시 방식도 Morphing 선례를 따르는 비파괴 오버레이로 확정 가능하다. blocked 상태를 해제한다.

## Technical Details

### 현재 동작

**actor 일괄 삭제 — 5개는 세션 끝까지 돌아오지 않는다**

`:1532-1543` 이 지우는 actor 중 5개는 추가하는 코드가 "처음 한 번만 실행되는" 가드 안에 있어 다시 추가될 경로가 없다.

| actor | 추가 지점 | 가드 |
|---|---|---|
| `m_morphingArrowActor` | `controller/DashHandleVisualizer.cpp:69` | `if (!m_morphingArrowActor)` |
| `m_surfaceHandleActor` | `:96` | `if (!m_surfaceHandleActor)` |
| `m_edgeActor` | `:134` | `if (!m_edgeActor)` |
| `m_mpMarkerActor` | `:150` | `if (!m_mpMarkerActor)` |
| `m_overlayActor` | `controller/DashHandlePickingInteraction.cpp:2865` | mapper 유무 분기 — 최초 1회만 추가 |

소유자 `DashHandleVisualizer` 는 `DashManager` 생성자 (`controller/DashManager.cpp:66`) 에서 1회 생성되고 재생성되지 않는다. 결과: Preview 를 한 번 실행하면 Geometry Parameterization 의 모핑 화살표 · 핸들 구 · 엣지 · 마킹플레인 마커 · 구속 오버레이가 앱 재시작 전까지 보이지 않는다.

같은 삭제에 걸리지만 복구되는 actor 도 있다 — `m_selectionActor` · `m_hoverActor` (`DashHandlePickingInteraction::Show()` 가 재추가), `m_surfaceEdgeActor` (`UpdateSurfaceGeometry()` 가 재생성), `m_cubeAxes` 와 morphing · cluster · physics preview actor (각 트리거가 재생성).

**일괄 삭제가 `DashRenderingManager` 의 관리 목록을 갱신하지 않는다**

renderer 에서만 떼어내므로 `m_actors` 에는 `LAYER_MORPHING` · `LAYER_SELECTION` 항목이 남는다. `hasFeConditionHighlight()` (`controller/DashRenderingManager.cpp:298`) 가 `m_actors` 를 읽으므로 화면에 아무것도 없는데 true 를 반환한다. 이 값을 믿는 `view/DashConditionParameterizationWidget.cpp:218` 의 재도색 가드가 일찍 반환해서, Preview 후 같은 조건 행을 다시 클릭해도 하이라이트가 복구되지 않는다. `controller/DashRenderingManager.h:82-84` 의 주석이 경고한 상황인데 가드가 `clearAllLayers` 만 상정하고 있다.

**로드된 모델 · 표시 컨텍스트 · 카메라 파괴**
- `:1527-1530` `registry.displayedActor()` 를 `removeAnalysisModelActor` 로 제거
- `:1545-1547` `LAYER_BASE_GEOMETRY` · `LAYER_COMPONENT_GEOMETRY` · `LAYER_RESULT` clear
- `:1549` `registry.setDisplayedContext(lastOutputFilePath)` — 부품 데이터를 얻기 위한 호출인데 부수효과로 표시 컨텍스트까지 옮긴다. `displayedContextChanged` 가 emit 되어 (`controller/DashAnalysisModelContextRegistry.cpp:69`) Condition Parameterization 위젯이 프리뷰 임시 파일 기준으로 갱신된다 (`view/DashMainWindow.cpp:432`). 사용자가 편집 중이던 해석 모델이 아니다
- `:1577-1578` `updateAllGeometry(combinedGrid)` + 무조건 `resetCamera()`
- 프리뷰 산출물은 `vtuBaseName + inputSuffix` (`:1489-1490`) 로 `.dat`/`.inp`, 위치는 프로젝트 폴더 하위 optimizer 디렉터리 → Project Tree 에 `Load` 버튼까지 달린다

### 완료 조건
- Preview 가 `DashOptimizerWidget` 소유가 아닌 actor 를 renderer 에서 떼어내지 않는다
- Preview 실행 후 로드된 모델이 씬에 남는다
- `registry.displayedFilePath()` 가 Preview 로 바뀌지 않는다. Condition Parameterization 위젯이 프리뷰 임시 파일로 갱신되지 않는다
- 씬에 기존 geometry 가 있으면 카메라가 리셋되지 않는다
- Preview 표시가 다음 `Load` 로 무효화된다
- `DashRenderingManager` 의 관리 목록과 renderer 의 실제 상태가 어긋나지 않는다

### 구현 방향 — 2026-09-21 확정
- 표시 방식은 Morphing Settings 선례를 따르는 **비파괴 오버레이** — 기존 씬 위에 preview actor 를 겹치고, 전용 등록·해제 API (`addMorphingPreviewActor` 방식) 로 매니저를 거친다. #318 의 "작업물형 콘텐츠" 정책과 정합한다
- 소유자 태그 · 소유자 질의 API 는 본 이슈 범위가 아니다 — #318 본 구현이 담당. 본 이슈는 태그 없이 성립한다

### 범위에서 제외하는 것
- CAD 경로는 손대지 않는다. `.stp` 프리뷰 (`view/DashOptimizerWidget.cpp:1607` 부근) → `loadStepFile` 이 `m_context->RemoveAll()` (`view/DashOcctViewWidget.cpp:210`) 로 OCCT 뷰에서 같은 종류의 덮어쓰기를 하지만 별건이다
- 프리뷰 명시적 off 토글 UI 는 만들지 않는다
- `view/DashModelRunnerWidget.cpp:1295` · `view/dialog/TopOptPostprocessDialog.cpp` 4곳의 `clearAllLayers()` 는 손대지 않는다. 후자는 자체 `vtkRenderer` 를 쓰므로 (`view/dialog/TopOptPostprocessDialog.cpp:1240-1252`) 공유 씬과 무관하다
- `clearModuleLayers` 미완성 함수 (`controller/DashRenderingManager.cpp:587-592`) 는 #318 이 판단한다
