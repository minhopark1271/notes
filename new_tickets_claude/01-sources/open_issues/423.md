## Goal

**설정 초기값(default)의 정책을 세우고 앱 전반에 반영한다.** 지금은 같은 설정 키를 여러 읽기 지점이 각자 리터럴 대역으로 읽고, `.ui` 초기값과 멤버 초기값이 같은 숫자를 따로 들고 있다. 값이 우연히 같아 증상이 없을 뿐, 어느 것이 "정책" 이고 어느 것이 "없을 때의 대역" 인지 코드에 구분이 없다.

이 티켓은 세 단계다.

1. **전수 조사** — 같은 키를 2곳 이상이 각자 대역으로 읽는 패턴, `.ui`/멤버 이중화, `QSettings` 대역을 저장소 전체에서 찾아 아래 표를 확정한다.
2. **정책 문서화** — 초기값의 분류·소유자·진입점·대역 사용 시 로그 규칙을 `docs/` 에 적는다.
3. **사례별 적용** — 모핑 반경부터. 이후 조사 결과의 우선순위대로.

## Technical Details — 정책 초안

### ⑴ 초기값을 세 종류로 나눈다

- **정책 default** — 사용자가 정하지 않았을 때의 값. 소유자 하나. UI 초기값과 모델 초기값은 소유자에서 읽는다.
- **escape(대역)** — 있어야 할 값이 입력에 없을 때. 정책값을 **재사용**하고 상수를 복제하지 않으며, 쓰였다는 사실을 WARN 으로 남긴다. 실행 경로에서 대역이 쓰였다는 것은 사용자가 정한 대로 돌지 않았다는 뜻이다.
- **sentinel** — `-1.0`, `""` 처럼 "없음" 을 뜻하는 값. 대역이 아니라 값의 정의역 일부다. 이름 있는 상수로 두고 비교 지점이 그 상수를 쓴다.

지금 코드는 셋을 같은 모양(`toDouble(리터럴)`)으로 쓴다.

### ⑵ 소유자

키마다 정책 default 를 소유하는 타입을 하나 정한다. 영속화된 값을 이미 드는 모델(`DashGeometryParameter` 등)이 1순위, 모델 없는 경로만 있는 키는 도메인 상수 헤더.

### ⑶ 진입점 하나

같은 JSON 절을 읽는 함수가 여러 개면(모핑 반경은 3개) 값 타입 하나와 `FromJson(obj)` 하나로 모아 같은 파서·같은 대역·같은 WARN 을 쓰게 한다. 호출부 시그니처의 낱개 `double`/`bool` 인자가 그 타입으로 바뀐다.

### ⑷ `.ui` 리터럴

코드에서 `setValue` 로 대체하거나, 남기면 소유자와 같은 값임을 테스트로 고정한다.

## 설계 논점 (착수 시 결정)

- 대역 사용 시 WARN 으로 둘지, 실행 경로(DOE·Runner·Optimizer)에서는 실패시킬지.
- `.ui` 리터럴 유지 여부 — Designer 에서 보이는 장점과 소유자 이중화의 단점.
- 센티널 `-1.0` 을 `std::optional` 로 바꿀지, 이름 있는 상수로 남길지.
- 조사 범위에 `enterprise/` 확장 규칙을 포함할지(`LGE_SpringRule` 이 이미 걸렸다).
