## 증상
결과 XML 작성기와 미리보기는 `GetFieldOutputVtk` 질의에 응답을 `operator` 로만 지정한다. 어댑터 `MatchResponse` 는 `field_output_name` → `operator` → `description` 순으로 응답을 고르는데(`model/preprocessor/wrapper/LegacyJsonPreprocessor.cpp:261-267`), `field_output_name` 을 싣는 호출자가 없어 항상 operator 로 고른다. operator 가 같은 main 항목이 둘이면 앞 항목을 돌려준다(`:247-249`).

- **배치** — 뒤 항목을 요청한 샘플은 grid 에서 요청한 배열을 찾지 못해 Missing 으로 빠진다 (`model/preprocessor/DashResultXmlWriter.cpp:813-836`)
- **미리보기** — "Cannot preview … has no array named …" 오류로 끝난다
- **Mode Shape · 원형도** — 배열을 이름이 아니라 성분 수로 골라, 다른 항목의 값이 조용히 쓰일 수 있다 (`:424-437`, `:1011`)
- **Ansys Motion 미리보기** — 질의에 응답 키를 아예 싣지 않는다(`state_id` 만, `model/DashAnalysisLauncher.cpp:2245`). 어댑터가 불일치로 거절하므로 질의까지 가면 "No field output …" 로 끝난다. 다만 지금은 위젯이 Load Step 을 `"States / State N"` 으로 넘겨 그 전에 형식 오류로 끝난다(#634). #634 를 고친 뒤에 드러난다

## 실현 가능성
- **Abaqus** — `result` 와 `operator_name` 이 같은 ODB 키다. operator 가 같으면 result 도 같아 카탈로그에서 하나로 합쳐지므로 Missing 은 나오지 않는다
- **Ansys Mechanical** — 실측 `.rst`(Student v261)의 main 13개는 operator 가 모두 달랐다(ENF · ENG_AHO · ENG_CO · ENG_INC · ENG_KE · ENG_SE · ENG_TH · ENG_VOL · EUL_NOD · NMISC · RF · SMISC · U). SDK 계약(`Types.hpp`)에 유일성 보장은 없다
- **Ansys Motion** — `operator_name` 값을 확인하지 못했다(파일 없음)

operator 중복은 재현 사례가 없는 잠재 결함이다. Motion 미리보기의 응답 키 누락은 코드상 항상 일어나지만 #634 에 가려져 있다.

## 수정 방향
- 카탈로그 main(`_`) 항목으로 만든 질의에 `field_output_name` 을 `operator` 와 함께 싣는다
  - `DashResultXmlWriter::writeFieldOutputToXml` — 일반 경로(`:761`). leaf 조회를 질의 앞으로 올리고 `:813-819` 의 재계산을 지운다
  - 같은 함수의 Mode Shape(`:420`) — 루프 밖 질의 객체라 반복마다 설정한다. 변위 항목을 고르는 규칙 자체는 #637 에서 고친다
  - 같은 함수의 원형도 변위 탐색(`:1003`)
  - 미리보기 — #619 머지 뒤 `DashResultQuery` 로 모인 한 곳(스택 끝 기준 `DashAnalysisLauncher.cpp:1618`). Motion 분기에도 응답 키를 싣는다
  - #626 의 Level 3 `TestRealResultFiles` 질의도 함께 맞춘다
- 선택 — `MatchResponse` 가 `field_output_name` 과 `operator` 를 함께 받으면 둘 다 맞는 항목을 먼저 고른다
- 같이 정리 — #627 에서 넣은 `result` 키 폴백(`DashResultXmlWriter.cpp:817-819`)은 dev 에서 내는 곳이 없다. #313 이후 어댑터는 `field_output_name` 만 낸다(`LegacyJsonPreprocessor.cpp:511`). 이 수정 때 지운다
- 손대지 않는 곳 — ILJIN 규칙(Abaqus 전용, 배열 이름 = operator), Function Expression(어댑터가 카테고리를 내지 않음)
