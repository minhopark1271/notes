## Goal

#313 이 `OperatorMorph`(가변 명령형) → mesh-ops 불변 4단 파이프라인으로 옮기면서 **대응이 없어 버리거나 GUI 가 직접 들고 있게 된 것**을 정리한다.

## Background

#313 §4 의 morphing 이행은 **컴파일과 기동에 필요한 최소한**만 했다. 그 과정에서 두 가지가 남았다.

1. mesh-ops 는 handle 반경을 **handle 마다** 갖는데 GUI 는 스칼라 하나로만 다룬다 → 이행에서는 전 handle 에 같은 값을 채워 넣었다
2. mesh-ops 에 이미 공개된 핸들 샘플링 알고리즘을 GUI 가 Eigen 으로 **중복 구현**하고 있다

> **버린 것 기록** — #313 은 solver 선택 · 스레드 수를 대응 부재로 **의도적으로 버렸다.** 필요해지면 별도 티켓으로 올린다.

## 1. handle 구성을 계면으로 노출 — per-handle `SupportRadius`

### As-is

mesh-ops 는 handle 반경을 **handle 마다** 갖는다 — handle polydata 의 `"SupportRadius"` point-data array (`HandleConfiguration.hpp`).

GUI 는 스칼라 하나로만 다루므로(`DashMorphingEngine::SetMorphingKernelRadius`) #313 은 `AttachUniformSupportRadius()` 로 **전 handle 에 같은 값**을 채웠다.

### To-be

per-handle 반경을 설정할 UI/계면을 만든다.

### 설계 논점

- **전역 반경 + per-handle override** 인지, **처음부터 per-handle** 인지. 전자가 기존 UX 를 깨지 않는다
- 자동 핸들 생성(`onGenerateAutomaticHandles`) 경로에서 반경을 어떻게 채울지

### 선행

**#333(`DashOptimizer::performMorphing` 의 kernelRadius 미전달)을 먼저 고쳐야 의미가 있다.** Optimizer 경로는 지금 반경이 10.0 으로 고정돼 있어, 계면을 열어도 그 경로에는 반영되지 않는다.

## 2. `selectHandlesGreedyByUnit` 을 mesh-ops `sample_handles()` 로 대체

> **#305(analyzer Eigen 정리)의 선행 조건**

### As-is

GUI 가 `controller/DashMorphingController.cpp:974~` 에서 직접 구현한다:

Wendland C2 커널 행렬 → `M.llt().solve(...)`(Cholesky) → `A * coeff` 잔차 → argmax 반복 채택.

### To-be

mesh-ops 에 **같은 알고리즘이 이미 공개돼 있다** — `MeshOps/Morphing/Sampling.hpp` 의 `sample_handles(pinned, samplable, SamplingPolicy)`:

> *"pinned 합집합을 초기 basis 로, 잔차의 argmax 를 반복 채택하고 최저 잔차 prefix 를 돌려준다"*

- `SamplingPolicy` 가 `tolerance` · `maximum_handles` · `regularization` · `stagnation_patience` · `minimum_improvement` 를 노출
- Cholesky 자리는 **MKL PARDISO** 가 대신한다

### 효과

교체하면 GUI 의 Eigen 선형대수 사용처가 `DashPearsonPlotter` **하나로 줄어** `eigen3` 제거가 사거리에 들어온다(#305).

### 리스크

**반복 채택 순서가 달라지면 선택되는 핸들 집합이 바뀔 수 있다.** 결과 동등성 확인 필요.

### 기존 이슈와의 관계

- **#327** (K 클램프가 고정점 제거 전에 이뤄져 오류 판정·팝업 수치가 어긋남) — 같은 경로를 고친다. 이 작업은 그 함수를 통째로 대체하므로 **#327 의 수정분이 증발할 수 있다.** `SamplingPolicy.maximum_handles` 가 K 클램프를 대신하므로, **설계 시 #327 의 판정 로직을 정책 인자로 옮기는지 명시**한다
- **#326** (`readCSVFile` 의 `std::stod` 예외 미포착) — 같은 파일 다른 영역. 논리 충돌은 없고 diff 충돌만 주의
