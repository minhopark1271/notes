## 1. `external/` 삭제

**안전성이 검증됐다** (#313 에서 실측):

- 생성된 `build.ninja` 에서 저장소 `external` 참조 **0건** (`external` 문자열 170건은 전부 MSVC 의 `-external:I` 시스템 include 플래그)
- `DashOpti.exe` 링크 입력이 전부 `vcpkg_installed/lib`
- import 폐포 171개 중 미해소 **0건**

**남길 것** — `external/DashOptiPythonExtensions` · `external/EncodeHeaderTool` (extension exe, 둘 다 `if(EXISTS)` 가드이고 현재 트리에 부재).

**할 일** — 삭제 + 클린 빌드 1회.

> 팀 전체가 로컬 `external/` 을 지워야 하므로 **공지 필요.** 디스크에서 수 GB 회수된다.

## 2. Qt6 deprecated 잔존 — `globalPos()` 14곳

**As-is** — 컴파일은 된다(Qt6 가 `globalPosition().toPoint()` 로 인라인 정의). deprecated 경고만 난다.

**To-be** — `globalPosition()` 으로 정리. `QPointF` 반환이므로 정수 좌표가 필요한 곳은 `.toPoint()` 를 명시한다.

**확인 완료** — `localPos()` · `QVariant::Type` · `AA_EnableHighDpiScaling` 은 **0건**(#313 이 이미 정리).

**착수 순서** — **#321(clang-format 전면 적용) 전에** 단독 커밋으로 넣는다. 순서가 반대면 의미 있는 변경이 재포맷 diff 에 묻힌다.

## 3. MSVC 재배포 런타임 배포를 `InstallRequiredSystemLibraries` 로 되돌린다

> **CMake 업스트림 대기 — 지금은 못 고친다**

**As-is** — `windeployqt` 를 걷어내면서 `--compiler-runtime` 이 하던 CRT 복사가 함께 빠졌고 **vcpkg 는 이걸 공급하지 않는다.** 개발 PC 는 시스템 설치본으로 돌지만 **비개발자용 패키지는 실행되지 않는다.** #313 은 고정된 툴셋 경로에서 직접 glob 하고 `CMakeLists.txt` 에 `//TODO` 를 남겼다(CRT 11개 + `vcomp140`).

**표준 모듈을 쓰지 못하는 이유 (실측)** — CMake 3.31 이 VS 18 의 redist 레이아웃(`x64/Microsoft.VC145.CRT`)을 몰라 `Microsoft.VC143.CRT` 를 찾다 `MSVC_REDIST_DIR-NOTFOUND` 로 끝난다.

**해제 조건** — CMake 가 v145 툴셋 redist 레이아웃을 알게 되면 수동 glob 을 지우고 모듈 `include` 로 대체.

**할 일** — CMake 릴리스 노트 추적. **이 항목만 `blocked`.**

## 4. `docs/vcpkg-migration-scope.md` 삭제

**사유** — 이 문서는 이행 계획을 담은 **migration log** 다. 이행이 끝난 지금 유지할 주인이 없고, 갱신해 두어도 **어차피 썩는다.** 실제로 #313 하나로 문서 전체가 이미 낡았다:

| 문서의 서술 | 현재 사실 |
|---|---|
| Phase 1 · 2 "미착수" | 완료 |
| `mesh-ops`: *"`vcpkg-vtk` feature 를 끄면 external VTK 9.4 유지 가능 — 탈출구가 설계돼 있다"* | 틀림. 현재 portfile 은 `-DDASH_MO_VTK_EXTERNAL=OFF` 를 **하드코딩**하며 default-features 비활성을 금지한다 |
| `preprocessor`: *"포트 없음 · upstream 저장소가 없다 · 가장 앞선 blocker"* | 틀림. 포트 `2026-09-10.1` 이 등록돼 있다 |

**할 일** — 파일 삭제. 이행 경위가 필요하면 **PR #313 본문이 정본**이므로 기록은 남는다.

**같이 볼 것** — `docs/vcpkg-migration-code-changes.md` · `docs/scratchpad/build-environment.md` 도 같은 성격인지 확인해 함께 정리한다.

> **운영 지식은 여기서 지우지 않는다** — 이행이 끝나도 계속 필요한 배포 구성(Qt6 플러그인 · CRT · MKL 복사 근거)과 GL 컨텍스트 가드 지식은 migration log 와 성격이 다르다. 추출은 별도 티켓에서 다룬다(docs format 확정이 선행).
