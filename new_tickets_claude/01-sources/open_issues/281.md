## Goal

**GUI 스레드 모핑 진입점 3곳**(2 · 5-Optimizer · 5-ModelRunner)이 `morphingSerialPool` WorkerJob 으로 이관되고, 그 선행으로 **Optimizer·ModelRunner 가 GUI 공유 RW 세션에서 전용 세션으로 떨어진다.** `MorphingGate` 의 함수 스코프 `Claim` 이 워커 스코프 `Reservation` 으로 늘어난다. 소유 view `processEvents` 5곳(QC 3 · Optimizer 2)과 중첩 이벤트 루프 1곳이 소멸하고, 죽은 진입점 1곳·중복 구현 1곳이 삭제되어 게이트 호출부가 **7 → 6곳**으로 줄어든다. 모핑 축 배제는 **`MorphingGate` 증명형을 유지한다** (설계 4안 중 A — Design 참조). RW 축은 세션 격리가 완결되어 `DashRwSession::MutationScope` 와 `isMutating` 이 소멸한다. **프리뷰 축(진입점 1·1b)은 무접촉** — 후속 과제로 분리한다.

### to-be

- **GUI 스레드 모핑 진입점 3곳** 처분 — 2 는 삭제(Claim 승격), 5 두 반쪽은 `morphingSerialPool` WorkerJob 이관.
- **`MorphingGate` 는 증명형 그대로 남는다** (설계 4안 중 A). 근거는 감사 요건 ③ 실패다 — 인스턴스를 나눠도 `vtkSMPTools::LocalScope` 가 VTK 전역 싱글턴을 통해 동시 실행을 깬다. `morphingSerialPool` 은 `maxThreadCount = 1` 로 유지한다(`ThreadPools.h:8`·`:21`).
- **RW 축 배제는 게이트가 아니라 격리 + 감금이다.** Optimizer·ModelRunner 가 `context->session()` 대신 자기 `DashRwSession::open(...)` 을 든다. 세 모핑 진입점이 각각 자기 세션을 들고, GUI 는 자기 세션을 계속 쓴다 — 거부 UX 가 필요 없다. `MutationScope`·`isMutating` 소멸.
- **두 축의 답이 다른 이유는 인스턴스 격리가 충분한가이다.** RW 모듈은 인스턴스당 격리가 되고 `DashRwThread` 감금이 실행 지점을 확정해 게이트가 불요하다. 모핑 DLL 은 인스턴스 격리는 되지만 VTK SMP 전역 때문에 동시 실행이 안 되므로 배제가 남는다.
- **토큰 수명은 GUI 진입 1회**다(`ThreadingContract` 7절, #277 신설). 세 진입점 모두 진입 1회 = Job 1개라 워커 스코프 `Reservation` 이 그 수명을 만족하지만, **QC 는 함수가 제출 직후 반환하므로 함수 스코프 Claim 으로는 부족하다** — 멤버 Claim 또는 Reservation 이 국면을 든다.
- **`Reservation` 해제는 `WorkerJob` 파괴에 묶여 있다.** `WorkerJob::start()` 가 task 사본을 풀에 넘기고 원본을 `m_task` 에 유지하므로(`WorkerJob.cpp:77`), task 캡처의 `shared_ptr<Reservation>` 은 **러너블 사본과 `m_task` 가 둘 다 죽어야** 풀린다(`tests/tst_worker_job.cpp:269-276` 이 그 수명을 직접 검증한다). 완료 슬롯이 `job->deleteLater()` 를 부르지 않으면 앱 재시작까지 게이트가 잠긴다.
- **엔진 소유 정리** — `DashManager::m_morphingEngine` 의 유일 소유자를 프리뷰로 만든다. QC 는 per-invocation 인스턴스를 쓴다. 4절이 이미 규정한 상태와 코드를 일치시킨다. **이것은 4안 공통 선행이다** — actor 안(B·C)도 호출 단위 직렬화라 공유 인스턴스의 2콜 프로토콜을 못 지킨다.
- **소유 view pE 5곳 → 0** · `dialog.exec()` 중첩 루프 → `open()` + `finished(int)`.
- **dead code 2곳 삭제** — 게이트 호출부 **7 → 6곳**, VTK writer 프로덕션 경로 **6 → 5곳**, `ExecuteOneSample` 호출부 **3 → 2곳**.
- **VTU/VTP 쓰기 live 4곳이 워커로 동반 이동** — 구 P5 가 워커화 작업 없이 종결한다. **워커가 파일을 쓰는 것은 규약 위반이 아니다**(7절 "워커 경계 규약" 디스크 쓰기 항) — 완결 판정은 워커 반환값이 소유한다. 본 축은 산출 파일의 참조(파일 테이블 행 · 렌더 등록)가 **완료 슬롯 소유**라 강제 종료 시 참조가 생기지 않는다. 장부 stage 나 temp+rename 은 불요.
- **워커 task 는 `WorkerJob::Task` 2인자 형을 쓴다** — `WorkerResult(const std::atomic<bool>&, const ProgressSink&)`(`WorkerJob.h:88`). **Phase C 는 `sink` 를 실제로 소비한다** — QC 다이얼로그의 `Step 1/2` → `Step 2/2` 진행 표시가 루프 안에 있다(`DashGeometryParameterWidget.cpp:1320`). 결과 페이로드는 `shared_ptr<Payload>` 값 캡처로 돌린다.
- **live 객체 경계 확립** — `performMorphingAndExport` 가 `DashMorphingInputSnapshot` 을 값으로 받고 `interaction`·`morphOperator` 인자를 잃는다. `RunVolumeMorphing` 이 DeepCopy 스냅샷으로 진입하고 결과에 GUI 배열을 심지 않는다.

## Design

### 현황 분석

RW 축이 먼저 착지했고 그 형태가 모핑 축의 선택지를 규정한다. **RW 는 세션 격리 + 전용 스레드 감금 2벌로 끝났고 게이트는 폐기됐다**(`eaa77a6`). 즉 레포에 선례가 있는 것은 "감금" 형이고, "감금 없는 인스턴스 격리" 형은 선례가 없다.

모핑 축은 그 근거를 소스 감사로 직접 만들었다(as-is 요건 표). **모핑 코드 자체는 깨끗하고, 배포본이 VTK SMP 전역을 통해 요건 ③을 깬다.** 원인이 `vtkSMPTools::LocalScope` 5곳 한 지점에 모여 있어 수정 범위는 작지만 우리 레포 밖이다.

**4안은 2배치 × 2변종이다.** A·A′ 는 진입점 배치가 완전히 같고 배제 기제만 다르며, B·C 는 배치가 같고 프리뷰 호출 형태만 다르다. 진입점별로 갈리는 것은 **프리뷰 하나뿐**이고 나머지 넷은 "워커냐 actor 큐냐" 2갈래로만 움직인다.

### 선택 — 방안 A (게이트 유지 + 모핑 3진입 워커화)

**선택 근거**: A 가 확인 요건 없이 지금 착수 가능한 유일한 안이다. A′ 가 넷 중 가장 좋지만(신설 코드 0 · 게이트 배관 소멸 · 배치 병렬화 열림 · Follow-up ⑴ 의 요청 병합·디바운스 불요) 요건 ③이 배포 0.0.4 에서 실패하고 그 해소가 레포 밖 일정에 걸려 있다. 그리고 **A 를 하는 동안 A′ 의 선행이 함께 쌓인다** — 두 안의 차이가 추가가 아니라 삭제이고(A′ = A + 게이트 철거 + 풀 병렬화), 프리뷰가 엔진을 단독 소유하는 것은 A 의 Phase B3 이 이미 한다.

**A 의 대가**: 게이트 배관이 그대로 남는다. 215-1 이 열거한 결함 3건이 전부 여기서 나오고, 본 티켓이 그 셋의 처방을 소유한다 — 토큰 스코프(to-be "토큰 수명은 GUI 진입 1회") · `Reservation` 수명(to-be "`WorkerJob` 파괴에 묶여 있다") · Claim 해제 시점(Phase C·D·E 의 완료 슬롯 `deleteLater`).

**기각된 대안**:

- **A′** — 요건 ③ 미충족. 선행이 레포 밖이라 기다리며 멈출 이유가 없다. Follow-up ⑶ 으로 전환 경로만 남긴다.
- **B·C** — `DashMorphingActor` 신설 비용이 `LocalScope` 5줄 수정보다 크고, 스레드 1개 감금이 **배치 샘플 병렬화를 영구히 닫는다.** B 는 프리뷰 거부가 대기로 바뀌어(대기 길이 = 앞선 모핑 1건) 게이트를 프리뷰 거부용으로 반쯤 남겨야 하고, C 는 본 티켓이 한 번 덜어낸 프리뷰 축(호출부 16곳 치환 + 병합·디바운스·결과 세대)을 도로 넣는다. 그리고 **감금은 인스턴스 분리를 대신하지 못한다** — actor 는 호출 단위로 직렬화하므로 A 의 `SetInitialHandles` → `ExecuteMorphing` 사이에 B 의 호출이 끼어든다. 즉 B·C 도 Phase B3 을 요구한다.
