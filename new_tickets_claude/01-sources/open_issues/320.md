## Original Request
> #315 에서 Load 버튼이 그린 vtk 렌더 화면을 optimizer preview 가 덮어쓰는 케이스가 있음을 발견함. vtk 렌더 화면을 덮어쓰는 경우가 어디어디에 있는지, 그 각각의 경우가 의도치 않게 다른 모듈의 렌더를 덮어써서 복구하지 못하는 경우가 얼마나 있는지 실측해봐. 복구 경로를 지정하거나, 오작동하는 경우가 있다면 렌더 층을 분리하거나 해야할 듯

## Goal
Modeling Tree 의 `.vtk/.vtu` 표시 토글이 실제로 해당 파일의 렌더만 켜고 끈다.

## Background
`DashMainWindow::m_vtuVtkActors` 에 **삽입하는 코드가 없다.** 선언 (`view/DashMainWindow.h:256`) 과 참조 8곳이 전부이고 8곳 모두 read 다. 항상 빈 맵이므로 이 맵을 조건으로 쓰는 분기가 전부 else 로 떨어진다.

그 결과 `.vtk/.vtu` 표시 토글 기능이 통째로 동작하지 않는다. 죽은 코드가 아니라 미구현이다 — 호출 구조는 다 있고 맵을 채우는 쪽만 비어 있다.

씬 인수 전수 조사 (#318) 중 발견했다.

## Technical Details

### as-is

`m_vtuVtkActors` 참조 8곳 전수 (전부 read, 삽입 0):

| 위치 | 코드 | 항상 빈 맵일 때의 동작 |
|---|---|---|
| `DashMainWindow.cpp:2284-2289` | Project Tree Load 의 제거 루프 | 루프 미진입 |
| `:2486-2487` | `vtk_parent` 자식 일괄 visibility | 무반응 |
| `:2544-2545` | `vtm_parent` 자식 일괄 visibility | 무반응 |
| `:2550-2551` | 체크 on — 캐시된 actor 표시 | 항상 miss → `loadVtkFile` (`:2554`) |
| `:2557` | 체크 off — actor 숨김 | **무반응. 끌 수 없다** |
| `:2729-2730` | `loadVtkFile` 진입부 캐시 분기 | 항상 miss → 매번 디스크 재read |
| `:3376-3379` | Start Morphing 의 "개별 VTK/VTU Actor 모두 숨기기" | 무반응 |

연쇄 결과:
- 체크 on 은 `loadVtkFile` (`:2727-2770`) 로 떨어지고, `isParent == true` 이므로 `updateAllGeometry` (`:2764`) → `LAYER_BASE_GEOMETRY` 를 포함한 씬 전체 인수. 파일 하나를 켜려는 조작이 다른 모듈의 렌더까지 지운다
- 체크 off 는 아무 일도 하지 않아 체크박스 상태와 화면이 어긋난다
- `vtm_parent` 아래 여러 `.vtu` 를 동시에 표시하는 것이 구조상 불가능하다 — `LAYER_BASE_GEOMETRY` 는 슬롯 1개다
- `loadVtkFile` 의 캐시가 항상 miss 라 토글마다 `vtkXMLUnstructuredGridReader` / `vtkDataSetReader` 가 다시 돈다

### to-be
- 체크박스 상태와 화면이 일치한다. 체크 off 에 반응하지 않는 현재 동작이 없어진다
- 체크 on 이 다른 레이어를 파괴하지 않는다
- 같은 파일 재토글이 디스크를 다시 읽지 않는다
- `vtm_parent` 일괄 토글의 요구 동작이 확정된다 — 다중 동시 표시가 요구라면 그것을, 아니라면 단일 표시 + 일괄 토글 UI 제거를 택한다. 현재 코드는 다중 표시를 전제로 쓰여 있으나 `LAYER_BASE_GEOMETRY` 슬롯이 1개라 성립하지 않는다

### not-to-be
- **해법을 본 티켓에서 확정하지 않는다.** 방향이 최소 3개다 — (a) `m_vtuVtkActors` 에 파일별 actor 를 채우고 renderer 에 직접 추가, (b) `DashRenderingManager` 에 파일별 actor 관리 창구를 두고 경유, (c) 다중 표시 요구를 접고 단일 슬롯 + 토글 UI 제거. (a) 는 #318 가 금지할 수 있는 직접 조작이고 (b) 는 #318 의 소유권 모델에 종속이므로 그 결과를 보고 결정
- Project Tree `Load` 로 `.vtk/.vtu` 를 띄우는 경로 (`onProjectFileLoadClicked` → `loadVtkFile`) 의 단일 표시 동작은 유지 대상. Modeling Tree 토글과 같은 메커니즘을 쓸지는 해법 선택에 달렸다
- `.dat/.inp` 파트 표시 (`ctx->controlVisibility`) 와 CAD 표시 (`handleCadToggle`) 경로는 별건
