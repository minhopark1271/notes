## 증상
Ansys Motion 결과에서 Output Response 의 Add 와 Preview 가 Load Step 을 `"States / State N"` 으로 넘긴다. 그런데 해석기는 `"State "` 접두(배치는 정수도)만 받는다. 코드 경로로 확인했고 `.dfr` 실측은 하지 않았다.

- **배치** — Function Expression 이 아닌 행은 모두 state 1 로 조회된다 (dev `model/DashAnalysisLauncher.cpp:1649-1676`, 스택 끝 `model/preprocessor/DashResultBatch.cpp:173`). 컴포넌트·Name 이 같고 State 만 다른 행은 같은 파일 `<comp>_1_0_<name>.xml` 을 덮어쓴다
- **미리보기** — "Invalid Load Step format for AnsysMotion" 오류로 끝난다 (dev `model/DashAnalysisLauncher.cpp:2235-2250`, 스택 끝 `model/preprocessor/DashResultQuery.cpp:58-60`)

## 원인
Load Step 트리는 Motion 시점을 `States` → `State N` 으로 보여 준다(`DashResultKeys::parseTimeSteps`). 그런데 Add·Preview 는 일반 해석처럼 `부모 / 자식` 으로 이어 붙인다 (`view/DashAnalysisLauncherWidget.cpp:832-836`, `:1040-1041`). `"State N"` 으로 바꾸는 곳은 선택 변경 처리뿐이다. dev 에도 같은 경로가 있어 #433 스택이 만든 회귀는 아니다.

## 수정 방향
- 한쪽으로 통일한다. 위젯이 Motion 이면 자식 텍스트(`State N`)만 넘기거나, 해석기(`DashResultQuery::parseMotionState`, `DashResultBatch::timeOf`, 처리기·작성기의 state 해석)가 `States / State N` 도 받게 한다
- 테스트에 화면 형식 `"States / State N"` 케이스를 더한다. 지금은 `"State N"` 과 정수만 쓴다

## 확인 방법
- `.dfr` 을 Load → Load Step `State 2` → Preview: 지금은 형식 오류 팝업이 뜬다
- 같은 컴포넌트·Name 으로 State 1 · 2 를 Add 하고 Process: 결과 파일이 `_1_0_` 하나만 남는다
