## Goal
파이프라인 산출물이 생성 시점의 **조합 id**(`parameterizationId`)와 **형상 deck**(`geometryDeck`)을 싣고, 각 홉이 자기 핀과 입력 id 의 일치를 검증한다. Geometry Set 을 지우고 동명·다른 deck 으로 재생성해도 기존 산출물의 무경고 재바인딩이 탐지·차단된다.

> 선행은 #367(G8 — 구현 완료 #510)과 **G11(#520 — setId 도입 + 조인 setId 전환)** 이다. 스탬프 배치는 D26, **산식은 SI-5 로 확정** — `{geometry setId}+{condition setId 정렬 연접 ","}`, 해시 없음·멱등·id 파싱 금지(조인은 병기 필드).

> **2026-09-21 재스펙** — SI-5 산식 확정 · D20 재개정(구버전 폴백 불도입 — 무스탬프 산출물 연결 차단 + 재실행 안내) · D21 부속(DOE Table 에 실행 템플릿 deck 기록 + 변종 경고 로그) 반영. 원문·사유는 처분 문서(Related).

## Background
> source: wiki [Project-Manifest-4-Ticket-Slicing](https://github.com/NumeRealWorks/DashOpti_GUI/wiki/Project-Manifest-4-Ticket-Slicing) "PR 상세" G9 절

Launcher 가 뱉은 데이터를 Preprocessor 가 파싱하고 Builder 가 학습하고 Runner·Optimizer 가 구동하는 전 과정이 **동일 DOE 조합** 기준이어야 하는데(D19 개정 — deck 단일성이 아니다. 해석 종류별 deck N 개가 한 DOE 에 들어오는 것이 정상이다 · D23), 현행은 deck 정체조차 중간 홉에서 유실된다 — Preprocessor 가 deck 라벨을 모듈 JSON 파일명으로 치환하고(`model/DashDataProcessor.cpp:2825-2838`), Builder 가 무해석 운반하고(`model/DashModelBuilder.cpp:545-556`), Runner·Optimizer 가 그 파일명으로 **사용 시점에 라이브 JSON 을 다시 열어** deck 을 해석한다(`model/DashModelRunner.cpp:1507-1527`).

산출물이 싣는 것이 deck 정체가 아니라 살아있는 Set JSON 참조라, `deleteSet` 으로 Geometry Set 을 지우고 동명·다른 deck 기준으로 재생성하면 기존 학습 산출물 전부가 무경고 재바인딩된다. 어느 홉에도 일치 검증이 없고 uuid 도 없어 탐지가 불가능하다 (문서 3 "파이프라인 스탬프").

## Technical Details

### as-is
- dataset XML 의 source 가 모듈 JSON 파일명("GeometryParameter_SetN.json") — deck 정체 유실 지점
- `model_info.json` 이 그 파일명을 무해석 운반
- Runner·Optimizer 의 deck 1차 출처가 라이브 체인(`getReferenceFileAndPart` `DashModelRunner.cpp:1473-1562`)
- Optimizer 프리뷰가 configs 전수 스캔 + 전량 morph (`view/DashOptimizerWidget.cpp:1468-1493`)
- DOE Table 은 실행마다 통째로 재기록된다(`model/DashDoeConfigManager.cpp:433-443`) — Table 하나가 run 묶음 하나
- 홉별 일치 검증 0

### to-be
- **조합 id 발급 + DOE Table 기록**(T27) — 나머지 세 티켓이 비교할 값을 만드는 자리. T21~T23 은 T27 이 낸 id 를 읽기만 한다. DOE Table 에 **실제 실행 템플릿 deck `{uuid, path}` 도 기록**(D21 부속 — 비차단), 변종 감지(템플릿 uuid ∉ 조합 deck 집합)는 경고 로그 1줄 — UI 안내 없음
- 3 스테이지 공통 패턴 — 최초 연결 시 입력의 `parameterizationId` 를 자기 핀으로 + {Set}.json 에 **즉시 저장** + 이후 다른 id 의 입력·연결·사용 **차단** + 무스탬프 구산출물 **연결 차단 + "재실행 필요" 안내**(D20 재개정 — 폴백 불도입)
- dataset XML 의 `model_info` 섹션 안에 `parameterizationId` + `geometryDeck` write-once 기록(D26)
- `model_info.json` 최상위에 같은 두 키 전사
- Runner·Optimizer 의 deck 1차 출처가 model_info 스탬프가 되고 라이브 체인은 part 명 조회 용도만 잔존(D20 재개정)
- Optimizer 프리뷰가 model_info 의 `geometryDeck` 1건만 morph — 산출물에 전사된 값이라 Launcher Set 이 지워져도 풀린다(D26)

### not-to-be
- 산출물 재스탬프 — 스탬프는 불변이고 재생성 시에만 찍는다
- 조합 상세·DV 키 매핑의 산출물 동봉 — 후속
- MCU 검증·스탬프 — 사용자 CSV 입력이라 deck-무관 계보다. 조합 미지정 허용
- 내용 드리프트(파일 덮어씀) 탐지 — uuid 가 상대경로 v5 파생인 현행에선 불가. sha256 이관은 후속작업 4
- Preprocessor 의 현행 source 치환 제거 — 유지하고 스탬프가 병행한다
- **deck 단일성 강제** — 같은 조합 안에서 deck 이 서로 다른 것은 정상이다(D23). 차단 기준은 조합 id 불일치뿐
- run 단위 식별자 — 같은 Set 에서 DOE 를 다시 돌리면 Table 은 교체되는데 옛 run 폴더는 남는다. 이 묶음의 범위 밖(후속)

## Design

### 홉별 핀·스탬프·검증 (D19 개정 — 단위는 조합 id)
| 모듈 | 핀 ({Set}.json) | 스탬프 (산출물 · write-once) | 검증 |
|---|---|---|---|
| Launcher (#367) | — 조합 **기록**만(`parameterization`, 편집 상태) | `DOE Table` 에 `parameterizationId` + 실행 템플릿 deck(T27 — D21 부속) — 실행 묶음에 고정 | 없음 — 기록만, 변종은 경고 로그 (D21) |
| Preprocessor | 최초 입력 연결 시 **입력 run 이 속한 DOE Table 의 id** | dataset XML `model_info` 섹션 — id + `geometryDeck` | 입력 id 와 자기 핀 일치 — 불일치 차단 (D20). **같은 조합 안의 deck 이 서로 달라도 정상** |
| Builder | 최초 dataset 연결 시 | `model_info.json` 최상위 — id + `geometryDeck` | dataset id 와 자기 핀 일치 — 차단. MCU 는 미지정 허용 |
| Runner · Optimizer | 최초 model_info 연결 시 | — | model_info id 와 자기 핀 일치 — 차단. 프리뷰는 `geometryDeck` 1건만 morph |

### 규칙 넷
- **핀은 id 를 든 첫 입력에서 1회.** 이후 다른 id 의 입력·연결·사용은 차단한다. "연결 시점 갱신" 개념은 없다
- **핀은 연결 즉시 저장한다** — 다음 저장 대기는 핀 없는 산출물 창(검증 기준값 부재)을 만든다. 연결 전 신규 Set 은 키 부재가 정상이다
- 차단 문구는 한 문형으로 통일 — "이 Set 은 {조합} 기준으로 고정되어 있습니다. 다른 기준 조합은 새 Set 을 만들어 사용하세요."
- **구버전 폴백 불도입** — 스탬프 없는 산출물은 **연결 차단** + "스탬프 없는 구산출물 — 재실행 필요" 안내(차단 문형 동형, D20 재개정). 라이브 상태에서 id 를 계산해 핀하는 것은 금지(D26). 라이브 체인은 part 명 조회 용도만 잔존

### 스키마 자리 (D26 확정)
- dataset XML — **`model_info` 섹션 안**의 `parameterizationId` 문자열 + `geometryDeck` dict. 루트 직하가 아닌 이유는 Builder 가 그 섹션만 head/tail 로 찾아 읽고 전사하기 때문(`DashModelBuilder.cpp:545-556`·`:1565-1620`). XML 어휘(`dict_item`·`dict`·`string`·`float`)로 충분하다 — 맵은 그대로 전사된다
- `model_info.json` — 최상위에 같은 두 키
- 홉별 검증은 id 문자열 비교. 조합 정의는 Launcher `{Set}.json`, 스탬프 기준값은 `DOE Table`
