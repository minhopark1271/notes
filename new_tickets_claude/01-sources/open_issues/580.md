## 현상
> PR #570 후속 — Enqueued 이후 상태 없는 `co_return` 4곳 (모핑 중 프로젝트 닫힘 · `ansysReady` 아님 · Motion 소스 dat 추출 실패 · Direct `taskCount == 0`) 은 기존 결함으로 후속 Issue.

DOE Start 뒤 이 경로들에 들어가면 케이스는 표에 Enqueued 로 남고, Stop 을 누를 때까지 Start 버튼이 잠긴다. PR #570 리뷰 (pullrequestreview-5337131871) 가 지적한 stall 클래스의 잔여분.

## 범위
- 건드림: `model/DashJobRunner.cpp` `runDoeJobs` · `runDirectJobs`, `model/DashJobRunnerAnsysMotion.cpp` `runAnsysMotionMorphingDoe`
- 안 건드림: `DashAnalysisLauncher` 의 런 추적 방식 (JSON 선등록 + `caseStatusUpdated` 집계) — 구조 자체는 유지. Enqueued 이전 사전 검증 3건은 #570 에서 완료

## 현재 구조
- `DashAnalysisLauncher::runDoeAsync` — DOE JSON 활성 키를 `m_expectedRunKeys` 에 넣고 추적을 켠 뒤 `DashJobRunner::runDoeJobs` 호출. 키 전부가 `caseStatusUpdated` 로 Done / Failed* / Cancelled 에 이르면 `analysisFinished`
- `DashJobRunner::runDoeJobs` — 사전 검증 실패는 `emitEnqueued` 이전에 `jobFailed` (#570 경계). 이후 실패는 케이스별 `caseStatusUpdated` 종결이 계약
- Direct 는 `runDirectJobs` 가 파일명으로 선등록된 키를 받고 `taskCount > 0` 일 때만 `jobStarted`
- Enqueued 이후 상태 없이 `co_return` 하는 곳 4군데: (1) `runDoeJobs` 모핑 `co_await` 뒤 프로젝트 닫힘 · `ioCtrl` 없음 (`DashJobRunner.cpp` 493-501), (2) `!prep.ansysReady` MAPDL 제출 생략 (525-529, 원문 `if (!ansysReady) continue;` 계열), (3) `runAnsysMotionMorphingDoe` 소스 dat 추출 실패 · 부재 (`DashJobRunnerAnsysMotion.cpp` 461-475) 와 모핑 뒤 프로젝트 닫힘 (507-515), (4) `runDirectJobs` `taskCount == 0` (`DashJobRunner.cpp` 701-703)

## 문제
런처 추적은 러너가 모든 키를 종결시킨다는 전제 위에 있는데, 4곳은 로그만 남기고 빠져나가 키가 영원히 Enqueued 다. (4) 는 `jobStarted` 도 안 내지만 런처가 이미 추적을 켠 뒤라 같은 결과.

## 변경
- 각 경로를 둘 중 하나로 확정: (a) 검사를 `emitEnqueued` 이전 사전 검증으로 옮겨 `jobFailed` 로 끝냄, (b) 활성 키 전부에 `caseStatusUpdated(key, "Failed" | "Cancelled")` 를 방출한 뒤 `co_return`
- (2) `ansysReady` — `prepareMorphingBatch` 가 Enqueued 이후에 초기화하므로 (a) 로 옮길 수 있는지 먼저 검토. 옮기면 `.dat` 도 모핑 전에 MAPDL 미설정을 거부하게 됨 (동작 변경, PR 본문에 명시)
- (3) 소스 dat 추출 실패 · 부재 — `sourceArray` 만으로 판정 가능하므로 (a) 후보. 프로젝트 닫힘은 (b) "Cancelled"
- (1) 프로젝트 닫힘 · `ioCtrl` 없음 — 모핑 완료 뒤 사용자 행위로 생기는 경로라 (b) "Cancelled"
- (4) Direct `taskCount == 0` — 선등록된 키가 전부 제출 실패한 상태이므로 `jobFailed` 로 런처가 `analysisFailed` 를 내게 함
- 기존 `if (!ansysReady) continue;` 계열 폴백 (`runTemplateFallback`) 의 같은 패턴도 함께 확인

## 기대
- 4 경로를 각각 강제로 유발했을 때 Start 버튼이 풀리고 표에 종결 상태 (Failed / Cancelled) 또는 `analysisFailed` 가 표시된다
- 정상 DOE 5경로 · Direct 4경로 · Stop 에서 상태·버튼 회귀 없음
- `runDoeJobs` · `runAnsysMotionMorphingDoe` · `runDirectJobs` 에 Enqueued 이후 상태 없는 `co_return` / `return` 이 남지 않는다
